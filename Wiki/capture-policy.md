# Wiki 프로젝트별 기록 정책

## 적용 원칙
[프로젝트 정책 레지스트리](project-policy.json)는 허용된 프로젝트 식별자, 기록 모드 및 공개 PR 자동 수집 대상의 단일 기계 판독 기준이다. 새 프로젝트의 자동 수집·기록 모드 변경은 사용자 명시 승인 후 레지스트리와 관련 문서를 함께 변경한다. 목록에 없는 기존 프로젝트는 명시된 결정 및 직접 검토 기록을 보존하며 자동 수집 대상으로 추정하지 않는다.

| 프로젝트 | 모드 | 기록 범위 |
| --- | --- | --- |
| `pawcycle` | full | 모든 의미 있는 작업·대안·실패·검증·진행; 공개 병합 PR 자동 수집 |
| `csforge` | full | 코드·커리큘럼·도식·QA·설계·CI; 공개 병합 PR 자동 수집 |
| `backend-systems-lab` | full | 통합 학습 프로젝트의 설계·실험·진행; 명시적 인수인계 |
| `logistics-learning` | full | 물류 설계·실험·진행; 상위 프로젝트 연결, 명시적 인수인계 |
| `devpedia` | design-only | 요구사항·도메인·API·DB·아키텍처·대안·설계 근거 |
| `dark-todo` | manual | 기존 승인 결정·스냅샷 유지; 상시 Journal 수집 제외 |
| `llm-wiki` | manual | 정책·스키마·Wiki 아키텍처 변경 |
| `shared` | manual | 공통 의사결정 및 검토된 재사용 지식 |

## 기록 수준
- full: 의미 있는 완료 작업, 설계 탐색, 보류, 실패·교정 및 검증 결과를 간결한 Journal/ledger로 남긴다. 중요한 확정 선택은 Decision으로, 반복 적용 가능한 교훈은 Lesson으로 기록한다. 작은 UI 수정도 의미 있는 작업이면 한 줄 기록한다.
- design-only: 설계 결정·검토 대안·미해결 설계 질문을 기록한다. DevPedia의 일반 구현, 커밋, 버그 수정, 테스트 일지는 제외하고 사용자 구현을 AI가 수행했다고 주장하지 않는다. [프로젝트 현황](projects/devpedia.md)을 따른다.
- manual: 사용자 요청 또는 이미 승인된 기록 범위의 중요 변경만 기록한다. 기존 기록은 삭제하지 않는다.
- 제안은 확정되지 않았음을 표시한다. 단순 질문·인사·반복·대화 원문·민감 정보는 제외한다.

## PawCycle 전체 이력 보존
[WIKI-0003](decisions/WIKI-0003.md)과 [원본 처리 원장](history/pawcycle-source-ledger/README.md)을 유지한다. 과거 PR/Issue는 번호별 처리 결과(독립 결정, 기존 기록 갱신, 실험·실패·보류, 별도 기록 불필요)를 남긴다. 자동 PR 영수증은 상세 검토를 대신하지 않으며 전체 이력 검토 완료를 뜻하지 않는다. 현재 코드·테스트·운영 원본이 현재 사실의 근거다.

## 통합 백엔드 시스템 연구실과 물류
기존 확정 [통합 프로젝트 현황](projects/backend-systems-lab.md), [물류 현황](projects/logistics-learning.md), [협업 방식](decisions/BLR-0014.md)을 따른다. 저장소 및 상세 Wiki의 존재·접근·쓰기 권한이 확인되기 전에는 중앙 Wiki를 사용한다. 이후 상세 원본에 도메인·교재별 설계/실험을, 중앙 Wiki에는 공통 결정·중요 진행·근거 링크를 보존한다. 양쪽의 기록 성공 여부를 분리한다. 저장소 존재 여부나 학습 진행은 이 정책에 고정하지 않는다.

## 저장 위치와 중복 방지
- projects: 최신 확인 상태, 다음 작업, 근거와 결정 링크.
- decisions: 하나의 독립적인 결정과 선택 이유.
- knowledge/lessons: 재사용 가능한 지식과 검증된 교훈.
- journal: 시간순 간결한 작업 결과. 자동 수집은 `repository#PR` 식별자로 중복 방지한다.
- history: 변경 경위와 원본 처리 이력. 원본 ADR·README 내용을 반복 복사하지 않는다.

## 수집과 승인
에이전트의 작업 종료 기록 평가와 GitHub Actions의 공개 PR 수집은 별개다. 자동 수집은 공개 병합 PR 메타데이터 영수증과 후보만 생성한다. [인수인계 계약](handoff.md)과 [에이전트 권한·검증·정리 기준](AGENTS.md)을 따른다. 접근 불가 또는 공개 불가능하면 기록하지 않고 미완료로 보고한다. 기존 리뷰 및 병합 승인은 유지한다.

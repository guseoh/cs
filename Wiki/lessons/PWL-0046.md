# 커밋한 통합 테스트 fixture는 실패·권한 중단 뒤에도 소유 범위에서 정리해야 한다

## Context

T10 parity test 는 BeforeEach transaction 에서 회원·catalog·SKU3개·order/payment·cart/coupon 등을 commit 했지만 AfterEach 가 없어 다른 Catalog cleanup 의 FK 실패를 유발할 위험이 있었다. DirtiesContext 는 DB 행 cleanup 을 대신하지 않는다.

## Observed lesson

소유 ID 를 보존하고 AfterEach 의 별도 transaction 에서 child→parent 로 삭제했다. first/second 뿐 아니라 missingInventorySku 세 번째 SKU 도 포함하고 전역 DELETE 로 다른 test 행을 지우지 않는다. polling 은 빈 결과에서 20ms 대기·interrupt 복원 후 명시 실패하며 timeout/lock assertion 은 유지한다.

## Alternatives and interpretation

Catalog 실패 전부를 이 fixture 로 단정하지 않았다. 반복 suite rerun·global truncate·DirtiesContext 만으로 해결됐다고 하지 않았다.

## Consequences and limits

assertion fault·권한 abort 뒤 cleanup 과 다른 회원/기본 category·brand 보존을 검증한다. committed fixture 가 필요 없는 테스트는 transaction rollback 을 사용한다. 동일 schema suite 순서 의존은 별도로 관리한다.

## Implementation and verification

#359 correction 의 UTC/Seoul parity13·관찰권한 skip·fault/abort cleanup 보고와 최신 CI 를 대조했다. #387의 고정 admin_id fixture 교정 및 #389 owned cleanup 도 같은 실패 경계에 연결한다. 모든 기존 suite 순서 문제가 해결됐다는 뜻은 아니다.

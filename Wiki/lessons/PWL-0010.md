# 초기 Discord 협업 알림의 false-green, HTTP 403 및 한글 PR 본문 손상

## Failure and correction sequence — 2026-07-03
최초 협업 워크플로는 Discord Webhook 전송 오류와 GitHub Actions 성공/실패 상태의 관계가 충분히 보호되지 않았다. [PR #9](https://github.com/guseoh/pawcycle-commerce/pull/9)의 본문과 스크립트 diff는 Webhook Secret 누락, HTTP 4xx/네트워크 문제 또는 재시도 후 실패에도 전송 스크립트가 성공 코드 0을 반환할 수 있던 **false-green** 경로를 보여준다. #9는 Secret 부재/실패를 종료 코드 1로 바꾸고, HTTP 2xx만 성공, 400/401/403/404 같은 비재시도 4xx는 즉시 실패, 429·5xx·네트워크 오류는 제한된 재시도(기본 3회) 후 실패하도록 수정했다. `workflow_dispatch` 수동 연결 테스트와 Repository Validation 성공/미통과 알림도 추가하고, 자체 Collaboration Notification을 감시하지 않아 재귀 실행을 피했다.

이어진 [PR #10](https://github.com/guseoh/pawcycle-commerce/pull/10)의 SRE handoff는 실제 [GitHub Actions run 28654703785](https://github.com/guseoh/pawcycle-commerce/actions/runs/28654703785)에서 **Discord 알림 HTTP 403, process exit 1**을 확인했다고 기록했다. 403의 근본 원인이 반드시 User-Agent 누락이라고 증명한 것은 아니다. 수정안은 공개 고정 `User-Agent` 헤더를 추가하고 URL/Secret/응답 본문을 노출하지 않도록 하며, 병합 후 실제 전송 재검증을 요구했다.

동시에 Windows 환경에서 PR #10 한글 본문이 물음표로 손상된 사례를 확인해, UTF-8 `--body-file` 경로, 원격 PR 본문 확인, U+FFFD/NUL/반복 `??` 차단 validator 및 테스트를 도입했다. 모든 인코딩 손상을 완벽하게 인지하는 복잡한 검증기는 선택하지 않았다.

## Verification boundary and learnings
#9/#10 문서와 diff에는 로컬 Python 단위 테스트/fixture·validator 보고가 있다. 특히 #10의 `pull_request_target` 이벤트는 **PR 분기 코드가 아니라 당시 기본 브랜치의 전송 스크립트를 실행**할 수 있어, PR 제출 시 나타난 403을 새 User-Agent 코드의 실패 결과로 해석하면 안 된다. PR #10의 실제 Actions 로그 전체를 이번 기록 작업에서 별도로 다운로드하지 않았으며, 실패 증거는 해당 PR 인수인계의 run ID/로그 요약에 근거한다.

**병합 및 CI 통과 ≠ 실제 Discord 채널 수신 검증.** 원본 #9/#10만으로 병합 후 HTTP 2xx와 채널 Embed 도착을 확인할 수 없으므로, 당시 해결의 실제 운영 확인은 미확인으로 남긴다. 원본 대장 #11 이후의 추가 작업이 확인되면 이 교훈 기록에 연결한다.

## Reuse rule
관측/알림 시스템에서 false-green은 장애를 숨긴다. Exit code, 비재시도/재시도 HTTP 분류, Secret 비노출, 실제 수신 테스트, 이벤트별 실행 권한과 브랜치 기준을 분리한다. 자동 생성된 PR 본문은 파일 작성 인코딩뿐 아니라 **원격 GitHub에 저장된 본문**까지 검증한다.


## #40의 후속 알림 correction

초기 false-green/HTTP403/인코딩 문제 다음의 상세 알림 변경은 [PWC-0043](../decisions/PWC-0043.md)에 연결했다. collector 부재를 exit0으로 숨기지 않고 실패시키며, 오래된 CI run SHA를 최신 PR SHA로 덮지 않고 수정 전204를 최종 안전 코드의 전송 증거로 재사용하지 않았다. #40 원본만으로 이후 기본 브랜치 Preview·채널 수신 완료를 확인한 것은 아니다.

# 컨테이너 실행과 정적 포트 설정만으로 localhost 접근을 보증할 수 없다

## Claim and applicability
Docker Compose의 publish 설정·`HostConfig.PortBindings`·컨테이너 `running` 상태를 실제 host listener와 동일시하지 않는다. 여러 Docker network가 `internal`인 환경에서는 runtime ports, host listener, HTTP readiness까지 확인한다.

## Observed failure
[PR #293](https://github.com/guseoh/pawcycle-commerce/pull/293)과 ARCH-012는 2026-09-11 OCI `app01` Docker Engine/Client 29.8.0에서 Application `app`과 Observability `observability` network 모두 `internal=true`였던 사실을 기록한다. Prometheus/Grafana는 `running=true`, restart 0이고 Compose·HostConfig에 loopback 9090/3000 publish가 있었지만, `NetworkSettings.Ports`는 `null`이었고 host listener도 없어 localhost health가 connection refused였다.

## Correction and verification method
Application network는 internal로 유지하고 Observability 공유 network만 일반 bridge로 변경했다. UI는 127.0.0.1 전용으로, Backend/metrics-proxy는 host 비공개로 유지했다. 저장소 회귀는 테스트 Application network를 `--internal`로 구성해 **실제 localhost HTTP 접근**을 확인하도록 수정했다.

## Limits
09-11 PR 병합은 **저장소 검증**이며 실제 운영 재적용 성공과는 별개다. Bridge 변경에 따른 outbound 노출 가능성·NSG·bind 주소를 함께 확인한다. 2026-10-25 운영 개요의 health 관측은 당시 제한된 범위만 뒷받침한다. 이번 작업에서는 Docker/OCI를 실행하지 않았다.

## 번호순 #293 재대조

원본의 running/restart0·HostConfig와 실제 runtime Ports null/host listener 부재를 대조했다. test Application network도 internal로 맞춰 localhost HTTP를 검증하도록 바꿨고 curl timeout 추가 리뷰를 보존했다. 당시 본문 Implemented/CI 진행중은 당시 상태이며 최종 head CI metadata와 별개다. 실제 OCI 재적용은 원본 PR만으로 확정하지 않는다. 앞선 archive 권한 실패는 [PWL-0039](PWL-0039.md)의 독립 원인이다.

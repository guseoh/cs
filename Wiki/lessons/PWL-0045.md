# 잠금 footprint 비교는 동일한 MVCC 물리 이력과 read-view 수명을 고정해야 한다

## Context

삭제된 레코드의 잠금이 두 번째 관찰에서 사라지면 SQL/JPA 전환 차이처럼 보일 수 있지만 read view 해제와 Purge 가 관찰 조건을 바꿀 수 있다.

## Observed lesson

T10 Seoul B-unpinned 차이로 STOP 한 뒤 Legacy→Legacy 와 Legacy→JPA 를 같은 이력으로 대조했다. 고정 A/B/C strict equality 는 유지하고 read-view release 는 9→8→8·삭제 레코드 1개 소실·새 잠금 없음과 competing insert 를 비교하는 별도 transition oracle 로 검증했다.

## Alternatives and interpretation

잠금 assert 전체 완화·원본 DELETE 검증 삭제·불안정 관찰을 'JPA 도 같을 것'으로 통과시키는 안을 피했다.10개 회귀 주입 거부는 특정 oracle 의 유효성 근거이며 모든 엔진 상태 증명이 아니다.

## Consequences and limits

최초 실제 Purge 시점은 관찰되지 않아 원인 확정으로 쓰지 않는다. 물리 observer 권한·수동 진단과 CI 의 결정적 필수 5건을 구분한다.

## Implementation and verification

로컬 결과가 당시 사용자/Codex 보고라는 출처 한계를 남기고 원본 STOP/교정·#359 미병합·#364 통합을 연결했다. 현재 DB lock 을 조회하거나 원시 build artifact 를 재실행하지 않았다.

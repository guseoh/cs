# 측정 도구의 수정도 실제로 한 번 돌려 봐야 한다 — k6 `json(undefined)`는 `json()`과 다르다

## Context

[#556](https://github.com/guseoh/pawcycle-commerce/pull/556) 리뷰에서 "본문이 JSON이 아니면 `response.json()`이 예외를 던져 오류율에서 빠진다"는 지적을 받았다. 그래서 예외를 삼키는 헬퍼를 넣었다.

```js
function jsonOf(response, selector) {
  try { return response.json(selector); } catch (error) { return undefined; }
}
const order = checkout.status === 200 ? jsonOf(checkout) : null;
```

단위 테스트는 통과했다. 그러나 1만 규모 환경에서 짧게 돌려 보자 **모든 Checkout이 실패**로 기록됐다. `jsonOf(checkout)`은 `checkout.json(undefined)`를 부르는데, k6는 인자가 있으면 selector 경로로 해석해 `undefined`를 돌려줬다. 응답은 정상이었는데 도구가 실패로 판정한 것이다.

같은 수정에서 넣은 "steady k6 종료 코드 ≠ 0이면 실패" 판정이 이것을 바로 잡았다(종료 99).

## Lesson

- 측정 도구의 판정 코드는 **측정 대상만큼 결함이 생길 수 있다.** 도구가 틀리면 멀쩡한 서버를 느리거나 망가진 것으로 기록한다.
- 리뷰 지적을 반영한 수정도 단위 테스트만으로 끝내지 말고, 실제 대상(또는 그 대상을 흉내 낸 stub)에 **한 번 돌려 본다.**
- 판정 장치를 겹쳐 둔다. 이번에는 계약 오류율 판정과 종료 코드 판정이 함께 있어서 한쪽이 빠져도 다른 쪽이 잡았다.
- 선택적 인자를 다른 API로 넘길 때 `undefined`를 "인자 없음"으로 바꿔 주는지 확인한다(`fn(undefined)`와 `fn()`이 다른 API가 있다).

## Applicability

k6 script, 측정 실행기, 알림 규칙처럼 "다른 시스템을 판정하는 코드" 전반.

## Limitations

k6의 selector 동작은 이번 시험 실행 결과로 확인했고, k6 소스나 공식 문서와는 대조하지 않았다.

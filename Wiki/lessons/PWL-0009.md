# 최초 Obsidian PR 기록은 신규 파일 감지 누락과 비ASCII 파일명 문제로 후속 수정됐다

## Evidence and symptom
2026-07-02 [PR #1](https://github.com/guseoh/pawcycle-commerce/pull/1)은 최초 협업 자동화와 함께 병합 PR의 Markdown 기록 생성 Python 스크립트, GitHub Actions, 검증 fixture를 도입했다. 바로 뒤의 [PR #2](https://github.com/guseoh/pawcycle-commerce/pull/2)는 **BOOTSTRAP-003 병합 후 확인 과정에서 발견된 PR 기록 워크플로 문제**라고 원인을 명시했다. 이 기록은 당시 PR body와 실제 수정 diff를 근거로 하며, 별도의 장애 로그나 운영 배포 실행을 새로 확인한 것은 아니다.

## Root mechanism and correction
첫 workflow는 `git diff --quiet -- docs/learning/pull-requests`로 커밋할 기록이 있는지 검사했다. **git diff는 미추적(untracked) 신규 파일을 일반적으로 포함하지 않으므로**, 최초 Markdown 파일을 생성해도 변경이 없다고 판단할 수 있었다. #2에서 검사식을 `git status --porcelain -- docs/learning/pull-requests`로 바꿔 미추적 신규 파일도 인식하도록 수정했다.

또한 최초 `slugify` 정규식은 한글 글자를 허용했다. #2는 소문자 영문·숫자·하이픈만 남기도록 변경하고, 검증 스크립트에 ASCII 파일명 조건을 추가했다. #1의 실제 기록 파일 `PR-1-ci-bootstrap.md`도 같은 변경에 포함됐다. **문제는 단순히 Obsidian의 렌더링이 아니라 Git 작업 트리의 파일 감지 경계와 파일명 호환성 계약**에 있었다.

## Trade-offs and limits
ASCII slug는 자동화와 파일 시스템 간 이름 규칙을 단순하게 하지만 원래 한글 제목을 파일명에 그대로 담지 않는다. PR 번호 및 본문 메타데이터를 남겨 추적성을 유지했다. 이 correction은 #1의 자동 기록 구조를 유지하면서 두 국소 원인을 수정했으며, 새로운 독립 아키텍처 채택으로 보지 않는다.

#1·#2 모두 병합되었지만, 그 사실만으로 당시 모든 merged-PR 기록이 빠짐없이 생성됐거나 외부 Discord webhook 전달까지 검증됐다고 주장하지 않는다. 확인 가능한 범위는 PR 본문·5개 수정 파일 diff·기록 파일 및 병합 상태다.

## Reuse rule
새 파일을 생성하는 자동화는 `git diff`와 `git status`의 추적 범위를 구별하고, 생성 직후 빈·미추적 파일·다국어 제목·중복 이름 같은 경계 사례를 fixture로 검증해야 한다. 최초 기능이 merge된 직후 발생한 correction은 최초 설계와 연결해 남겨야 뒤에 “처음부터 정상 작동했다”고 기억하는 오류를 막을 수 있다.

# migration predicate 밖의 row와 insert도 locking scan에 막힐 수 있다

격리 MySQL8.4 RR에서 실제 migration locking query를 300 legacy+중간 managed row로 실행했다. managed update와 adjacent insert가 data_lock_waits에 5/5 귀속됐다. mvp2_managed index 없는 full-scan locking read의 영향은 predicate 대상 row만이 아니었다.

100-row 실행 시간 median809.2ms와 lock probe의300-row 실행은 다른 조건이다. legacy update wall-clock 대기는 직접 wait entry 귀속이 없어 exact hold time이 아니다. 운영 source-write freeze·Production 규모·parent lock·backup/restore 검증은 없다.

병합 뒤 lock count·wait 필터·CRLF provenance·rollback assertion 등 지적이 추가됐다. 해당 문제의 확정·해결 여부는 후속 근거가 필요하다. 이 실측을 운영 migration 승인으로 확대하지 않는다.

# Frontend /products HTTP 200만으로 Backend 정상 상태를 판정할 수 없다

## Claim and applicability
Frontend 페이지는 Backend에 실제 접근하지 않아도 HTTP 200을 반환할 수 있다. probe는 어떤 실행 경계를 검증하는지 정확하게 구분해야 한다.

## Observed production incident drill
[OPS-INC-001 #146](https://github.com/guseoh/pawcycle-commerce/issues/146)의 2026-08-14 **AWS 실제 Production** Backend 단일 컨테이너 stop/start 중 다른 MySQL/Frontend/Proxy/metrics-proxy는 유지됐다. Prometheus target은 **up → down → up**으로 변했지만 Backend 중단 중에도 /products 페이지는 **HTTP 200**이었다. 이 경로는 Backend 장애 probe에 부적합했다. 복구 후 /api/products 200, Backend healthy, Prometheus up을 확인했으며 current/previous Release SHA·MySQL volume·Flyway는 변경하지 않았다.

## Lesson and limits
후속 [OPS-AUTO-009 #147](https://github.com/guseoh/pawcycle-commerce/issues/147)은 Backend API, Docker health, metrics-proxy 및 Prometheus target을 함께 읽는 진단 도구로 이어졌다. 당시 장애 주입 및 healthy transition의 정확한 초 단위 시각을 모두 남기지 못했으므로 확정 **MTTR 수치가 없다**. Grafana 화면 순간 변화도 별도 캡처한 완료 증거는 아니다. 이 기록은 AWS 당시 실험이며 현재 OCI live health의 증명이 아니다.

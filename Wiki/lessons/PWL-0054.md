# GitHub Actions 재실행은 처음 이벤트의 PR 본문을 다시 쓴다

## Context

[PR #555](https://github.com/guseoh/pawcycle-commerce/pull/555)에서 `Commit and PR conventions`가 PR 본문 형식 때문에 실패했다. 본문을 고친 뒤 실패 job을 재실행(`gh run rerun --failed`)했지만 같은 오류로 다시 실패했다. 로그의 검사 대상은 수정 전 본문이었다.

## Lesson

- 재실행은 원래 workflow 실행의 **이벤트 payload**(`github.event.pull_request.body` 등)를 그대로 다시 쓴다. PR 본문을 고쳐도 기존 실행을 재실행하면 반영되지 않는다.
- PawCycle에서는 두 workflow가 본문을 검사한다.
  - `PR Metadata Validation`: `edited` 이벤트로 실행되어 본문을 고치면 자동으로 새 본문을 검사한다.
  - `Repository Validation`의 conventions job: `opened`·`synchronize`·`reopened`·`ready_for_review`에서만 실행된다. 본문 수정만으로는 다시 돌지 않는다.
- 새 커밋 없이 현재 본문으로 Repository Validation을 다시 돌리려면 PR을 닫았다 다시 연다(`reopened`). #555에서는 이렇게 해서 9개 job이 모두 통과했다.
- 외부 원인(예: Gradle 저장소 일시 장애)으로 실패한 job은 재실행이 맞다. **본문·제목처럼 이벤트에 실린 값**이 원인이면 재실행으로는 고쳐지지 않는다.

## 함께 확인한 검증기 규칙

`scripts/validate-task-artifacts.py`는 `- 라벨: 값`처럼 **같은 줄의 값**만 읽는다. 라벨 아래 하위 bullet에만 내용이 있으면 빈 값으로 판정한다. `실행 구분`은 허용 값만 받으며, 뒤에 괄호 설명을 붙이면 실패한다.

## Applicability

PR 본문·제목을 검사하는 모든 workflow. 다른 저장소에서도 `pull_request` 이벤트 기반 검사는 같은 방식으로 동작한다.

## Limitations

GitHub의 재실행 동작은 #555 한 번의 관찰과 workflow 트리거 설정으로 확인했다. 공식 문서와 대조하지는 않았다.

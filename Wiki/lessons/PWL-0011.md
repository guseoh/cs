# 리뷰 반영 커밋이 있어도 본문·인수인계의 의미 일치는 따로 확인해야 한다

## Observed failure
2026-07-05 #17 리뷰는 이미 Accepted인 SubscriptionQuantity/DeliveryCycle의 채택 여부를 다시 열지 말라고 지적했다. 최종 DATA-001 본문은 구현 형태·JPA 매핑만 후속으로 넘겼지만 handoff에는 “도메인 값 객체 사용 여부”가 남았다.

2026-07-06 #19 리뷰는 subscriptionId+인증 회원 조건 조회를 의무화하라고 요청했다. 최종 handoff는 “항상 함께”로 강화됐지만 AUTH-001 본문에는 “가능하면”이 남았다. 두 사례 모두 review 반영 커밋과 보고가 존재하는데도 소비 문서별 의미가 완전히 같지 않다.

## Verification / applicability
PR 최종 diff·공개 리뷰·commit 목록을 대조했고, 2026-11-03 조회한 main `caad5233269f52ccd31f6e93e54c77a464766b36`에서도 DATA handoff의 값 객체 재결정 문구와 AUTH 본문의 선택적 표현을 확인했다. 승인된 입력 → 본문 → handoff → 검증표를 같은 불변 조건으로 비교해야 한다. review의 “Addressed”나 녹색 문서 validator만으로 의미 검증을 대신할 수 없다.

## Limits
이것은 재현 가능한 **문서 의미 불일치**다. 운영 인가 우회, 값 객체 제거, DB 오류가 발생했다고 주장하지 않는다. 사용자 지정 일부 반영이었던 경우 미반영을 무조건 구현 실패로 해석하지 않으며, 무엇을 선택하지 않았는지와 남은 모호함을 기록한다. 원본 제품 저장소는 이번 작업에서 수정하지 않았다. 이후 해결 여부는 실제 후속 diff·계약·코드에서 별도로 추적한다.

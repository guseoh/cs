# 장애 재현은 disposable 자원·실제 lock·복구 신호까지 확인한다

공유 DB에 row lock/fixture를 넣으면 다른 ACTIVE 구독까지 변경할 수 있다. 실행별 project·volume을 사용하고 실제 merged Compose 자원 범위를 확인한다. 가상의 상속 volume 위험은 실제 model 대조로 판정한다.

실제 row lock 확인 후 장애를 유도하고 lock timeout·counter·target·로그로 판정한다. 복구에는 session KILL 후 종료 polling, scheduler+scrape 여유, 초 미만 UTC log 경계와 새로운 실패 부재가 필요하다. 실행 오류와 cleanup 오류를 함께 보존하고 부분 생성 자원도 정리한다.

#116은 disposable 실패1→복구 실패0과 공유 volume 불변을 보고했다. 사용자 승인 일반 등급은 유지했고 기존 Backend/MySQL 관측 증거를 재사용한 범위와 새 reconciliation 실측을 구분한다. Production 장애/자동 복구 증거는 아니다.

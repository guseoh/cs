# OCI 최초 운영 전환에서 Python 메서드 이름 충돌이 서비스를 바꾸기 전에 차단됐다

## Observed failure — actual operations, 2026-10-31
[OPS-OCI-CD-011 실제 운영 보고서](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/reports/OPS-OCI-CD-011/README.md)에는 사용자가 승인한 **초기 OCI 감독형 배포/Adopt/CD 활성화 시도**가 기록돼 있다. 승인 main/source/이미지·용량·기존 세 서비스 healthy·외부 인증서 검증 HTTPS 200 등을 확인하고, 보호된 설치 실행파일과 mirror/receipt를 준비했다.

그러나 `CDHost.paths(base, head)`가 상속받은 `Host.paths(manifest)`를 같은 이름으로 덮어써 실제 `materialize` 중 **TypeError**가 발생했다. Python 상속의 메서드 이름 충돌이 테스트 fixture에서 놓친 Runtime 상호작용으로 이어진 사례다.

## Blast radius and verified stop
실제 운영 작업은 **target image pull 및 Backend/Frontend/Proxy 서비스 교체 이전에 중단**됐다. 보고서는 기존 운영 SHA·앱/Proxy container ID·StartedAt·Runtime·Compose·Nginx·sibling/network/certificate volume이 변하지 않았고, 여전히 세 서비스 healthy/외부 두 HTTPS 경로 200이라고 기록했다. Release State·policy·enable sentinel은 없고 systemd Timer는 inactive였다. **서비스 상태가 변하지 않아 Rollback은 필요하지 않았으며, 정상 previous Release 또는 강제 Rollback 성공 증거는 확보하지 못했다.**

## Minimal correction, alternatives, limitations
[PR #491](https://github.com/guseoh/pawcycle-commerce/pull/491)은 Git diff 기능을 `changed_paths`로 이름 바꾸고 **기존 Host.paths(manifest) snapshot 동작을 보존**했다. 실제 CDHost의 snapshot/Compose, Frontend·Backend·양쪽 서비스 선택과 복귀 호출을 격리 회귀에 추가했다. 로컬 WSL Linux/root 기준 Controller 36 PASS, Release 61 PASS를 보고했고 2026-10-31 병합됐다. 이는 정적 함수 존재 검사보다 실제 subclass와 inherited contract의 조합을 검증해야 한다는 교훈이다.

오류가 운영에서 나타났다는 사실을 **실제 운영 배포 성공**으로 쓰거나, 이후 PR이 병합됐다는 이유만으로 운영 도구의 재설치·Timer 활성화·추가 rollout·Rollback이 자동 완료됐다고 쓰지 않는다. 사고 당시 별도 DB/Cloud/Secret 변경도 수행하지 않았다.

## Reuse rule
운영 실행 전 smoke는 승인 source SHA, 설치된 root 파일 hash, 실제 상속 Host 구현, 실제 subprocess 인자와 snapshot path까지 검증해야 한다. 이상/불확실성 발생 시 service mutation 전 차단하고, 이전 안정 Release가 입증되지 않으면 'rollback 예정' 대신 **변경이 없었음**을 명시한다.

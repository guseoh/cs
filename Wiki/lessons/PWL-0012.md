# 초기 build 실패는 toolchain·실행 경로·동시 프로세스와 코드 결함을 구별해야 했다

## Observed history
#21에서 create-next-app의 npm exec/typegen 실패 후 skip-install·고정 TypeScript·lockfile 생성으로 전환했고 install/lint/build 성공을 보고했다. 최초 FE 실행 timeout은 프로세스 잔존 확인 뒤 시간 한도를 늘려 재시도했다. POSIX wrapper는 최초 100644에서 100755로 수정됐으며 최종 Git tree mode를 확인했다.

#22에서 기본 Java21 환경은 Java25 toolchain을 찾지 못했다. 임시 Temurin25를 써도 원래 동기화/비ASCII 경로에서 테스트 class load가 실패했지만, 같은 diff를 ASCII 임시 worktree에 적용한 test/build 성공을 보고했다. 이는 경로 조건과 결과의 상관 관측이며 문자 인코딩·동기화 프로그램 중 무엇이 근본 원인인지 확정한 실험은 아니다.

#25~#30의 일부 로컬 Java17/21·Node22와 CI Java25/Node24 조건도 다르다. #27은 로컬 Backend 실패를 유지하면서 원격 Java25 validation 성공을 별도로 기록했다. #29의 병렬 npm ci는 Windows ENOTEMPTY로 실패한 후 프로세스 종료 확인·단독 실행에서 성공했다고 보고했다.

## Lesson and applicability
toolchain 탐지 실패는 테스트 assertion 실패와 다르다. OS/shell·JDK·Node·실행 경로·timeout·동시 실행을 같은 조건으로 맞춘 후 코드 원인을 좁혀야 한다. 로컬 실패를 CI 녹색으로 지우거나 CI 성공을 사용자 PC 검증 완료로 바꾸지 않는다. 환경을 바꾼 재검증은 바뀐 조건과 남은 설명 한계를 함께 남긴다.

## Limits
역사적 보고·diff·Git mode의 소급 검토다. 이번 세션에서 옛 Windows 환경/timeout/클래스 로딩/ENOTEMPTY를 재현하지 않았다. 현재 빌드나 운영의 같은 증상을 보장하지 않는다. 자동 dependency 강제 수정·전역 toolchain 교체·프로세스 종료를 이번 작업에서 실행한 것도 아니다. [#21–#30 배치](../history/pawcycle-source-ledger/batch-021-030.md)를 따른다.

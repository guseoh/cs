# 수동 sudo와 SSM Agent root는 Git 신뢰 환경이 다르다

SSM SendCommand 성공/무출력exit1은 deploy 실패 지점을 설명하지 못했다. v3 ENV_VAR self-reference fallback, v4 heredoc 진입, v5 positional5개 전달을 차례로 조사했다. 직접주입 script성공과 Agent실패를 분리하고 bpftrace로 첫 실패 executable이 Git임을 특정했다.

수동 sudo의 SUDO_UID와 처음부터 root인 Agent환경은 다르다. ssm-user소유 control을 exact path하나만 process-scoped safe.directory로 허용해 자식Git까지 상속했다. wildcard/global 설정/chown/사용자전환은 배제하고 실제 부정대조군을 검증했다.

#135는 v6 immutableversion·manualpreflight1회·AWSDeploy·FlywayV9~V11·SchedulerOFF를 당시 Production Verified 근거로 보고한다. due0이라 최초ON/주문생성은 미검증이다. Documentversionrollback은 DB/applicationrollback이 아니며 AWS근거를 현재OCI검증으로 쓰지 않는다.

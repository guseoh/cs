# RowMapper와 RowCallbackHandler의 cursor를 다시 이동하면 null 실패나 첫 행 누락이 생긴다

## Context

Spring JDBC callback 은 호출 시 cursor 위치의 계약이 있다. query API 의 RowMapper/RowCallbackHandler 안에서 다시 rs.next()를 호출하면 현재 행을 건너뛴다.

## Observed lesson

#351 대사 단건 RowMapper 는 null 을 반환해 stream.findFirst NPE 를 냈다. completion 은 rollback 되고 이미 commit 된 attempt 만 남았다. rs.getInt(1) 한 줄로 고쳐 cart5→3과 완료 원자성을 복구했다. #373 trend callback 은 첫 product 집계 행을 버렸다. frozen legacy 와 다른 결과가 나오자 STOP 하고 PO 가 모든 실제 집계 행 반환을 승인한 뒤 교정했다.

## Alternatives and interpretation

대사 cart 소비 누락이라는 최초 가설을 그대로 확정하지 않고 실제 NPE 로 좁혔다. legacy 결과가 oracle 이라는 이유로 첫 행 누락을 새 구현에 복제하거나 기대값만 조용히 바꾸지 않았다.

## Consequences and limits

callback API 차이와 실제 consumer 를 함께 본다. provider/운영 영향 건수는 미확정이다. #351 당시 cart version 미증가 부채는 후속 #415와 별개다.

## Implementation and verification

실 MySQL fail-before/pass-after 와 transaction/rollback 상태로 원인을 검증했다. 이 소급 조사에서는 테스트나 운영을 재실행하지 않았으며 공개 원본·patch·CI 를 대조했다.

## Provenance

공개 GitHub 원본의 당시 선택을 2026-11-04에 복원했다. 저장소 구현·테스트 보고·CI·운영 사실을 구분하며, 이번 작업에서 제품·DB·Provider·부하를 새로 실행하지 않았다.

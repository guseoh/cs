# MySQL 프로세스 응답과 실제 애플리케이션 계정의 readiness는 다르다

## Failure / correction
mysqladmin ping은 인증실패에도 서버가응답하면 성공할 수 있어 기존volume의 credential불일치를 healthy로 오인한다. #45는 실제QA사용자·대상DB·TCP SELECT1로 바꾸고 정상0/틀린password·DB non-zero를 확인했다. 재시작후 즉시smoke하는 race에는 Compose --wait를 적용했다.

## Trade-off / limits
중첩PowerShell→Docker→shell 인용오류는 직접docker exec와project/service label선택으로 줄였다. 실제credential은 process메모리만 사용했다. 연결성검사는 모든schema/업무정합성을 증명하지 않으며 비QA/타프로젝트data보존에는 별도대조가 필요하다. [상세](../history/pawcycle-source-ledger/batch-041-050.md).

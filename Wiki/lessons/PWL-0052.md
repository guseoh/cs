# 외부 연동 설정은 끝까지 한 번 실행해 봐야 키 종류 같은 전제 오류가 드러난다

## Context

PawCycle의 Toss 테스트 연동은 키 접두사 검사, 단위 테스트, preflight 스크립트를 모두 갖추고 있었다. 그런데 결제 화면은 결제위젯(SDK v2 `widgets()`)을 쓰는데, 검사 코드는 API 개별 연동 키(`test_ck_`/`test_sk_`)만 받았다. Toss 문서상 결제위젯은 별도의 "주문서형·결제창형 연동 키"(`test_gck_`/`test_gsk_`)를 쓴다. 결제 흐름을 실제 Toss로 끝까지 돌린 적이 없어서, 사용자가 처음 Runbook을 따라 키를 찾을 때까지 드러나지 않았다.

## Lesson

접두사 검사와 테스트는 "우리가 정한 규칙을 지키는지"만 확인한다. 그 규칙 자체가 외부 서비스의 실제 요구와 맞는지는 확인하지 못한다. 외부 연동을 준비할 때는 다음을 지킨다.

- 키·토큰 종류는 사용하는 SDK 진입점(위젯, 자체창, 빌링 등)별로 공식 문서에서 확인하고 근거를 남긴다.
- 테스트 환경이라도 실제 외부 서비스로 한 번은 끝까지 실행한다. 실행하지 못했으면 "미실행"으로 남긴다.

## Limits

키 종류 판단은 Toss 공식 문서와 사용자의 개발자센터 화면 확인에 근거한다. 위젯 표시는 확인했지만, 이 키로 backend 승인까지 한 실행(S1)은 아직 없다.

# 독립적인 시스템 설계 전에 아키텍처 개념과 Java·Spring 예제를 학습한다

## 배경
처음부터 도메인 모델, API, 트랜잭션과 트레이드오프를 혼자 결정하는 설계 문제는 현재 학습 단계에 부담이 되었습니다. 사용자와 논의한 방향은 설계를 포기하는 것이 아니라, 충분한 개념·사례·코드 이해 뒤에 설계 실습으로 점진적으로 이동하는 것입니다. 기존 초안 [#35](https://github.com/guseoh/cs/pull/35)와 [#36](https://github.com/guseoh/cs/pull/36)은 서로 같은 `BLR-0007` ID를 사용했으나, 해당 ID는 현행 Wiki에서 Ubuntu 학습 결정으로 이미 확정되어 있습니다.

## 결정
1. 공개적으로 확인 가능한 아키텍처 강의의 **8개 섹션·59개 주제**를 독립 학습의 주제별 참고 목차로 활용합니다. 유료 강의 수강이나 비공개 강의 내용 재현을 전제하지 않습니다.
2. 각 주제는 문제 배경과 핵심 개념 → 실행 흐름이 보이는 Java/Spring 코드·도식 → 설계 대안과 비용·실패 경계 → 국내 기술 기업 사례와 공식 문서 대조 → 작은 검증 순서로 설명합니다.
3. 초기에는 강사의 설명형 수업처럼 안내하고, 이후 실제 저장소의 설계·코드를 역설계해 원인과 트레이드오프를 이해한 뒤 가이드형 시스템 설계로 넘어갑니다. 독립 문제 풀이와 퀴즈는 학습 진도를 통과시키는 의무 조건으로 두지 않습니다.
4. 국내 엔지니어링 블로그(우아한형제들, NAVER D2, Toss, LY Corporation 등)는 구체적인 장애·제약·실험이 포함된 근거를 선별하여 링크와 함께 설명합니다. 링크를 읽지 않아도 이해할 수 있도록 핵심 내용은 학습 본문에 설명합니다.

## 두 초안의 범위
- **사용자가 확정한 공통 원칙:** 아키텍처 기초를 이해한 뒤 실전 사례를 분석하고, Java/Spring 코드 및 트레이드오프로 설계 판단을 학습합니다.
- **초안 #36의 제안:** 공개 강의의 원래 8섹션·59주제 순서를 독립 커리큘럼의 기준으로 삼는 구체적인 구성입니다.
- **초안 #35의 제안:** 개념·도메인·아키텍처 스타일·백엔드 운영·역설계·가이드형 설계의 6단계는 설명 및 예제의 교수법 틀이지, 별도 승인된 새 강의 목차는 아닙니다.

## 선택하지 않은 대안
핵심 개념 없이 곧바로 복잡한 예약·재고·동시성 시스템을 백지 설계하거나, 패턴 이름만 나열하거나, 공개 강의 자료를 무단 재현하거나, 외부 링크만 제공하는 방식은 선택하지 않습니다.

## 결과와 제약
[설계 도서 학습](BLR-0004.md), [도메인 설계·AI 활용 개발](BLR-0005.md), Large-scale Board·DevPedia·PawCycle의 기존 흐름은 그대로 유지합니다. 이 문서는 **학습 방식의 확정**이지 59개 주제 학습 완료, 코드 실행, 배포, 기존 스케줄러 변경의 증거가 아닙니다. Java/Spring 핵심 우선·과도한 정리 축소라는 [후속 학습 결정](BLR-0012.md)과 함께 적용합니다.

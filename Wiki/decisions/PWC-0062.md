# 동일 fixture 실측 후 현재 page의 연관 row를 batch 조회한다

#102가 100건 fixture·page 10/20/100·warm-up 3·9회로 N+1을 먼저 측정하고 #103이 API·schema 변경 없이 현재 page ID의 관계만 batch 조회했다. 캐시·DB index·새 의존성 도입 대신 작은 fetch 변경을 선택했다.

Questions median은 plans 32/52/212→14/14/14, subscriptions 51/91/411→15/15/19였다. global counter의 healthcheck 잡음을 포함하므로 정확한 application SQL count나 Production 수용량으로 일반화하지 않는다. latency와 세부 조건은 [원본별 처리](../history/pawcycle-source-ledger/batch-101-110.md)에 있다.

병합 후 After 코드 provenance와 역할 경계 리뷰가 추가돼 재현 SHA 완전성은 별도 미확인으로 보존한다. 후속 구조 분리는 기존 PWC-0006과 연결해 읽는다.

# 초기 상세 협업 알림은 신뢰 코드·원본 CI SHA·불확실성·민감정보 경계를 보존했다

## Context
2026-07-13 #40(OPS-007)은 단순 상태 알림을 작업/검증/리뷰/다음 행동의 정규화 context와 1~3 embeds로 바꿨다. 별도 CI 알림 workflow를 없애 Repository Validation 완료를 단일 workflow_run 경로로 모으고 중복 main push·일반 review comment·미병합 close 알림은 제외했다.

## Selected boundaries
- Secret과 실행되는 collector/builder/sender는 기본 브랜치의 신뢰 코드를 사용한다. PR branch script와 Secret을 같이 실행해 Preview하지 않는다.
- 기본 브랜치에 필수 collector가 없으면 명시 실패한다. notify=false/exit0으로 누락을 숨기는 호환안은 제거했다.
- 완료된 CI는 run.head_sha를 보존한다. 최신 PR SHA가 다르면 변경 정보·검증 맥락을 이전 run/확인 불가로 표시하고 오래된 결과를 새 커밋 결과처럼 전송하지 않는다.
- API 실패에도 event payload의 PR 번호는 보존한다. 없는 값과 조회 실패를 구분하고 review thread는 전체 페이지를 합산하되 중간 실패/반복 cursor면 확인 불가로 남긴다.
- Issue 자유 본문은 전달하지 않고 task ID 추출에만 제한적으로 쓴다. PR fenced code 제거·정규화·주요 Secret 패턴 마스킹·mention 비활성화·길이 제한을 적용한다.

## Corrections / alternatives
리뷰 뒤 QA/validation heading 중복 배정을 막고 JSON 형태의 인용부호 Secret assignment, AWS/PEM marker, 전체 context 비전파 검증을 보강했다. API fallback에서 확인 불가를 0이나 성공으로 만들지 않았다. job timeout은 10분, embed 전체 텍스트는 6000자 한도다. pattern 검사는 모든 개인정보/비밀의 완전한 redaction 보장이 아니며 전체 raw diff/로그/stack trace를 보내지 않는다.

## Verification / rejected evidence reuse
최종 원본은 fixture20·단위36 통과와 Repository Validation 성공을 보고한다. PR 병합 전 알림은 기본 브랜치 collector 부재로 실패했으며 sender까지 도달하지 않았다. 수정 전 branch script의 HTTP204는 최종 안전 코드의 전송 성공 근거로 재사용하지 않았다. 수정 후 Preview/채널 수신·가독성은 기본 브랜치 병합 후 별도 확인 대상으로 남겼다.

이번 Wiki 작업에서는 알림·메시지 전송·workflow dispatch·Secret 변경을 실행하지 않았다. [#40 상세 처리](../history/pawcycle-source-ledger/batch-031-040.md)와 초기 실패 [PWL-0010](../lessons/PWL-0010.md)을 함께 읽는다.

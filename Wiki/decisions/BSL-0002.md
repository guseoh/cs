# 시스템 설계 교재 1·2권을 여섯 도메인과 같은 저장소의 별도 설계 트랙으로 운영한다

## 배경

기존 [BLR-0004](BLR-0004.md)는 『가상 면접 사례로 배우는 대규모 시스템 설계 기초』 1·2권을 장별로 학습하기로 확정했지만 어느 저장소에 실습 기록을 둘지는 정하지 않았다. 2026-11-19 사용자는 여섯 개의 **서로 독립 실행되는 Spring Boot 도메인 애플리케이션**과 **교재 두 권의 설계 학습**을 같은 신규 GitHub 저장소에 두겠다는 방향을 명확히 확정했다.

## 결정

1. **같은 저장소, 다른 트랙:** 시스템 설계 교재 1·2권은 여섯 도메인 애플리케이션과 **같은 Monorepo**에서 진행한다. 하지만 책의 각 장을 일곱 번째 Spring Boot 서비스나 각 장마다 별도 운영 서버로 구현할 필요는 없다.
2. **교재 학습 결과:** 장마다 문제 정의와 가정, 기능/비기능 요구사항, 규모 추정, 핵심 데이터 흐름, 개략 아키텍처, 병목·정합성·장애 고려, 대안·트레이드오프, 남은 질문을 **독자적인 설계 산출물**로 정리한다. 모든 장을 동일한 분량으로 정리하거나 모든 샘플을 구현하는 것은 강제하지 않는다.
3. **선택적 실험:** 실제 동작 검증의 학습 가치가 높은 제한된 기술(예: 처리율 제한, ID 생성, 메시지 중복, 분산 집계)은 작게 실행 가능한 코드 실험을 허용한다. 도메인과 자연스레 연결되면 그 도메인에 재사용할 수 있으나 **의미 없는 의존성이나 공유 모듈 추출은 금지**한다.
4. **AI 역할:** 기존 [BLR-0014](BLR-0014.md)처럼 요구사항·설계를 함께 토론하고, 사용자가 선택 이유를 설명할 수 있도록 힌트를 우선 제시한다. 필요하면 Java/Spring 예제·테스트 코드를 채팅으로 제공하고, 실제 실행 여부는 별도로 확인한다.
5. **책-도메인 관계:** 교재 주제와 도메인 실험을 상호 참조하는 매핑을 기록하되, 동일한 개념이 두 번 등장해도 각 도메인의 고유 정책과 장애 조건을 유지한다.
6. **기록:** 신규 저장소가 생성되면 교재별 설계·실험의 상세 원본은 프로젝트 Wiki/버전 관리 문서에 두고, `guseoh/cs/Wiki`에는 진행 범위·주요 결정·학습 성과·링크를 함께 기록한다.

## 확인한 교재 범위

- **1권:** 규모 확장과 대략적 용량 산정, 처리율 제한, 안정 해시, 키-값 저장소, 분산 ID, URL 단축, 웹 크롤러, 알림, 뉴스 피드, 채팅, 자동완성, 유튜브, 구글 드라이브 설계 등이다.
- **2권:** 근접성 서비스, 주변 친구, 구글 맵, 분산 메시지 큐, 모니터링·경보, 광고 클릭 집계, 호텔 예약, 분산 이메일, 객체 저장소, 실시간 순위표, 결제, 전자 지갑, 증권 거래소 등이다.
- **근거:** 출판사 공개 도서 소개·목차를 직접 확인했다. 교보문고 상세 페이지는 본문이 정상 추출되지 않았으나, 같은 상품 링크를 연결하는 공개 서적 스터디와 출판사 자료를 대조했다. 이는 목차 확인이며 책 전체 본문을 읽었다는 의미는 아니다.

## 선택하지 않은 대안

- 교재 1·2권을 여섯 도메인 밖의 또 다른 GitHub 저장소에서 별도로 운영하는 방법.
- 모든 교재 장을 강제로 Spring Boot 실행 앱으로 구현하는 방법.
- 책의 예시 설계를 그대로 정답으로 베끼거나 기술을 문제의 필요 없이 선도입하는 방법.

## 결과와 제약

**동일 저장소의 설계 트랙 운영 자체는 사용자 확정**이다. 그러나 구체적인 `design-studies/` 폴더명, 각 장의 코드 실험 수준과 순서, 연계 모듈, 라이브러리/인프라 구성은 현재 **제안**이며 후속 설계에서 정한다. 장별 진도·완료·프로젝트 저장소 생성은 확인되지 않았다. 기존 교재 학습 결정 BLR-0004의 근거는 보존한다.

## 구현 및 검증

현재는 저장소 구조·학습 방법의 결정만 이루어졌다. 교재 내용 독후 기록, 장별 설계 수행, 실행 실험, 부하·성능 수치 및 신규 저장소/Wiki 생성은 **미완료·미검증**이다.

## 출처와 결정 경위

2026-11-19 사용자의 명시 요청으로 동일 저장소 통합을 확정했다. 서적의 구체적 목차는 출판사 자료로 검증했으며 이를 공개 교재 요약·목차 수준으로만 기록하고 저작물 원문을 복제하지 않는다.

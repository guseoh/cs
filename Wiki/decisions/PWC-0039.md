# Backend 최초 구현 후보는 의존성·DB·인증·CI를 함께 결정해야 했다

## Context and evolution
#21 scaffold와 #22 CI가 존재해도 DB/API/Auth/Architecture 승인까지 완료된 것은 아니었다. #23 ARCH-002는 지금 가능한 일을 계획·의존성 검토로 제한했다. #24 ARCH-003은 기능별 package·구현 순서·테스트를 제안했고, #25 ARCH-004는 12개 선택과 보완 4항을 결정 요청으로 묶었다. #27 논리 ERD 이후 #28 ARCH-005는 보완 5항과 구현 전 중단 지점을 정리했다. 모두 후보/계획이며 승인 문서가 아니다.

## Alternatives and proposed trade-offs
| 판단 | 제안과 대안·비용 |
| --- | --- |
| 구현 범위 | API 5개로 수직 흐름을 보려는 추천 vs 공개 상품 2개 우선(인증 결정을 늦추지만 구독 흐름 미완성) vs 문서 추가 분할(위험 축소·착수 지연) |
| 의존성 | JPA/JDBC/Flyway/Security/security-test 최소 묶음 vs Testcontainers 추가(실제 MySQL 검증·Docker/CI 비용) vs OpenAPI 도구(계약 drift 감소·생성물/원천 결정) vs 무의존성(임시 저장소/인증 위험) |
| 데이터 | DATA-001/002를 첫 입력으로 사용 vs 세부 수정 후 사용 vs in-memory(나중 DB 전환 비용). 논리 후보를 최종 DDL 승인으로 보지 않음 |
| Migration | Flyway V1 이력(재현·리뷰 가능, 첫 DDL 변경 비용) vs JPA 자동 생성(빠르지만 이력·운영 전환 비용) vs 의존성만 선도입(첫 DB 흐름 차단 가능) |
| 로컬 DB | 환경 변수 우선(값 비공개·개발자 설정 필요) vs ignored properties(실수 위험) vs Compose(재현·OPS 범위) vs CI Secret 즉시 연결(서비스/권한 검토) |
| 인증 | session 우선(브라우저/복귀와 자연스러움·CSRF/cookie 책임) vs token(발급/저장/만료/refresh 비용) vs 공개 API만 먼저. 고정 member는 추천하지 않음 |
| CSRF | session+CSRF 추천 vs 비활성화(보안 부채) vs token 모델 변경. cookie/header 전송과 JSON endpoint 중 전달 계약도 필요 |
| API | 문서 후보+Controller test 우선 vs 후보 수정 vs OpenAPI 선행. API 실패 JSON과 화면 redirect 구별 |
| 오류 | code/message/fieldErrors 우선 vs ProblemDetail(계약 조정) vs endpoint별 message(일관성 저하) |
| package | 기능별 domain/application/infra/api 우선(경계 설명·파일 증가) vs 전통 계층(익숙함·기능 경계 약화) vs 단일 package(빠름·혼재) |
| CI | test profile 최소 경로 vs MySQL service vs Testcontainers vs OpenAPI 확장 vs DB 도입 보류. 실제 DB 검증 강도와 변경 범위의 교환 |
| 승인 범위 | 원본 Proposed 전체 격상 대신 이번 구현에 사용할 부분만 명시. 승인되지 않은 설정·코드는 만들지 않음 |

## Review-driven corrections
#23은 구현 조건에 ARCH-001을 빠뜨린 문제와 validator가 허용하지 않는 BE-001 예시를 고쳤다. #24는 기존 Spring Boot scan root인 com.pawcycle.backend 하위로 package 후보를 맞추고 보호 API를 인증 경계와 같은 변경에서만 추가하도록 했다.

#25 리뷰는 JPA/Flyway 도입과 CI datasource를 한 묶음으로, 보호 API와 실제 login/session/principal 경로를 한 묶음으로, API 401/403 JSON과 CSRF token 전달 계약까지 함께 결정하도록 보완했다. #28은 DATA-002 논리 ERD도 후보 입력으로 추가했다. 일부 오래된 보고 line ref 지적은 원본별 대장에 남기며 새로운 승인으로 계산하지 않는다.

## Result / later decision
사용자는 후속 #29에서 추천 API 5개 전체 대신 **공개 상품 2개+최소 세션 로그인, 세 테이블**만 제한 승인했다([PWC-0029](PWC-0029.md)). 초기 추천과 실제 선택을 섞지 않는다. JWT·구독·Testcontainers·OpenAPI는 당시 보류다. 현재 구현이 영구히 그 범위라는 뜻은 아니다.

## Evidence limits
당시 문서/보고/handoff와 공개 리뷰·최종 diff를 대조했다. 앱·DB·보안 동작을 여기서 실행하지 않았다. [#21–#30 처리](../history/pawcycle-source-ledger/batch-021-030.md)에서 시점·실패·미확인을 확인한다.

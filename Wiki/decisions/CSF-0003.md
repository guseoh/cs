# Use textbook-style SVG-first learning visualizations with three pilot benchmarks

## Context
CSForge diagrams exist to teach CS/Java/Spring/backend behavior, not to display technology stacks or architectural topology. Earlier [CSF-0002](CSF-0002.md) established that restrained monochrome editorial diagrams are preferred and interactivity must be justified by a real state-transition learning benefit. The next question was how to make these visuals consistently and verify their quality.

## Decision
The user selected the **instructional composition** approach of [Hello Algo](https://github.com/krahets/hello-algo) combined with the **simple standalone SVG/CSS implementation** approach of [Learn DSA Visually](https://github.com/rajeshgoyalg/Learn-Data-Structures-and-Algorithms-Visually). This is an inspiration and implementation strategy, not a license to copy source images.

Make static structure or before/after SVGs the default; use step animation or direct manipulation only when that improves the learning objective. Start with three explicit quality benchmarks:
1. Heap: binary tree ↔ array index/value correspondence and min-heap invariant.
2. Java Pass-by-Value: a copied reference value and parameter reassignment that leaves the caller reference unchanged.
3. TCP Sliding Window: byte-based sequence/ACK semantics, cumulative acknowledgment and constrained sender-window movement.

Prefer content geometry, explicit assumptions, readable typography, neutral colors and desktop Reader light/dark accessibility over decorative layouts. The visual form should differ appropriately by subject.

## Rejected alternatives
- Use cloud-architecture templates, generic flowcharts or repeated boxes for every concept.
- Make all diagrams interactive; add React Flow/D3/animations preemptively.
- Copy third-party educational images into canonical content without checking permissions and technical fit.

## Consequences and constraints
The three fixtures are **quality gates**, not a promise to replace all existing Java/Network/DSA diagrams or to change the content import pipeline. For Java distinguish JLS semantics from JVM implementation layout; for TCP declare window, segment-size and loss/congestion assumptions. Static SVG previews do not by themselves verify dark/light Reader rendering.

## Implementation/verification
The isolated [agent-skills Draft PR #3](https://github.com/guseoh/agent-skills/pull/3) contains a new skills-only `cs-learning-visualization` plugin, three independently created example SVGs, packaging/marketplace updates, and automated schema/state checks. Its GitHub Actions `Skill validation` run #42444304980 completed **successfully** on the first PR HEAD (observed 2026-11-08). That does not establish visual QA, plugin installation, CSForge integration, or runtime behavior. The PR remains unmerged pending review.

## Provenance
The design approach and three benchmark concepts were directly confirmed by the user on 2026-11-08. Plugin and CI facts are from the linked GitHub PR/run. Hello Algo's content reuse requires respecting its licensing; the sample SVGs were newly authored.

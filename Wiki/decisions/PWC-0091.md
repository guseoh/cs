# Backend 구조 리팩터링은 typed 경계에서 JPA semantic repository로 단계별 수렴한다

#273 357Java감사는typedDTO·Interactionpersistence·MDC·formatting을추가하되Map/JDBC/flatpackage부채를남겼다. #275는feature-first분해·v2정리·V28과직접JDBC제거를했지만EntityManager NativeQueryExecutor/ResultSetproxy라는genericshim을명시DEFER했다.duplicate-keycatch가outerJPA TX를rollback-only로만드는문제는lock→존재확인→insert로교정했다.

#278은genericshim/Map응답/ControllerTX를제거하고typedsemanticview·featureadapter·applicationorchestration·processor로분해했다. #279는Cart/Checkout/Payment/Catalog등을JpaRepository/typedprojection/entitytransition으로수렴했다. 기존atomicupsert/lockscope/conditional1row/CAS/replay/UTC를보존하고N+1/firstcreationrace를교정했다.broadCataloglock축소는최적화가아닌concurrencyprotocol변경이라분리했다.

잔여JDBC와paymentfinalize/reconciliation/cartversion/SKUlockorder·after-sales·brandId1fixture부채는DEFER/EXCEPTION이다. #280 HTTP/client계약수렴은별도변경으로연결한다. 단계별CI/통합회귀가있어도모든SQL제거·성능향상·Production검증을의미하지않으며과거shim단계주장을현재구조로덮어쓰지않는다.

## 2026-11-04 단계별 경계 수렴 후속

#337/#338은 read/Quick Reorder 책임을 먼저 분리했고 #339 이후 Querydsl/JPQL/native 를 실제 query 성격으로 선택했다. #387/#388의 중립 command·순수 정책/codec, #391 내부 Failure, #392–#400 API 입력/응답 경계는 별도 검증된 Delta 다. 이전 shim 단계나 당시 잔여 부채를 최신 결과로 덮어쓰지 않는다.

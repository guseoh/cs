# Retire Inbox UI without deleting INBOX data

## Context
The Inbox UI became unnecessary while legacy records with planningState INBOX still represented real user data.

## Decision
Remove Inbox navigation, standard creation selection and old Inbox route; redirect legacy #/inbox to #/all. Make existing INBOX records discoverable as unplanned in All Todos. Preserve server validation, old saved views and exports.

## Rejected alternatives
- Delete or mass-migrate historical INBOX records for a UI-only cleanup.
- Move historical rows silently to Today or Someday.

## Consequences and constraints
UI absence is not proof that the underlying DB records can be discarded. Explicit scheduling remains the only reason to change a legacy row's state.

## Implementation/verification
[PR #125](https://github.com/guseoh/dark-todo-planner/pull/125) merged 2026-10-30, with no D1 migration/production data write in its PR scope. Current README describes legacy INBOX records via unplanned filter.

## Provenance
Merged PR and current README.

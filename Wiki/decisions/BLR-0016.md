# Spring 학습을 구조화된 정리와 문제 해결·코드 발전 중심으로 전환

## 배경

Spring 7개 과정·34개 주제를 모두 긴 설명형 문단으로 다루면 핵심 원리를 가려내기 어렵고 PDF의 코드·도식보다 문서를 읽고 완성하는 데 시간이 많이 든다. 개념을 정확하게 이해한다는 목표는 유지하되, 완성도 높은 장문 설명과 Obsidian 기록 자체를 학습의 목표로 삼지 않기로 사용자가 확정했다.

이 문서는 2026-11-20 사용자가 확정한 **Spring Framework·Spring Boot의 수업 전달 방식**만 다룬다. 비공개 대화나 강의 PDF 원문을 옮기지 않는다.

## 결정

1. **기본 산출물은 구조화된 개념 정리이다.** 이는 단순 요약이 아니다. 중요한 등장 배경·필요성·내부 원리·조건·실제 실행 결과·실무적 제약은 유지하되, 긴 설명형 문단 일색에서 벗어나 글머리 기호·표·코드·이미지를 주제에 맞게 적극 사용한다. 이해가 어려운 인과관계는 자연스러운 설명 문단으로 연결하고, 중요하지 않은 세부사항은 짧게 처리한다.
2. **기본 학습 전개는 ‘현재 코드에서 발생하는 문제 → 왜 문제가 되는가 → 책임·구조·동작의 개선 → 개선 코드의 실행 원리 → 현행 Spring에서의 사용’이다.** 김영한 강의의 점진적인 설명 방식을 활용하되, 무조건 네 단계 또는 모든 과거 버전을 나열하지 않는다. 바뀐 코드와 달라진 책임·의존관계·호출 순서·결과를 비교한다. 객체지향·IoC/DI는 구체적인 문제 코드부터 시작하고, MVC·AOP·DB·Boot는 해당 기술이 해결하는 이전 방식의 한계를 보여준다.
3. **과거 코드는 역사 재현을 위해 늘리지 않는다.** 문제를 보여주는 데 필요한 현실적·가까운 이전 방식을 우선 사용한다. 더 오래된 기술이나 여러 개의 중간 버전은 등장 이유를 이해하는 데 꼭 필요한 경우에만 도식·핵심 코드로 다룬다. 이미 확정한 Servlet/수제 MVC 버전별 전체 재구현 제외 방침을 유지한다.
4. **PDF는 개념 발전 순서와 코드·도식을 위한 우선 자료다.** 관련된 실제 그림을 가능한 범위에서 채팅 본문에 직접 제시하고, 그림의 객체·의존 화살표·상태 변화가 코드의 무엇을 나타내는지 설명한다. 원본 자료의 이용 조건과 사실 관계를 지키며, 해당 자료의 원본·본문 전체를 공개 Wiki에 복제하지 않는다.
5. **현행 코드와 오래된 코드를 구분한다.** 과거 강의 코드가 여전히 올바르면 그대로 사용하고, 동작하지만 더 권장되는 방식이 있으면 차이와 선택 기준을 설명한다. 호환성이 깨졌거나 API가 변경된 경우에만 확인한 현행 구현으로 전환한다. 버전별 동작·제거·권장 사항은 주제별로 현행 Spring Framework·Spring Boot 공식 문서와 비교하고, 사용한 버전 및 검증 여부를 명시한다. 코드를 실행하지 않았다면 테스트 결과를 꾸며내지 않는다.
6. **참고 자료는 한국어 개발 기술 블로그·국내 IT 기업 기술 블로그를 적극 탐색하고, Spring 공식 문서로 정확성을 검증한다.** 주제 자체를 설명하는 글, 구조·원리를 심화하는 글, 확장 개념을 이해하는 글을 구분해 관련 위치에 링크와 볼 지점을 안내한다. 링크를 읽어야만 본문을 이해할 수 있게 작성하지 않는다.
7. **이해가 완료 조건이고 문서 완성은 완료 조건이 아니다.** 설명을 읽고 문제의 원인과 개선 이유, 현재 코드의 실행 흐름을 이해했다면 다음 주제로 이동할 수 있다. 모든 자료·도식·세부 동작을 빠짐없이 정리하거나 Obsidian에 재작성할 의무는 없다. 이해가 막히거나 실제 코드에 필요할 때 별도 질문으로 심화한다. 자동 퀴즈·실습은 제공하지 않는다.
8. **기존 Spring 7과정·34주제·17개 최우선 심화 우선순위를 유지한다.** 이번 변경은 주제·과정 수를 변경하지 않고, 각 주제를 어떻게 가르칠지에만 적용한다. 시작점은 다시 01 「객체지향 설계와 IoC·DI」이며 기존 답변을 학습 완료로 인정하지 않는다. Java·JPA·Spring Security의 개별 학습 운영 지침 및 프로젝트별 코드 작성 계약까지 자동으로 변경하지 않는다.

## 선택하지 않은 대안

- 모든 주제를 기존처럼 긴 설명형 문단과 같은 분량의 심화로 작성: 핵심 구분과 학습 진행 효율을 떨어뜨리므로 채택하지 않음.
- 핵심 원리까지 제거한 한 페이지 암기 요약: 코드의 이유와 실제 동작을 이해하기 어려우므로 채택하지 않음.
- 모든 과거 강의 버전·수제 프레임워크를 순서대로 재현: 현재 백엔드 개발 학습과 무관한 작업이 커지므로 채택하지 않음.
- 모든 원본 코드를 무조건 최신 문법으로 치환: 버전 차이·동작 원리를 감추고 불필요한 변경을 유발하므로 채택하지 않음.
- 모든 주제에서 그림·참고 자료·Obsidian 완성본을 수량 기준으로 의무화: 필요보다 형식을 우선하게 되므로 채택하지 않음.

## 결과와 제약

- 교사는 **문제와 개선 이유가 충분히 드러나는 정리형 학습 자료**를 제공한다. 사용자는 이해되지 않는 지점에서만 추가 심화를 요청할 수 있다.
- 예제 코드는 **문제 코드·개선 단계·최종 코드의 차이**를 보여주는 목적 중심으로 최소 구성한다. 장황한 예제 도메인 설명은 생략한다.
- 자료 사용 가능 여부와 코드·버전 검증 여부는 매 주제마다 다르다. 강의의 개별 PDF 전수 검증, 모든 코드의 최신 Spring 실행 성공, 학습 완료는 이 결정에서 확인되지 않았다.

## 구현 및 검증

**확정 범위:** 2026-11-20 사용자가 Spring 개념 학습의 새 형식과 점진적 코드 개선 접근을 명시적으로 선택했다. 이는 학습 방법 승인 기록이며 코드 실행·강의 PDF 전수 검토·실제 학습 효율 측정의 검증 결과가 아니다.

## 출처와 결정 경위

# Java·Spring 재시작과 JPA·Security 분리 학습의 핵심 이해 중심 운영

## 배경

기존 학습은 Java, Spring, CS 등의 핵심 지식을 폭넓게 다루면서도 강의 PDF·도식·기술 블로그·코드 예제·Obsidian 정리까지 주제마다 충실하게 갖추려는 방식이었다. 정확성과 재사용성은 장점이지만, 모든 주제를 완성도 높은 설명문으로 정리하는 작업이 학습의 진입 장벽이 될 수 있다. 학습 기록의 분량과 이해·적용 능력은 동일하지 않다.

이 기록은 공개 가능한 **학습 운영 결정만** 추린 것이며 개인적인 감정 상태, 원문 대화 및 비공개 강의 자료는 포함하지 않는다.

## 확정 결정

1. **현재 우선순위는 Java/Spring 백엔드 개발자 역량**이다. 인프라·네트워크 전문 직무를 당장 병행 준비하지 않는다. 운영 지식이 실제 백엔드 이해에 필요하면 맥락에 맞게 공부할 수 있다.
2. **Java와 Spring을 처음부터 다시 학습**한다. 기존 진도·정리 문서를 자동으로 완료 처리하거나 무조건 이어서 진행하지 않는다. 이미 이해한 기초는 빠르게 확인하고 넘어가며, 각 주제를 처음부터 다시 장문으로 작성하지 않는다.
3. **JPA와 Spring Security는 Spring Core/Boot와 별도의 학습 과정**으로 유지한다. 두 과정에도 동일하게 핵심 중심·실무 활용 중심의 설명 원칙을 적용한다.
4. 각 개념의 최소 학습 기준은 **무엇이며 왜 필요한지, 코드에서 어떻게 동작하는지, 언제 사용하고 무엇을 주의할지**를 이해하는 것이다. 핵심 원리와 안전·정합성에 직결되는 제약은 정확하게 설명한다. 관련된 모든 내부 클래스·부가 API·역사·특수 사례의 완전 암기는 요구하지 않는다.
5. 개념 설명은 **필요한 만큼 충분하게** 제공하되 길이 자체를 목표로 삼지 않는다. 실행 흐름이 어려우면 코드와 결과를 단계별로 설명하고, 단순 API는 간결하게 다룬다. 실무·코딩 테스트에 필요한 적용 능력을 중시하되, 코딩 테스트의 알고리즘 문제 풀이 훈련은 별도 영역으로 구분한다.
6. **Obsidian 문서 완성은 학습 완료 조건이 아니다.** 혼동되는 개념, 재발하는 실수, 나중에 찾을 판단·근거만 선택적으로 기록한다. 기존 노트를 삭제하거나 전면 재작성하지 않는다.
7. **공식 문서·한글 기술 블로그·제공 PDF·도식은 이해를 돕는 도구**이다. 매 주제에서 자료의 개수·이미지 유무·장문 완성도를 맞추는 절차를 의무화하지 않는다. 버전이나 보안에 민감한 주장은 설명 시 공식 자료로 확인한다.
8. **일일 시간·주제 수·문서 수를 강제하지 않는다.** 사용자가 원하거나 이해에 필수적인 경우 외에는 퀴즈·별도 실습 과제를 자동으로 만들지 않는다. 이해 확인이 필요할 때는 짧은 코드 결과 예상이나 자기 설명으로 충분히 판단할 수 있다.

## 유지되는 커리큘럼과 이전 결정의 관계

- [BLR-0002](BLR-0002.md)의 백엔드 우선순위를 **유지**한다.
- [BLR-0010](BLR-0010.md) 및 [BLK-0002](../knowledge/BLK-0002.md)의 Spring **7과정·34주제·17개 최우선 심화 대상**을 **보존**한다. '심화'는 필수 원리를 정확히 이해한다는 우선순위이지 17편의 긴 글이나 일괄 내부 구현 분석을 요구하지 않는다.
- [BLR-0009](BLR-0009.md)의 PDF 선별·현대 REST 백엔드 중심 구성·중복 방지·필수 원리 설명은 **유지**한다. 다만 기존의 '매 주제 완결된 장문 설명글과 풍부한 도식·참고 자료'에 대한 기대가 부담이 되는 경우, **이 결정의 선택적 경량화 원칙을 최신 운영 기준**으로 적용한다. 이전 결정 전체를 폐기하거나 삭제하지 않는다.
- Java의 기존 강의 기반 단계, 별도 JPA·Security 학습 범위는 유지하되, 상세 원본 목차가 Wiki에 모두 등록되었다고 가정하지 않는다. 네 과정의 적용 가이드는 [BLK-0003](../knowledge/BLK-0003.md)를 따른다.

## 채택하지 않은 대안

- 네 과정을 한꺼번에 촘촘한 일일 시간표로 운영: 현재는 선택하지 않음.
- 모든 주제에서 깊은 내부 구현·상세 자료 조사·Obsidian 완성본을 필수로 만드는 방식: 부담이 커서 선택하지 않음.
- 반대로 핵심 원리를 누락할 만큼 극단적으로 요약하는 방식: 정확성과 실무 활용을 해치므로 선택하지 않음.
- 백엔드에 대한 불확실성을 이유로 인프라·네트워크 전문 직무를 즉시 병행 준비: 현재는 선택하지 않음.

## 결과와 제약

새로운 운영 원칙은 학습 자료의 길이와 정리 의무를 조정한다. **학습 목차 자체, 프로젝트 코드, 강의 원본, 기존 Obsidian Study/ 노트, 타 프로젝트의 검증·구현 계약은 변경하지 않는다.** 실제 학습 재시작·이해도 향상·취업 성과가 검증되었다는 뜻도 아니다.

## 이행 및 검증

2026-11-17 사용자의 직접적인 학습 방향 확정을 정리한 **운영 결정**이다. 다음 Java 학습은 입문편 첫 범위부터, 다음 Spring 학습은 01번 「객체지향 설계와 IoC·DI」부터 시작할 수 있다. 두 과정을 하루에 반드시 병행해야 한다는 뜻은 아니다. JPA·Security 착수 시점과 세부 진도는 아직 고정하지 않는다.

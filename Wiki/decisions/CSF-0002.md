# Java reader diagrams favor accurate editorial visualizations

## Context
Generic box-heavy diagrams and excessive interactivity can obscure Java relationships and enlarge Reader layouts.

## Decision
Favor restrained monochrome editorial diagrams. Animate or step only when a state transition adds learning value; preserve canonical semantics, intermediate state behavior and keyboard navigation.

## Rejected alternatives
- Apply one generic flowchart template to all topics.
- Add universal interactivity even where a static diagram is clearer.

## Consequences and constraints
Distinguish isolated browser screenshot coverage from authenticated deployed Reader and PWA verification. Reader typography issue #294 is separate.

## Implementation/verification
[PR #293](https://github.com/guseoh/csforge/pull/293) merged 2026-10-31. Follow-up [PR #295](https://github.com/guseoh/csforge/pull/295) remains open as of inspection; its isolated [Chromium QA](https://github.com/guseoh/csforge/actions/runs/41185892113) passed, but live Owner/Guest/PWA not verified.

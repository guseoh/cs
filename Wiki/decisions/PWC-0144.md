# PawCycle은 완료 작업의 중앙 Wiki review PR 생성·병합을 기본 위임하고 에이전트·하네스 규칙 중복을 정리한다

## 배경

기존 PawCycle 저장소 규칙(`WIKI-CAPTURE-002`)은 중앙 Wiki(`guseoh/cs`)의 `full` 기록 모드를 채택하면서도 일반 코드·설계 작업 승인만으로 타 저장소 PR 생성을 허용하지 않아, 실제 작업 종료 시 Wiki 기록이 후보 텍스트로만 남고 반영이 보류되는 마찰이 반복됐다. 또한 루트 `AGENTS.md`, 경로별 `AGENTS.md`, `docs/roles/**`, `.agents/skills/**`, `docs/runbook/**` 전반에 코드 불변식·리뷰 자동화 정책·CI 분류 목록이 2~3중으로 중복되거나 특정 AI 도구명(`ChatGPT`, `Codex`)에 강하게 결합된 표현과 문서 드리프트가 확인됐다.

## 결정

1. **중앙 Wiki review PR 생성·병합 기본 위임 (`WIKI-CAPTURE-003`, PR #559)**
   - `Repository Change` 완료, 승인된 `Design / Plan`(설계 확정) 완료, 또는 `Operations Execution` 완료 시 공개 안전성과 도구 권한이 충족되면 `guseoh/cs`에 고유 임시 브랜치로 review PR을 생성하고, 중앙 Wiki 검증(`wiki_validate.py`, `wiki_query.py evaluate`, `unittest`, CI) 통과와 최신 HEAD·mergeable 재확인 후 병합 및 임시 브랜치 정리까지 수행하는 것을 기본 위임한다.
   - 단순 질의형 `Read / Analyze`는 별도 Wiki 기록 평가를 생략할 수 있으며 타 저장소 PR 생성·병합을 수행하지 않는다.
   - 직접 `main` write, 검증 없는 자동 병합, 공개 불가 정보(Secret·운영 원시값·개인정보·비공개 대화 원문) 게시, 범위 밖 타 저장소 쓰기는 금지한다. 이 위임은 `pawcycle-commerce` PR의 자동 병합이나 실제 운영 실행 승인을 의미하지 않는다.
2. **에이전트·역할·하네스 규칙 중복 제거 및 드리프트 정리 (`HARNESS-CLEANUP-001`, PR #560)**
   - `docs/roles/{backend-engineer,frontend-engineer,platform-sre,qa-engineer}.md`의 세부 불변식 중복을 각 경로 `AGENTS.md` 단일 원본 참조로 슬림화한다.
   - `.agents/skills/{pr-readiness-review,codex-delta-prompt}/SKILL.md`에 중복된 리뷰 자동화 정책 설명을 루트 `AGENTS.md` 단일 원본 참조로 통합하고, 일반 실행·리뷰 주체 표현을 벤더 중립 용어(`구현 에이전트`, `리뷰/오케스트레이터 에이전트`)로 정리한다.
   - 루트 `AGENTS.md` 권위 원본 목록에 `docs/design/**`를 추가하고, `docs/runbook/collaboration-automation.md`의 CI 분류 목록을 `scripts/classify-validation-changes.py`·`lean-harness.md` §9와 동기화한다.
   - `scripts/AGENTS.md`를 신설해 Harness/CI 스크립트 및 연결된 워크플로우의 fail-safe 분류, release side effect 차단, validator 경계, 민감정보 redaction 및 `Review guidelines`를 정의한다.
3. **위임된 구현 에이전트의 리뷰 명령 발행 완화 (`HARNESS-REVIEW-002`, PR #561)**
   - 사용자가 위임했거나 승인된 실행 범위에 포함된 경우 구현 에이전트(예: Codex)도 user-authenticated GitHub 경로로 최신 HEAD를 재확인한 뒤 `@coderabbitai review`·`@codex review`를 HEAD당 한 번 요청할 수 있도록 완화한다.
   - `repository automation`(GitHub Actions bot)의 대신 발행 금지, 일반 `Read / Analyze` 비포함, 근거 없는 finding 임의 resolve 금지 및 요청 코멘트만으로 review 완료 주장 금지 경계는 유지한다.

## 선택하지 않은 대안

- **Wiki 후보만 텍스트로 남기는 기존 보류 모드 유지**: `full` 기록 정책의 목적(결정안·설계안·작업 단위 기록의 지속 축적)과 어긋나며 사용자가 매번 별도로 Wiki PR 승인을 반복해야 한다.
- **중앙 Wiki `main` 직접 push 허용**: 검증·이력·충돌 보호 경계([WIKI-0004](WIKI-0004.md), [WIKI-0005](WIKI-0005.md))를 약화시키므로 채택하지 않았다.
- **`scripts/classify-validation-changes.py`에 `.github/AGENTS.md` 경로를 함께 추가**: classifier 자체 변경 시 전체 앱 lane을 유발하므로, 이미 `harness=true`로 분류되는 `scripts/AGENTS.md`와 루트 `AGENTS.md`로 범위를 한정했다.

## 결과와 제약

- 앞으로 승인된 PawCycle 구현·설계 확정·운영 실행 작업은 도구 권한과 공개 안전성이 충족되면 중앙 Wiki에 자동으로 review PR → 검증 → 병합 → 임시 브랜치 정리까지 이어진다.
- 중앙 Wiki 쓰기 권한이 없거나 검증 실패·충돌이 발생하면 병합을 중단하고 미반영 사유만 보고하며, 제품 코드 검증이나 실제 운영 검증을 소급 실패로 만들지 않는다.
- 문서·Skill 정리만 포함하므로 제품 런타임 및 배포 경로에는 영향이 없다.

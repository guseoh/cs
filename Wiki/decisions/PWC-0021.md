# 신규 Wishlist·Cart 시각은 UTC, 기존 행의 표시 재해석은 승인된 대가다

## Context
[Issue #448](https://github.com/guseoh/pawcycle-commerce/issues/448)은 Asia/Seoul Clock에서 얻은 LocalDateTime을 MySQL DATETIME(6)에 저장하고 UTC Instant로 해석하면서 **+9시간 오류**가 발생한 사실을 격리 MySQL/JVM UTC·Seoul에서 확인했다. 원시 Legacy 행에는 저장 당시의 timezone·writer provenance가 없고, 신규 UTC write를 고쳐도 과거 행의 HTTP/화면 표시 의미가 바뀔 수 있었다.

## Decision
[2026-10-22 사용자 정책 1안 승인](https://github.com/guseoh/pawcycle-commerce/issues/448#issuecomment-6333150357)은 신규 Wishlist/Cart 시각을 Clock.instant 기반 UTC LocalDateTime 및 해당 필드만의 LocalDateTimeJdbcType 바인딩으로 통일한다. **기존 행의 HTTP 시각이 이전과 다르게 해석되는 것을 허용**하지만 과거의 실제 Instant를 복원한 것으로 주장하지 않는다. 사용자 UI는 UTC Instant를 한국 시간으로 표시한다. 추천 30일 인기는 UTC rolling window, 최근/이전 7일 추세는 Asia/Seoul calendar-day 경계를 UTC로 변환한다.

## Rejected alternatives
- 전체 Legacy 행의 9시간 일괄 SQL 보정: 정확한 원본 시간 의미를 보장할 수 없다.
- Legacy/신규를 근거 없는 날짜·패턴으로 추정 분류: false conversion의 위험이 있다.
- 전역 Clock/Hibernate 시간대 변경: 결제·재고를 포함한 다른 경로의 시간 의미가 바뀐다.
- 오류 유지: 신규 데이터·추천 기간 경계의 정합성 문제를 남긴다.

## Consequences and constraints
Legacy/new 혼재에서 과거 시각의 정렬·30일/7일 집계 오차를 모두 복원할 수 없다. 새 Release/구 Release의 mixed 운영이나 Rollback 시 같은 DB 값의 의미가 달라질 수 있다. 실제 운영 데이터 조회·이행·복구와 Production 적용은 별도 Gate다.

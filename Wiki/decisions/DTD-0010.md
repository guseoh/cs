# 개인용 Windows Tern의 변경 영역별 CI/CD 경량화

## 배경
웹 중심 전체 검증을 PR과 main에서 반복하면서 네이티브 설치 파일까지 두 번 생성했다. 트레이 아이콘 수정 사례에서 PR 일반 CI 3분 35초, PR Windows 빌드 7분 37초, main CI 3분 32초, main Windows 릴리스 2분 57초가 확인됐다. 이는 개별 workflow 경과 시간이며 과금 시간이나 사용자 대기 시간 합계가 아니다.

## 결정
- 일반 PR은 타입·단위·프런트엔드 빌드 및 변경 영역별 검증으로 제한한다. 이전 PR 실행은 취소하고 문서만 변경되면 애플리케이션 검증을 생략한다.
- Rust/Tauri 및 의존성 변경 PR은 Windows cargo check를 실행하되 NSIS 설치 파일 생성은 main 릴리스에서 한 번만 수행한다.
- 기존 서명 키와 단조 증가 릴리스 버전, main 변경 자동 발행 및 업데이트 정책을 유지한다. 발행 전 같은 main 커밋의 필수 검증을 통과해야 한다.
- Worker·D1 변경에는 로컬 인증·CRUD·복원·롤백 검증을 유지하고 운영 배포 전에도 실행한다. 주간 암호화 D1 백업은 변경하지 않는다.
- 후속 사용자 확정: 운영 웹 UI/PWA를 완전히 제외한다. Worker는 API 전용으로 전환하고 정적 에셋·SPA fallback·React 빌드 의존성을 제거한다. 기존 Chromium 웹/PWA 회귀 자동화는 제외하고 Windows 네이티브 시작 스모크는 수동 실행으로 분리한다. 주간/수동 전체 의존성 감사 및 API 회귀와 의존성 변경 PR 감사는 유지한다. 실제 설치·업데이트는 로컬 확인이 필요하다.

## 선택하지 않은 대안
전체 CI와 설치 파일을 PR/main에서 계속 반복하는 방식은 작은 변경에도 비용과 시간을 늘린다. 반대로 모든 통합 검증을 삭제하는 방식은 개인 데이터와 인증의 위험을 증가시키므로 채택하지 않는다.

## 구현 및 검증
[소스 PR #178](https://github.com/guseoh/dark-todo-planner/pull/178)에 변경을 구현했다. 최초 경량화 커밋의 [일반 CI](https://github.com/guseoh/dark-todo-planner/actions/runs/45329565583) 및 [Windows cargo check](https://github.com/guseoh/dark-todo-planner/actions/runs/45329565394)는 성공했다. 이후 API 전용 Worker, PWA 설치 UI 제거, 네이티브 QA workflow를 같은 PR에 추가했다. 최신 변경의 검증·main 병합·운영 배포 및 실제 Windows 스모크 실행은 별도로 확인한다.

- 2026-11-24: [최종 CI](https://github.com/guseoh/dark-todo-planner/actions/runs/45330615667) 및 [Windows 검사](https://github.com/guseoh/dark-todo-planner/actions/runs/45330615591) 성공 후 [PR #178](https://github.com/guseoh/dark-todo-planner/pull/178)을 [커밋 `f1b0fcf`](https://github.com/guseoh/dark-todo-planner/commit/f1b0fcf99ff298b067fd8a1df71e423039b3c116)으로 병합했다. Cargo.lock 추적과 빌드 경계 분리를 포함한다. [Windows 릴리스](https://github.com/guseoh/dark-todo-planner/actions/runs/45330985143) 및 [Worker 배포](https://github.com/guseoh/dark-todo-planner/actions/runs/45330985210)는 최종 성공했다. Worker 운영 헬스 체크 및 API 전용 루트 404 확인도 성공했으며 [v0.3.4](https://github.com/guseoh/dark-todo-planner/releases/tag/tern-v0.3.4) 서명 설치 파일·manifest가 게시되었다. 실제 로컬 업데이트 설치 성공은 별도 검증 대상이다.
- 사용자가 기존 데스크톱 화면 개편을 종료하기로 결정하여 [#152](https://github.com/guseoh/dark-todo-planner/pull/152) 및 [#153](https://github.com/guseoh/dark-todo-planner/pull/153)을 미병합 종료했다. 기존 구현 이력을 보존한다.

- 2026-11-24: [#176](https://github.com/guseoh/dark-todo-planner/pull/176) 및 [#179](https://github.com/guseoh/dark-todo-planner/pull/179)의 최신 CI와 Windows 컴파일 검증 성공 후 병합했다. [main `6ee0fec`](https://github.com/guseoh/dark-todo-planner/commit/6ee0fec981c4fbb16b3a243ad8ab5fae2d184003)의 npm lockfile에서 Sharp 0.35.5, Wrangler 4.167.0, Undici 7.30.2, postcss-selector-parser 6.1.6, Vitest/mocker 4.1.12, Vite 8.3.8, source-map-js 1.2.4를 확인했다. 중복 PR #112/#111/#109/#108/#92는 미병합 종료했다.
- Rust [Dependabot 로그](https://github.com/guseoh/dark-todo-planner/actions/runs/45331780213)는 glib 0.18.5의 보안 패치 최소 버전 0.20.0을 현재 제약에서 설치하지 못해 security_update_not_possible로 종료했다. [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html), [Tauri 2.12.7 manifest](https://docs.rs/crate/tauri/2.12.7/source/Cargo.toml), [Cargo resolver](https://doc.rust-lang.org/cargo/reference/resolver.html)의 플랫폼별 의존성 규칙을 확인했다. GTK/glib는 Linux/BSD 경로로 판단되며 Windows 대상 그래프의 실제 cargo tree 검증은 미수행이다. Cargo.lock 유지, 강제 버전 변경 및 경고 무조건 무시 금지를 권고한다. 운영 대상 변경 또는 상위 Tauri 의존성 갱신 시 재검토한다.

- 2026-11-24 운영 안정화: [v0.3.6](https://github.com/guseoh/dark-todo-planner/releases/tag/tern-v0.3.6) 발행 및 [Worker 배포](https://github.com/guseoh/dark-todo-planner/actions/runs/45333319965) 성공을 확인했다. [PR #180](https://github.com/guseoh/dark-todo-planner/pull/180)에 업데이트 동시 실행/승인 버전 검증, 인증 후 스냅샷 표시, Windows Credential Manager 세션 보관, 편집 초안 보호, 프로세스 파일 잠금 및 재연결 복구를 구현했다. 평문 세션 파일·웹 UI 복원·운영 DB 변경은 하지 않는다. [최신 일반 CI](https://github.com/guseoh/dark-todo-planner/actions/runs/45335870552)에서 테스트 195개와 로컬 API/D1 회귀가 성공했다. [Windows 검사](https://github.com/guseoh/dark-todo-planner/actions/runs/45335870498)의 대상 의존성 검사에서 glib가 없음이 확인되었다. [Windows 시작 스모크](https://github.com/guseoh/dark-todo-planner/actions/runs/45335870487), main 병합, 새 릴리스, 실제 설치본의 자동 업데이트·세션 유지·초안 보존은 기록 시점 미확인이다.

- 후속 검증(2026-11-24): 사용자가 Windows 설치본에서 v0.3.6 업데이트 알림을 확인하고 설치 버튼을 눌러 자동 설치 및 재시작까지 성공했다고 보고했으며 설정의 설치 버전 0.3.6 표시도 확인했다. 사용자 확인 범위는 실제 업데이트 성공이며 서명 검증은 기존 updater 동작에 근거하고 독립적인 서명 로그 확인은 하지 않았다. 기존 데이터 보존은 미확인이다. [PR #180 Windows 컴파일](https://github.com/guseoh/dark-todo-planner/actions/runs/45335870498)은 성공했지만 [시작 스모크](https://github.com/guseoh/dark-todo-planner/actions/runs/45335870487)는 첫 창 확인 이후 두 번째 프로세스가 15초 안에 종료되지 않아 실패했다. 중복 실행 안정성은 미완료이며 #180은 미병합 상태다.

- 후속 수정: [PR #180 최신 커밋 `2753768`](https://github.com/guseoh/dark-todo-planner/commit/2753768a1b809586ed5b9eb2906833bcafc7904a)은 Tauri/WebView2 초기화 전 Windows 로컬 앱 데이터의 OS 파일 잠금을 확보하도록 변경했다. 중복 실행 실패 원인이 초기화 순서였다는 가설을 실제 검증하기 위해 기존 프로세스 종료 후 재실행 스모크를 추가했고, Rust 단위 테스트 및 별도 시험용 Credential Manager 항목 저장·조회·교체·삭제를 동일 release 프로파일에서 실행하도록 했다. [일반 CI](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970182), [Windows 검사](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970333), [Windows 스모크 및 Rust 테스트](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970171)는 기록 시점 실행 중이며 수정 효과 및 병합·운영 배포는 미확인이다.

- 최종 자동 검증 및 병합(2026-11-24): [일반 CI](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970182), [Windows 컴파일·glib 검사](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970333), [Windows 시작 스모크·Rust 테스트](https://github.com/guseoh/dark-todo-planner/actions/runs/45337970171) 모두 성공. Rust 테스트 5개 성공(IPC URL, 세션 토큰 형식, updater 동시 실행, OS 파일 잠금, 시험용 Credential Manager 저장·조회·교체·삭제). 실제 runner에서 첫 창 생성, 두 번째 프로세스 종료, 첫 프로세스 종료 후 재실행 성공을 로그로 확인했다. 사용자 승인으로 [PR #180](https://github.com/guseoh/dark-todo-planner/pull/180)을 [main `64a276a`](https://github.com/guseoh/dark-todo-planner/commit/64a276abfff7b26abc252de0b4a336d3d89011bc)에 squash 병합했다. [서명 Windows 릴리스](https://github.com/guseoh/dark-todo-planner/actions/runs/45339156959)는 기록 시점 진행 중이다. 안정화 구현과 자동 검증은 완료, 신규 설치본의 세션 유지·초안 복원·트레이/단축키·재연결 및 신규 버전 설치 후 데이터 보존은 미확인 상태다.

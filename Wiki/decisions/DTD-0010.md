# 개인용 Windows Tern의 변경 영역별 CI/CD 경량화

## 배경
웹 중심 전체 검증을 PR과 main에서 반복하면서 네이티브 설치 파일까지 두 번 생성했다. 트레이 아이콘 수정 사례에서 PR 일반 CI 3분 35초, PR Windows 빌드 7분 37초, main CI 3분 32초, main Windows 릴리스 2분 57초가 확인됐다. 이는 개별 workflow 경과 시간이며 과금 시간이나 사용자 대기 시간 합계가 아니다.

## 결정
- 일반 PR은 타입·단위·프런트엔드 빌드 및 변경 영역별 검증으로 제한한다. 이전 PR 실행은 취소하고 문서만 변경되면 애플리케이션 검증을 생략한다.
- Rust/Tauri 및 의존성 변경 PR은 Windows cargo check를 실행하되 NSIS 설치 파일 생성은 main 릴리스에서 한 번만 수행한다.
- 기존 서명 키와 단조 증가 릴리스 버전, main 변경 자동 발행 및 업데이트 정책을 유지한다. 발행 전 같은 main 커밋의 필수 검증을 통과해야 한다.
- Worker·D1 변경에는 로컬 인증·CRUD·복원·롤백 검증을 유지하고 운영 배포 전에도 실행한다. 주간 암호화 D1 백업은 변경하지 않는다.
- 기존 Chromium UI 전체 회귀 및 전체 의존성 감사는 주간/수동으로 이동하되 의존성 변경 PR은 감사한다. Chromium 테스트를 실제 Tauri 실행 검증으로 간주하지 않는다.

## 선택하지 않은 대안
전체 CI와 설치 파일을 PR/main에서 계속 반복하는 방식은 작은 변경에도 비용과 시간을 늘린다. 반대로 모든 통합 검증을 삭제하는 방식은 개인 데이터와 인증의 위험을 증가시키므로 채택하지 않는다.

## 구현 및 검증
[소스 PR #178](https://github.com/guseoh/dark-todo-planner/pull/178)에 변경을 구현했다. 작성 시점에 새 PR 검증 진행 중이므로 main 병합, 경량화 후 실측 시간 및 운영 발행 성공은 아직 주장하지 않는다. Worker 정적 자산 구조 분리와 실제 Windows 런타임 스모크는 후속 검토 대상으로 남긴다.

# readiness·알림·OIDC 배포는 서로 다른 증거와 승인 단계다

readiness는 main 포함 SHA와 두 image 존재를 확인한다. Discord 알림은 이 결과 전달이며 배포 성공을 뜻하지 않는다. 실제 workflow event는 표시 이름 대신 고정 path로 식별하고 Target SHA만 strict title에서 추출한다.

배포는 Environment 승인·OIDC·고정 단일 target·제한/버전 고정 SSM Document로 기존 deploy 경계를 재사용한다. 장기 key·SSH·임의 shell 대신 제한 입력을 선택했지만 IAM/Environment/Document 운영 설정은 별도다.

첫 실제 SSM 배포의 contract drift 중단(#128)과 image parser 단계 중단(#130)은 다른 실패다. #130의 OCI는 image format이다. 정적/fixture 성공, 원격 수신, command 성공, Production Verified를 혼동하지 않는다. 이후 SSM 실패 연쇄는 후속 번호에서 누적한다.

# API-001의 다섯 경로·오류·날짜 계약은 후속 승인을 기다린 최초 후보였다

## Context / status
2026-07-05 #18은 공개 상품 2개와 보호 구독 3개 API의 Proposed API Contract다. 승인된 제품 규칙을 API 후보로 옮긴 문서이며 URI·필드·HTTP 전체 승인이나 구현이 아니다.

## Proposed contract
`GET /api/products`, `GET /api/products/{productId}`, `POST /api/subscriptions`, `GET /api/subscriptions`, `GET /api/subscriptions/{subscriptionId}`를 제안했다. 생성 요청은 skuId/quantity/deliveryCycleWeeks, 성공은 201과 subscriptionId/nextOrderDate 후보다. 인증 회원은 본문 memberId로 선택하지 않는다. 빈 목록은 200+빈 배열이며 본인 조건 조회를 요구했다.

오류는 code/message/fieldErrors 후보, 401 AUTH_REQUIRED, 400 필수 누락/수량/주기, 404 상품/SKU/구독, 409 SKU_NOT_SUBSCRIBABLE, 500 PRODUCT_LIST_UNAVAILABLE로 분리했다. 다른 회원 구독을 403 대신 없는 구독과 같은 404 SUBSCRIPTION_NOT_FOUND 후보로 두어 존재 정보 노출을 줄였다.

## Alternatives / consequences
날짜는 ISO-8601 local date와 달력 연도 `yyyy-MM-dd`를 명시하고 화면 표현과 구분했다. SKU 표시 가격은 제공하되 할인/총 결제액/쿠폰은 제외했다. 상위 VALIDATION_FAILED를 추가하는 대신 정의된 필드 오류 코드로 요약을 맞췄다. 이는 FE/BE/QA 간 계약 불일치를 줄이지만 최종 DTO·예외 매핑·라우팅 승인은 별도로 필요하다.

삭제/탈퇴/보관/익명화·soft delete, pagination/search/filter/sort, OpenAPI 도구, API 버전 전략, 세션/토큰·쿠키·CSRF는 보류했다. 첫 MVP의 제한을 현재 Commerce 전체 정책으로 일반화하지 않는다.

## Review / implementation / verification
리뷰 6개 지적과 최종 3개 문서 diff를 대조했다. VALIDATION_FAILED 제거·SKU price 제외 문구 수정·주 기반 연도 혼동 방지·목록 조회 실패의 handoff/QA 보강을 확인했다. 보고된 원격 check 성공과 문서 검사는 실제 endpoint/브라우저 실행의 증거가 아니다. 최신 main `caad5233269f52ccd31f6e93e54c77a464766b36`에서도 역사적 API-001은 Proposed다.

## #39 입력 오류 계약의 후속 선택

#39 API-003은 이 초기 API-001 후보의 REQUIRED_FIELD_MISSING/INVALID_QUANTITY/INVALID_DELIVERY_CYCLE 분리 대신 VALIDATION_FAILED+fieldErrors를 승인했다. 입력 form의 code 분기와 fieldErrors 역할 중복을 줄이려는 당시 선택이며 SKU 상태·조회 불가·endpoint별 서버 오류는 별도 code를 남겼다. [PWC-0031](PWC-0031.md)과 [원본 판정](../history/pawcycle-source-ledger/batch-031-040.md)을 따른다. 원래 API-001 문서 상태를 바꾸지 않는다.

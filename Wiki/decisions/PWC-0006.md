# Subscription V2는 명시 SQL과 유스케이스 트랜잭션 책임을 분리한다

## Context
V2 구독 구현에서는 SQL 기반 잠금·버전 비교·unique 충돌 처리와 도메인 명령, HTTP 응답 생성이 한 경계에 혼재하면 불변식의 소유자를 검증하기 어렵다. [ARCH-011](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/adr/ARCH-011-subscription-v2-runtime-structure.md)은 기존 외부 계약을 유지하는 책임 분리를 선택했다.

## Decision
V2의 명시적 JDBC SQL, `FOR UPDATE`, version compare-and-set 및 unique 충돌 처리는 `V2SubscriptionJdbcStore`에 유지하되, persistence store는 typed projection만 반환한다. 검증·멱등성/replay 판단·상태 전이·API 결과 조합은 Pet/Plan, creation, query, command, reconciliation application service가 소유한다. `V2SubscriptionService`는 기존 내부 호출자용 호환 facade로만 남고 SQL·트랜잭션 annotation·HTTP response 생성을 소유하지 않는다. Controller는 typed result를 기존 HTTP status와 `Location`, `ETag`, `Idempotency-Replayed` header로 변환한다.

## Rejected alternatives
- **SQL store가 API 응답과 도메인 명령까지 처리:** 영속성과 유스케이스 결정을 결합하므로 선택하지 않았다.
- **구조 정리와 동시에 API·DB·Lock 계약을 바꾸기:** 회귀와 리팩터링의 경계를 흐리므로 기존 계약을 고정했다.
- **JDBC를 이유만으로 즉시 전면 제거:** 명시적 잠금/CAS/충돌 처리 경계가 필요하므로 이번 결정에서는 유지했다.

## Consequences and constraints
기능 외부 결과가 같더라도 책임 분리 후 트랜잭션 소유자가 달라지지 않아야 한다. Reconciliation의 구독별 `REQUIRES_NEW` 계약을 보존한다. 이 기록은 **2026년 8월 당시의 선택**을 보존하며 이후 JPA 전환이나 재리팩터링까지 현재 그대로라고 주장하지 않는다.

## Implementation/verification
[PR #141](https://github.com/guseoh/pawcycle-commerce/pull/141)이 2026-08-14 병합된 것을 확인했다. 당시 구조 변경의 저장소 반영 근거이며, 최신 런타임에 동일 클래스 구성이 그대로 남았는지 및 운영 회귀는 이번 조사에서 독립 확인하지 않았다.

# 최초 공개 상품 API-002 D1~D7의 사용자 승인 계약과 기각 대안

## Context and historical authority
2026-07-12 [API-002](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/api/API-002-public-product-api-contract-proposal.md)는 `GET /api/products`와 `GET /api/products/{productId}`에 대해 사용자가 **D1-A, D2-A, D3-PUBLIC, D4-A, D5-A, D6-A, D7-A**를 명시 승인했다([PR #35](https://github.com/guseoh/pawcycle-commerce/pull/35)). 최초 [API-001](https://github.com/guseoh/pawcycle-commerce/pull/18) 전체는 여전히 Proposed였다. 이후 이력의 변경까지 7월 승인이라고 소급하지 않는다.

## Approved D1–D7 choices and trade-offs
1. **D1 목록 가격:** `skuPriceSummary.skuPrices[{skuId, skuName, price}]`로 SKU별 실제 가격을 보낸다. 최소·최대 가격만 보내는 D1-B보다 응답이 크지만 SKU 식별·선택 의미를 잃지 않는다.
2. **D2 상세 배송 주기:** 각 SKU에 `availableDeliveryCycles`를 둔다. subscribable true는 `[2,4,8]`, false는 `[]`; 상세 최상위 한 번만 주는 대안은 반복을 줄일 수 있지만 SKU별 선택 가능성과 연결이 약하다.
3. **D3 공개 Product:** `display_status=PUBLIC`만 공개, 목록과 상세 동일. 비공개·미존재 모두 404, `displayStatus`는 응답으로 노출하지 않는다. `VISIBLE` 또는 여러 공개 상태/상태 필드 노출은 미선택이다. 사용자에게 내부 존재·가시성 상태를 누설하지 않는다.
4. **D4 결정적 순서:** Product `productId ASC`, SKU 및 가격은 `display_order ASC, id ASC`다. 정렬 자유도·큐레이션을 포기하지만 화면·QA 결과가 안정적이다. 검색·정렬 요청 파라미터는 첫 MVP 범위 밖이다.
5. **D5 빈 값:** 빈 목록과 SKU 집합은 `[]`, nullable 응답 필드는 명시적인 `null`. 공개 Product에 SKU가 없어도 숨기지 않고 `hasSubscribableSku:false`를 보낸다. 미선택 대안은 필드 생략·빈 상품 제외로 payload를 줄이는 방법이다.
6. **D6 가격:** Backend JSON **number**로 전송하고 원화 기호·천 단위·소수점 표시는 FE 책임이다. 고정 소수 자릿수를 유지하는 문자열 가격은 parsing/산술 비용 때문에 미선택이다.
7. **D7 오류:** 비공개와 미존재는 동일 404로 취급하고, 목록/상세의 예기치 못한 500은 경로별 안전 코드로 표시한다. 공통 `INTERNAL_ERROR` 하나로 통일하는 대안보다 재시도/오류 표시 위치 구분이 가능하다. 내부 SQL/상태는 응답하지 않는다.

## Consequences, later evolution and verification
공개 여부·스키마·빈값·안전 오류·응답 순서가 Backend projection/FE/QA 공동 계약이므로 독립 검증이 필요했다. [PR #35](https://github.com/guseoh/pawcycle-commerce/pull/35) 문서 병합은 구현 완료가 아니다. 후속 [PR #36](https://github.com/guseoh/pawcycle-commerce/pull/36)과 [#37](https://github.com/guseoh/pawcycle-commerce/pull/37)이 구현·독립 검증의 역사를 구성한다.

**MVP3의 additive visibility 변경**은 Product `PUBLIC` 공개 조건을 유지하면서 응답에 포함하는 SKU를 `status=ACTIVE`로 좁혔다. 따라서 최신 API-002 문서에는 **원래 D1~D7과 후속 가시성 결정이 함께 존재**한다. 이 결정은 7월 승인, MVP3 변경은 별도 시점으로 추적하며 모든 SKU가 항상 그대로 나온다고 주장하지 않는다. 현재 코드/Production 응답의 완전 동일성은 이번 과거 결정 기록이 새로 증명하지 않았다.

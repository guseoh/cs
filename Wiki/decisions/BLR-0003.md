# Keep the existing Large-scale Board roadmap for direct implementation and failure experiments

## Context

Large-scale Board already has an explicit learning progression and detailed failure/performance experiments. Replacing it with a new generic roadmap would erase prior planning and mix up this project with separate AI-first domain-design practice.

## Decision

Use the existing [Large-scale Board README](https://github.com/guseoh/large-scale-board/blob/main/README.md), [ROADMAP](https://github.com/guseoh/large-scale-board/blob/main/docs/ROADMAP.md) and [PROJECT_HANDOFF](https://github.com/guseoh/large-scale-board/blob/main/docs/PROJECT_HANDOFF.md) as the canonical scope and completion criteria. Plan to spend **about two hours per day** progressing through direct Java/Spring implementation, measurement, concurrency, high-load and failure experiments.

Preserve the actual sequence: Pure Java J01–J05 → Project Design Baseline → Spring S01–S08 → existing Phase 0–7 → Phase 8–13. Follow the original Phase-specific experiments, measurements and verification requirements; do not replace them with a simplified stage outline.

The learner writes and runs implementation code directly; AI assists with understanding and option/trade-off analysis according to the project handoff. Do not silently change Git/commit authorship or introduce mandatory quizzes against the existing project rules.

## Rejected alternatives

- Redesign or compress Phase 0–13 as part of this Wiki task: rejected.
- Treat Large-scale Board as another AI-vibe-coded domain application: rejected.
- Count unrun performance/incident experiments as complete after code appears: rejected.

## Consequences and constraints

- Continue the source repository's own GitHub Wiki for its detailed design changes and experimental results, as already documented in PROJECT_HANDOFF. This central AI Wiki records the **cross-project learning decision**, not a second copy of every experiment.
- The time target is a planned routine, not a verified daily activity log.
- A README state captured on 2026-10-22 is historical, not proof of the current implementation state. Recheck repo/main before resuming coding.
- Specific Sentry policy is recorded separately in [BLR-0006](BLR-0006.md).

## Implementation/verification

Verified the linked repository learning documents on 2026-11-04. No Board code, experiment, roadmap, deployment or runtime state was changed or re-tested by this record.

## Provenance

Direct user confirmation on 2026-11-04 that the prior concrete roadmap remains authoritative, with daily two-hour study and multiple failure experiments.

# Frontend는 CSRF 실패 POST를 재실행하지 않고 인증 응답의 세대를 검증한다

## Context / decision
#43의 CSRF는 메모리 lazy 획득·login뒤회전·익명전환폐기다. CSRF_INVALID 때 token을 새로 받아도 원 POST는 자동 재실행하지 않는다. API가 중복구독을 허용하고 멱등성저장소가 없어 사용자가 결과를 확인하고 수동 재시도해야 한다.

## Correction / trade-off
오래된 auth/me가 최신login/logout을 덮는 경쟁은 generation무효화로 막았다. 성공login 뒤 token갱신만 실패하면 성공결과를 유지하고 token을 비워 다음 변경요청에서 획득한다. 성공을 실패처럼 표시하여 중복행동을 유도하는 경로를 교정했다.

## Verification / limits
순수로직12·typecheck/lint/build가 보고됐고 DOM flow renderer는 신규dependency 미승인으로 보류했다. 실제cookie/CSRF browser검증은 #45~48의 same-origin QA로 후속됐다. timeout 멱등성·오류상태 browser전범위는 미확인이다. [상세](../history/pawcycle-source-ledger/batch-041-050.md).

# Production DB 복원은 source 보존·candidate 검증·트래픽 차단 후 전환으로 준비했다

## Context / decision
격리복원성공만있고actualDBrestore runbook이없어#75운영기준선은부분충족이었다. #76 OPS-025는sourcevolume을그대로보존하고논리backup을별도production-compatible candidate에복원·manifest검증·cutover/revert하는절차를준비했다. in-place복원·rawdatadir·schema downgrade·Flyway수정은제외했다.

## Failure / trade-off
공유release lock·protectedrecord·activevolume state/실제mount·쓰기를막은proxy중지→DB/App기동→manifest검증→proxy개방을택했다. cutover중간실패는source, revert준비실패는candidate를재활성화한다. source/candidate/state는자동삭제하지않아보존/폐기정책이남는다.

## Verification limits
fake/격리lifecycle/CI통과는실제production훈련이아니다. #77/#80도actualDBrestore를미실행으로유지한다. physicalvolume/EBS손상·RPO/RTO·중단시간·데이터의미검증은별도승인/근거가필요하다. [상세](../history/pawcycle-source-ledger/batch-071-080.md).

## #101~#200 순차 조사 후속

#159/#160의 candidate parser는 실제 single-quoted materializer와 다른 fixture 때문에 발견하지 못한 결함을 수정했다. #159는 미병합 대체, #160은 동일 HEAD를 canonical branch에서 병합했다. 격리 restore MATCH와 candidate 단계 중단은 RDS import/cutover 완료가 아니다. #158 최종 폐기와 후속 RDS runtime 증거의 차이는 PWC-0011에 보존했다.

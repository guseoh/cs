# 첫 구독 MVP UX의 네 가지 제품 정책과 선택하지 않은 화면 흐름

## Context and authority
[PS-003](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/product/PS-003-ux-product-decisions.md)은 [UX-001](https://github.com/guseoh/pawcycle-commerce/pull/11)에서 결정을 보류했던 네 가지 제품 정책을 **사용자가 승인한 Product Decision**으로 기록했다. [PR #13](https://github.com/guseoh/pawcycle-commerce/pull/13)은 2026-07-05 병합됐고 [#14](https://github.com/guseoh/pawcycle-commerce/pull/14)가 후속 UX 문서를 정렬했다. 이것은 화면·도메인의 승인이지 당시 URI, HTTP JSON, Spring Security 구현 전체를 승인한 것은 아니다.

## Approved choices and alternatives
1. **비회원 상품 목록/상세/SKU·구독 가능 여부 공개, 생성·내 구독 조회는 인증 필수.** 모든 상품 탐색도 로그인 전용으로 만드는 대안은 고객 탐색을 과도하게 제한하므로 선택하지 않았다.
2. **보호 기능 접근 후 로그인에 성공하면 안전한 서비스 내부 GET로 복귀**, 유효하지 않으면 상품 목록으로 이동한다. 항상 상품 목록으로 되돌리는 대안은 흐름을 잃고, 외부 URL/검증되지 않은 경로 허용은 Open Redirect 위험이다. 입력 폼 자동 복원과 이전 POST 자동 재실행은 구독 중복·멱등성 위험과 MVP 범위 때문에 제외했다.
3. **구독 생성 성공 시 영구 성공 페이지 대신 생성된 구독 상세로 이동**해 ID·서버 확정 다음 주문 예정일과 성공 메시지를 보여준다. 별도 성공 페이지는 기존 상세와 역할이 중복되어 UI·라우팅·QA 비용을 늘린다.
4. **생성 전 정확한 다음 주문 예정일은 표시하지 않는다.** 선택한 2·4·8주 주기와 '생성 후 확인' 안내만 제공한다. 생성 후 서버 계산 결과를 목록/상세에서 `YYYY. M. D.`로 표시하며 '다음 배송 예정일'과 구별한다. 클라이언트에서 미리 날짜를 계산하는 대안은 날짜 기준·시간대·서버 확정값 불일치 위험 때문에 미선택이다.

## Consequences, deferred decisions and verification
공개 탐색·인증·POST 자동 replay 금지·구독 상세로의 탐색·서버 계산 날짜를 여러 화면과 QA에서 함께 보호해야 한다. 하지만 **구체 라우트, 복귀 경로 저장·검증 방식, HTTP 응답·오류 JSON, 세션/CSRF 구현**은 당시 Deferred Technical Decision이었다. 구독 API는 후속 승인 [API-003](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/api/API-003-subscription-api-contract-decision-request.md)에서 별도로 확정됐다. PR #13/#14의 문서 병합은 전체 브라우저 E2E 성공의 증거가 아니다.

## Provenance

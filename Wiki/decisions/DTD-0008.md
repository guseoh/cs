# Tern 오늘 화면을 계획·집중·실행·마무리 중심으로 정리

## 배경
기존 Today 화면은 Todo 입력·집중 계획·지난 일정·타이머·주간 목표·루틴·GitHub 잔디를 한곳에 표시했지만, 작업이 없는 날에는 다음 행동을 안내하기 어려웠다. 지난 일정 일괄 이동의 실패 여부가 UI에서 확인되지 않았고, 시간 기록 조회 실패를 실제 0분과 구분하지 않았다.

## 결정
2026-11-23 사용자의 오늘 화면 전반 분석 요청 이후, 안전성/불필요한 중복 정리(T1)와 데스크톱 UI의 실행 동선 개편(T2)을 구현하고 운영에 반영하도록 명시적으로 요청받았다. UI는 **계획 → 집중 → 실행 → 마무리** 원칙으로 정리하며 다음 계약을 유지한다.

- **빠른 Todo 입력을 헤더 가까이에 유지**하며, 요약은 입력 아래로 배치한다.
- Todo가 비어 있으면 기존 후보 작업을 직접 오늘로 가져오거나, 지난 일정을 선별 검토하도록 유도한다.
- 지난 일정은 선별 검토를 기본 동작으로 하고 전체 일괄 이동은 2차 메뉴로 이동한다. API 실패는 오류로 알려야 한다.
- Todo가 0개여도 하루 회고가 가능하며, 기록 조회 실패와 측정 시간이 0분인 상태를 구별한다.
- 주간 달력·타이머·목표를 유지하고, 루틴·GitHub는 필요할 때 확장하는 보조 영역으로 다룬다.
- 실행 날짜(`date`)를 지난 일정과 마감일(`dueDate`)이 지난 작업은 별개로 표현한다.
- 기존 Todo/TimeEntry/Goal/Reflection API, 데이터 스키마, 인증·오프라인 큐 계약은 임의로 변경하지 않는다.

## 선택하지 않은 대안
- **Today를 대형 통계 카드 대시보드로 재구성:** 빠른 입력을 밀어내고 중요 작업 탐색을 어렵게 하므로 제외한다.
- **지난 일정을 자동으로 오늘로 이동:** 사용자의 날짜 계획을 무단 변경하므로 제외한다.
- **루틴·GitHub 기능 제거:** 기존 기능의 손실을 만들기보다 접힌 보조 영역에 배치한다.
- **기존 Todo/시간/루틴 API 재구현:** 데이터 정합성·회귀 위험 대비 이점이 부족하다.

## 결과와 제약
[소스 PR #171](https://github.com/guseoh/dark-todo-planner/pull/171)에서 구현·브라우저 회귀를 검증한다. 이 결정이 accepted라는 것은 사용자 요청에 근거한 구현 방향을 뜻하며, **PR 병합·Production Worker 배포·Windows Tern 실제 사용 검증 완료를 뜻하지 않는다**. 코드 테스트와 운영 결과는 각 출처로 별도 갱신한다.

## 구현 및 검증
- 소스: [Dark Todo PR #171](https://github.com/guseoh/dark-todo-planner/pull/171)
- 최초 CI에서 기존 빠른 입력의 헤더 간격 회귀를 발견했으며, 요약의 위치를 수정한 뒤 다시 실행했다.
- Windows 설치본 직접 조작·체감 성능 및 두 기기 동기화 충돌은 이 기록 작성 시점에 확인되지 않았다.

## 출처와 결정 경위
사용자가 기존 Tern 오늘 화면을 공유하고 개선안·사용하지 않는 코드의 구체적 검토를 요청했으며, 이어서 구현 및 운영 배포를 명시적으로 요청했다. 소스 코드와 CI 결과는 별도의 관측 근거로 구분한다.

# 개발 작업 도구를 Orca로 통일

## 배경

사용자가 앞으로 사용하는 공통 개발 도구를 Orca(Stably AI의 Agent Development Environment)로 고정하겠다고 명시했다. 이 결정은 단일 프로젝트의 프레임워크나 실행 환경 변경이 아니라 여러 프로젝트에 걸친 **로컬 개발 작업 공간 선택**이다.

## 결정

- 새 개발 작업의 기본 도구를 Orca로 통일한다.
- Orca의 코드 편집·터미널·Git Worktree·AI 코딩 에이전트·변경 사항 검토 기능을 우선 평가하고 구성한다.
- Claude Code와 Codex의 역할 분담, 자동화, 메모리 최적화, 플러그인 구성은 **권고안·검토 항목**이며 사용자가 구체적인 수치나 설치 여부까지 확정한 것은 아니다.

## 선택하지 않은 대안

- VS Code와 IntelliJ를 계속 주 개발 환경으로 병행하는 방식은 이번 결정의 기본안에서 제외했다. 다만 Java의 IDE 고유 기능 등 Orca에서 부족한 기능에 대한 예외 사용을 금지한다는 뜻은 아니다.
- 다수의 플러그인과 에이전트를 모두 켜 놓는 방식은 성능·보안 비용이 있으므로 현재 확정된 설정으로 간주하지 않는다.

## 결과와 제약

- 기존 프로젝트 코드, 저장소 구조, 프레임워크, 브랜치 정책, CI, 배포 방식은 이 결정만으로 변경되지 않는다.
- Orca가 VS Code 확장 프로그램과 호환되거나 IntelliJ의 Java 인덱싱·디버깅을 대체한다는 주장은 하지 않는다.
- 개별 프로젝트의 AGENTS.md, 검증·PR·병합 권한, 사용자 코드 작성 계약은 계속 우선한다.

## 구현 및 검증

**사용자 확정:** 2026-11-21 Orca를 개발 도구로 고정하기로 선언했다.

**미검증:** 설치 완료 여부, 실제 개발 성능, 메모리 사용량, 플러그인 설치, Claude Code·Codex의 로컬 로그인 및 프로젝트별 적용 여부. 별도 실행·성능 시험은 하지 않았다.

## 출처와 결정 경위

도구 선택은 사용자 직접 선언(`evidence_level: user-confirmed`)을 기준으로 기록했다. Orca의 공개 문서는 도구 기능을 이해하기 위한 참고자료이며, 사용자가 특정 설정이나 플러그인 설치를 승인했다는 증거가 아니다. 비공개 대화 원문이나 시스템 정보를 기록하지 않는다.

# AgentLab은 백엔드 개발자를 위한 AI Agent 원리·통합 학습 프로젝트로 유지한다

## Context

Java/Spring 백엔드 역량과 도메인 기반 시스템 설계가 주 학습 목표다. 별도 도메인 프로젝트에서 AI 활용 개발·코딩 에이전트 위임·검증을 실습하므로, AgentLab에서 독자적인 Agent Framework나 AI 전문 인프라를 만드는 방향은 역할이 중복된다. 반면 기존 Spring AI 예제를 단순 API 호출법으로만 공부하면 Agent Runtime의 책임과 LLM/백엔드 경계를 이해하기 어렵다.

## Decision

- AgentLab(`guseoh/spring-ai-agent`)은 **AI Agent의 일반 원리 → Spring AI의 Java 추상화 → 최소 직접 구현 및 검증 → 필요 시 Hermes 등 실제 Agent 구현 비교**를 목적으로 한다.
- Java/Spring 백엔드 개발자가 AI 기능을 통합할 때의 설계 판단에 집중한다. LLM을 직접 학습·서빙하거나 복잡한 AI Agent 플랫폼을 개발하는 전문 AI 엔지니어링은 우선하지 않는다.
- AI 코딩·하네스·바이브 코딩의 실전 능력은 별도 도메인 설계·개발 프로젝트에서 기른다. AgentLab에 별도의 코딩 에이전트 개발 커리큘럼을 중복 추가하지 않는다.
- 기존 **13단계 로드맵의 이름과 순서를 유지**하며, 후속 기술의 독립적인 상세 학습을 앞 단계로 당겨오지 않는다.

## Rejected alternatives

- Spring AI의 fluent API만 암기하는 강의: Agent의 일반 원리와 실제 경계를 놓치므로 선택하지 않았다.
- AgentLab을 독자적인 Agent Framework, 복잡한 멀티 에이전트 플랫폼 또는 별도 포트폴리오 제품으로 확장: 현재 백엔드 중심 우선순위와 맞지 않는다.
- 코딩 에이전트용 하네스·프롬프트 작성 실습을 AgentLab의 모든 단계에 강제로 추가: 이미 별도 도메인 프로젝트에서 학습하기로 했다.

## Consequences and constraints

- Agent의 **일반 문제**, Spring AI가 제공하는 **추상화**, Hermes가 택한 **특정 구현 방식**을 구분한다.
- Tool Calling, Agent Loop, Conversation, RAG, MCP 등의 기본 연동은 직접 검증할 가치가 있다. 각 단계별 구현 깊이 조정과 Structured Output/평가 보강은 **논의된 권장안이며, 기존 로드맵 변경으로 확정되지 않았다**.
- Backend 도메인 로직, 접근 권한, 데이터 정합성·검증, 외부 API 실패 및 운영 판단은 LLM의 출력만으로 보장하지 않는다.

## Implementation/verification

2026-11-05 GitHub 공개 `master`의 `AgentService.java`를 확인했다. 현재 코드는 `ChatClient.prompt().user(message).call().content()`를 사용하는 **v0.1 단일 LLM 호출**이다. 2단계의 `SystemMessage + UserMessage → Prompt` 예제는 채팅에서 제시된 **v0.2 학습 제안**이며, 저장소 반영·컴파일·실행 검증은 확인하지 않았다. `build.gradle`은 Spring AI BOM 2.0.0과 2.0.1을 중복 선언하는 상태로 관찰되었으나 이 Wiki 작업에서 수정하지 않는다.

## Provenance

사용자가 반복 확인한 학습 목적과 범위의 공개 가능한 요약이다. 비공개 대화 원문은 게시하지 않았다. "코드를 사용 중"이라는 주장은 공개 원본 파일 확인에 한정되며 실환경 호출 성공과는 다르다.

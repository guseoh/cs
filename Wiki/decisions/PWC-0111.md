# Package topology 이동은 결합 제거와 재분류를 구분해 검증한다

## Context

Commerce·Subscription·Recommendation·Interaction 의 flat root 가 실제 책임과 guard 의 layer 탐지를 가렸다.

## Decision

기존 feature 내부 api/application/domain/persistence/infrastructure/automation 위치로 옮기되 SQL·JPA mapping·transaction·lock·idempotency·provider 동작은 유지한다. Entity 는 이름이 아니라 실제 behavior 와 consumer 로 분류한다. package-private 접근은 가능한 co-location 으로 유지하고 public 확대는 실제 cross-package 호출에 필요한 만큼만 허용한다.

## Alternatives and interpretation

이동과 persistence 현대화의 동시 수행, 빈 layer/의미 없는 interface, projection 을 이름만 보고 domain 으로 이동하는 안을 제외했다. 기존 edge 가 layer 명명 뒤 탐지된 것은 RECLASSIFIED 로 증명하며 신규 semantic debt 와 구분한다.

## Consequences and limits

baseline 숫자가 늘어도 coupling 을 새로 만든 것과 같지 않다. 반대로 package 이동으로 coupling 자체가 해결됐다고 하지 않는다. bytecode graph·context discovery·MySQL 보호 비용을 수용한다.

## Implementation and verification

#343 root93→0, visibility 확대 0, 정규화 817class/7,602edge 동일 보고와 baseline131→145의 14 RECLASSIFIED 를 확인했다. #345는 root74→0 뒤 누락 persistence-api guard·불필요 public 을 교정해 최종 204edge 를 freeze 했다. MySQL59/전체 432 PASS·최종 CI 성공과 최초 compile/guard 실패를 나눠 보존한다.

# 콘텐츠 개수 테스트는 고정값 대신 콘텐츠 선언에서 기대값을 계산한다

## 배경

CSForge 백엔드·프런트엔드 테스트는 canonical 콘텐츠의 전체 문항 수(`CanonicalInventory.QUESTIONS = 2_549`), 토픽 수 `134`, Java 팩별 문항 수, 영역별 감사 테스트의 Concept·`questions.json`·SVG 개수를 정수로 고정하고 있었다. 2026-11-26~27에 영역별 콘텐츠 확충 PR 15개(#321~#340)와 #339가 동시에 열렸고, 어느 PR도 공통 기준값을 갱신하지 않아 각 브랜치의 Repository Validation이 같은 원인으로 모두 실패했다. 각 PR이 같은 줄을 바꾸게 되면 하나를 병합할 때마다 나머지 PR이 충돌·재검증해야 하는 구조였다.

dev 대상 PR에는 Repository Validation이 자동 실행되지 않아(main 대상 PR과 push에만 실행) 이 실패는 수동 `workflow_dispatch`로 처음 드러났다.

## 결정

1. 콘텐츠 PR들을 먼저 병합하고 공통 기준값은 별도 PR(#343) 하나에서 최종 개수로 맞춘다. (사용자 선택: 일괄 병합 후 일괄 수정)
2. 이후 재발을 막기 위해 개수 기대값을 콘텐츠와 콘텐츠 선언에서 계산한다(#346).
   - `CanonicalInventory`: 패키징된 canonical 파일을 import 파서와 **독립적으로** 센다. Markdown 파일 = Concept, `topics.json`/`questions.json` 배열 원소 = Topic/Question.
   - 영역 감사 테스트: 개수 대신 "영역 `topics.json`에 선언된 토픽마다 `questions.json`이 정확히 하나, Concept는 선언된 토픽 폴더 안에만" 존재하는지 검사한다(`AreaContentInventory`).
   - SVG 개수 대신 "참조된 SVG 집합 = 영역의 디스크 SVG 파일 집합"을 검사한다(누락·고아 자산 모두 실패).
   - Network 유형별 문항 수는 "Concept마다 서술형·시나리오 1개, 객관식 1개 이상" 규칙으로 계산한다.
   - G1 full-pack 테스트는 테스트가 정의한 픽스처(`ASSETS`, `CHANGED`, `STATIC_ASSETS`) 크기와 선언 토픽 수에서 계산한다.
   - 정본 근거가 없는 영역 전체 문항 수와 Network G1 도식 마일스톤(53/54)은 `>=` 하한선으로 둔다. 추가는 통과하고 감소는 실패한다.
3. 객관식 선택지 4개 같은 정책 불변식과 기존 품질 하한선(`>=`)은 유지한다.

## 선택하지 않은 대안

- **PR마다 고정값 갱신:** 병렬 콘텐츠 PR이 같은 줄을 수정해 연쇄 충돌·재검증이 발생한다. 이번 사례에서 직접 확인된 비용이다.
- **기대값을 import 플래너 결과 그대로 사용:** 검증 대상과 기대값이 같은 코드에서 나와 테스트가 무의미해진다. 그래서 파일 종류와 JSON 배열 길이만으로 독립 계산한다.
- **커리큘럼 YAML의 `visualization: DIAGRAM` 개수를 도식 기준으로 사용:** Network는 DIAGRAM 53개와 실제 `csforge-viz` 54개가 정확히 일치하지 않는다(정적 SVG로 대체한 Concept, TEXT 분류 pilot). 새 불변식으로 쓰기 어려워 하한선을 택했다.
- **영역 감사 고정값 유지:** 처음에는 각 영역 PR의 의도된 인벤토리 계약으로 보고 범위에서 제외했으나, 사용자가 동일 원칙 적용을 요청해 포함했다.

## 결과와 제약

- 콘텐츠를 추가하는 PR은 더 이상 개수 상수를 수정할 필요가 없다. 대신 토픽 선언 누락, 선언되지 않은 폴더의 Concept, 참조되지 않은 SVG처럼 **구조 불일치**는 계속 실패한다.
- 하한선으로 바꾼 값은 콘텐츠 감소를 잡지만, 의도적으로 문항·도식을 줄이는 변경은 하한선 수정이 필요하다.
- 영역 감사 테스트의 Javadoc 등 일부 설명에는 작성 당시 수치("10개 Concept")가 남아 있다. 수치는 더 이상 단언되지 않는다.
- 이 결정은 테스트 기대값 정책이며, 운영 콘텐츠 동기화 정책([CSF-0001](CSF-0001.md))을 바꾸지 않는다.

## 출처와 결정 경위

사용자가 2026-11-27 세션에서 "일괄 병합 후 기준값 일괄 수정"을 선택했고, 이어서 "고정 개수 대신 콘텐츠에서 계산"과 "영역별 감사 테스트 고정값도 계산"을 차례로 요청했다. 계산 기준(토픽 선언·디스크 SVG·픽스처 크기·하한선)은 에이전트가 현재 콘텐츠에서 불변식이 성립하는지 확인한 뒤 선택했다.

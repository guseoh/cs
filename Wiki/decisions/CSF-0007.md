# 학습 영역 단위 도식·콘텐츠 개선 및 전체 영역 통합 QA

## 배경

Network, Database, OS의 도식 개선과 브라우저 및 격리 Import QA를 병렬로 수행하면서 CI 재실행과 각 영역의 검증 대기로 전체 구현이 지연되었습니다. 특히 Ubuntu 26.04와 기존 Playwright의 비호환으로 브라우저 실행이 중단된 사례가 있었습니다. 사용자는 2026-11-25 개별 영역 QA를 이관하고 영역별 도식화와 콘텐츠 개선을 함께 진행하도록 확정했습니다.

## 결정

한 LearningArea에서 기존 감사 근거와 현재 소스를 읽고, 도식 필요성에 따른 유지·정밀 개선·구조 개선·신규 도식 작성 및 Concept/Question 설명 품질 교정을 같은 구현 단위로 수행합니다. 다른 영역으로 이동하기 전에 남은 콘텐츠 작업을 명시합니다. 전체 영역의 소스 개선이 끝난 뒤 격리 Import, 동일 파일 재import UNCHANGED, 개인 이력 보존, 자동 회귀 및 실제 Reader 테마·데스크톱 시각 검증을 일괄 실행합니다. 기존 테스트와 기술 의미 검토는 보존합니다.

## 선택하지 않은 대안

개별 도식과 영역마다 긴 실행 QA를 반복해 구현을 중단하는 기존 일정을 사용하지 않습니다. 반대로 검증 없이 제품 코드를 승인하거나 운영 DB에 반영하고 배포하는 방식도 채택하지 않습니다.

## 결과와 제약

초기 구현 속도를 높이고 영역별 본문·그림·문항을 정합화할 수 있습니다. 여러 영역의 변경이 누적되므로 최종 QA에서 발견된 결함의 원인을 찾기 어려워질 수 있습니다. 각 영역의 브랜치, 변경 목록, 미검증 항목을 유지하고 기존 테스트를 삭제하지 않으며, 통합 검증 전까지 완료 상태를 소스 구현과 최종 승인으로 분리합니다. stable key, 공유 Reference 및 개인 데이터 보호 계약을 유지합니다. 실제 운영 사고 #300 해결과 병합 권한은 별개입니다.

## 구현 및 검증

Network #305의 도식 개선 후보 36개가 소스에 반영되었습니다. 73문항과 우선 12개 Concept 본문을 개선했습니다. 남은 115개 개별 문체/깊이 검토, 문항별 최종 규격 대조 및 통합 QA는 미완료입니다. 현재 정책은 사용자 확정이며 구현 결과와 검증 결과의 증거 수준은 별도로 기록합니다. 다른 영역의 완료 또는 배포를 주장하지 않습니다.

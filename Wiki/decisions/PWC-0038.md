# AUTH-001은 인증 컨텍스트·내부 GET 복귀·Open Redirect 검증 경계를 제안했다

## Context / status
2026-07-06 #19는 Proposed Authentication Design이며 DATA-001/API-001을 Approved로 바꾸지 않는다. PS-003의 제품 수준 로그인 복귀 승인을 세션·쿠키·CSRF 기술 선택까지 확장하지 않았다.

## Proposed security boundary
회원 식별자는 클라이언트 memberId 대신 인증 컨텍스트에서 얻고, 본인 목록과 상세를 소유자 조건으로 제한한다. 공개 API에는 개인 구독 정보가 없어야 한다. 브라우저 보호 화면의 로그인 이동과 API 401 AUTH_REQUIRED 후보를 구별한다. 없는 구독/다른 회원 구독은 같은 404 후보로 숨긴다.

복귀는 allowlist의 서비스 내부 GET 화면만 허용한다. 단순 `/` 접두 검사 대신 외부 scheme/host, `//`, 역슬래시, 인코딩·이중 인코딩 우회, 제어 문자, 허용되지 않은 query, API/POST/로그아웃/관리 경로를 배제하고 실패하면 상품 목록으로 보낸다. 폼 자동 복원·POST replay는 하지 않는다.

## Alternatives / trade-offs
returnTo query는 FE에서 간단하지만 노출·조작 검증이 필요하고, 서버 세션은 검증·수명 관리가 가능하지만 세션 선택이 선행돼야 한다. 임시 쿠키는 이동과 결합하기 쉽지만 속성·CSRF·만료 결정이 필요하며, sessionStorage도 신뢰 원천이 될 수 없다. 이 네 후보의 저장 위치·수명은 선택하지 않았다. FE 사전 필터만으로 보안을 확정하지 않고 Backend/auth boundary를 최종 검증 경계 후보로 뒀다.

세션/토큰, 쿠키, CSRF, 실제 Security 설정·principal·라우트·ReturnPathValidator 코드와 테스트는 후속 승인 사항이다.

## Review / implementation / verification
최종 변경은 설계/보고/handoff 3개와 AUTH task-ID validator/fixture 2개다. 당시 validator fixture 통과 보고를 제품 인증 테스트 작성/통과로 확대하지 않는다. PowerShell sh 실패 후 Git Bash 검증 보고도 남겼다.

리뷰는 소유자 복합 조회의 의무화와 “테스트 미작성” 범위 정정을 요청했다. 최종 handoff는 “항상 함께 조건으로 조회”지만 ADR 본문은 “가능하면”이 남아 있다. 최신 main `caad5233269f52ccd31f6e93e54c77a464766b36`에서도 이 본문을 확인했다([PWL-0011](../lessons/PWL-0011.md)). 이는 문서 불일치 관측이지 실제 인가 취약점의 재현이 아니다.

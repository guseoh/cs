# AWS 별도 관측 호스트와 OCI 동일 호스트 Lean Observability를 구분한다

## Context
과거 AWS app EC2는 2 vCPU·약 1.9 GiB RAM, `MemAvailable` 약 500 MiB·swap 0이었다. [ARCH-012](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/adr/ARCH-012-production-observability-boundary.md)은 당시 MySQL·Backend·Frontend의 메모리 근거로 full same-host를 제외하고 별도 ARM64 `t4g.small` 관측 EC2·SSM forwarding·metrics-proxy를 선택한 역사적 이유를 보존한다. OCI Always Free로 전환하면서 비용·capacity 조건이 달라졌다.

## Decision
2026-09-09 병합 [PR #287](https://github.com/guseoh/pawcycle-commerce/pull/287)은 OCI `app01`(1 OCPU/6 GB)에서 **same-host Lean baseline**을 선택했다. Prometheus/Grafana는 Application release와 별도 Compose project, metrics-proxy는 sibling project로 운영하고, DB는 Application Compose가 소유하지 않는 Managed MySQL이다. metrics-proxy는 `/actuator/prometheus`만 전달하고 Backend 8080·metrics-proxy 9464를 호스트에 publish하지 않는다.

2026-09-11 병합 [PR #293](https://github.com/guseoh/pawcycle-commerce/pull/293)은 실제 OCI의 localhost publish 실패를 계기로 Application `app` network는 internal로 유지하면서 Observability shared network만 일반 bridge로 보정했다. Prometheus와 Grafana UI는 각각 `127.0.0.1:9090`, `127.0.0.1:3000`에만 publish하며 NSG public ingress를 열지 않는다.

## Rejected alternatives
- **추가 관측 Compute 즉시 확보:** 비용과 가용 capacity를 소모하므로 실제 same-host 자원/지연 overhead 또는 monitoring failure-domain 격리 요구가 생길 때 재검토한다.
- **Application release에 관측 stack 동거:** 독립 재배포·rollback 경계가 사라진다.
- **Application internal network까지 일반 bridge로 변경:** Backend 네트워크 격리 계약을 깨므로 관측 네트워크만 수정한다.
- **관리 UI public publish·Managed Observability/Loki/OpenTelemetry 즉시 도입:** 불필요한 공개·의존성과 비용 위험을 만든다.

## Consequences and constraints
새 VM 비용은 줄지만 CPU·RAM·disk·failure domain을 Application과 공유한다. 최초 resource limit Prometheus 384 MiB/0.25 CPU, Grafana 256 MiB/0.15 CPU, metrics-proxy 32 MiB/0.05 CPU는 튜닝 결과가 아닌 출발값이다. 30초 scrape, 7일/5GB retention을 사용한다. 당시 추가 OFF/ON 측정은 2026-09-22 Issue #300의 최종 완료 기록에서 PASS로 보고됐다. Observability 변경·복구는 Application release SHA, MySQL/Flyway, TLS·인증서와 관측 volume을 변경하지 않는다.

## Implementation/verification
PR #287(09-09)과 #293(09-11)은 저장소에 병합됐다. ARCH-012는 09-11 실제 OCI 실패 근거를 보존한다. [운영 개요](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/architecture/production-operations-overview.md)는 **2026-10-25 A07 읽기 전용 조사**의 제한된 Prometheus/Grafana health와 Backend metrics 수집을 보고한다. [Issue #300 최종 결과](https://github.com/guseoh/pawcycle-commerce/issues/300#issuecomment-5772603571)은 **2026-09-22 당시** Production READY, release stable, Backend healthy, public /api/products 200, metrics-proxy 200, Observability NORMAL, Prometheus backend target up 및 same-host OFF/ON calibration PASS를 기록한다. 최종 판단은 **same-host KEEP / separate Observability Compute DEFER / memory overhead WATCH**였다. 그 당시 반복되는 latency/error/CPU 측정 왜곡은 baseline을 무효화할 정도로 관측되지 않았고 OOM/restart·지속 swap I/O도 보고되지 않았다. 이는 과거 특정 시점의 운영 결과다. 이번 Wiki 작업은 OCI에 재접속하지 않았으며 **2026-11 현재** overhead, 알림, rollback, DB restore의 Production Verified를 새로 주장하지 않는다.

## Provenance
AWS separate-host는 과거 당시 자원 측정 기반 결정이고 OCI same-host는 2026-09-09 승인 구현, 이후 09-11 네트워크 correction이다. Wiki 등록일은 2026-11-03이다.

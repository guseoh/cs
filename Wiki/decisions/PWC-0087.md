# 다음 배송 Add-on은 주문·결제·재고와 원자적으로 처리하고 HELD 액션을 제한한다

#245는 V25~27 개인화·반복구매 확장에서 Add-on snapshot/금액 DECIMAL18,2를 common Order·Payment·재고 예약·Subscription order/history와 같은 TX로 처리했다. subscription_order_items의 부모는 subscription_orders이며 ID를 다르게 만든 MySQL 테스트로 검증했다. 재고/catalog 불가 due는 ORDER_STOCK_UNAVAILABLE HELD로 재평가하고 승인되지 않은 plan/cycle/reschedule/skip/pause/SET을 막는다. 실제 Add-on이 있으면 REMOVE와 CANCEL만 노출한다.

#247은 command와 SCHEDULED availableActions의 불일치를 수정했다. 로컬 command integration JDBC 설정 실패는 보존하며 #248 disposable 인증 Browser 14 PASS에서 SCHEDULED/HELD를 후속 확인했다. 최종 통합 CI 성공과 실제 Provider·Production migration·복구 미실행은 별개다. #246의 post-merge stale state/security 리뷰는 후속 확인 대상으로 유지한다.

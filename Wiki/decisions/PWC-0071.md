# 운영 진단은 두 호스트의 읽기 신호를 결합하고 알림 실패와 분리한다

실제 AWS Backend drill에서 frontend /products200이 계속돼 단일화면 probe의 한계를 확인했다. Production은 container·API·metrics bridge·release snapshot을 읽고 Observability는 자기localhostPrometheus의 단일target을 결합한다. 필수값·freshness·curl성공·state안정성이 모두 일치해야 NORMAL/exit0이다.

release lock을 획득하지 않고 read-only fd와 전후state로 동시변경을 감지한다. stale·모순·parse/Docker실패는 UNKNOWN으로 닫는다. #147댓글은 두EC2정상상태검증이며 실제down재실행은 별도다. #148병합후 runtimeSHA/mount/endpoint/artifact추가지적은 해결을 추정하지 않는다.

알림은 NORMAL무전송, 비정상/불확실양채널독립시도다. dispatcher가 정책, sender가 전송, 진단이 상태판정을 맡으며 전송실패가 서비스판정을 바꾸지 않는다. boundedrawbytes/regularfile/FIFO/UTF8/필드조합/URL/secret/임시artifact경계를 검증했다. 저장소성공과 #151실제수신·scheduleDEFER를 연결한다.

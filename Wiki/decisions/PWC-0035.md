# ARCH-001은 서버·도메인·화면·영속성의 책임 경계를 제안했다

## Context
2026-07-05 PR #15는 PS-002/DOMAIN-001/PS-003/UX-002를 DATA/API/BE/FE/QA에 전달하기 위한 첫 수직 MVP 아키텍처 문서다. 제품 정책은 승인 입력이지만 ARCH-001 자체는 Proposed Architecture Decision이었다. PR 병합을 아키텍처 전체의 별도 사용자 승인으로 치환하지 않는다.

## Proposed boundary
화면은 입력·표시·라우팅, API는 공개 상품/보호 구독과 오류 표현, 애플리케이션은 인증 회원 식별·SKU 조회·생성 트랜잭션·소유자 조건 조정, 도메인은 수량/주기/구독 불변 조건과 다음 주문 예정일 계산, 영속성은 저장·조회를 책임지는 경계를 제안했다. FE가 생성 전 정확한 날짜를 계산하지 않고 서버 확정값을 보여주도록 했다.

로그인 복귀 검증은 인증 경계의 책임으로 보내고 내부 GET만 허용하며 POST 재실행은 제외했다. 다른 회원 구독과 없는 구독은 같은 사용자 표현으로 묶되 HTTP 상태 선택은 API-001로 남겼다.

## Alternatives and deferred choices
Product/SKU Aggregate를 묶을지, Subscription이 SKU 객체 전체 또는 ID/필요 스냅샷을 보유할지, Clock/날짜 값 객체, JPA 매핑·실제 트랜잭션 어노테이션, SQL 제약·인덱스, 세션/토큰, URI·JSON·401/403/404는 확정하지 않았다. 제안의 대가는 후속 DATA/API/인증 결정을 기다려야 한다는 점이다. 원본에 없는 마이크로서비스 대안이나 채택 이유는 만들어 넣지 않는다.

## Implementation/verification
ADR·보고서·인수인계 3개 문서만 추가했다. 보고서의 validator/추적성·범위 검사는 문서 검증이며 앱/DB/브라우저 검증이 아니다. 공개 issue comment/review/inline comment는 조회 시 모두 0건이었다.

최신 PawCycle main `caad5233269f52ccd31f6e93e54c77a464766b36`에서도 이 역사적 ADR의 Proposed 표기를 확인했다. 이것이 현재 구현 전체가 미승인이라는 뜻은 아니다. 후속 제한 구현 승인 [PWC-0029](PWC-0029.md)와 별도로 추적한다.

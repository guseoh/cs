# 결제 대사가 장바구니 항목을 변경하면 Cart version을 정확히 한 번 올린다

## Problem and authority
MVP4의 [API-011](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/api/API-011-mvp4-purchase-consistency-api.md)에서 Cart 항목이 실제로 바뀌면 `version`을 한 번 증가시키고, 항목이 변하지 않으면 버전을 유지해야 한다. 그런데 결제 성공 대사에서 주문 상품 수량만큼 Cart item을 차감·삭제하면서도 version을 그대로 두는 구현·테스트 기대가 존재했다. 이 경우 사용자가 보유한 `cartVersion`이나 Checkout 최초 요청의 snapshot/replay 판단이 실제 Cart 상태와 불일치한다([R1-01 #414](https://github.com/guseoh/pawcycle-commerce/issues/414)).

## Accepted decision and minimal correction
기존 Cart 행 `FOR UPDATE` → Cart item `FOR UPDATE`의 물리 잠금 순서, 해당 행의 차감/삭제·결제/주문/재고 완료를 묶는 기존 완료 트랜잭션은 유지한다. **Cart item의 실제 삭제 또는 수량 변경이 하나 이상 성공할 때만 전체 배치에서 Cart version +1**, 변경 0이면 version 불변으로 한다. Cart가 없거나 매칭되는 Order item이 없어도 임의의 Cart 생성/버전 증가를 하지 않는다. 기존 `updatedAt` touch, 없을 때의 no-op 및 rollback semantics는 별도 계약으로 보호한다.

## Alternatives and trade-offs
- **item 개수만큼 version 증가:** 버전이 '한 Cart 변경 작업'의 식별자라는 API 계약에 어긋난다.
- **항목이 없어도 version 증가:** No-op을 변경으로 보고 충돌을 확대한다.
- **편의를 위해 lock 순서·Provider confirm·reconciliation attempt gate까지 교체:** 외부 승인, 중복 대사, 주문·재고 정합성과 원인 분리를 위험하게 한다.
- **대사 시 Checkout 버전 검증 완화:** 최초 snapshot과 replay fingerprint의 무결성을 깨뜨린다.

## Evidence of implementation and failure handling
[PR #415](https://github.com/guseoh/pawcycle-commerce/pull/415)는 2026-10-20 병합됐고, 실제 MySQL 8.4.11 및 Fake Provider에서 Cart 수량 5→3, version 7→8, 여러 항목 변경도 한 번만 증가, 빈 변경·동시/중복 대사, Checkout replay/fingerprint/rollback을 검증했다. 최신 [PaymentReconciliationPersistenceAdapter.consumeCart](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/backend/src/main/java/com/pawcycle/backend/commerce/payment/persistence/PaymentReconciliationPersistenceAdapter.java)는 `changed`를 각 affected rows로 합산해 `if (changed) cart.version + 1` 조건부 UPDATE를 수행한다. **updatedAt touch는 changed 여부와 무관하게 기존 의미를 유지**하므로 '완전 no-write'를 의미하지 않는다.

R1-01 Issue #414는 이 F01 수정과 F07 특성 분석만 종료됐다. **NORMAL/PROCESSING 복구 구현은 [Issue #417](https://github.com/guseoh/pawcycle-commerce/issues/417) Open**이고 [PWC-0016](PWC-0016.md)으로 분리한다. Repository CI 통과는 실제 Toss/Production 결제 검증이 아니다.

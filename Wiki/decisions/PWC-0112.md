# Read model은 query 성격과 시간·결과 동등성으로 persistence를 선택한다

## Context

Order/Operations/Membership/Recommendation 에 JDBC row parsing 과 vendor-specific SQL 이 섞여 있어 일괄 변환하면 query 수·정렬·clock·null 의미가 달라질 수 있었다.

## Decision

고정 Order8개·Membership read 는 typed JPQL, optional mapped Recommendation family 는 Querydsl, Operations16종 UNION·JSON_TABLE·DATE/DB clock 등은 typed native 로 선택한다. 기존 caller transaction 과 materialized scalar/typed row 경계를 유지하며 frozen JDBC·실제 HTTP·UTC/Seoul·microsecond/null 동등성을 비교한다. 이미 typed 인 Cart/Wishlist 와 완료된 Querydsl 은 다시 구현하지 않는다.

## Alternatives and interpretation

모든 query 를 Querydsl 로 확대하거나 UNION 을 여러 JPQL 로 분해하고 새 entity 를 억지로 매핑하는 안을 제외했다. T05의 Metrics/residual JDBC KEEP 은 당시 단계의 보류이며 최종 Runtime0의 영구 예외는 아니다.

## Consequences and limits

Hibernate UTC Calendar 와 JDBC Timestamp/LocalDate 추출 차이를 명시적으로 관리해야 한다. typed view·mapping 유지 비용이 생긴다. 기존 plan1+3N 은 T12-A 에서도 유지하며 성능 개선을 주장하지 않는다.

## Implementation and verification

#347 전체 438 PASS, #349 전체 448 PASS·CI 와 최초 test oracle/DB clock 실패를 구분했다. #373은 5owner 를 제거해 Runtime15→10으로 수렴했다. trendScores 첫 행 누락은 동등성 STOP 뒤 PO 가 별도 승인한 동작 수정이며 frozen legacy 누락을 정확성 oracle 로 고정하지 않았다.

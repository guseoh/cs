# 초기 MySQL CI는 mutable 8.4 tag와 실제 버전 검사를 함께 선택했다

## Context / authority
2026-07-10~11 #32(OPS-006)는 승인된 첫 Backend DB 구현 전에 CI에 MySQL service를 제공했다. digest 고정 리뷰는 처음에는 별도 결정이 없어 보류됐고, 후속 커밋의 보고·runbook·handoff는 사용자가 mysql:8.4 유지와 tag drift 위험을 수용했다고 기록한다. 처음의 미결정 답변과 최종 승인을 구별한다.

## Decision and alternative
mysql:8.4 tag를 유지하고 실행된 서버의 8.4.*·utf8mb4·기본 collation을 검사한다. digest 고정은 재현성·공급망 검증에 유효한 대안이지만 당시 단계에서는 적용하지 않았다. 예상치 못한 image 변화나 CI 불안정, DB/Flyway 호환 문제가 생기면 digest 정책을 다시 검토한다. 현재 모든 CI의 영구 이미지 정책으로 확대하지 않는다.

동적 host port와 health check를 사용하고 test/build에 동일 datasource 환경을 제공했다. 테스트용 비운영 fixture는 production 재사용을 금지하며 여기에는 값을 복제하지 않는다. 로컬 Docker daemon/JDK25 부재와 원격 CI 성공은 별도 사실이다.

## Verification boundary and evolution
#32 당시 앱은 아직 datasource/Flyway를 소비하지 않았다. container initialize/version 검사 및 기존 test/build 녹색은 JDBC 연결·migration 검증 완료가 아니었다. #33에서 실제 MySQL·Flyway V1·JPA와 negative-path 검증이 추가됐다.

#33 리뷰의 MySQL 버전 assertion을 8.x로 완화하자는 제안은 8.4.* 실행 계약을 약화하므로 반영하지 않았다. reviewer도 이를 철회했다. 이는 무조건 리뷰 수용 대신 승인된 테스트 목적을 보존한 사례다.

## Costs / unresolved evidence
patch/digest drift·image pull/network·초기화 대기와 비용이 남는다. 최신 source main의 현재 이미지/운영 DB 버전을 이 역사적 기록만으로 판단하지 않는다. [번호순 #32/#33 근거](../history/pawcycle-source-ledger/batch-031-040.md), [DB 테스트 실패 교훈](../lessons/PWL-0013.md)을 따른다.

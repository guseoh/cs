# OCI는 현재 호스팅 후보, AWS는 운영·배포 학습의 주 플랫폼으로 구분한다

## Context

사용자는 현재 PawCycle의 실제 호스팅을 비용 관리 때문에 OCI Always Free에 두고 있지만, 취업 및 실무 운영·배포 역량은 AWS를 중심으로 학습하기를 확정했다. PawCycle 저장소에는 과거 AWS의 EC2/RDS/S3/CloudWatch/SSM/복원·배포 실험을 뒷받침하는 역사적 근거가 보존되어 있다. 현재 Production Overview는 과거 AWS 실행 경로가 active production contract에서 제거됐음을 명시한다.

## Decision

**실서비스 호스팅과 학습할 클라우드 공급자를 분리**한다. OCI는 A1 자원을 확보할 수 있고 데이터·네트워크·비용 안전조건을 충족할 때만 저비용 실제 호스팅 대상으로 삼는다. 실제 운영/배포 기술과 사고 대응 역량을 키우는 학습은 AWS를 중심으로 진행한다.

AWS 학습 범위는 요구·아키텍처 판단을 동반한 VPC/서브넷/SG/IAM, EC2·RDS·S3, CI/CD·불변 이미지·롤백·블루그린 후보, CloudWatch/알림, 백업·복원·RTO/RPO 및 장애 시나리오다. 공급자 중립인 Java/Spring 애플리케이션과 로컬 격리 실험은 재사용하고, AWS 고유 동작과 복구는 비용·권한을 승인한 별도 AWS 실습에서 검증한다.

개발·설계의 최우선 학습 목표는 Java/Spring 백엔드 역량이다. AWS 실습을 이유로 기존 리팩터링과 도메인/설계 역량 학습을 중단하거나 불필요한 상시 유료 Production을 재생성하지 않는다.

## Rejected alternatives

- 현재 호스팅이 OCI라는 이유로 운영 학습을 OCI에만 제한: AWS 중심 학습 목적과 불일치.
- AWS로 즉시 실제 Production 재전환: 기존 비용 관리 의사결정과 충돌하고 사용자 승인이 없다.
- 과거 AWS 운영 Runbook과 리소스를 현재 승인된 실행 계약으로 재활성화: 역사적 증거를 현재의 실운영 사실로 오인.
- LocalStack·Docker 등의 모의 실험을 AWS에서 실제 동작한 증거로 취급: 실제 IAM·네트워크·비용·복구 동작의 차이를 가림.

## Consequences and constraints

AWS 관련 설계/실습은 현재 OCI Production 경계와 분리된 랩·문서·테스트로 관리한다. 실제 AWS 계정 리소스 생성, 과금, RDS/EC2 장기 유지, 실제 장애 실험, 데이터 이동에는 별도 승인·비용 상한과 격리가 필요하다. OCI의 배포 검증을 AWS 학습 완료로 대체하지 않는다. 과거 AWS 성과와 당시 검증 한계는 기존 기록 그대로 보존한다.

## Implementation/verification

이는 **사용자가 확정한 학습 전략의 변경**만 기록한다. 새로운 AWS 클라우드 리소스/CI/학습 랩은 생성·실행하지 않았다. AWS 교육 과정과 실제 배포 실습은 Java/Spring 우선순위에 따라 순차 설계할 수 있다.

## Provenance

2026-11-06 사용자가 직접 "지금은 OCI로 배포하지만 운영 및 배포 학습은 AWS 위주"를 확정. [PWC-0013](PWC-0013.md)의 OCI 비용 관리형 호스팅 선택을 대체하지 않고 역할을 분리한다.

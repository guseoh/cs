# 메모·낙서장 Tiptap 3 통합 편집 및 읽기 중심 UI

## 배경
기존 메모는 Markdown 원문 작성과 별도 미리보기를 전환해야 하며, 메모 카드의 긴 본문은 좁은 공간에서 잘리기 쉬웠다. 낙서장에는 이미 Tiptap 3 시각 편집기가 있었지만 원본 편집·미리보기·중복 서식 메뉴가 함께 노출돼 도구 모음이 복잡했다. 2026-11-23 사용자는 두 화면의 통합 편집 경험과 UI 개선을 함께 진행하기로 결정했다.

## 결정
- 메모·낙서장 모두 Tiptap 3 기반 시각 편집에서 입력과 동시에 서식이 적용되도록 구성한다.
- 편집기 코어와 기본 서식 도구를 재사용하되, 메모의 명시적 저장 및 Todo·프로젝트 연결, 낙서장의 700ms 자동 저장과 파일 편집 등 기능별 책임은 분리한다.
- 메모의 편집/미리보기 별도 탭은 기본 편집 흐름에서 제거한다. 메모 카드에는 스캔 가능한 짧은 본문 요약을, 전체 읽기 화면에는 별도 읽기 렌더러를 유지한다.
- 제목·본문의 정보 계층, 중립 회색, 작은 기능 버튼과 구분선 등 기존 [DTD-0001](DTD-0001.md)의 콘텐츠 중심 시각 정책을 따른다.
- 기존 Markdown 문자열 및 Workers/D1 API 계약, 브라우저 복구 초안과 저장 절차를 변경하지 않는다. 새 JSON/HTML 저장 형식으로 강제 마이그레이션하지 않는다.
- 변환 손실 우려가 있는 표·HTML·이미지·수식·YAML Frontmatter 등은 Markdown 원본 편집 경로를 유지한다. 원본 편집 모드를 전면 삭제하지 않는다.

## 선택하지 않은 대안
- **원문과 미리보기의 상시 분할 화면:** 편집 화면을 좁히고 상태를 중복해서 표시하므로 현재의 빠른 기록 목적에 맞지 않는다.
- **메모와 낙서장의 저장·복구 로직까지 하나로 통합:** 서버 저장 주기와 연결 모델이 다르므로 편집기 UI만 공통화한다.
- **Tiptap JSON 중심 스키마 전환 및 원본 모드 제거:** 현재 Tiptap Markdown 확장이 Beta인 만큼, 기존 문서 호환성과 데이터 보존 측면에서 채택하지 않는다.

## 결과와 제약
Tiptap 내부 문서가 Markdown으로 직렬화되는 과정에서 원본 공백·마커 등의 형태가 정규화될 수 있다. 지원하지 않는 문법의 보호와 기존 문서의 읽기·쓰기 왕복 검증이 우선이며, 모드 전환·한글 IME·Undo/Redo·동기화·복구 실패를 함께 확인해야 한다. 노트북과 데스크톱의 동시 편집 충돌 제어는 이번 UI 작업에 포함하지 않으며 별도 과제로 남긴다.

## 구현 및 검증
[Dark Todo Planner PR #167](https://github.com/guseoh/dark-todo-planner/pull/167)에서 공통 Tiptap 편집기 분리, 메모 시각 편집, 카드 요약, 낙서장 도구 정리 및 글자 크기 개선을 구현해 2026-11-23 [커밋 `e9c092f`](https://github.com/guseoh/dark-todo-planner/commit/e9c092f2128c1234026181435da9b24666243fb2)으로 `main`에 병합했다. 이 기록의 `accepted`는 사용자 설계 선택의 확정을 의미한다. 병합 사실은 운영 배포·Windows 설치본 시각 QA·모든 Markdown 유형의 무손실 변환이 완료됐다는 뜻은 아니다.

2026-11-23 [Preview 배포 Actions #45134811012](https://github.com/guseoh/dark-todo-planner/actions/runs/45134811012)에서 `dark-todo-planner-preview` Worker 업로드와 독립 Preview D1 헬스 응답 `status=ok, database=connected`를 확인했다. Production DB 마이그레이션·운영 배포는 수행하지 않았다. Preview 배포 성공은 사용자 로그인 및 메모·낙서장 수동 사용성 검증과 구분한다.

[최종 PR GitHub Actions CI #45135007610](https://github.com/guseoh/dark-todo-planner/actions/runs/45135007610)은 타입 검사, 단위 테스트, 빌드·의존성 감사, 로컬 Worker/D1·Chromium 브라우저 회귀와 다크·라이트 반응형 검증에 성공했다. 이는 해당 PR 코드의 자동 검증 결과이며, 운영 배포나 Windows 설치본의 수동 시각 QA 완료를 의미하지 않는다.

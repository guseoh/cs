# 과거 문서는 고치지 않고, 현재 상태는 색인과 현재 상태 문서에서 관리한다

## Context

문서 542개 중 현재 작업 기준은 약 11%였다. ADR·DATA·API 문서 상당수가 구현 뒤에도 원문 상태 `Proposed`로 남아 있었다. 그러나 Lean Harness §15는 과거 문서의 소급 수정을 금지한다. 결제·재고·쿠폰 같은 커머스 영역은 현재 도메인 문서가 없었다.

## Decision

- **ADR 상태:** 원문을 고치지 않고 `docs/adr/README.md`의 상태 색인에서 실제 상태를 관리한다. 상태는 유효, 채택 후 변경, 대체됨, 확인 필요, 승인 과정 기록으로 나눈다(#523).
- **현재 상태 문서:** 현재 동작은 다음 문서에 모은다(#526). 문서와 코드가 다르면 코드와 migration이 원본이다.
  - `system-overview.md`, `domain/state-machines.md`, `data/current-schema.md`, `product/current-scope.md`, `architecture/known-risks.md`
- **역사 문서:** reports·handoffs 등 역사 문서는 경로를 유지하고, 링크가 없던 문서만 현재 문서에서 링크한다(#522).

## Rejected alternatives

- **원문 상태 표기 직접 수정:** §15 위반이고, 당시 판단의 기록이 사라진다.
- **역사 문서를 archive 폴더로 이동:** 상대 링크와 Wiki의 `main` 링크 21개가 깨진다.

## Consequences and constraints

- 현재 상태 문서는 `main` `70af0c3d` 기준이다. API 색인을 빼면 코드와의 어긋남을 자동으로 검사하지 않는다.
- ARCH-007(구독 비관적 잠금)은 "확인 필요"로 남았다.
- 알려진 위험 R1~R9는 후보 목록이며, 재현된 것은 R1(#417)뿐이다.

## Implementation/verification

#522, #523, #526 병합. 새 문서의 상대 링크와 스키마 색인의 테이블 61개를 migration과 대조했다. CI 성공. 운영 검증은 해당 없음.

# GitHub MCP 읽기 단계는 실제 권한과 Tool·저장소 allowlist를 구별해 통제했다

## Context / prepared policy
#92~95는탐색/선택실수의우발Issue로not_planned종료됐고독립제품결정은없다. #97은동적GitHub필요시에만최소읽기·repo/ref/evidence path를사용하고조건부승인branch/Draft쓰기와merge/delete/rerun/권한/Secret금지를분리한RepositoryPrepared계약이다.

## Actual capability / trade-off
#100은89개노출Tool중25읽기를repo인자로제한했으나credential과Tool목록자체는readwrite였다. 따라서강제read-only가아니라호출운영통제이고benchmark쓰기0·production0만관찰했다. 향후권한수용/실업무pilot는별도판단이다. legacybranch archive삭제는해당작업사용자명시승인과보존검증에한한예외다.

## Limits
tool이름/페이지/권한은실행시점확인하며과거allowlist를현재전권허가로쓰지않는다. 사고Issue의정확오선택Tool은미확인이다. [상세](../history/pawcycle-source-ledger/batch-091-100.md).

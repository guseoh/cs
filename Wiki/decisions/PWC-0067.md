# 자동화 배포는 OFF로 시작하고 contract·migration 경계는 별도 승인한다

정기 주문의 저장소 구현과 Production 활성화를 분리한다. deploy/rollback/restore는 Scheduler OFF이며 aggregate preflight·명시 입력 후 활성화한다. cadence·batch·후보 최대치·이상 기준은 별도 결정이다.

migration bundle 변경 뒤에는 application 자동복귀가 DB 복구를 보장하지 않아 fail-closed·application stop·MySQL 보존을 택한다. contract와 Flyway boundary는 정확한 SHA 승인과 deploy lock 아래 재검사를 요구한다. Control 전환은 자동화하지 않는다. transition marker로 부분 release state를 감지한다.

#122 병합 후 preflight 식별자 표현식·batch 상한·후보수 race 지적은 후속 확인이 필요하다. #128 첫 실제 배포는 안전 gate에 중단됐고 #129의 저장소 보완과 실제 운영 완료는 다르다. 최종 #128은 AWS 종료로 not_planned이며 일반 요구는 #452로 이관됐다.

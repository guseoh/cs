# Practice user-led architecture and AI-assisted implementation in a separate domain project

## Context

Direct backend implementation, system-design study and AI-assisted delivery train different competencies. Conflating them would undermine Large-scale Board's established learning contract.

## Decision

Use a **separate domain candidate** to practice designing a system and then implementing and validating it with AI assistance (vibe coding). The target learning process is to make requirements, data and architectural decisions explicit, analyze alternatives and trade-offs, use AI to implement a chosen scope, and verify the resulting behavior rather than accepting generated code uncritically.

Discussed domain **candidates** include real-time logistics/delivery, real-time event analytics and real-time video streaming. The logistics-oriented example architecture is an **illustrative candidate**, not an approved final technology stack or project kickoff.

Keep this track distinct from:
- **Large-scale Board:** hands-on Java/Spring implementation, tests, measurements and failure experiments under its existing roadmap.
- **DevPedia:** user-authored implementation with AI as design/review assistance; maintain its design-only Wiki capture policy.
- **PawCycle:** existing AI-assisted implementation, reverse engineering, harness and operational learning; do not duplicate its source/history decisions here.

## Rejected alternatives

- Replace the Board's experiments with AI-generated feature delivery.
- Assume Kafka, PostgreSQL or microservices must be used simply because they appeared in an illustrative diagram.
- Claim logistics was selected as the final domain or that a new project was already started.

## Consequences and constraints

- Domain choice, system boundaries, exact feature scope and launch timing remain undecided.
- Future design may be revised after trade-off analysis and measurement.
- This record authorizes **no repository changes, cloud deployment, provisioned resources or source-code work**.

## Implementation/verification

User confirmed the learning distinction on 2026-11-04; no new domain system was implemented or tested in this Wiki update.

## Provenance

The user clarified that the previously shown domain candidates are for system-design and vibe-coding practice, separate from the already-designed Large-scale Board exercises.

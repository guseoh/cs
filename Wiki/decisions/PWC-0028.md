# 최초 Harness는 역할별 브랜치·검증·보고 인수인계·사용자 병합권으로 시작했다

## Historical problem
프로젝트 첫날에는 실제 Spring/Next/MySQL 앱보다 **협업 검증, 자동화, 기록 책임**을 먼저 만들기로 했다. [PR #1](https://github.com/guseoh/pawcycle-commerce/pull/1)은 commit/PR convention, local hook, GitHub Actions, Discord 협업 알림, Obsidian merged-PR 기록, 민감 파일 보호를 구현했다. 이 도구들은 제품 기능이 아니며 Secret이 실제 설정돼 Discord 전송까지 검증됐다는 뜻은 아니다.

## Historical selected policy — BOOTSTRAP-004
2026-07-02 [PR #3](https://github.com/guseoh/pawcycle-commerce/pull/3)은 당시 루트 `AGENTS.md`를 권위 기준으로 하고 역할 브랜치 `spec/po`, `design/ux`, `feat/be`, `feat/fe`, `test/qa`, `ops/sre`, `ops/tl`를 역할별 작업 분리 방식으로 확정했다. 필수 검증을 통과하면 commit/push까지 수행하되 **PR 병합은 사용자가 최종 검토 후 승인**하도록 했다. 한국어 명사형 commit/PR 제목 규칙, task report, handoff, PR metadata와 `validate-task-artifacts.py`의 연결을 결정했다.

## Alternatives and deliberately unresolved inputs
- 과거 작업 `ops/bootstrap-002`를 기계적으로 cherry-pick하면 새로운 `main`의 자동화를 대량 제거할 수 있어 **역할 브랜치 개념만 안전하게 수동 반영**했다. 사용자 승인 없이 원격 작업 브랜치를 삭제하지 않았다.
- CODEOWNERS, LICENSE, Dependabot/CodeQL 적용 시점과 세부 값, Backend/Frontend 실제 프레임워크 버전은 **당시 미확정**이었다.
- 무조건 최소 리뷰어 1명을 필수로 두면 1인 소유 저장소의 본인 PR 승인 제약이 생길 수 있어 GitHub UI settings의 실제 적용과 PR 문서만으로는 같은 상태를 주장하지 않았다.
- 단순 task ID 기반 산출물 validator는 빠르지만 정교한 코드 안전성 판단을 대체하지 못한다.

## Immediate post-merge correction — PR #2

The [2026-07-02 PR #2](https://github.com/guseoh/pawcycle-commerce/pull/2) fixed the new Obsidian PR-record pipeline after the first merge: `git diff --quiet` did not detect a new untracked record, and Korean letters were permitted in the generated filename slug. The correction used `git status --porcelain` and ASCII-only slug normalization, and added filename validation. The first PR's recorded metadata was also checked in. This is a **correction of the original automation**, not a separately approved architecture choice; see [PWL-0009](../lessons/PWL-0009.md). No claim is made that every later workflow invocation or real Discord webhook succeeded.

## Narrow task-ID corrections — PR #6 and #8

The initial task-artifact and automation parsers did not yet recognize every role's task IDs. [PR #6](https://github.com/guseoh/pawcycle-commerce/pull/6) aligned DOMAIN/API three-digit IDs across the artifact validator, Discord workflow and Obsidian record producer; [PR #8](https://github.com/guseoh/pawcycle-commerce/pull/8) extended the same mechanism to UX/DATA. Both kept the pre-existing naming scheme and avoided a whole harness redesign. The reported test fixtures were local, not evidence that every real GitHub run succeeded. These changes extend the *initial harness policy* rather than create unrelated decisions.

## Consequences, evolution and evidence limits
Harness·보고·PR 기록을 앱 구현보다 먼저 구축해 승인과 실행을 분리했다. 첫 PR 검증은 유효/무효 commit fixture, Python compile, Discord/Obsidian payload validator 및 Actions 기본 구조 검사였다. 실제 Discord delivery·Secret 설치·Production 검증은 아니다.

**현재의 상시 브랜치 `main` 하나+임시 Task Branch 방식은 이 7월 역할별 유지 브랜치 모델에서 진화했다.** 역사적 원칙의 효력을 현재 Git 운영과 혼동하지 않는다. 오늘의 최신 AGENTS/Harness와 사용자 승인 Gate가 권위가 높으며, 이 기록은 최초 선택 이유와 변천의 출발점이다. 후속 브랜치 정책 변경이 특정된 PR/승인 일자는 전체 연대기 조사에서 별도 연결한다.

## #22 / #26 최소 CI와 산출물 검증 진화

#22는 기존 conventions 뒤 Java25 test/build와 Node24 npm ci/lint/build를 추가하고 action SHA pinning·checkout 자격 증명 비영속화를 적용했다. 실제 DB/배포 CI가 아니며 로컬 JDK/경로 실패와 원격 성공은 [PWL-0012](../lessons/PWL-0012.md)로 분리한다.

#26은 AI Tech Lead를 검토·권고 역할로 명시하고 최종 결정권은 사용자에게 남겼다. QA 필요/생략과 리뷰 미반영 이유를 보고·handoff·PR template에 연결하고 validator를 파일 존재에서 필수 heading/증거 내용 검사로 확장했다. 표 헤더만 있는 빈 검증표 통과, 짧은 risk/limit alias 오탐, 중복 순회를 수정했으며 최종 fixture 14개와 보고의 14 tests를 대조했다. 과거 모든 보고서를 재검증하거나 의미·실행 성공을 자동 보장하지 않는다. [배치 #21–#30](../history/pawcycle-source-ledger/batch-021-030.md)이 고정 원본이다.

## #32 CI 환경과 #40 알림의 후속 경계

[MySQL CI 정책](PWC-0041.md)은 image tag drift를 승인된 제한으로 남기고 환경 제공과 앱의 DB 소비를 구분했다. [상세 알림](PWC-0043.md)은 원본 CI run SHA·event PR 번호를 보존하고 API 실패/collector 누락을 성공으로 숨기지 않도록 바뀌었다. 기본 브랜치 신뢰 코드와 Secret의 경계 때문에 수정 전 branch-script HTTP204를 안전한 최종 전송 근거로 재사용하지 않았다. 기존 최초 알림 정책을 지우지 않고 #40 correction으로 연결한다.

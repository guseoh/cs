# Tauri 2 기반 Windows 데스크톱 앱 추가

## 배경
Dark Todo Planner는 React 기반 웹 애플리케이션과 Cloudflare Workers/Hono/D1 백엔드로 운영되고 있다. 사용자는 Todo를 확인하고 기록하기 위해 브라우저에서 서비스를 찾아 들어가는 흐름보다, Windows에서 상시 접근할 수 있는 데스크톱 사용 경험을 원했다.

사용자가 공유한 Codex 정적 분석 보고서는 기존 HTTPS 웹 애플리케이션을 Tauri 2의 얇은 데스크톱 셸에서 여는 방식이 기존 화면·인증·API·데이터 계층을 재사용하는 최소 변경 경로라고 판단했다.

## 결정
Windows 데스크톱 앱은 **Tauri 2 기반으로 추가**한다. 기존 운영 HTTPS 웹 애플리케이션을 데스크톱 앱의 메인 창에서 열고, React 화면과 기존 백엔드·데이터 흐름을 재사용한다. 기존 웹/PWA는 계속 유지한다.

첫 구현 단위는 다음으로 제한한다.
1. Tauri 2 기본 앱과 단일 메인 창 구성
2. 시스템 트레이에서 열기·숨기기·종료 제공
3. 창 닫기 동작은 프로세스 종료 대신 트레이로 숨김
4. 전역 `Ctrl+Shift+K`로 메인 창을 표시·포커스하고 기존 Todo 빠른 입력 흐름 호출
5. 기존 `openQuickAdd` 및 입력·저장 로직 재사용

## 선택하지 않은 대안
- **Edge PWA만 사용:** 독립 창과 작업 표시줄 접근은 가장 적은 변경으로 얻을 수 있지만, 앱 전용 트레이와 다른 프로그램에서 호출하는 전역 단축키가 필요한 목표를 충족하지 못한다.
- **Electron:** 구현 대안으로 검토했지만, 현재 프로젝트에서 Node.js 런타임과 Chromium을 별도로 포함해야 할 필요성이 낮아 첫 선택으로 채택하지 않는다.
- **네이티브 UI 전면 재작성 또는 로컬 SQLite 도입:** 기존 React UI·Worker API·D1을 재사용할 수 있으므로 중복 구현과 동기화 복잡도를 만들 이유가 없다.
- **로컬 `dist`와 별도 API 출처 조합:** 기존 쿠키·Origin 보안 계약을 불필요하게 바꾸지 않도록, 첫 버전은 기존 HTTPS 앱을 같은 출처로 연다.

## 결과와 제약
- 기존 React/TypeScript 화면, Hono API, Cloudflare Workers 및 D1을 유지한다.
- 기존 인증, Todo API, 데이터 동기화, IndexedDB 오프라인 큐를 재작성하지 않는다.
- Tauri WebView는 Edge 브라우저와 별도 사용자 데이터 프로필을 사용하므로 기존 브라우저 로그인 쿠키가 자동 승계된다고 가정하지 않는다. 데스크톱 앱에서 별도 로그인 흐름을 확인한다.
- 원격 HTTPS 콘텐츠의 Tauri IPC 접근은 정확한 신뢰 출처로 제한하고, 트레이·전역 단축키·빠른 입력에 필요한 최소 권한만 노출한다.
- 별도 빠른 입력 창을 만들지 않고 단일 메인 창과 기존 빠른 입력을 재사용한다.
- 자동 실행, Windows 알림, 자동 업데이트, 미니 창은 첫 구현 범위에서 제외하고 핵심 흐름 검증 후 별도 결정한다.

## 구현 및 검증
2026-11-22 사용자가 Tauri 2 적용 방향을 확정했다. 근거가 된 Codex 보고서는 로컬 `main`의 `10e4532`를 기준으로 한 정적 분석 결과이며, 이번 Wiki 기록에서 소스 코드를 다시 검사하지는 않았다.

**현재 상태:** 방향 결정만 완료. Tauri 코드 추가, Windows 빌드, 트레이·전역 단축키·React 연동, 인증, 설치 패키지 및 운영 배포는 아직 구현·검증된 것으로 간주하지 않는다.

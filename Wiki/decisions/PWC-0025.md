# OCI Release는 정확한 이미지·소스·DB 호환 근거를 승인하고 불명확한 복구는 차단한다

## Context
AWS에서 OCI 단일 호스트로 바꾸면서 GHCR 이미지 발행은 됐지만 정확한 **running Backend/Frontend 이미지 쌍, Compose/Nginx 실제 설정, 현재 정상 기준선, Flyway/DB 호환성, 용량과 복귀 상태**를 하나의 Release 계약으로 다루지 못했다. 과거 AWS 배포·Rollback 스크립트를 그대로 복원하거나, 이미지 SHA만 확인하고 자동 배포하면 긴급 복구를 보장할 수 없었다([Issue #471](https://github.com/guseoh/pawcycle-commerce/issues/471)).

## Decision
2026-10-28 병합 [PR #472](https://github.com/guseoh/pawcycle-commerce/pull/472)는 **별도 OCI Release CLI**에 root-owned source/runtime/state, 승인 입력 및 protected lock, 정확한 main SHA, GHCR manifest/config digest, 로컬 Docker image/platform, Compose/Nginx의 독립 source SHA와 적용 bytes hash, DB migration tree/epoch 및 pair compatibility 근거, disk budget, 단독 서비스 health/HTTPS, metrics sibling 불변 조건을 요구한다.

**기본은 mutation OFF.** `adopt/preflight/activate/rollback/recover-state`를 실행하더라도 보호된 승인 Gate·정상 이전 상태·동일 DB/runtime 호환 증명이 없으면 거부한다. `current` 상태는 smoke 검증 뒤에만 durable commit한다. 실패·예외 때는 검증된 이전 정상 local image로만 자동 복귀를 시도하며, transition/commit 불명확성과 복귀 실패는 marker와 disabled 상태를 남겨 사람이 판단한다. 실제 Registry 장애 상황의 명시 rollback은 보존 local image를 검사하되 무조건 네트워크 없는 복구까지 보증하지 않는다.

[PR #475](https://github.com/guseoh/pawcycle-commerce/pull/475)는 containerd Image Store의 Index/Manifest/Config와 Legacy overlay2 식별 차이를 수정했다. 확인하지 못한 Store나 local descriptor를 임의 Config digest로 치환하지 않는다.

## Rejected alternatives
- **PR/CI 성공 = 실제 OCI 실행 승인:** Repository Verified와 운영 실행·Recovery Verified는 서로 다른 경계다.
- **이미지 태그만 믿고 적용:** 동일 tag의 잘못된 registry digest, local image platform/source, 실행 설정 drift를 놓친다.
- **이전 이미지가 존재하므로 언제나 rollback 가능:** 정상 이전 릴리스 및 DB 앱·데이터 양방향 호환 증명이 없다.
- **무조건 자동 재시도/force state 정리:** 실패 중 DB/Runtime과 실제 live 구성이 다를 수 있다.
- **DB Restore/Schema downgrade까지 코드 복귀로 묶기:** 애플리케이션 롤백은 데이터 복구를 포함하지 않는다.

## Implementation, verification and boundaries
[PR #472](https://github.com/guseoh/pawcycle-commerce/pull/472)에는 Linux disposable Release 회귀 39건, 수정 [#475](https://github.com/guseoh/pawcycle-commerce/pull/475)에는 47건 등 격리 검증과 Repository CI 성공이 기록됐다. 최신 [oci-release.py](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/infra/production/oci-release.py)는 protected state, image provenance 및 rollback preflight 계약을 포함한다. Runbook은 동일 migration tree도 데이터 의미의 호환성 **증거로 단정하지 말 것**을 명시한다.

이 결정은 **Release Engine의 저장소 구현**과 승인 방식에 관한 것으로, 최초 OCI 운영 activation·실제 강제 Rollback·DB Restore가 성공했다는 기록이 아니다. 2026-10-31 실제 최초 전환 시도와 차단 사례는 [PWL-0008](../lessons/PWL-0008.md)에 독립 기록한다.

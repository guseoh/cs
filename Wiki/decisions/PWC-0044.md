# 첫 구독은 도메인의 정확한 날짜 등식과 DB의 날짜 순서 제약을 구분했다

## Context / decision
API-003 D7은 DB에서 next_order_date > created_date, 도메인에서 생성일+배송주기의 정확한 등식을 보호한다. #42의 등식 CHECK 강화 제안은 한때 반영됐다가 승인 범위를 복원했다. DB 직접 SQL이 등식을 우회할 수 있다는 대가를 숨기지 않고 비등식 이후날짜 허용 테스트를 뒀다.

## Alternatives / consequences
DB의 더 강한 CHECK는 무승인 물리계약 변경이므로 채택하지 않았다. 2·4·8을 상품표시/구독런타임/정적migration 사이 공용상수로 결합하지 않았으며 각각 계약테스트로 drift를 통제한다. pagination·예외전체로깅은 승인API/식별자·SQL 비노출 경계를 이유로 보류했다.

## Implementation / verification
생성 쓰기transaction·목록/상세read-only·소유조건 fetch join1query·strict정수JSON·안전500 정확검증이 구현됐다. MySQL PK metadata 실패는 PRIMARY assertion을 고쳤다. 로컬Java25/MySQL 미실행과 최종원격CI 성공은 별개다. [상세](../history/pawcycle-source-ledger/batch-041-050.md).

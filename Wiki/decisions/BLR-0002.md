# Prioritize Java and Spring backend depth before dedicated AI and infrastructure study

## Context

AI-assisted development broadens the kinds of work a backend developer can attempt. This raises questions about frontend, cloud, infrastructure and AI engineering depth, but also creates a risk of spreading study time too thinly.

## Decision

Make Java and Spring backend proficiency the current top priority, supported by CS, OOP, databases, transactions, concurrency, testing, design reasoning and problem diagnosis. Keep previously acquired AI-assisted development and cloud/operations experience usable in existing projects. **Defer dedicated expansion** of AI/harness engineering and infrastructure/cloud engineering until more backend depth is built; this is a sequencing decision, not a ban on using those skills today.

Cloud deployment and operational literacy are relevant adjacent capabilities for a backend developer, but this discussion did not set a goal to master every cloud/platform-engineering specialization. Deep frontend code study is not a present priority.

## Rejected alternatives

- Divide new study time equally among backend, AI, frontend, and cloud: not selected.
- Stop using AI or cloud tools until backend studies finish: not selected.
- Treat AI code generation as a substitute for understanding and verifying backend systems: not selected.

## Consequences and constraints

- Existing projects and working infrastructure are not to be reset merely to follow the new priority.
- Current priority does not imply a confirmed calendar date or a defined competency threshold for switching focus.
- Adjacent field scope may be revisited with concrete project needs; no decision was made to adopt new infrastructure tooling.

## Implementation/verification

Priority was directly confirmed on 2026-11-04. This records learning allocation, not completed proficiency, employment readiness or any project deployment.

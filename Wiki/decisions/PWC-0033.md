# 첫 수직 MVP 도메인은 수량·배송 주기를 값 객체로 보호하고 날짜 계산은 Subscription에 둔다

## Historical problem
PS-001/PS-002는 로그인 회원, 단일 SKU, 수량 1–10, 2/4/8주, 자신의 구독 조회와 다음 주문 예정일을 제품 규칙으로 정의했다. [2026-07-03 PR #7](https://github.com/guseoh/pawcycle-commerce/pull/7)은 이를 실제 코드·DB 설계 전에 도메인 책임과 불변 조건으로 번역했다. 이 PR은 문서 기반 설계 승인이지 Java 구현이나 Production 검증이 아니다.

## Accepted domain decisions
- `Member`는 인증 자격의 사용자, `Customer`는 커머스 행위자라는 관점을 구분하되 MVP에서는 로그인한 회원을 구독 주체로 삼는다.
- `Product`는 공통 카탈로그, `SKU`는 실제 구독 선택 단위이며, SKU가 구독 가능 여부를 제공한다. 재고·품절·일반 판매 상태는 이 MVP의 구독 성공 불변 조건이 아니다.
- `Subscription`은 소유자, SKU 하나, 수량, 배송 주기, 생성일과 다음 주문 예정일의 도메인 의미를 보유한다. 인증 사용자 조회와 타 회원 접근 차단의 HTTP 표현은 애플리케이션/API 책임이다.
- `SubscriptionQuantity` 값 객체는 1–10 제약을 생성 시점에 보장한다. `DeliveryCycle` 값 객체는 허용된 2/4/8주와 날짜 계산에 쓰이는 기간 의미를 묶는다. 첫 MVP에서 구독 상태 모델은 두지 않는다.
- 애플리케이션이 `Asia/Seoul` 기준 날짜를 공급하고 **구독 도메인이 생성일+배송 주기로 다음 주문 예정일을 계산**한다. 표시용 주문 예정일과 실제 정기 주문 자동 생성/배송 예정일은 구분한다.

## Alternatives explicitly deferred or proposed
- `SubscriptionCreatedDate`와 `NextOrderScheduledDate`를 각각 별도 값 객체로 만드는 방식은 추가 불변식과 행위가 아직 부족하여 **Deferred**. 일반 날짜 의미로 먼저 표현하고 이후 변경 정책이 생기면 재검토한다.
- `SubscriptionEligibility` 값 객체 역시 상태/저장 계약 미확정으로 **Deferred**. SKU의 Boolean/enum/VO 중 구현 표현은 후속 결정이다.
- Product+SKU를 같은 Aggregate로 묶을지, Subscription이 SKU 전체와 식별자/스냅샷 중 무엇을 참조할지, 날짜 공급을 Clock으로 추상화할지는 **Proposed Technical Design**, Accepted로 승격하지 않는다.
- API 상태/오류 JSON, JPA/테이블/FK/물리 ERD, 인증 구현, 복수 SKU, 구독 관리, 실제 정기 주문·결제·재고·배송은 **당시 범위 밖**이다.

## Verification, consequences, evidence limits
이 분리는 수량/배송 주기 검증 중복과 날짜 계산 책임 분산을 예방하기 위해 채택된 **설계**다. PR #7은 8개의 PS-002 REQ 추적과 Markdown/validator 검사 통과를 보고했으나, 이번 Wiki 작업은 실제 Java 테스트·DB 상태를 재실행하지 않았다. 이후 구현이 문서와 일치하는지 판단하려면 후속 PR/현재 `main`을 확인해야 한다.

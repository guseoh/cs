# AI는 채팅에서 구현을 돕고 사용자가 물류 시스템을 실행·검증하며 의사결정한다

## 배경

최초 합의는 AI 기본 틀·핵심 공동 구현과 사용자 주도 결정을 강조했으나, 후속 대화에서 실제 진행 방식이 명확해졌다. 사용자는 **현재 채팅에서 정답 코드를 받고 직접 빠르게 작성**하기를 원한다. 모든 구현을 AI에게 위임하거나 모든 핵심 코드를 독립 구현하는 획일적 방식 모두 학습 목적에 맞지 않는다.

## 결정

1. **진행 환경·코드 전달:** ChatGPT 채팅이 학습과 설계의 중심 공간이다. 프로젝트 초기 설정, 개발 환경, 반복 코드, 일반 API·테스트·문서·리팩터링 등의 **완성 코드와 명령어는 채팅에 제공**한다. 사용자가 이를 로컬 IDE에서 작성·실행하며 결과를 공유한다. AI가 사용자 로컬 파일을 수정하거나 테스트했다고 간주하지 않는다.
2. **공동 논의·판단:** 요구사항, 도메인 모델, 핵심 로직, 알고리즘, 트랜잭션·동시성, 성능 실험, 기술적 의사결정은 **AI와 사용자가 함께 분석**한다. AI가 대안과 근거, 트레이드오프, 질문과 예시를 제공하고 사용자가 최종 선택한다. 단독 구현·단독 설계를 통과 조건으로 두지 않는다.
3. **힌트 우선 영역:** Kafka, 이벤트 처리, 장애 복구, 데이터 수집·정제·파이프라인, 캐싱, 고급 성능 최적화 및 처음 접하는 어려운 기술은 문제 정의 → 필요한 핵심 개념 → 단계별 힌트 → 사용자 첫 시도 → 피드백·검증 순으로 진행한다. 이는 **첫 시도 기회**를 우선 제공한다는 뜻이지 혼자 완성할 의무가 아니다. 사용자가 정답 코드·상세 설명을 원하면 제공한다.
4. **새 기술의 학습:** Kafka처럼 사용 경험이 없는 기술을 전제로 설계 결정을 강요하지 않는다. 최소 실행 흐름·왜 필요한지·대안 및 부작용을 이해한 다음 실제 문제를 통해 단계적으로 구현한다.
5. **완료 기준:** 코드의 핵심 실행 흐름과 선택 이유, 실패 시 영향, 테스트 기준과 결과를 사용자가 설명하고 평가할 수 있는지 우선한다. 설명·코드 제공, 로컬 작성, 테스트 통과, 성능 검증, 배포는 각각 별도의 상태다.
6. **프로젝트 적용:** 현재 물류 학습 프로젝트부터 이 방식을 적용한다. 기존 PawCycle·Large-scale Board·DevPedia의 이미 확정된 개별 구현 계약을 자동 대체하지 않는다.

## 선택하지 않은 대안

- 모든 핵심 로직을 AI가 저장소에 직접 작성해 놓았다고 가정하는 방식.
- 트랜잭션·알고리즘 등 모든 핵심 내용을 반드시 사용자 혼자 처음부터 구현하도록 강제하는 방식.
- Kafka 등 새로운 기술을 충분히 설명하지 않고 바로 완성 코드로 대체하는 방식.
- AI의 제안만으로 최종 기술을 확정하거나 실제 실행 확인 없이 검증 완료라고 기록하는 방식.

## 결과와 제약

이 결정은 **학습 진행 방식**에 관한 것이며 프로젝트 특정 아키텍처나 기술 도입을 승인하지 않는다. 사용자가 채팅의 코드를 실제 작성했는지, 테스트했는지는 사용자 결과 또는 저장소 증거로 확인한다. 대규모 트래픽·분산 기술은 학습 대상으로 검토하되 실측과 필요성이 확인되기 전까지 필수 조건이 아니다.

## 구현 및 검증

2026-11-19 사용자 후속 요청으로 채팅 기반 코드 제공 및 힌트 우선 경계를 구체화해 기존 미병합 초안을 보완했다. 사용자가 방식과 물류 프로젝트 시작을 확인했을 뿐, 앱 코드 작성·테스트·배포는 아직 수행되었다고 주장하지 않는다.

## 출처와 결정 경위

사용자 명시 결정에 기반한 공개 가능 요지이며 원문 대화를 게시하지 않는다.

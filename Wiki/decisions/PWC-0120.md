# Subscription 내부 실패는 domain 의미로 전달하고 HTTP는 API가 결정한다

## Context

Application7개·Persistence2개가 HTTP 숫자를 가진 SubscriptionApiException 에 직접 의존했다.

## Decision

내부 41개 상수 실패 지점을 SubscriptionFailure Kind/code/message/cause 로 바꾸고 기존 Advice 가 400/404/409/412/428로 매핑한다. Controller 의 If-Match 문법 검사는 기존 API 예외와 handler 를 유지한다. 예외 조건·우선순위·메시지·cause·SQL/Clock/transaction 은 바꾸지 않는다.

## Alternatives and interpretation

공통 exception framework, domain 의 Spring Web/HTTP 숫자 의존, concrete assertion 약화, controller 오류와 application replay/version 검사의 순서 변경을 제외했다.

## Consequences and limits

직접 내부 caller 의 구체 예외 타입은 바뀌지만 HTTP body/status 는 유지해야 한다. Kind 와 API switch 의 대응을 함께 관리한다.

## Implementation and verification

정확한 9edge 만 제거해 baseline202→193, 작은 23/신규 HTTP10·Seoul·실 MySQL/최종 CI·physical5 PASS 였다. 최초 stale baseline 실패와 DB 초기화 socket 실패를 보존했다. 새로운 제품 정책이나 운영 검증은 아니다.

## Provenance

공개 GitHub 원본의 당시 선택을 2026-11-04에 복원했다. 저장소 구현·테스트 보고·CI·운영 사실을 구분하며, 이번 작업에서 제품·DB·Provider·부하를 새로 실행하지 않았다.

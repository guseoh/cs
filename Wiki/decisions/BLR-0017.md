# Large-scale Board는 Spring REST API 기본기부터 완성하고 이후 대규모 시스템 실험으로 확장한다

## 배경

Large-scale Board는 단순한 Java/Spring 게시판을 구현하고 데이터·트래픽·장애를 추가하면서 한계를 경험하도록 계획되었습니다. 그러나 `main`에는 Article CRUD보다 앞서 Snowflake, 공통 예외 처리, 추적 로깅, 데이터 생성·성능 비교, 관측/장애 훈련 및 아키텍처 규칙이 상당 부분 구현되어 있습니다. 일부는 실제 성능·장애 실험으로 검증되어 유의미하지만, Spring REST API의 기초 구현을 학습하려는 현재 목표와 순서가 맞지 않습니다.

## 결정

1. **현행 최우선 과제:** Spring REST API S01~S08의 Article Controller/HTTP, 요청·응답 DTO, 기본 Validation, JPA 엔티티·Repository/CRUD, 트랜잭션, 목록·페이징, 필요한 예외 처리, 기능 테스트를 먼저 구현합니다. S01은 기존 환경을 간단히 확인하고 S02부터 시작합니다.
2. **필수 선행 조건 제거:** Pure Java J01~J05는 막히는 문법·객체 개념이 있을 때 선택적으로 복습합니다. 광범위한 Domain Map/ERD/NFR/분산 설계 문서나 기존 0단계 인프라 전체를 새 REST API의 진입 조건으로 삼지 않습니다. S06 인증은 실제 사용 사례의 필요 시 진행합니다.
3. **최소 구현 원칙:** Controller → Service → Repository → DB의 작은 흐름을 먼저 동작시킵니다. Article의 첫 ID 전략으로 기본적인 JPA 방식을 학습하고 Snowflake/`BaseEntity`를 자동 강제하지 않습니다. Spring MVC의 기본 오류 처리와 Validation을 우선 경험하며, 근거 없는 모든 예외 캐치·중첩 원인 탐색·엄격 JSON 전역 설정·과도한 오류 코드 세분화·미래 대비 추상화는 피합니다.
4. **안전 보장:** 입력 검증, 유니크·외래 키 등 DB 무결성, 정확한 트랜잭션, 필요 시 인증·인가, 비밀정보 비노출 및 실패의 올바른 표현은 단순화를 이유로 생략하지 않습니다.
5. **고급 학습 시점:** 기본 API 동작을 실행/테스트로 검증한 다음 기존 Phase 0~13을 활용합니다. 새로운 최적화는 기준선 → 문제 재현 → 측정 → 가설·대안 비교 → 결정 → 구현 → 동일 조건 재측정의 순서를 지킵니다.
6. **기존 자산·역할 보존:** 이미 구현/검증한 Snowflake, `Persistable`, 대량 적재 실험, Prometheus/Grafana, 장애 훈련 및 ADR을 삭제하거나 실패로 취급하지 않습니다. [BLR-0015](BLR-0015.md)의 사용자 `src/main` 직접 구현, AI 테스트·스크립트 지원 원칙은 유지합니다.

## 선택하지 않은 대안

- **현재 구조를 그대로 확장:** 기반 설계의 완성도가 높아져도 작은 REST API를 직접 만드는 학습 목적이 계속 뒤로 밀립니다.
- **기존 성능·장애 실험을 모두 삭제하고 재시작:** 이미 확보한 측정 결과와 학습 근거를 잃으므로 선택하지 않았습니다.
- **기초 API에 모든 공통 구조를 의무 적용:** Snowflake/`Persistable`, 복잡한 전역 오류 계약과 고급 아키텍처 규칙을 이유 없이 도입하면 원리를 경험하기 어렵습니다.

## 결과와 제약

새 규칙은 **진행 순서와 미래 변경의 기준**입니다. 기존 상세 Phase 0~13의 실험 목적·완료 조건은 유지합니다. 이 결정은 모든 기존 코드를 리팩터링하라는 뜻이 아니며, 이미 검증된 DB 타임아웃·Snowflake·JPA 저장 최적화의 의미를 부정하지 않습니다. 기존 회원가입/인증 브랜치의 구현 결과는 보존하되 현재 진행의 선행 작업으로 강제하지 않습니다.

- 이 결정이 수용되었다는 것과 **API 구현·테스트 완료, PR 병합, 운영 검증**은 별개입니다. 병합 여부는 GitHub PR 상태로 확인합니다.

## 출처와 결정 경위

2026-11-21 사용자는 Spring REST API 기본기보다 대규모 시스템의 선제 설계에 학습이 잠식되었다고 판단하고, 저장소의 진행 원칙과 중앙 Wiki 반영 및 병합을 명시적으로 요청했습니다. 비공개 대화 원문은 옮기지 않고 공개 가능한 요지와 코드 근거만 기록합니다.

# Large-scale Board 1단계: 사용자는 main 코드, AI는 테스트·스크립트·측정 도구를 작성한다

## 배경

Large-scale Board 1단계(회원과 인증)를 Claude Code 채팅에서 진행하면서, 처음 합의한 "AI가 정답 코드를 주고 사용자가 모두 입력"하는 방식이 두 가지 이유로 느렸다. 코드를 하나 쓸 때마다 전체 테스트를 돌렸고, 설명이 코드와 떨어져 있어 읽기 불편했다. 사용자는 운영 규칙을 조정했다.

## 결정

1. **역할 분담:** 사용자는 `src/main` 코드를 직접 작성한다. **테스트 코드, 스크립트, 성능 측정 도구는 AI가 작성**하고 설명한다.
2. **정답 코드는 처음부터 보여 준다.** 이 프로젝트는 학습 프로젝트이므로 힌트 단계를 두지 않는다. 코드 블록마다 **바로 아래에 짧은 설명**을 붙이고, 모르는 부분만 사용자가 질문한다.
3. **진도는 묶음 단위로 빠르게 간다.** 묶음 중에는 해당 테스트만 돌리고, 묶음 끝에 전체 테스트를 한 번 돌린다.
4. **Lombok을 쓰고 최신·실무 스타일로 작성한다.** 1단계가 모두 끝나면 Wiki와 저장소 문서에 과정과 설명을 구체적으로 기록한다.
5. AI는 사용자 요청 없이 `src/main`을 수정하지 않는다. 커밋·푸시·PR·병합은 사용자가 시킬 때만 한다.

## 선택하지 않은 대안

- 0단계처럼 AI가 모든 코드를 직접 작성하는 방식(비즈니스 단계에서는 직접 작성하며 배우는 목적에 맞지 않는다).
- 모든 테스트까지 사용자가 직접 작성하는 방식(진도가 느려지고, 학습 초점이 아닌 도구 코드에 시간이 쓰인다).

## 결과와 제약

[BLR-0014](BLR-0014.md)(신규 물류 프로젝트의 협업 방식)와는 별개로, **Large-scale Board의 기존 프로젝트별 계약을 구체화**한 것이다. 사용자가 작성한 코드와 AI가 작성한 테스트를 구분해 기록하며, 테스트 통과는 사용자 저장소에서의 실행 결과로만 주장한다.

## 구현 및 검증

2026-11-19 1단계 1-A(시간·`BaseEntity`·`Member`·ID 문자열화)와 1-B-3(트랜잭션 실험)에서 이 방식으로 진행했다. 사용자가 작성한 main 코드와 AI가 작성한 테스트로 구성된 PR이 병합되었다(PR 번호와 시점은 [프로젝트 현황](../projects/backend-learning.md)의 2026-11-19 항목 참조). 1-B의 가입 API main 코드는 사용자 작성 대기 중이다.

## 출처와 결정 경위

사용자 명시 요청에 기반한 공개 가능 요지다. 원문 대화는 게시하지 않는다. 운영 규칙의 상세는 Large-scale Board Wiki의 인수인계 페이지(§8.1)가 정본이다.

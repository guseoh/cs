# 학습용 단일 저장소에서 여섯 도메인을 독립 Gradle 하위 프로젝트로 관리하는 안 (검토 중)

## 배경

현재 사용자는 물류 학습 도메인을 먼저 선택했으나, 물류만이 아니라 앞서 비교한 대중교통 경로 검색·부동산 실거래가 검색 및 분석·티켓 예매·주차장 검색/예약·실시간 이벤트 분석까지 **단일 GitHub 저장소의 각 모듈로 관리하는 방향**을 문의하였다. 아직 구조를 최종 승인하거나 저장소를 생성한 것은 아니다.

## 제안

- **Monorepo + Gradle 멀티 프로젝트:** 하나의 소스 저장소 안에 독립적인 실행·테스트 단위인 `apps/logistics`, `apps/transit-search`, `apps/real-estate`, `apps/ticketing`, `apps/parking`, `apps/event-analytics`를 점진적으로 추가한다.
- **6개 독립 도메인/실험:** 이는 하나의 물류 서비스 아래에 다섯 기능을 결합하는 모듈형 모놀리스나 처음부터 상호 호출하는 마이크로서비스가 아니다. 각 도메인이 자체 비즈니스 모델·API·테스트·데이터베이스 또는 스키마, 실행 설정을 가진 독립 학습 애플리케이션이다.
- **처음에는 첫 모듈만 생성:** 현재 사용자의 별도 물류 학습 선택을 존중하여 첫 모듈을 물류로 시작하고, 다른 주제는 실제 학습을 시작할 때 추가한다. 초기부터 6개 Spring Boot 스캐폴딩/DB/컨테이너를 만드는 것을 강제하지 않는다.
- **공통화 최소화:** Java·Gradle 도구 버전·빌드 규칙·테스트 인프라 지침·문서 템플릿은 공통화 가능하지만, 엔티티·서비스·Repository·스키마는 단순한 모양의 유사성만으로 공유하지 않는다. 공통 라이브러리는 반복 필요성이 실증되면 추출한다.
- **Wiki 구조:** 실제 소스 저장소가 생기면 도메인별 상세 Wiki/ADR/실험 로그를 두고, 중앙 `guseoh/cs/Wiki`는 선택한 실험, 확정 결정, 재현 근거 링크, 진행 상태를 관리한다. 저장소 Wiki 접근·쓰기 가능 여부는 생성 후 검증한다.
- **학습 운영:** 한 번에 하나의 도메인을 주요 진도로 진행하고 각 실험·설계·성과를 검증한다. 모든 모듈 완성을 최초의 의무 조건으로 설정하지 않는다.

### 예시 폴더 (최종 설계 미확정)

```text
backend-systems-lab/
├── settings.gradle.kts
├── build.gradle.kts
├── gradle/
├── apps/
│   ├── logistics/
│   ├── transit-search/
│   ├── real-estate/
│   ├── ticketing/
│   ├── parking/
│   └── event-analytics/
└── docs/
```

각 `apps/*`는 **독립 Gradle 하위 프로젝트**의 예시다. 위 파일·폴더는 현재 생성되어 있지 않다. `settings.gradle.kts`의 include 대상 역시 실제 시작한 모듈로 한정한다.

## 비교한 대안과 트레이드오프

- **도메인별 분리 저장소:** 빌드/의존성/CI 격리가 명확하지만 공통 학습·운영 기록과 빌드 설정이 분산될 수 있다.
- **단일 저장소 + 단일 Spring Boot 애플리케이션:** 초기에 단순하지만 무관한 도메인의 데이터 모델과 설정·테스트 경계가 뒤섞일 수 있다.
- **단일 저장소 + 각 도메인 독립 하위 프로젝트(제안):** 버전 관리·학습 기록을 모으면서 구현을 격리할 수 있다. 대신 루트 빌드 설정, 변경 영역별 CI, 여러 앱의 메모리/인프라 자원 관리 비용을 고려해야 한다.

## 결과와 제약

**제안 단계이며 사용자의 최종 승인 전**이다. 사용자가 이미 확정한 것은 물류 학습 프로젝트라는 첫 방향과 채팅 기반 AI 협업·Wiki 기록 원칙이다. 단일 저장소로 범위를 확장할지, 여섯 도메인의 실행 형태와 우선순위를 최종 정할지는 아직 미결이다. 기존 [LGR-0001](LGR-0001.md)의 확정 이력을 소급 변경하지 않는다.

## 구현 및 검증

실제 멀티 프로젝트 빌드, 도메인 애플리케이션, 테스트, CI, 저장소, 프로젝트 Wiki는 생성·검증되지 않았다. Gradle·Spring 공식 자료는 구현 가능한 방식의 참고일 뿐 사용자 승인이나 실행 검증의 증거는 아니다.

## 출처와 결정 경위

2026-11-19 사용자가 여러 학습 도메인을 하나의 저장소에서 모듈별로 진행하는 **가능성을 질문**했다. 따라서 기록을 `status: proposed` 및 `evidence_level: unverified`로 보관한다.

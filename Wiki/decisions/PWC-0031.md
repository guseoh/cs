# 첫 구독 생성·조회 API-003 D1~D8 승인과 멱등성 미도입의 당시 대가

## Scope and authority
[API-003](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/api/API-003-subscription-api-contract-decision-request.md)은 2026-07-13 **사용자가 'D1~D8 전체 추천안 승인'**을 명시했고 [PR #39](https://github.com/guseoh/pawcycle-commerce/pull/39)는 이를 Approved API Contract로 저장했다. 원본 API-001·DATA-002 전체의 Proposed 상태는 유지됐다. 이는 2026년 7월 **첫 구독 수직 MVP** 계약이며 이후 MVP2/3·V2 Subscription이 채택한 재생/상태 전이까지 동일하다는 뜻은 아니다.

## Approved D1–D8 and rejected alternatives
1. **D1 Endpoint/HTTP:** `POST /api/subscriptions`는 인증·CSRF 필수 `201`, 본인 목록과 `/{subscriptionId}` 상세는 GET `200`. `200` 생성 성공, `/api/v1` 버전 접두사와 `/create` 액션 URI는 처음에는 불필요한 계약·운영 비용으로 거절.
2. **D2 생성 DTO:** 요청은 `skuId`, `quantity`, `deliveryCycleWeeks`만 받고 응답은 `subscriptionId`, `nextOrderDate`로 상세 화면 이동을 지원. 클라이언트 생성일·다음 주문일 입력은 도메인의 날짜 권한을 훼손하므로 미선택. 응답에 상세 전체를 중복 포함하지 않음.
3. **D3 조회 DTO/순서:** 본인 구독 목록·상세에 Product/SKU 중첩 요약, 목록은 `subscriptionId DESC`, 상세에 필요한 가격/생성일을 보낸다. 평탄화·목록의 과한 필드·무정렬 응답은 의미 혼합·조회 비용·QA 불안정 때문에 기각. N+1은 MySQL 테스트 대상.
4. **D4 인증/소유권:** 세 API 모두 session principal의 `memberId`로 소유자 범위를 정하며 request body의 memberId를 신뢰하지 않는다. **미존재·타인 소유·비숫자 ID 모두 404**와 같은 안전 오류를 쓴다. 403 등으로 소유 여부를 구별하는 대안은 정보 누설 위험이 있다.
5. **D5 안전 오류:** 입력 누락·JSON/type·수량·주기 검증은 하나의 `VALIDATION_FAILED` 400 + 필드 오류, SKU 미존재 404, SKU 구독 불가 409, 구독 미존재 404. 생성/목록/상세 예상 밖 오류는 구분된 안전 500 코드로 반환하고 raw DB/Security 예외를 노출하지 않는다.
6. **D6 중복·멱등성:** 동일 회원의 동일 SKU·수량·주기 **복수 구독을 허용**하고 유효한 HTTP 호출 하나마다 하나를 생성한다. 동일 조건 unique/index와 `Idempotency-Key` replay 저장소는 **첫 MVP에서 미도입**. Client는 처리 중 제출 버튼 비활성화만 적용한다. 타임아웃 후 반복 POST는 실제 중복 구독을 만들 수 있는 위험을 사용자가 승인했다.
7. **D7 물리 데이터:** 새로운 Flyway `subscriptions` 테이블에 id, member_id, sku_id, quantity, delivery_cycle_weeks, created_date, next_order_date. FK, NOT NULL, quantity 1~10/주기 2·4·8/날짜 순서 CHECK, `(member_id,id)` 인덱스만 우선 추가한다. 상태/가격 snapshot/결제/배송/과거 시각 컬럼·측정 없는 추가 인덱스는 제외.
8. **D8 구현/검증:** 이 API 3개와 migration은 **하나의 Backend PR**에서 원자 TX 생성·read-only 조회·Clock 주입·좁은 JPA 관계·N+1 검증·Security/MySQL 테스트로 구현한다. API별 여러 PR/QA 분할은 반복 migration·모델 조정과 완료 지연 비용 때문에 미채택. FE 완료 후 수직 흐름 전체 QA는 별도 검증한다.

## Consequences, temporal boundary and evidence
D6의 idempotency 미도입은 당시 **의도된 Trade-off**이지 최근 구독 V2의 멱등성 부재를 뜻하지 않는다. 결제·재고·배송·상태 변경·자동 주문·OpenAPI 도구/추가 dependency는 그 시점 명시 제외였다. 후속 [PR #42](https://github.com/guseoh/pawcycle-commerce/pull/42)가 구독 구현, [PR #43](https://github.com/guseoh/pawcycle-commerce/pull/43)가 FE, [PR #46](https://github.com/guseoh/pawcycle-commerce/pull/46)가 통합 QA의 연대기 출처다. PR #39 자체는 계약 승인 기록이며 런타임 구현이나 운영 검증은 아니다.

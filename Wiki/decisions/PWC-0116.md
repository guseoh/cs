# 필수 MySQL 물리 잠금 회귀는 실제 JUnit 실행을 fail-closed로 검사한다

## Context

물리 잠금 observer 가 권한 부족으로 SKIP 돼도 일반 CI 가 성공할 수 있었고, test source 의 존재만으로 실행 성공을 알 수 없었다.

## Decision

폐기되는 GitHub Actions MySQL8.4 서비스에만 필요한 P_S SELECT 와 조건부 PROCESS 를 준비하고 privilege/consumer preflight 를 통과해야 한다. 비관리자 application test 계정을 유지한다. Backend test→필수 JUnit gate→build 순서를 강제하며 T09 정확 1 PASS, T10 소스가 모두 있을 때 A/B/C 각 1과 physical1 PASS 를 요구한다. 누락·중복·SKIP·FAIL·부분 소스는 거부한다.

## Alternatives and interpretation

root 로 전체 테스트 실행, 운영 DB 권한 확대, if/continue-on-error 로 gate 우회, 같은 A invocation3회를 A/B/C 로 세기, 비결정적 Purge 수동 진단을 모든 PR 에 강제하는 안을 제외했다.

## Consequences and limits

전역 PROCESS 는 일회용 CI 내부 T10 관측에만 조건부 적용된다. JUnit display name 과 ValueSource 의 대응도 계약이므로 실제 XML 기반 회귀가 필요하다. 전역 JAVA_TOOL_OPTIONS 는 하위 프로세스를 오염시켜 Gradle Test 범위 init-script 로 제한했다.

## Implementation and verification

#363에서 gate 우회/중복 false-green 두 review finding 을 negative mutation 으로 교정했다. T10 소스가 없던 시점은 T09만 실제 실행됐다. #364 실제 display name 통합 뒤 1/3/1 총 5 PASS 를 확인했다. 첫 실패와 같은 HEAD rerun 은 별도 기록이며 이 gate 가 과거 Purge 시점을 증명하지 않는다.

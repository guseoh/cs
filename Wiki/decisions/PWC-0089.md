# AWS 임시 Auto-CD는 성공한 main image SHA를 기존 Production Deploy에 전달한다

MVP4 반복 수동 target_sha 복사를 줄이기 위해 성공한 main push 이미지 workflow만 기존 Production Deploy workflow_dispatch로 연결했다. manual image publish는 제외하고 success/push/main/SHA를 이중검사한다. actions:write dispatcher는 직접AWS접근이나 migration승인값을 만들지 않으며 기존 immutable image·SSM·concurrency·contract/Flyway gate를 유지한다.

병합자체가 첫 자동배포를 유발할 수 있는 고위험 변경이다. #253은 저장소준비 근거이며 실제 chain·환경승인·Production결과는 아직 확인되지 않았다. dispatcher성공≠deploy성공이다. 임시workflow삭제는 수동정책복귀이며 rollback/restore실행과다르다. 이 기록은 과거AWS경로로 보존하고 현재OCI Host Pull CD와 혼동하지 않는다.

#277은activeAWS임시Auto-CD/SSMworkflow를retire하는OCI repository안을담았지만최종closed-unmerged이므로해당PR만으로main/실환경retirement완료를확정하지않는다.

#283은#282merge/imagepublish뒤ProductionDeploy#40자동dispatch가발생한사건을근거로임시autoCD를제거했다. OIDC실패뒤SSM명령은skip됐으므로실제배포성공이아니다. #284는activeAWS실행표면을실제mergedPR로철거했고당시target없음/CDDEFER로정렬했다. #277미병합안과구분한다.

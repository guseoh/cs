# 두 번째 MVP는 Pet·PlanVersion·불변 snapshot과 구독 관리로 확장한다

## Context
첫 MVP의 단일 SKU 구독 생성·조회만으로는 반려동물별 패키지 구성과 이후 가격 변경을 안전하게 표현하기 어렵다. [PS-004](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/product/PS-004-second-mvp-requirements.md)는 확정 제품 정책을, [DOMAIN-002](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/domain/DOMAIN-002-second-mvp-subscription-domain.md)는 이를 만족하는 Accepted Domain Design을 명시한다.

## Decision
회원 소유 Pet(DOG/CAT), 대상 종에 호환되는 PlanVersion, 선택 당시 가격·구성과 배송 주기의 불변 snapshot을 도입한다. 구독은 ACTIVE·PAUSED·CANCELED 상태와 SCHEDULED·SKIPPED·HELD·CANCELED Schedule을 갖는다. 플랜 변경은 다음 실행 가능한 회차에 적용할 pending snapshot을 만들며, 구독당 pending은 최대 하나이고 새 변경은 기존 pending을 교체한다. 과거 PlanVersion과 snapshot을 수정하지 않고 기존 1차 MVP 구독은 별도 legacy 이행 정책으로 보존한다.

## Rejected alternatives
- **활성 PlanVersion 또는 과거 snapshot을 제자리 수정:** 이미 생성된 구독의 가격·구성 의미를 바꾸므로 승인된 불변성 계약과 맞지 않는다.
- **MVP1 계약을 소급 교체하거나 레거시 데이터를 초기화:** 기존 API/데이터 보존 요구와 충돌한다.
- **구독 관리와 동시에 실제 Order 자동 생성:** 당시 MVP2 제품 범위에서는 제외했으며 후속 [SUB-AUTO-001](PWC-0005.md)에서 별도 승인했다.

## Consequences and constraints
현재 적용 snapshot과 다음 회차 pending snapshot의 구분을 유지해야 한다. 대상 Pet 소유권, PlanVersion 유효 기간과 종 호환성, 명령 멱등성·Schedule cardinality는 독립 검증할 불변 조건이다. 세부 HTTP `If-Match`·낙관적 버전·DB unique·migration 실행 설계는 별도 [ARCH-007](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/adr/ARCH-007-second-mvp-subscription-consistency.md)에 **Proposed**로 작성돼 있으므로 이 Decision의 승인 범위에 포함시키지 않는다.

## Implementation/verification
이 항목은 승인된 제품·도메인 판단을 보존한다. 최신 main에 해당 문서가 존재함을 확인했으나 이번 작업에서 코드·migration·실제 MySQL concurrency test를 독립 실행하지 않았다. 제품 승인과 구현 검증은 별개다.

# 역사적 AWS DB 선택: Docker MySQL에서 private RDS Single-AZ를 준비하고 생성한다

## Context
2026-08 AWS EC2 한 대의 Docker MySQL은 애플리케이션과 DB가 같은 장애 영역을 공유했다. 논리 백업과 격리 복원 근거는 있었지만 자동 백업/PITR, 패치·호스트 생명주기, 장애 복구 목표에는 공백이 있었다. [Issue #152](https://github.com/guseoh/pawcycle-commerce/issues/152)는 **현재 Docker MySQL 유지 / RDS Single-AZ / RDS Multi-AZ**를 비용·가용성·복구·운영 책임 기준으로 비교하도록 했다.

## Decision
[ARCH-013](https://github.com/guseoh/pawcycle-commerce/blob/main/docs/adr/ARCH-013-rds-single-az.md)은 당시 단일 EC2 운영 규모와 비용에 맞는 **private RDS MySQL Single-AZ**를 준비 대상으로 선택했다. Multi-AZ는 DB 쪽 가용성을 높일 수 있어도 단일 EC2 애플리케이션의 종단 간 HA를 제공하지 않으며 비용이 더 든다. SG 출발지 제한, 비공개 subnet, TLS, encryption, 자동 백업/PITR은 이 준비 계약의 일부다. read replica, RDS Proxy, app multi-instance, 자동 장애 조치 검증은 이 결정의 완료 범위가 아니다.

## Rejected alternatives
- **Docker MySQL 무기한 유지:** 당시의 backup/PITR 및 DB lifecycle 관리 부담을 개선하지 못한다. 기존 volume과 백업은 이행 과정에서 보존했다.
- **즉시 Multi-AZ:** 더 큰 비용에 비해 단일 EC2가 남아 있는 전체 서비스 가용성의 개선은 제한적이다.
- **Replica, RDS Proxy, app multi-instance 동시 도입:** DB 운영 전환 목표에 비해 변경/운영 범위가 확대된다.

## Consequences and constraints
2026-08-18 [PR #154](https://github.com/guseoh/pawcycle-commerce/pull/154)는 **Repository Readiness**만 준비했지만, 그 다음 [Issue #157](https://github.com/guseoh/pawcycle-commerce/issues/157)의 작업 결과 댓글에는 승인된 private Single-AZ 인스턴스를 실제 생성해 `available`, encryption 및 7일 백업 보존 설정을 확인했다고 적혀 있다. **'저장소 준비만 했고 RDS를 만들지 않았다'는 해석은 이 후속 근거와 충돌한다.** 반면 이 생성만으로 Production datasource 전환, PITR 실제 restore, 서비스 운영 검증을 주장할 수 없다.

[Issue #158](https://github.com/guseoh/pawcycle-commerce/issues/158)의 2026-10-23 마감 댓글은 AWS RDS migration rehearsal의 import/schema/Flyway 완료 근거가 없음을 명시하고, 실제 완료가 아닌 **Not planned(타깃 폐기)**로 종료했다. 이력의 종료/전환 사실은 RDS를 생성한 과거 사실을 지우지 않는다.

## Implementation/verification
근거 수준은 저장소 PR #154의 검증 결과와 Issue #157에 남은 **과거 승인된 AWS 실행 결과 보고**다. 이번 세션에서 AWS 콘솔/실제 과거 DB를 직접 조회하지 않았다. 고가용성 failover·PITR restore·RDS cutover 실증은 미확인 또는 미수행 범위다.

## Provenance
원래 설계 날짜: 2026-08-18. 실제 생성 보고: 같은 날 Issue #157 댓글. 계획된 rehearsal은 2026-10-23 '미실행 상태로 대상 폐기' 판정. 이후 장기 운영 플랫폼을 OCI Always Free로 바꾸는 [PWC-0013](PWC-0013.md)이 이 역사적 AWS 목표를 대체했다. 현재 AWS 운영 결정을 뜻하지 않는다.

## #152~#158 판단 순서와 검증 상한

처음Docker유지/Single-AZ/Multi-AZ를비교해추가판단으로두고0원우선·운영책임/PITR을대조한뒤Single-AZ후보를골랐다. #154는RDS sslModeREQUIRED를준비하되CA/hostname검증부재를실cutover승인에서다시수용하거나hardening하도록했다. #157은실MySQL8.4.6/micro/private/encrypted/20GiB/backup7일생성Verified다.

#158의import/schema/Flyway완료근거는없고OCI전환후not_planned로마감됐다. 격리restoreMATCH와candidate파싱실패는RDSrehearsal완료가아니다. RPO/RTO·PITRrestore·실cutover를검증완료로확대하지않는다. [번호순원본](../history/pawcycle-source-ledger/batch-151-160.md).

## #163~#168 후속 RDS 사용 증거와 #158 마감의 긴장

#163~#165는RDSruntime/cutover이후preflight routing·stdin결함을보고한다. 특히#168실AWS성능댓글은db.t4g.micro의CPU/connection/메모리/latency와Backend지표를같은실행시간에대조했다. 따라서후속RDS사용증거가전혀없다고해석할수없다.

반면#158최종댓글은rehearsal완료Gate의근거없음을이유로not_planned마감했다. 이마감과후속운영관측을둘다보존한다. #168은당시RDS사용/부하관측근거이며rehearsal/import/cutover전체승인·일관성·rollback/PITR감사기록을대신하지않는다. 이차이는미확인으로남긴다. [상세근거](../history/pawcycle-source-ledger/batch-161-170.md).

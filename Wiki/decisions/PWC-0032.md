# FOUNDATION-000 최초 기술 버전 추천안은 Proposed였고 일부만 별도 구현 승인했다

## Historical stage
2026-07-06 [FOUNDATION-000](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/adr/FOUNDATION-000-technology-version-decision.md)과 [PR #20](https://github.com/guseoh/pawcycle-commerce/pull/20)은 Spring/Next/MySQL 첫 앱을 만들기 전에 호환 가능한 toolchain·DB·CI 후보를 제시했다. **문서 Status: Proposed.** 원본 자체는 그 안의 기술 버전 전체에 대한 사용자 승인서가 아니다. 실제 초기 구현은 [ARCH-006](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/adr/ARCH-006-first-backend-implementation-approved-inputs.md)에서 범위를 정해 승인한 입력으로만 출발한다.

## Original proposed option set
| 범위 | 2026-07-06 추천 | 검토 이유·대가 |
| --- | --- | --- |
| Java | 25 LTS | 장기 지원·Spring/Gradle 호환을 기준으로 선택하되 로컬 toolchain 검증 필요 |
| Spring Boot | 4.1.x | Spring Framework 7/Jakarta 기반 제안. 실제 Gradle/JDK 호환 점검 필요 |
| Gradle | 9.1 이상 9.x patch | Java 25 runtime/toolchain과 Boot plugin 호환 우선 |
| Node / Next / TypeScript | Node 24 LTS / Next 16.x / TS 6.0.x | 첫 프로젝트에 별도 runtime 관리 부담 축소, 실제 scaffold/build 호환 검증 요구 |
| FE package/build | npm + package-lock, ESLint/typecheck/Next build | pnpm/Yarn과 새 E2E runner를 필수로 도입하지 않음 |
| DB | MySQL 8.4 LTS + Flyway | 8.0 지원 종료 후 안정적 LTS·SQL migration 재현성 우선, 최신 9.x 즉시 도입 부담 회피 |
| Local DB / CI | 최초 로컬 수동 MySQL, 앱 생성 이후 Backend test/FE lint-build | Product 구현 전 Docker Compose·배포·성능 인프라를 일괄 도입하지 않음 |

## Decision status and deliberate exclusions
- **Proposed**는 Accepted가 아니다. Java 25·JPA·MySQL JDBC·Flyway·Security/CI 중 초기 Backend에 필요한 부분은 [ARCH-006/#29](https://github.com/guseoh/pawcycle-commerce/pull/29)의 **명시 사용자 승인 범위**를 통해서만 실효적 구현 입력이 됐다.
- 전체 Node/TS/Gradle 정확한 patch, Backend Boot 구현 설정, Flyway 실제 schema와 Secret 전달은 후속 scaffold/PR 검증에서 판정돼야 한다. 같은 추천 표를 실제 운영 적용 증거로 소급하지 않는다.
- Session/JWT/CSRF의 상세 구현, API URL/JSON, Production 비용·서버, 추가 OpenAPI/Testcontainers, Redis/Kafka/Kubernetes는 FOUNDATION-000에서 전체 승인되지 않았다.

## Implementation/verification
[PR #21](https://github.com/guseoh/pawcycle-commerce/pull/21) 및 [#22](https://github.com/guseoh/pawcycle-commerce/pull/22)는 후속 앱 scaffold·검증 설정의 출처다. [PR #27](https://github.com/guseoh/pawcycle-commerce/pull/27)은 Windows 로컬 Java 21 환경에서 필요한 Java 25 toolchain이 없어 Backend build/test가 실패했지만 원격 Java 25 CI는 성공했다고 보고했다. 이 차이를 초기 추천의 로컬 검증 성공으로 바꾸지 않는다. 현재 main의 버전이 7월 추천의 모든 값을 따른다고 자동 주장하지 않는다.

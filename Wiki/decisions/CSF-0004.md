# Prioritize a five-concept Network Pilot Pack instead of reopening all Java diagrams

## Context

The Java LearningArea contains a broad, heterogeneous set of diagrams. After the three textbook-style quality pilots were implemented in CSForge PR #297, the user preferred the narrower Network & HTTP area for learning-visualization expansion. Existing [Issue #278](https://github.com/guseoh/csforge/issues/278) has a much broader all-Java/all-Network content remediation scope and remains a separate contract.

## Decision

Use five concept-sized, ordered Network Pilot work units:

1. N-01 TCP three-way handshake (`network-http.core.tcp.three-way-handshake`): improve existing `tcp-handshake` state renderer; show five client/server protocol states and in-flight vs received arrow distinction.
2. N-02 HTTP request/response over TCP (`network-http.core.request-journey.transport-establishment` as the primary target): distinguish logical HTTP messages from the carrying TCP byte stream.
3. N-03 DNS resolution (`network-http.core.dns.iterative-resolution`): recursive resolver, referrals, authoritative answer, and optional cache bypass.
4. N-04 TCP termination/TIME_WAIT (`network-http.core.tcp.connection-teardown`, related `time-wait`): direction-specific FIN/ACK closure and TIME_WAIT rationale.
5. N-05 TCP sliding window (`network-http.core.tcp.sliding-window`): reuse and integrate the existing static before/after byte-range visual after semantic review.

Every concept gets the least interactive representation that satisfies its actual learning objective. Prefer small independent reviewable packs over sweeping replacements or a new generic graph system.

## Rejected alternatives

- Reopening the entire Java diagram area before validating the new editorial visual standard with a manageable domain.
- Rebuilding all Network & HTTP concepts simultaneously without concept-level technical and screenshot validation.
- Adding animation or arbitrary drag-and-drop behavior as a default.
- Altering canonical content keys, stored personal/history data, or live DB in visual-only prototypes.

## Consequences and constraints

N-01 reuses the existing `tcp-handshake` v1 contract and five-step protocol model. In its rendering, a half-length arrow indicates a packet still in flight, not already received at the destination. Specifically, during the last ACK's flight, the client is ESTABLISHED while the server remains SYN-RECEIVED. New renderer contracts for later packs need explicit frontend/backend validation if canonical Markdown is changed.

Respect the existing [Issue #278](https://github.com/guseoh/csforge/issues/278), `AGENTS.md`, `DESIGN.md`, current curriculum and the source/import verification workflow. Desktop 1280/1440 light/dark visual QA is the initial benchmark, not evidence of authenticated Reader or Production deployment.

# Quick Reorder의 순수 정책과 durable replay codec만 분리한다

## Context

persistence adapter 안에 이미 잠근 snapshot 의 순수 구매 가능 판단과 오래 저장된 JSON 해석까지 섞여 독립 검증이 어려웠다.

## Decision

QuickReorderPolicy 는 status/category/nullable stock/quantity 만 받아 기존 skip reason 우선순위를 적용한다. ResultCodec 은 저장 응답 필드·목록 순서·숫자 형식·비정형 legacy 해석을 유지한다. adapter 가 SQL·잠금·cart version·최종 response insert 와 저장 실패 경계를 계속 소유한다.

## Alternatives and interpretation

DB protocol 을 application 으로 옮기기, 새 Port/runner 추상화, tolerant JSON 을 strict schema 로 바꾸는 안을 제외했다. non-map added item 의(0,0), Number narrowing, nullable reason 도 호환 대상이다.

## Consequences and limits

작은 2개 클래스 관리 비용을 수용한다. 읽기 실패 409와 저장 IllegalStateException 을 구분하며 과거 데이터 해석을 강화하려면 별도 결정이 필요하다.

## Implementation and verification

Policy12/Codec13 PASS, 실제 MySQL frozen 비교·rollback·statement/lock footprint 와 CI 성공을 확인했다.13native SQL literal 은 원문·순서가 동일하다. SQL 수 감소나 성능 개선은 성과로 주장하지 않는다.

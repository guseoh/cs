# PawCycle은 AWS·RDS 시간제 운영으로 전환하고 구축 과정에서 설계와 운영을 학습한다

## 배경

과거 AWS에서 비용을 줄이기 위해 OCI Always Free로 전환했다. 그러나 Tokyo A1 용량은 사용자 보고상 수주간 확보하지 못했고, 2026-11-26 감시 Health Alert에는 직전 24시간 정기 조회 성공 2회와 3시간 이상 공백이 보고됐다. 용량 미확보와 감시 공백은 별개이며 전체 기간 내 가용 용량이 없었다고 단정할 수 없다. 포트폴리오 프로젝트에 24시간 공개 서비스는 필수 조건이 아니므로, 무료 인프라 확보를 기다리는 대신 필요한 실환경을 제한된 시간만 운영하는 방향으로 재평가했다.

## 결정 — 사용자 확정

- AWS를 PawCycle의 다음 운영 환경으로 선택하고 Amazon RDS MySQL을 포함한다. 상시 가동이 아니라 실험·시연·운영 학습에 필요한 시간만 실행한다.
- 월 AWS 비용은 최대 15,000원으로 제한하고 실제 지출은 가능한 한 최소화한다. 이는 목표 상한이지 AWS가 보장하는 과금 차단 장치가 아니다.
- OCI 전용 활성 실행 코드·감시·배포 경로를 의존성 분석 후 정리하고 AWS 환경을 구축한다. 기존 AWS·OCI ADR, PR, 보고서, 실패·복구 근거를 역사로 보존한다. 실제 OCI 종료와 삭제는 데이터 보존·복구 및 별도 운영 승인 후에만 수행한다.
- DuckDNS 대신 저가 독립 도메인 구매를 검토한다. 구매 여부·이름·등록기관·DNS 사업자·연간 비용은 아직 미확정이다.
- AI는 구현을 지원하되 사용자가 도입 목적, 내부 원리, 설계 대안, 트레이드오프, 보안, 비용, 실제 검증을 이해하고 판단한다. 기존 [PWC-0141](PWC-0141.md)의 분담을 운영 구축 전 과정에 적용한다. 과잉 설계를 피하며 Java/Spring·DB 해체 분석과 격리 성능/정합성 학습을 병행한다.

## 선택하지 않은 대안

- OCI A1을 무기한 기다리거나 AWS 학습과 OCI 호스팅을 계속 분리하는 방향: 무료 용량 의존성 및 지연에 비해 상시 공개의 가치가 낮다.
- AWS EC2/RDS 상시 운영: 비용 목표와 포트폴리오 목적에 맞지 않는다.
- AWS 기본 DB를 Docker MySQL로만 사용하는 방식: 저렴하고 OS/엔진 접근이 자유롭지만 이번에는 관리형 DB, 네트워크 격리, TLS, 백업·PITR 학습을 위해 RDS를 선택했다. 로컬 Docker MySQL은 유지한다.
- RDS Multi-AZ, NAT Gateway, ALB, EKS, RDS Proxy, Replica, 복잡한 GitOps를 초기부터 도입: 현재 상시 가용성 및 확장 요구에 비해 비용과 복잡성이 크다. 실제 필요성이 확인되면 별도로 재검토한다.

## 설계 후보와 트레이드오프 — 미확정

| 영역 | 초기 후보 | 이유와 제약 |
| --- | --- | --- |
| 네트워크 | 서울 리전, Public EC2, Private RDS, 최소 2 AZ DB Subnet Group, 단일 AZ DB | DB 인터넷 노출 없이 접근 경계 학습; subnet group과 Multi-AZ 배포는 다르다 |
| 컴퓨팅 | t4g.medium 4GB, 필요 시 m7g.large 8GB | 저렴한 기본 검증; 버스트 CPU 크레딧과 관측 오버헤드는 측정 통제 대상 |
| DB | MySQL 8.4, db.t4g.small 2GB, gp3 20GB, Single-AZ | 관리형 백업·복원 학습; RAM 및 권한 제약, DB HA 미제공 |
| 스토리지 | EBS gp3 30GB, 제한된 S3/백업 | 중지 상태에서도 저장 비용 발생; 삭제 전 복구 검증 |
| 배포 | Docker Compose, Nginx, GHCR, 기존 CI/Host Pull의 최소 공통 경로 | 기존 자산 재사용; OCI 전용 코드·과도한 정책은 의존성 확인 후 정리 |
| 보안 | MFA, 최소 IAM Role, SSM, IMDSv2, DB SG 3306 App SG만, 암호화, TLS VERIFY_IDENTITY, 역할별 DB 계정 | SSM 연결·CA/truststore·Flyway 권한 및 Secret 주입 검증 필요; 관측 포트 비공개, 합성 데이터/Fake Provider |
| DNS/HTTPS | 독립 도메인 + 무료 Cloudflare DNS, Nginx/Let's Encrypt | IP 변경 시 DNS 갱신·인증서 유지 필요; Route 53 hosted zone 비용·Elastic IP 상시 과금 회피 후보. 첫해보다 갱신비·등록 가능 여부 확인 |
| 자동화 | 초기 콘솔/CLI로 원리 확인, 반복이 확인된 범위만 IaC·시간 제한·종료 자동화 | 구축 복잡도 최소화; 중지/삭제 실패 및 잔존 자원 확인 필수 |

기존 [ARCH-013](https://github.com/guseoh/pawcycle-commerce/blob/318dfab4fb1a40fb69236cbec4f7c6a080ab8325/docs/adr/ARCH-013-rds-single-az.md)은 db.t4g.micro, private Single-AZ와 TLS REQUIRED를 저장소 준비 범위로 승인했었다. 당시 실제 RDS 전환·PITR은 미검증이다. 새 설계 후보의 db.t4g.small 및 VERIFY_IDENTITY는 별도 설계 검토 대상이며 과거 실행 상태를 소급 변경하지 않는다.

## 비용 및 운영 생명주기

공개 단가 기반 대화 중 추정은 EC2 4GB + RDS 2GB, 월 30~40시간 사용, 스토리지를 실행 기간에만 유지하는 조건에서 약 7,000~10,000원이었다. 환율·세금·실제 보존 기간·CPU 크레딧·백업·추가 복구 인스턴스 및 실제 청구에 따라 달라지는 예산 추정이며 현재 계정 할인 또는 청구 검증이 아니다. 구매 도메인의 연간 비용을 별도 관리하는 것은 제안이다. 실행 전 AWS Pricing Calculator와 Billing에서 다시 계산하고, 15,000원 이내의 예상 총비용과 예비비를 확인한다.

EC2/RDS 중지 중에도 스토리지 요금이 남으며 RDS는 연속 7일 중지 후 자동 재시작된다. 짧은 연속 실험은 Start/Stop, 긴 공백은 검증된 백업·증거 보존 후 삭제/재생성을 후보로 한다. AWS Budgets는 지연되는 경보이지 실시간 상한 차단이 아니므로 실행 시간·자원 수·종료 후 전체 리전 잔존 비용을 확인한다. 예산 초과 위험, 미확인 비용, 복구 불가 또는 데이터/Secret 위험이면 실행을 중단한다.

## 작업 순서와 검증 기준

1. OCI 읽기 전용 인벤토리·Billing·DB 백업/복원·모니터링 상태·기존 코드 의존성 조사. 기존 데이터와 운영 근거 보존; 실제 감시 중지/자원 삭제/절체는 별도 실행 승인.
2. 최신 main 기준 OCI 전용 실행 코드와 공통 배포/관측/성능 자산 분류, 최소 Delta로 AWS 운영 계약 준비. CI·회귀·리뷰 후 PR 승인; 기존 운영에 영향을 주는 변경은 안전한 종료/절체와 조율.
3. AWS 계정·IAM·예산·VPC/서브넷/라우팅/SG·EC2/EBS/SSM·RDS를 목적/대안/보안/비용 근거와 함께 설계하고 별도 실행 승인 후 구축.
4. 이미지 배포, DB TLS/권한/Flyway, HTTPS/DNS, smoke, 비용 및 중지·재실행/백업 복원 경계를 검증한다. 단기 RDS 복원 대상은 합성 데이터로 격리한다.
5. 기존 GHCR·Prometheus/Grafana·k6·Dataset·측정 수집 코드를 재사용하여 AWS 기준선을 새로 얻고 장애·복구 및 병목 개선을 진행한다. 로컬/OCI 결과와 AWS 결과를 직접 동일 기준선으로 합치지 않는다.

각 단계에서 필요한 기술만 도입하고 먼저 이유와 내부 동작·대안·트레이드오프를 설명한 뒤 AI 구현 및 사용자 검토·실제 검증을 수행한다. 별도의 기술 목록이나 문서량을 성과로 삼지 않는다.

## 구현 및 검증

2026-11-27 사용자 방향 확정과 공개 GitHub 원본 조회만 완료했다. PawCycle main은 `318dfab4fb1a40fb69236cbec4f7c6a080ab8325`로 확인했고 기존 OCI 전용 workflow, infra/oci-a1, infra/oci-capacity-cron, oci-release.py, oci-cd.py, systemd·운영 validator 및 공통 Docker/관측/성능 자산의 존재를 확인했다. 전체 의존성 조사, 실제 AWS/OCI 계정 및 Billing, 데이터 복원, 신규 EC2/RDS, 도메인 구매, 코드 삭제, CI/CD 전환, 클라우드 운영·비용 실측은 아직 미실행/미검증이다. 이 Wiki 기록은 별도 클라우드 자원 생성·삭제, 비용 지출, 제품 저장소 변경·병합을 승인하지 않는다.

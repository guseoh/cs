# Subscription read는 feature별 typed 경계로 나누고 command facade를 보존한다

## Context

SubscriptionAggregatePersistence 의 상속 read·합성 write facade 를 query 와 command/automation 이 함께 사용했다. 단순한 클래스 치환으로는 호출 계약과 관리 상태가 달라질 수 있었다.

## Decision

23개 읽기를 Pet/Plan/Subscription/Delivery 네 feature-local query 경계로 수렴했다. 단순 조회는 derived DTO, 고정 join 은 DTO rewriting, 배송 NOT EXISTS 와 HELD/SCHEDULED 조합만 Querydsl 을 선택했다. 필요한 13개 immutable scalar mapping 은 기존 대응 테이블/엔티티와 비교하고 command/public facade·lock·write·transaction 은 T09까지 보존했다.

## Alternatives and interpretation

테이블별 interface 폭증, 긴 constructor FQCN 반복, 모든 Querydsl 확대, read 전환에 command 재작성까지 합치는 안을 제외했다.

## Consequences and limits

중복 mapping 은 실제 mutable 엔티티 재사용 가능성·테이블 차이·immutable 특성을 근거로 관리한다. test context cache 가 만드는 connection 비용도 검증 조건이다. null Pet legacy 조회를 지원해야 한다.

## Implementation and verification

#355는 목록에 legacy pet:null 만 있을 때 HTTP500을 재현하고 null lookup 만 고쳐 200으로 복구했다. 이는 의도적인 기존 결함 수정이며 단순 behavior no-op 으로 쓰지 않는다. CI·frozen read/HTTP 회귀와 최초 cache/nullable 교정을 보존하고 Production 은 주장하지 않는다.

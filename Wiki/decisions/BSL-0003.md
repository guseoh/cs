# 통합 학습의 중심을 백엔드·시스템 설계·RAG로 정하고 교재 1·2권은 후순위로 둔다

## 배경

통합 연구실은 한 저장소 안에서 여섯 독립 Spring Boot 앱을 개발하고 시스템 설계 교재 두 권도 함께 공부하기로 확정했으나, 프로젝트의 핵심 학습 축과 교재의 시작 시점은 명확하지 않았다. 사용자는 **현재는 저장소·프로젝트 이름을 검토하며, 교재 학습은 당장 진행하지 않는다**고 명시했다.

## 결정

1. **세 가지 중심 축:** 신규 연구실은 **Backend Engineering(Java/Spring), System Design, RAG(Retrieval-Augmented Generation)** 역량을 학습하는 목적을 갖는다. 별개의 포트폴리오 서비스 개발이나 단순 도구 도입이 아니라 문제 정의·원리 이해·설계 판단·검증이 우선이다.
2. **기존 여섯 앱 보존:** [BSL-0001](BSL-0001.md)의 여섯 독립 실행 도메인 애플리케이션은 유지한다. 시스템 설계는 도메인 아키텍처와 실험, RAG는 검색·생성 파이프라인/백엔드 통합에 관한 학습 축으로 추가한다.
3. **RAG 세부 주제(학습 후보):** 데이터 적재·청킹, 임베딩, 벡터/하이브리드 검색, 리랭킹, 프롬프트/컨텍스트 구성, 검색 품질·근거성 평가, 지연/비용 최적화, 권한·데이터 격리. **RAG를 일곱 번째 독립 실행 앱으로 만들지, 여섯 도메인 중 하나에서 실습할지, 별도 실험 디렉터리로 다룰지는 미확정**이다.
4. **교재 일정 변경:** 기존 [BSL-0002](BSL-0002.md)에 따른 『가상 면접 사례로 배우는 대규모 시스템 설계 기초』 1·2권의 **동일 저장소 학습 계획 자체는 유지**하되, **당장 착수하지 않는 후순위/보류 항목**으로 조정한다. 정해진 시작일·완료 의무는 없다.
5. **이름 후보:** `backend-systems-lab`(백엔드 시스템 학습 연구실), `backend-ai-systems-lab`, `systems-engineering-lab`, `backend-learning-lab`, `system-design-playground`는 **제안**일 뿐 어느 하나도 사용자 최종 선택이나 실제 GitHub 저장소 생성으로 간주하지 않는다. 이름 후보는 저장소/프로젝트 브랜드를 위한 것이지 도메인·아키텍처 결정이 아니다.
6. **AI 협업·Wiki:** 현재 [BLR-0014](BLR-0014.md)의 AI 채팅 중심 구현·힌트 우선과 [통합 프로젝트 현황](../projects/backend-systems-lab.md)의 위키 이중 기록 원칙은 변경하지 않는다.

## 선택하지 않은 대안

- 교재 두 권을 즉시 의무 커리큘럼으로 시작하여 여섯 앱과 무조건 병렬 진행하는 방식.
- RAG의 기술 스택 또는 독립 앱 개수를 요구사항 없이 확정하는 방식.
- 아직 선택하지 않은 저장소 가칭을 확정명으로 공개 기록하는 방식.
- RAG를 단순 LLM API 호출과 동일시하고 검색 품질·근거·평가를 생략하는 방식.

## 결과와 제약

세 학습 축과 교재의 후순위 조정은 **사용자 확정**이다. `backend-systems-lab`을 최우선 추천하되 실제 저장소 이름, RAG 구현 단위, 교재 시작 시점, AI/벡터 DB 스택, 초기 도메인 요구사항은 **미결**이다. 여섯 독립 도메인의 기존 설계·학습 목적은 변경하지 않는다.

## 구현 및 검증

2026-11-19의 학습 목표와 우선순위 변경을 기록한 정책 결정이다. 신규 GitHub 저장소, Wiki, RAG 구현·실험·모델 평가, 교재 장별 학습/코드 결과는 **아직 실행·검증되지 않았다**.

## 출처와 결정 경위

사용자가 현재 대화에서 교재 후순위와 세 학습 축을 직접 명시했으며 프로젝트 이름은 추천을 요청했다. 비공개 대화 원문을 공개하지 않고 재사용 가치가 있는 결정·미확정 사안만 기록했다.

# PawCycle 코드·설계 학습을 OCI A1 용량과 분리하여 로컬 우선으로 진행한다

## Context

사용자는 2026-11-06 OCI Free Trial 만료 이후 기존 E5 앱 VM이 중단되고, Tokyo A1.Flex 호스트 용량 확보가 확인되지 않아 G0-R2.3 데이터 보존 조사도 토큰 제한으로 중단된 시점에서 개발 진행 방식을 재검토했다. A1 물리 용량 실패는 Java/Spring 코드, DDD·설계, 리버스 엔지니어링, 통합 테스트의 기술적 선행 조건이 아니다. 한편 Active MySQL.Free의 데이터 원본·독립 백업·TLS·계정·네트워크는 미해결이며, A1 생성 성공만으로 즉시 안전한 운영 배포가 가능한 것도 아니다.

## Decision

**로컬·CI에서 독립적으로 진행할 작업을 재개/지속**하고, A1 가용성 모니터링과 Compute 준비는 별도 흐름으로 수행한다. Java/Spring 리팩터링, 도메인/DB/API/아키텍처 분석, 장애·동시성 실험, 테스트 및 리버스 엔지니어링은 승인된 합성 테스트 데이터와 격리된 로컬 MySQL 등의 환경에서 수행한다. AWS/OCI 실제 운영 환경의 특성을 로컬 재현 결과만으로 증명했다고 주장하지 않는다.

A1 확보 전에는 ARM64 이미지/배포 프로세스, 최소 네트워크 구성을 **검증 가능한 설계·리포지토리 수준으로 미리 준비**할 수 있다. A1을 확보하면 먼저 **인스턴스 기본 설정과 비프로덕션 스모크 검증**을 진행한다. 운영 데이터 연결, 공개 배포, 트래픽 절체, 스케줄러 전환은 백업·복원·TLS·비용·호환성·운영 승인 Gate 뒤에만 진행한다. `AVAILABLE` 알림 자체는 자동 인스턴스 생성이나 Production Cutover 승인이 아니다.

기존 E5를 재가동하는 것을 개발 선행조건으로 두지 않는다. 단, E5 부트 볼륨과 Active MySQL.Free DB는 데이터·설정 복구 가치가 미확인인 동안 임의 삭제·분리·초기화하지 않는다. 기존 백업의 실제 시간별 상태도 별도로 추적해야 한다. G0-R2.3 조사 중단은 데이터 보존 의무 해제가 아니다.

## Rejected alternatives

- A1이 제공될 때까지 모든 개발·설계·리팩터링 중단: OCI의 물리 용량 제약을 불필요하게 코드 개발의 의존성으로 만든다.
- Trial E5 재가동 또는 유료 업그레이드를 개발 필수 조건으로 취급: 비용·자원 회수 위험과 모순된다.
- A1 생성 즉시 확인되지 않은 Active DB와 연결한 자동 공개 배포: 원본 DB·복구 사본·TLS·ARM64 이미지·단일 writer 검증 누락.
- 개발 편의를 위해 운영 데이터·비밀을 로컬 테스트 DB로 복제: 개인정보·복구/권한 경계 위반.

## Consequences and constraints

코드 구현/로컬 테스트/CI 통과와 실 OCI 서비스 운영·복구는 별도 검증 결과로 남긴다. 기존 이미지 배포 Workflow의 `linux/amd64` 고정은 A1의 `linux/arm64` 지원을 위해 수정·회귀검증 필요. 1개 MySQL.Free 시스템 제한 및 고정 1일 자동 백업, Cloud Shell TLS/계정 접근 문제를 무리하게 우회하지 않는다. 데이터가 확인되지 않으면 **격리된 데모만 별도 명시 승인**할 수 있고 Production Verified라 하지 않는다.

## Implementation/verification

이 문서는 사용자가 확정한 **개발/용량 분리 운영 방식**의 Wiki 기록이다. 이번 기록으로 로컬 테스트, ARM64 빌드, 독립 백업, OCI A1 생성, 운영 배포가 실제 실행된 것은 아니다. A1 모니터 활성화 변수는 과거 사용자 CLI 출력상 true였으나 최근 Workflow 성공/실제 호스트 용량은 미확인이다.

## Provenance

2026-11-06 사용자 요청: A1을 못 만들더라도 리팩터링·설계·리버스 엔지니어링을 로컬로 진행하고, 서버·데이터 백업·네트워크는 별도로 준비한 뒤 A1이 확보되면 배포 검증 단계로 이어가기로 함. 배포 최종 승인과 운영 데이터 접근은 이 결정의 범위 밖이다.

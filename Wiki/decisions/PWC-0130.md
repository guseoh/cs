# PawCycle A1 확보·배포 준비와 로컬 개발을 병렬로 진행한다

## Context

사용자는 2026-11-06 OCI Free Trial 만료 이후 기존 E5 앱 VM이 정지되고 Tokyo A1.Flex 용량이 확보되지 않은 상황에서, **A1 확보·배포 준비와 로컬 코드 개발을 중단 없이 동시에 진행**하려는 운영 방식을 확정했다. G0-R2.3 조사만 토큰 제한으로 중단됐으며 A1 확보 작업을 보류하거나 로컬 개발로 전환하겠다는 뜻이 아니다. A1 물리 용량 실패는 Java/Spring·디자인·DDD·리버스 엔지니어링의 개발 선행 조건이 아니다. Active MySQL.Free 원본·백업·TLS·계정·네트워크 문제는 별도로 해결해야 하며 A1 생성 성공이 즉시 운영 공개 허용을 뜻하지 않는다.

## Decision

**동등하게 진행하는 두 개의 병렬 작업 흐름**을 유지한다. (1) OCI에서는 GitHub Actions의 A1 용량 감시와 확보 시도·인스턴스 준비, 기존 DB/부트 볼륨 보존·백업, ARM64 이미지 및 네트워크·TLS·배포 사전 검증을 지속한다. (2) 로컬·CI에서는 백엔드 리팩터링, 프론트엔드 디자인 수정, 기능 구현, Java/Spring·DDD·아키텍처 설계, 리버스 엔지니어링, 동시성·장애 실험과 테스트를 계속한다. 두 작업은 서로의 진행을 선행조건으로 두지 않으며, 어느 쪽도 보류하거나 낮은 우선순위로 전환하지 않는다. 격리된 테스트 데이터와 로컬 MySQL 등을 사용하고 로컬 결과를 AWS/OCI 운영 검증이라고 주장하지 않는다.

A1 확보 전에도 ARM64 이미지/배포 프로세스, 네트워크·보안 구성, 배포 사전검증을 준비하며, 용량이 생기면 **명시적으로 승인된 인스턴스 확보를 즉시 진행할 수 있도록** 한다. 실제 A1을 확보하면 서버 초기 설정, 네트워크·이미지 Pull 및 비프로덕션 스모크 검증을 우선 수행하고, 충분히 준비된 코드의 배포로 연계한다. 다만 운영 데이터 연결, 공개 배포, 트래픽 절체, 스케줄러 전환은 백업·복원·TLS·비용·호환성·운영 승인 Gate 통과 후 진행한다. `AVAILABLE` 알림은 자동 Compute 생성이나 Production Cutover 승인이 아니다.

기존 E5를 재가동하는 것을 개발 선행조건으로 두지 않는다. 단, E5 부트 볼륨과 Active MySQL.Free DB는 데이터·설정 복구 가치가 미확인인 동안 임의 삭제·분리·초기화하지 않는다. 기존 백업의 실제 시간별 상태도 별도로 추적해야 한다. G0-R2.3 조사 중단은 데이터 보존 의무 해제가 아니다.

## Rejected alternatives

- A1이 제공될 때까지 모든 개발·설계·리팩터링 중단: OCI의 물리 용량 제약을 불필요하게 코드 개발의 의존성으로 만든다.
- '로컬 우선'이라는 명목으로 A1 확보·데이터 백업·네트워크 준비의 진행을 늦추거나 중단: 사용자가 확정한 병렬 추진 의도와 다르다.
- Trial E5 재가동 또는 유료 업그레이드를 개발 필수 조건으로 취급: 비용·자원 회수 위험과 모순된다.
- A1 생성 즉시 확인되지 않은 Active DB와 연결한 자동 공개 배포: 원본 DB·복구 사본·TLS·ARM64 이미지·단일 writer 검증 누락.
- 개발 편의를 위해 운영 데이터·비밀을 로컬 테스트 DB로 복제: 개인정보·복구/권한 경계 위반.

## Consequences and constraints

코드 구현/로컬 테스트/CI 통과와 실 OCI 서비스 운영·복구는 별도 검증 결과로 남긴다. 기존 이미지 배포 Workflow의 `linux/amd64` 고정은 A1의 `linux/arm64` 지원을 위해 수정·회귀검증 필요. 1개 MySQL.Free 시스템 제한 및 고정 1일 자동 백업, Cloud Shell TLS/계정 접근 문제를 무리하게 우회하지 않는다. 데이터가 확인되지 않으면 **격리된 데모만 별도 명시 승인**할 수 있고 Production Verified라 하지 않는다.

## Implementation/verification

이 문서는 사용자가 확정한 **개발/용량 분리 운영 방식**의 Wiki 기록이다. 이번 기록으로 로컬 테스트, ARM64 빌드, 독립 백업, OCI A1 생성, 운영 배포가 실제 실행된 것은 아니다. A1 모니터 활성화 변수는 과거 사용자 CLI 출력상 true였으나 최근 Workflow 성공/실제 호스트 용량은 미확인이다.

## Provenance

2026-11-06 사용자 최초 요청 후 **추가 정정**: 'A1 인스턴스 확보 준비는 하되, 백엔드 리팩터링이나 디자인 수정은 로컬에서도 동시에 진행'하는 것이 정확한 의미다. 이전 기록의 '로컬 우선'은 OCI 확보 준비를 뒤로 미룬다는 오해를 줄 수 있어 동일 결정 PWC-0130의 설명을 정정했다. 서버 준비·백업·네트워크와 로컬 개발 모두 진행하고, A1 확보 이후 배포 검증을 거쳐 운영 공개 여부를 판단한다. 개별 운영 변경/최종 공개/데이터 접근은 별도 승인이 필요하다.

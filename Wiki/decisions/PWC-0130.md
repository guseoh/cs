# PR별 학습 노트는 cs Vault로 옮기고 PawCycle 저장소에는 작업 기준 문서와 증거만 둔다

## Context

2026-11-14 문서 정리(0단계)에서 PawCycle `docs/**/*.md` 542개를 분류했다. 그 결과 `docs/learning` 218개가 가장 큰 묶음이었다. 이 파일들은 PR #1~#216 무렵의 PR 메타데이터를 자동으로 내보낸 기록과 README·템플릿이다.

- 내보내기 자동화는 [협업 자동화 Runbook](https://github.com/guseoh/pawcycle-commerce/blob/b3b2235db1d0b36f79b93ae6db3daa2b8e25a98b/docs/runbook/collaboration-automation.md)에서 이미 retire됐다. 2026-09-06 이후 새 파일이 없다.
- 제품 코드, CI, Skill, 중앙 Wiki 어디에서도 개별 노트를 링크하지 않는다. 문서 쪽 언급은 색인 문장과 과거 성능 보고서 한 건뿐이다.
- 그런데 [README](https://github.com/guseoh/pawcycle-commerce/blob/b3b2235db1d0b36f79b93ae6db3daa2b8e25a98b/README.md) 16행은 AWS 시기 증거를 `docs/learning/**`에 "삭제하지 않는다"고 명시하고 있었다.

## Decision

사용자가 2026-11-14에 다음을 확정했다.

1. `docs/learning/**` 218개를 내용 변경 없이 cs Vault의 `Project/pawCycle/PR학습노트/`로 옮긴다.
2. PawCycle 저장소에서는 이 폴더를 제거한다. README, 운영 개요, Runbook에서 이 폴더를 가리키던 현재 문장은 새 위치로 고친다.
3. README의 보존 정책은 `docs/reports/**`와 `docs/adr/**`에 계속 적용한다. learning에 대해서만 이 결정으로 대체한다.

## Rejected alternatives

- **PawCycle 안 `docs/archive/learning`으로 보관:** 저장소 안에서 찾을 수는 있지만, 작업 기준 문서 사이의 잡음과 AI 탐색 비용이 그대로 남는다.
- **그대로 두기:** 현재 기준 문서(전체의 11%)와 과거 기록의 경계가 계속 흐려진다.
- **삭제만 하기:** Git 이력에는 남지만 학습·포트폴리오 자료로 다시 찾는 경로가 사라진다.

## Consequences and constraints

- 원본은 PawCycle Git 이력과 커밋 고정 링크로 계속 확인할 수 있다.
- Lean Harness §15(과거 문서 비소급)에 따라 과거 보고서 `PERF-008`의 learning 경로 언급은 고치지 않는다. 그 경로는 당시 커밋에서 유효하다.
- 노트는 이미 공개 저장소에 있던 PR 메타데이터다. 이동 전에 이메일, 토큰, Webhook, 키 패턴을 다시 검사했고 해당 사항이 없었다.
- 이번 결정의 범위는 learning 폴더뿐이다. 나머지 분류(역사 증거는 경로 유지, 현재 상태 문서 신설 등)는 아직 **제안** 상태다.

## Implementation/verification

- cs로 옮긴 218개 파일의 Git blob 해시가 원본 커밋 `b3b2235d`와 모두 일치한다.
- 두 저장소의 변경은 각각 Draft PR이며, **이 기록을 작성한 시점에는 병합되지 않았다.**
- 병합 순서는 cs 쪽(사본 생성)이 먼저다. PawCycle 쪽 제거는 그다음이다.

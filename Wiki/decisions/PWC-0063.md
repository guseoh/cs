# 구독 reconciliation은 구독별 독립 transaction으로 실패를 격리한다

전체 배치 transaction은 한 실패가 앞선 성공과 뒤 처리를 침해한다. catch만 넣거나 self-invocation 메서드에 annotation을 붙이는 대안은 rollback-only·프록시 우회를 해결하지 못한다.

outer loop transaction을 제거하고 TransactionTemplate REQUIRES_NEW로 구독마다 lock·reconcile·commit한다. 실패 구독만 rollback·ID ERROR 로그 후 계속한다. command 내부 reconcile은 command transaction 안에 남는다. Docker Java25/MySQL8.4 관련 18개 및 동일 DB 재실행이 보고됐다.

재시도·backoff·metric·cadence·운영 scheduler 활성화는 별도다. 정기 주문의 비즈니스 중복 방지인 PWC-0005와 실패 격리 목적을 구별한다.

# Credential 검증은 AuthenticationProvider가 소유하고 Session 계약은 유지한다

## Context
초기 [PWC-0007](PWC-0007.md)·AUTH-003은 사용자가 서버 세션·CSRF와 HTTP 인증 계약을 승인한 결정이다. 후속 MVP3 cleanup의 쟁점은 새로운 인증 방식 선택이 아니라 회원 조회·비밀번호 검증과 Session lifecycle 조율 책임의 분리였다.

## Decision
Accepted [ARCH-010](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/docs/adr/ARCH-010-authentication-provider-ownership.md)과 [PR #140](https://github.com/guseoh/pawcycle-commerce/pull/140)에 따라 MemberAuthenticationProvider가 회원 조회, BCrypt password 비교, 미존재 회원 dummy-hash 비교, session-safe principal/USER·ADMIN authority 생성을 맡는다. AuthenticationManager를 통해 이를 호출한다. AuthApplicationService는 성공 이후 session fixation 방어, CSRF rotation, SecurityContext Session 저장 및 logout orchestration을 소유한다.

## Rejected alternatives
- Authentication 관련 책임을 한 application service에 계속 혼합: Spring Security provider의 인증 책임을 사용할 이유가 사라진다.
- JWT/OAuth2로 함께 변경: 기존 승인 Session·CSRF·HTTP 계약을 변경하는 별도 고위험 결정이다.
- unknown user를 별도 메시지·검증 경로로 구분: 일관된 generic invalid-credential 경계를 잃는다.

## Consequences and constraints
내부 인증 호출 구성이 바뀌어 Provider 및 Session lifecycle 양쪽 회귀가 필요하다. 로그인/logout/me·CSRF URI, JSESSIONID, JSON error, 400/401/403, role 및 DB schema는 변경하지 않는다.

## Implementation/verification
현재 [MemberAuthenticationProvider](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/backend/src/main/java/com/pawcycle/backend/member/application/MemberAuthenticationProvider.java)에서 dummy hash와 BCrypt matches, principal/authority 생성이 확인된다. PR #140은 2026-08-13 병합되었고 관련 Backend/Security 테스트를 보고한다. 이번 Wiki backfill에서 Production 로그인·CSRF를 새로 검증하지 않았다.

## Provenance
2026-08-13 Accepted ADR/병합. PWC-0007의 초기 인증 방식 선택을 대체하지 않는 후속 구현 경계 결정.

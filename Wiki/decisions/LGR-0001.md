# 물류 시스템을 채팅 기반 학습 프로젝트로 시작하고 설계·실험 이력을 이중 기록한다

## 배경

도메인 탐색 단계에서 물류, 교통·검색, 이벤트 분석 등이 후보였으나 사용자가 **물류**를 선택하고 현재 채팅 세션에서 바로 요구사항과 설계를 시작하기로 명시했다. 포트폴리오용 결과물을 우선하는 대신 Java/Spring, 물류 도메인, 트랜잭션·동시성·이벤트·성능의 이해를 우선한다. 새 소스 저장소는 아직 생성되지 않았다.

## 결정

1. **도메인·목적:** 신규 독립 프로젝트의 도메인은 물류이며, 현재 단계는 **학습·설계 착수**다. 포트폴리오 전환은 이후 검증된 고도화와 결과물을 기준으로 별도 판단한다.
2. **작업 공간:** 설계 토론·힌트·코드 제시·피드백은 현재 ChatGPT 채팅에서 진행한다. AI가 채팅에 완성 코드를 보여주면 사용자가 자신의 개발 환경에서 빠르게 작성·실행하고 결과를 공유한다. AI가 로컬 IDE/저장소에 코드를 직접 반영했다고 주장하지 않는다.
3. **학습·의사결정:** 요구사항, 도메인 모델, 비즈니스 로직, 알고리즘, 트랜잭션·동시성, 측정 계획·기술 선정은 함께 논의한다. 모든 설계가 AI의 독단적 결정으로 확정되지 않도록 사용자의 최종 선택을 확인한다. 협업 방법은 [BLR-0014](BLR-0014.md)를 따른다.
4. **고난도 기술:** Kafka 이벤트, 장애 복구, 데이터 수집·정제·파이프라인, 캐싱, 고급 성능 최적화와 낯선 알고리즘은 **기본적으로 개념과 단계별 힌트부터** 안내하고 첫 시도 기회를 제공한다. 사용자가 정답·예제 코드를 요구하거나 막혔을 때는 완성 코드까지 제공할 수 있다.
5. **지식 기록:** 중요한 매 작업의 결정·대안·근거·설계 변경·실험·실패·진행 상태를 자세히 기록한다. 새 저장소가 생기기 전에는 `guseoh/cs/Wiki`가 실재하는 기록 위치다. 새 저장소 생성 후 **프로젝트 고유 Wiki에 상세 정본**, `guseoh/cs/Wiki`에는 관련 결정·핵심 진행 현황·근거 링크를 함께 유지한다. 두 저장소의 갱신 여부는 각각 검증하고 실패하면 미완료로 보고한다.
6. **검증과 이력:** 제안·확정·코드 작성·사용자 로컬 실행·테스트 성공·운영 적용을 섞지 않는다. 결정·성능 수치는 재현 조건과 측정 결과를 기록한 뒤에만 검증 상태로 바꾼다. Wiki 변경은 검증 가능한 PR을 기본으로 하며 사용자 요청에 따라 병합한다.

## 선택하지 않은 대안

- 이미 포트폴리오나 운영 서비스임을 전제한 과도한 기능·배포 확장.
- 프로젝트를 만들기 전에 Kafka·Redis·마이크로서비스 등 기술을 필수 구성으로 확정하는 방식.
- 코드 전체를 AI가 저장소에 직접 작성했다고 간주하거나, 사용자의 핵심 코드 단독 구현을 일괄 강제하는 방식.
- 대화 전문을 공개 Wiki에 복사하거나 실행하지 않은 실험을 성과로 기록하는 방식.

## 결과와 제약

물류 프로젝트 선택과 학습 우선, 현재 채팅 진행, 이중 기록 원칙은 확정이다. 그러나 **출고센터 결정·재고 할당**은 현재 권장하는 첫 학습 범위일 뿐 사용자가 세부 스코프를 승인하기 전에는 제안이다. 저장소 이름·주소, GitHub Wiki 사용 가능 여부, 정확한 데이터 모델·기술 스택·일정은 미정이다.

새 프로젝트의 상세 기록은 저장소 생성 전까지 `Wiki/projects/logistics-learning.md`, `Wiki/knowledge/LGK-0001.md`, `Wiki/journal/logistics-learning/2026-11.md`를 사용한다. 생성 후 프로젝트 Wiki의 읽기·쓰기 경로와 동기화 절차를 확인한 다음 두 곳을 갱신한다.

## 구현 및 검증

2026-11-19 사용자 선언으로 물류 도메인·학습 운영·기록 원칙을 확인했다. **신규 저장소 생성, 실제 코드 작성, 로컬 테스트, 부하 실험, GitHub Wiki 갱신은 아직 검증되지 않았다.**

## 출처와 결정 경위

같은 날 사용자의 명시적인 프로젝트 선택과 협업·기록 원칙 합의에 따른다. 공개 가능한 요지와 결정만 보존한다. 별도의 공개 원본 URL은 없으며 사용자 대화 원문은 공개하지 않는다.

# DATA-001의 최소 네 테이블·날짜·구독 가능 여부는 데이터 설계 후보였다

## Context / status
2026-07-05 #17은 Member/Product/SKU/Subscription만으로 상품 탐색·구독 생성·본인 조회를 지원하는 Proposed Data Design이다. DDL·Entity·migration 구현이나 최종 DB 승인이 아니다.

## Proposed choices
Member는 식별자·표시명 등 최소 정보만 두고 주소/전화/결제 정보와 인증 테이블은 제외했다. Product 1:N SKU, Member 1:N Subscription, SKU 1:N Subscription 후보를 뒀다. Subscription은 회원·SKU ID·수량·배송 주기·생성일·다음 주문 예정일을 보존한다. 상태·결제·재고·배송·pause/cancel/skip/resume 컬럼은 첫 MVP에서 제외했다.

`subscribable` Boolean 후보는 재고·품절·판매 상태와 분리했다. 서버 계산 날짜는 DATE 후보로 저장하고 감사 시각과 분리하며 Asia/Seoul 날짜·보정 없음 조건을 유지한다. 수량 1~10·주기 2/4/8·필수 FK·날짜 관계를 도메인 검증과 DB 제약 후보에 함께 적었다.

## Alternatives / trade-offs
과도한 테이블 분리·범용 모델을 피하고 enum/정책 테이블은 사유·상태 전이 필요 시 재검토하도록 했다. 인덱스 `skus(product_id)`, `subscriptions(member_id,id)`, `subscriptions(member_id,next_order_date)`, `products(display_status,id)`는 측정 전 후보일 뿐이다. MySQL CHECK 지원·실제 DDL·연관관계/cascade/fetch·Clock·Aggregate/SKU 참조 방식은 후속으로 남겼다. 최소화로 빠르게 경계를 만들지만 실효 제약·성능을 증명하지 못한다.

## Review / implementation / verification
최종 diff 3개 문서와 리뷰 지적 5건을 대조했다. 필수 상품 표시 데이터·배송 주기, 누락 필드 오류, `subscribable` 추적성, 날짜가 생성일보다 뒤이며 생성일+주기라는 조건을 보강했다. 값 객체는 본문에서 이미 Accepted인 채택을 유지하고 구현/JPA 매핑만 후속으로 남겼다. 그러나 인수인계에는 여전히 “도메인 값 객체 사용 여부”가 남는다. 리뷰 전부를 반영했다고 주장하지 않는다([PWL-0011](../lessons/PWL-0011.md)).

보고된 validator/문서 검사는 앱·migration·실제 MySQL CHECK 검증이 아니다. 최신 main `caad5233269f52ccd31f6e93e54c77a464766b36`의 이 설계도 Proposed로 남아 있다. 후속 승인 [PWC-0029](PWC-0029.md)과 구별한다.

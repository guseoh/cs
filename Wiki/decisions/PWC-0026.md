# OCI Host Pull CD는 검증된 main 변경을 서비스별로만 적용하고 위험 변경은 수동 Gate로 보낸다

## Problem and decision sequence
매번 사람이 운영 Release를 실행하는 비용을 줄이면서도 **PR HEAD CI ≠ squash merge 후 main SHA CI**, GHCR publish ≠ Production 적용, 오래된 후보가 최신 변경을 덮을 위험을 다뤄야 했다. [Issue #470](https://github.com/guseoh/pawcycle-commerce/issues/470)는 사용자의 PR merge 승인만 유지하고, 별도의 최초 상시 실행 정책 승인 이후 main의 허용된 변경을 Host Pull 방식으로 자동 적용한다는 방향이다. 호스트가 outbound pull하는 구조를 선택해 새로운 공개 SSH·상주 Runner·추가 Compute를 전제하지 않는다.

2026-10-28 [PR #474](https://github.com/guseoh/pawcycle-commerce/pull/474)는 exact main SHA의 필요한 CI, Backend/Frontend registry digest·revision·platform, protected root policy·kill switch, stale/double merge barrier, FF source CAS, 만료된 승인 근거, capacity/lock/recovery를 연결했다. 당시 기본 policy는 **OFF**이며 실제 OCI 설치·배포는 수행하지 않았다. 이후 [PR #486](https://github.com/guseoh/pawcycle-commerce/pull/486)의 `frontend-cosmetic-v1`은 **CSS 두 토큰만** 허용하는 제한된 자동 정책으로 시작했고 Backend·Proxy를 재생성하지 않도록 frontend 단독 `compose up --no-deps frontend`를 사용했다.

[PR #490](https://github.com/guseoh/pawcycle-commerce/pull/490)는 후속 `application-v1`로 확장해 일반 Frontend·Backend·공유 입력 변경에서 실제 바뀐 서비스만 배포하도록 했지만, **Migration/SQL·운영 Runtime/Compose/Nginx·배포기 자신·unknown·비가역 data change는 자동 허용하지 않는다**. Schema tree/hash와 단순 경로 이름만으로 DB 의미 호환성을 증명하지 않으며 위험 변경은 리뷰에서 수동 배포 표식/별도 Gate로 전환한다. 바뀌지 않은 서비스 이미지 source_sha/digest/config는 보존한다.

## Alternatives and trade-offs
- **모든 main 변경을 자동 배포:** Docs-only/CI-only도 불필요한 재배포를 촉발하고 DB/data 영향 변경이 안전으로 오분류될 수 있다.
- **Frontend-only 변경에도 Backend·Proxy 강제 recreate:** 불필요한 가용성/Session/인증서 위험이 생긴다.
- **PR HEAD 통과 또는 이미지 빌드 성공만으로 activation:** 머지 후 main SHA를 검증하지 못한다.
- **CI나 PR의 미검증 코드에 운영 root 실행 권한 제공:** 공급망 신뢰 경계와 Secret을 훼손한다.
- **DB compatibility 자동 추정:** 애플리케이션 rollback과 데이터 정합성을 혼동한다.

## Implementation and verification
현재 [oci-cd.py](https://github.com/guseoh/pawcycle-commerce/blob/540464a9b875f7bc6bdda11ecf499efdea2e2d43/infra/production/oci-cd.py)는 `changed_paths`, first-parent history 검사, 필수 CI·image identity, application_scope, service 별 sourceSHA 및 disabled/attempt 보호 경계를 포함한다. [PR #490](https://github.com/guseoh/pawcycle-commerce/pull/490)의 격리 Linux/root Release 61·Controller 35 회귀와 CI, [PR #486](https://github.com/guseoh/pawcycle-commerce/pull/486)의 Frontend-only 회귀가 **Repository Verified** 근거다. [PR #488](https://github.com/guseoh/pawcycle-commerce/pull/488)의 1채널 CSS 변경은 실제 OCI 자동 E2E 테스트의 의도된 candidate이지만 **PR 본문 자체에는 운영 E2E 미실행**이라고 기록돼 있다. 최초 2026-10-31 운영 적용 실패 [PWL-0008](../lessons/PWL-0008.md)도 별개다.

**중요:** 이후의 운영 자동 배포 성공 여부는 당시 실제 Host receipt·상태·외부 HTTPS 관측으로만 결론 낼 수 있다. 이번 소급 등록은 GitHub에 있는 위 PR과 최초 실패 보고서까지의 명시 범위를 따르며 **현재 CD 활성화/Frontend 또는 Backend 운영 E2E 성공, 실제 Rollback·DB Restore를 새로 검증했다고 주장하지 않는다.**

# Guard canonical synchronization to protect learning history

## Context
The packaged canonical content and live DB can drift, but overwriting a question that carries attempts can change the meaning of old learning results.

## Decision
Use guarded, scope-bounded atomic synchronization for Topics, Concepts and Questions. Preserve user progress/history; reject unexpected identity/structural changes and defer unsafe attempted-question edits. Require protected environment, restricted role, source/deployment identity checks and recovery gates for writes.

## Rejected alternatives
- Overwrite attempted Questions or delete history-bearing records to force matching content.
- Treat successful frontend deployment as successful DB reconciliation.
- Automatically restore the entire production database after a partial import error.

## Consequences and constraints
Green CI verifies code, not production activation or current data equality. Failed transactions must not advance checkpoints or silently delete user data.

## Implementation/verification
[PR #288](https://github.com/guseoh/csforge/pull/288) merged 2026-10-30. Live production sync, historical totals and current flags were not examined here.

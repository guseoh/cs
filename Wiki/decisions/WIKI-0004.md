# Wiki PR 병합 후 일회성 원격 브랜치 정리

## 배경
Wiki 기록 PR이 병합된 뒤에도 작업 브랜치가 남아 관리 비용이 커졌다. 2026-11-24 저장소 조회에서 자동 head 브랜치 삭제 설정은 비활성화 상태였다.

## 결정
사용자는 승인된 Wiki PR의 병합뿐 아니라 해당 일회성 원격 브랜치의 안전한 삭제 및 재확인까지 완료 기준으로 지정했다. 직접 PR과 자동 후보 PR에 동일한 원칙을 적용한다. 상세 기준은 [Wiki 에이전트 규칙](../AGENTS.md)을 따른다.

## 선택하지 않은 대안
- 브랜치 이름만으로 일괄 삭제: 미반영 기록 및 운영 브랜치 손실 위험 때문에 제외한다.
- Git 조상 여부만으로 판단: squash/rebase 병합을 누락할 수 있어 실제 PR 병합 이력과 head SHA를 대조한다.
- 승인 없이 Wiki PR 자동 병합: 기존 리뷰 및 검증 계약을 유지한다.

## 결과와 제약
기본·보호·장기 운영 브랜치와 열린 PR의 head/base, 병합 후 추가 변경이 있는 브랜치는 삭제하지 않는다. 삭제 기능이 없는 클라이언트는 미완료를 명시한다. 로컬 worktree 삭제는 별개다.

## 구현 및 검증
정책 문서의 적용, GitHub 저장소 설정의 활성화, 기존 브랜치의 실제 삭제는 서로 별개의 검증 항목이다. 설정 및 삭제는 실제 조회로 확인하기 전까지 미완료로 취급한다.

## 출처와 결정 경위
2026-11-24 사용자 명시 확정 및 저장소 조회에 근거한다. 비공개 대화 원문을 저장하지 않는다.

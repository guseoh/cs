# Tern을 Windows 네이티브 배포 대상으로 전환하고 서명된 자동 업데이트 도입

## 배경
기존 [DTD-0004](DTD-0004.md)는 운영 HTTPS 웹 애플리케이션을 Tauri 셸에 표시하며 웹/PWA를 병행하는 정책이었다. Tern 0.2.0 설치 파일·업데이트 manifest가 배포되어 있지만, 현재 소스 저장소의 기본 브랜치에서 Tauri Rust/설정과 Windows 빌드 파이프라인을 추적할 수 없었다. 2026-11-24 사용자는 웹 UI 사용을 중단하고 Windows 데스크톱 앱을 주 사용·배포 대상으로 변경하라고 명시했다.

## 결정
- Windows 11 x64 Tern을 유일한 **프런트엔드 릴리스 기준**으로 사용한다.
- React·Vite 정적 화면은 Tauri 2 설치 파일에 번들하고, Cloudflare Workers는 API·인증·D1 데이터·스케줄러 백엔드로 유지한다.
- main의 데스크톱 코드가 변경되면 GitHub Actions에서 Windows 설치 파일을 빌드·서명해 GitHub Releases와 최신 업데이트 manifest를 게시하도록 한다.
- Tern은 실행 시 새 버전 확인을 자동 수행하며, 데이터 손실 방지를 위해 사용자가 업데이트 설치를 승인하도록 한다.
- 기존 GitHub Actions 웹 프런트엔드 배포와 Windows 릴리스를 분리한다. 백엔드 변경에만 Worker/D1 배포가 일어난다.
- 서명 키를 GitHub에 평문 저장하지 않는다. 기존 Tern 0.2.0과 동일한 updater 개인키·공개키 및 설치 ID를 재사용할 수 있는지 확인한다.

## 선택하지 않은 대안
- **이전처럼 main 병합 때마다 웹 Worker UI를 배포:** Windows 사용자가 설치한 앱 버전과 릴리스의 불일치를 해소하지 못한다.
- **운영 HTTPS 화면만 여는 원격 Tauri 셸:** 실제 프런트엔드 버전을 추적하기 어렵고 웹 UI 배포에 종속된다.
- **서명 없이 설치 파일을 자동 업데이트:** Tauri updater 서명 검증과 기존 설치본의 신뢰 연속성을 깨므로 제외한다.
- **데이터를 로컬 DB로 옮기기:** 기존 D1, 인증, 백업과 동기화 계약을 불필요하게 재작성하므로 제외한다.

## 결과와 제약
기존 [DTD-0004](DTD-0004.md)의 웹/PWA 유지 및 원격 HTTPS WebView를 전제로 한 배포 결정을 대체한다. 다만 해당 결정의 과거 채택 배경과 검증 한계는 그대로 보존한다.

Windows 네이티브 소스·릴리스 워크플로의 구현은 [PR #174](https://github.com/guseoh/dark-todo-planner/pull/174)에서 진행 중이며, **PR 생성·CI·main 병합·실제 Windows 설치·자동 업데이트 성공은 서로 다른 상태**다. 기존 0.2.0의 개인키 또는 앱 식별자가 호환되지 않으면 기존 설치자는 한 번 수동 재설치해야 할 수 있다. 현재 native HTTP 세션 저장소는 메모리 기반으로 앱 재시작 시 재로그인이 필요할 수 있다.

## 구현 및 검증
- 2026-11-24: PR #174에서 Rust 소스, 네이티브 API 전송 및 Tauri updater 명령, Windows Actions 빌드/릴리스, Backend 분리 워크플로를 추가했다. 이 기록 시점에서는 아직 main 미병합이고 Windows 실사용 업데이트 검증도 완료되지 않았다.
- 최초 Windows CI에서 serde_json 의존성 누락을 발견해 수정했다. 최종 Windows CI 성공 여부는 별도 확인할 것.
- 서명키의 실제 GitHub Actions Secret 등록과 0.2.0에서의 자동 업데이트 성공은 **미검증**이다.

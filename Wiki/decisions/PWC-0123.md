# Catalog Import는 중립 Command를 직접 검증하고 실제 apply·rollback을 별도로 확인한다

## Context

HTTP DTO에서 옮긴 Command에 constraint가 없어 Bean Validation 호출이 실효성을 잃었다. validate의 경계값 수용도 DB 쓰기 성공과 달랐다.

## Decision and alternatives

Import 입력의 명시 검증과 persistence→API8개 제거를 함께 처리했다. invalid manifest185건과 허용25개 실제 apply·재고/version 보존·19개 테이블 rollback/cacheafterCommit을 나눠 검증한다.

## Consequences and verification limits

임시 mock shell 실패를 제품 회귀로 혼동하지 않고 미변경 shell과 영향 Java/DB를 구분했다. 광역 PUBLIC UPDATE 테스트도 소유 fixture로 바꿨다. 운영 Import 실행은 이 저장소 검증에 포함하지 않는다.

저장소 구현·CI·당시 보고를 대조한 역사 기록이다. 이번 작업은 제품 테스트·Provider·운영/DB를 재실행하지 않았다. source별 최초 실패·수정·최신 HEAD CI와 리뷰 한계는 아래 대장을 따른다.

# Obsidian Vault 안정화·성능 진단과 설정 정리 (2026-11-25 ~ 2026-11-27)

## 요약

Obsidian 1.15.1, Windows 11, 약 1,290개 파일, 활성 커뮤니티 플러그인 23개 환경에서 공식 Obsidian CLI로 시작 시간·콘솔 오류·메모리·플러그인 사용 여부를 실측했다. 11-25에는 사용자가 한 번 측정한 시작 시간이 7,655ms였다. #105의 시작 패치 이후인 11-27에는 2.1~4.8초로 측정되었다. 이번 설정 정리(아래)가 시작 시간을 줄였다는 증거는 없다. 측정 편차가 변경 효과보다 컸다. 콘솔 오류는 시작 시와 플러그인별 재로드 중 모두 0건이었다.

## 측정 방법과 재사용 지침

- `obsidian dev:startup`이 설정 화면과 같은 시작 시간 breakdown을 출력한다. `obsidian dev:errors`는 시작 시점부터 잡힌 예외를 보여 준다. `dev:console`은 `dev:debug on` 후 다음 CLI 호출까지만 유지되므로, 콘솔 출력을 잡으려면 `obsidian eval` 안에서 `console.error/warn`을 감싸야 한다.
- `obsidian eval`은 Promise를 기다리지 않는다. 비동기 작업은 결과를 `window` 변수에 저장한 뒤 다음 호출로 읽는다.
- 플러그인별 비용은 `app.plugins.disablePlugin(id)`→`enablePlugin(id)`로 재로드하며 측정할 수 있다. 설정 파일은 바뀌지 않는다. 이 값은 시작 시간과 다르다. Dataview는 재로드 시 전체 재색인 때문에 1,310ms로 가장 컸다.
- `obsidian restart` 기반 반복 측정은 값이 회차마다 단조롭게 줄었다(4,763→4,279→3,917→2,334ms). 이는 캐시가 데워진 효과다. 한 번은 커뮤니티 플러그인 단계만 17,859ms인 이상값도 나왔지만 재현되지 않았다. 수십 ms 단위의 설정 효과는 이 방법으로 구분할 수 없다. 비교 측정은 같은 조건에서 여러 번 반복하고, 기능 동작 확인과 함께 판단한다.
- 노트의 코드 블록 사용 여부를 검색할 때는 ```` ``` ````뿐 아니라 `~~~` 펜스도 포함한다. 첫 진단에서 이를 놓쳐 Dataview를 "사용 0건"으로 잘못 판단했다. 실제로는 `References/Tech Articles/기술 자료.md`의 `~~~dataviewjs` 블록이 Daily Tech 대시보드를 렌더링한다.
- Obsidian Git이 15분마다 작업 트리 전체를 commit-and-sync하므로, Vault 작업 트리에서 브랜치를 바꾸면 안 된다. 문서 PR은 Vault 밖 `git worktree`에서 작성한다. 설정 실험 중 생긴 변경도 다음 주기에 main으로 push된다.
- 플러그인 API로 설정을 저장하면 파일이 크게 바뀔 수 있다. Excalidraw는 키를 정렬해 다시 쓰고, Obsidian Git은 기본값 키를 추가한다. 의미상 바뀐 키만 원래 순서로 반영하면 리뷰가 쉬워진다. 두 플러그인 모두 다음에 저장할 때 파일을 다시 쓸 수 있다.
- 그래프 뷰가 열린 상태에서 재시작하면 `graph.json`의 `scale` 부동소수점 값이 다시 저장되어 자동 커밋된다. 최근 30일 자동 커밋에서 `graph.json`이 18회 바뀐 원인 중 하나다.

## 측정 결과

| 항목 | 11-25 (사용자 제공, 1회) | 11-27 첫 실행 | 11-27 재시작 반복 |
| --- | ---: | ---: | ---: |
| 전체 시작 시간 | 7,655ms | 4,702ms | 2,081~4,763ms |
| 커뮤니티 플러그인 | 3,202ms | 1,764ms | 867~2,139ms |
| Editing Toolbar | 789ms | 116ms | — |
| Excalidraw | 495ms | 339ms | 164~441ms |
| Hover Reveal | 290ms | 54ms | 96~233ms |

- 렌더러 JS 힙은 설정 정리 전후 모두 128~134MB였다.
- Git 상태 조회(`git status --porcelain -uall`)는 약 90~107ms로 병목이 아니었다.
- 편집기의 `.cm-line:has(...)` CSS 규칙 5개를 CSSOM에서 임시로 뺀 뒤 63KB 노트에서 스타일 재계산을 3회 비교했다. 규칙이 있을 때 중앙값 5.7~13.4ms, 뺐을 때 9.7~18.7ms로 비용 차이가 없었다. 측정 중 창이 가려져 있어 10~21줄만 렌더링된 점이 한계다.

## 적용한 변경

- [fc3d890](https://github.com/guseoh/cs/commit/fc3d8906646e706e379d67361069b53a75df180a): Dataview 플러그인과 DataviewJS는 유지한다. 사용 0건인 인라인 DQL(`dv=`), 코드 블록 내 인라인 쿼리, 인라인 필드 렌더링은 끈다. Excalidraw `aiEnabled=false`로 바꿨다(모든 제공자 API 키가 비어 있었다). 설정된 적 없는 코어 Sync는 비활성화했다. 대시보드 렌더링은 변경 전후 동일했다(텍스트 17,204자, 오류 없음).
- [2cf14c9](https://github.com/guseoh/cs/commit/2cf14c9f4b81c1ade0f53ba07354e66a71287b0d): 사용자 요청으로 Obsidian Git `autoPullOnBoot`를 다시 켰다. 11-25에 시작 지연 진단을 위해 껐던 설정이다. 재시작 약 10초 후 `FETCH_HEAD` 갱신으로 시작 Pull 실행을 확인했다. 15분 commit-and-sync, Push 전 Pull, 30초 상태 갱신은 그대로 둔다.
- [#116](https://github.com/guseoh/cs/pull/116): Editing Toolbar 4.1.12의 Vault 전용 패치를 보호한다. 4.1.14 업데이트가 대기 중이며, 업데이트하면 시작 툴바 가드와 편집 화면 Prism 토큰이 사라진다. 업데이트 금지·복구 절차와 `Inspect-ObsidianVault.ps1` 점검을 추가했다.
- 로컬 정리: Git에서 제외된 `.obsidian/cache/`(11-18 작업 자료, 3.4MB)를 해시 확인 후 Vault 밖 백업 폴더로 옮겼다. `.obsidian/graph-backup/`은 [동기화 가이드](../../.github/OBSIDIAN_SYNC.md)의 보존 결정에 따라 유지한다.

## 채택하지 않은 대안

- [#106](https://github.com/guseoh/cs/pull/106)을 닫고 이 기록으로 대체한다. 자동 Pull 복원은 2cf14c9로 이미 반영되었다. 동기화 문서 규칙은 main과 충돌했다. 측정 스크립트는 Windows PowerShell 5.1에서 `ConvertFrom-Json` 배열이 펼쳐지지 않아 활성 플러그인 수를 23개가 아닌 1개로 집계했다. Editing Toolbar AI Manager 지연 초기화 계획은 해당 플러그인 시작 비용이 116ms로 줄어 효과가 작다. 또한 플러그인 코드 수정이라 이번 범위 밖이다. Dataview 갱신 간격 2.5초→5초는 화면이 대시보드 하나뿐이라 적용하지 않았다.
- Dataview 비활성화: Daily Tech 대시보드가 깨지므로 하지 않는다.
- Typography as You Type 설정 변경: 코드상 fenced·인라인 코드, URL, 수식, frontmatter를 변환하지 않으므로 유지한다.
- `Ctrl+X`(Callout Integrator) 단축키: 사용자가 유지를 선택했다.

## 한계와 남은 작업

- 모든 측정은 한 기기에서 수행했다. 다른 기기는 2cf14c9 이후 한 번 수동 Pull해야 시작 자동 Pull 설정을 받는다. 그 뒤 `Inspect-ObsidianVault.ps1`로 상태를 확인해야 한다.
- Git, Outliner, Excalidraw, Typography as You Type 업데이트가 대기 중이다. Editing Toolbar는 #116 절차에 따라 건너뛴다.
- `graph.json` 자동 커밋 반복과 Obsidian Git merge 방식에서 생기는 merge 커밋(최근 30일 10건)은 현행 정책상 허용 범위로 두었다.

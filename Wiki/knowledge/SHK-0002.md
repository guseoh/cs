# Obsidian Vault 안정화·성능 진단, 설정 정리와 시작 화면 깨짐 보정 (2026-11-25 ~ 2026-11-27)

## 요약

Obsidian 1.15.1, Windows 11, 약 1,290개 파일, 활성 커뮤니티 플러그인 23개 환경에서 공식 Obsidian CLI로 시작 시간·콘솔 오류·메모리·플러그인 사용 여부를 실측했다. 11-25에는 사용자가 한 번 측정한 시작 시간이 7,655ms였다. #105의 시작 패치 이후인 11-27에는 2.1~4.8초로 측정되었다. 이번 설정 정리(아래)가 시작 시간을 줄였다는 증거는 없다. 측정 편차가 변경 효과보다 컸다. 콘솔 오류는 시작 시와 플러그인별 재로드 중 모두 0건이었다. 반복되던 "실행 직후 화면 깨짐"은 Obsidian의 시작 화면 저장본(workspace snapshot)과 Editing Toolbar의 중첩 버튼 구조가 만나 생긴 문제였고, 공유 CSS 스니펫으로 보정했다(아래).

## 측정 방법과 재사용 지침

- `obsidian dev:startup`이 설정 화면과 같은 시작 시간 breakdown을 출력한다. `obsidian dev:errors`는 시작 시점부터 잡힌 예외를 보여 준다. `dev:console`은 `dev:debug on` 후 다음 CLI 호출까지만 유지되므로, 콘솔 출력을 잡으려면 `obsidian eval` 안에서 `console.error/warn`을 감싸야 한다.
- `obsidian eval`은 Promise를 기다리지 않는다. 비동기 작업은 결과를 `window` 변수에 저장한 뒤 다음 호출로 읽는다.
- 플러그인별 비용은 `app.plugins.disablePlugin(id)`→`enablePlugin(id)`로 재로드하며 측정할 수 있다. 설정 파일은 바뀌지 않는다. 이 값은 시작 시간과 다르다. Dataview는 재로드 시 전체 재색인 때문에 1,310ms로 가장 컸다.
- `obsidian restart` 기반 반복 측정은 값이 회차마다 단조롭게 줄었다(4,763→4,279→3,917→2,334ms). 이는 캐시가 데워진 효과다. 한 번은 커뮤니티 플러그인 단계만 17,859ms인 이상값도 나왔지만 재현되지 않았다. 수십 ms 단위의 설정 효과는 이 방법으로 구분할 수 없다. 비교 측정은 같은 조건에서 여러 번 반복하고, 기능 동작 확인과 함께 판단한다.
- 노트의 코드 블록 사용 여부를 검색할 때는 ```` ``` ````뿐 아니라 `~~~` 펜스도 포함한다. 첫 진단에서 이를 놓쳐 Dataview를 "사용 0건"으로 잘못 판단했다. 실제로는 `References/Tech Articles/기술 자료.md`의 `~~~dataviewjs` 블록이 Daily Tech 대시보드를 렌더링한다.
- Obsidian Git이 15분마다 작업 트리 전체를 commit-and-sync하므로, Vault 작업 트리에서 브랜치를 바꾸면 안 된다. 문서 PR은 Vault 밖 `git worktree`에서 작성한다. 설정 실험 중 생긴 변경도 다음 주기에 main으로 push된다.
- 플러그인 API로 설정을 저장하면 파일이 크게 바뀔 수 있다. Excalidraw는 키를 정렬해 다시 쓰고, Obsidian Git은 기본값 키를 추가한다. 의미상 바뀐 키만 원래 순서로 반영하면 리뷰가 쉬워진다. 두 플러그인 모두 다음에 저장할 때 파일을 다시 쓸 수 있다.
- `obsidian dev:screenshot`은 실제 창과 다른 크기(이번 환경 1920×1020)로 페이지를 다시 그려, 실제로는 정상인 화면이 깨진 것처럼 찍혔다. 시작 화면 판단에는 Win32 `PrintWindow`로 실제 창을 프레임 단위(80~200ms 간격)로 캡처한 결과를 쓴다.
- 시작 과정의 DOM은 `Obsidian.exe --remote-debugging-port=9222`로 실행한 뒤 CDP `Runtime.evaluate`로 관찰 스크립트를 최대한 일찍 넣어 기록했다. 측정 후에는 포트 없이 다시 실행한다.
- 그래프 뷰가 열린 상태에서 재시작하면 `graph.json`의 `scale` 부동소수점 값이 다시 저장되어 자동 커밋된다. 최근 30일 자동 커밋에서 `graph.json`이 18회 바뀐 원인 중 하나다.

## 시작 화면 깨짐의 원인과 보정

- **증상:** Obsidian을 실행하면 약 2~3초 동안 Editing Toolbar의 목록·정렬·서식 복사·색상 하위 메뉴가 거대한 회색 블록과 아이콘으로 편집 영역을 덮은 뒤 정상 화면으로 바뀌었다. 실제 창 프레임 캡처로 재현했다.
- **원인:** Obsidian 1.15는 시작 직후 이전 세션의 HTML 저장본(`%APPDATA%/obsidian/snapshots/<appId>.snapshot`의 `html`)을 스크립트 없는 iframe(`#startup-snapshot`, `srcdoc`)에 먼저 그린다. Editing Toolbar는 JS로 `<button>` 안에 하위 메뉴 `<button>`을 넣는다(실제 화면 툴바에서 중첩 버튼 35개). 이 DOM을 HTML 문자열로 저장했다가 다시 파싱하면, HTML 파서가 열린 버튼 안의 새 `<button>` 시작 태그를 만날 때 바깥 버튼을 닫는다. 그래서 하위 메뉴와 아이콘이 툴바 밖 레이아웃 컨테이너로 흩어진다. 툴바 안의 버튼은 60개에서 11개만 남았고, 나머지는 스타일 없이 편집 영역을 덮었다.
- **배제한 가설:** #105의 시작 툴바 가드는 실제 툴바 DOM에만 적용된다. 콜드 스타트와 앱 재로드 모두에서 툴바 CSS(1,674ms / 1,015ms)가 툴바 생성(3,352ms / 2,102ms)보다 먼저 들어왔다. 즉 실제 툴바의 스타일 적용 지연은 원인이 아니었다.
- **보정:** 플러그인 코드는 바꾸지 않고 공유 스니펫에 두 규칙을 추가했다. ① 툴바·팝오버·메뉴·모달·설정 밖으로 빠져나온 Editing Toolbar 버튼과 색상 선택기를 숨긴다. ② 저장본 iframe에서만 붙는 `.app-container.mod-starting` 아래에서, 레이아웃 컨테이너에 직접 붙은 `button`·`svg`를 숨긴다. 두 선택자 모두 실제 앱 DOM에서는 일치 요소가 0개다.
- **결과:** 보정 전후 콜드 스타트 프레임을 비교해, 저장본 구간에서 깨진 블록과 흩어진 아이콘이 사라진 것을 확인했다. 다만 재파싱 때 닫히지 않은 버튼이 뒤따르는 편집기(`.cm-editor`)까지 감싸므로, 저장본 구간(약 2초) 동안 노트 본문은 비어 보인다. 실제 앱이 준비되면 정상 본문으로 바뀐다. 툴바 줄에 하위 메뉴 항목(예: H1) 하나가 섞여 보일 수 있다.
- **재발 방지:** 저장본은 종료 시점의 DOM으로 다시 만들어지므로, 스니펫을 바꾼 뒤에는 한 번 종료하고 다시 실행해야 보정이 반영된다. 비슷한 증상이 다시 나오면 저장본 파일을 실행 중인 앱의 iframe에 띄워 DOM으로 분석한다(스크린샷만으로 판단하지 않는다). Editing Toolbar를 업데이트하거나 툴바 구성을 바꾼 뒤에도 같은 방법으로 확인한다.

## 채택하지 않은 대안

- [#106](https://github.com/guseoh/cs/pull/106)을 닫고 이 기록으로 대체한다. 자동 Pull 복원은 2cf14c9로 이미 반영되었다. 동기화 문서 규칙은 main과 충돌했다. 측정 스크립트는 Windows PowerShell 5.1에서 `ConvertFrom-Json` 배열이 펼쳐지지 않아 활성 플러그인 수를 23개가 아닌 1개로 집계했다. Editing Toolbar AI Manager 지연 초기화 계획은 해당 플러그인 시작 비용이 116ms로 줄어 효과가 작다. 또한 플러그인 코드 수정이라 이번 범위 밖이다. Dataview 갱신 간격 2.5초→5초는 화면이 대시보드 하나뿐이라 적용하지 않았다.
- Dataview 비활성화: Daily Tech 대시보드가 깨지므로 하지 않는다.
- Typography as You Type 설정 변경: 코드상 fenced·인라인 코드, URL, 수식, frontmatter를 변환하지 않으므로 유지한다.
- `Ctrl+X`(Callout Integrator) 단축키: 사용자가 유지를 선택했다.
- 저장본 깨짐을 Editing Toolbar 코드 수정(중첩 버튼 제거, 종료 전 툴바 분리)이나 저장본 기능 끄기로 해결하는 방안: 전자는 업데이트 때마다 다시 적용해야 하는 플러그인 코드 수정이 늘어나고, 후자는 Obsidian 설정에 끄는 옵션이 확인되지 않아 CSS 보정을 택했다.

## 한계와 남은 작업

- 모든 측정은 한 기기에서 수행했다. 다른 기기는 2cf14c9 이후 한 번 수동 Pull해야 시작 자동 Pull 설정을 받는다. 그 뒤 `Inspect-ObsidianVault.ps1`로 상태를 확인해야 한다.
- 2026-11-27 기준 업데이트가 남은 플러그인은 Editing Toolbar(4.1.14)뿐이며 #116 절차에 따라 보류한다. 다른 기기에서는 Pull 후 Excalidraw 그림, Outliner 목록 이동, 따옴표 변환, 시작 화면을 확인해야 한다.
- 저장본 구간의 빈 본문과 툴바 줄의 하위 메뉴 항목 한 개는 Editing Toolbar의 중첩 버튼 구조가 바뀌어야 완전히 사라진다.
- `graph.json` 자동 커밋 반복과 Obsidian Git merge 방식에서 생기는 merge 커밋(최근 30일 10건)은 현행 정책상 허용 범위로 두었다.

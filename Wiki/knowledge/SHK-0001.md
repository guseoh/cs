# AWS Emulator — 로컬 AWS API 검증과 AI 에이전트 개발 루프 (2026-11-13)

## 확인된 기술과 적용 범위

[AWS Emulator](https://github.com/aws/aws-emulator)는 AWS가 2026-11-11 발표한 Rust 기반 로컬 AWS API 에뮬레이터다. AWS 계정 없이 로컬·CI 환경에서 AWS CLI와 SDK 요청을 HTTPS 엔드포인트(기본 `https://127.0.0.1:9297`)로 보내어 애플리케이션 로직을 테스트한다. 각 실행은 자체 서명 키·자격 증명과 메모리 상태를 사용하며 종료하면 에뮬레이션된 리소스가 사라진다. 서버 모드는 SDK 언어에 무관하며, Rust SDK는 embedded mode도 제공한다.

- **Fidelity:** AWS API 모델(Smithy)과 실제 AWS에서 검증한 테스트에 근거해 결과, 오류, 부수효과의 일치도를 측정한다. [평가 스위트](https://github.com/aws/aws-emulator-evaluation-suite)의 테스트가 통과했다는 사실은 해당 시나리오에만 적용된다. 테스트에 없는 동작은 검증되지 않았다.
- **서비스 경계:** 리소스 생성·설명·갱신·삭제 등 control plane과의 일치도가 상대적으로 높다. S3 오브젝트 처리 등 data plane, CloudFormation/Terraform/CDK의 충실도는 서비스·API별로 달라 사전 확인해야 한다. 미구현 작업은 HTTP 501 `NotImplemented`를 돌려준다.
- **보안 경계:** IAM 권한 경계, 리소스 정책, KMS 키 정책, 계정·리전 간 접근은 실제 AWS 보안 검증을 대체하지 못한다. EC2/VPC/RDS 리소스 API 응답을 얻었다고 실제 라우팅, 방화벽, OS 실행, 성능·장애 복구가 검증되었다는 뜻은 아니다.
- **배포·라이선스:** Linux x86_64/aarch64 네이티브 패키지와 Windows/macOS Docker 사용을 지원한다. 소스 전체 디버그 빌드에 권장되는 100GB `target/` 공간은 사전 빌드 패키지 사용에 필요한 공간과 구분한다. 라이선스는 대부분 CC0-1.0, `vendor/`는 Apache-2.0이다. 텔레메트리는 기본 활성화이며 `--telemetry off` 또는 `EMULATOR_TELEMETRY=off`로 중단할 수 있다.

## Java/Spring Boot 및 CI에서의 주의

1. 테스트 프로세스의 `AWS_ENDPOINT_URL`을 로컬 에뮬레이터로 지정하고 별도 생성된 에뮬레이터 자격 증명·설정 파일만 사용한다. 실제 AWS 키·프로필과 격리하고, 인스턴스 시작 뒤 `aws sts get-caller-identity`의 계정 `000000000000`을 확인한다.
2. AWS SDK for Java 2.x는 자체 서명 인증서를 신뢰하려면 에뮬레이터가 만드는 `truststore.p12`를 JVM에 지정해야 한다. `AWS_CA_BUNDLE`만으로는 Java TLS 신뢰 설정이 완료되지 않는다. 기존 JVM 기본 trust store를 교체하는 부작용도 주의한다.
3. SDK의 호스트 접두어 및 S3 경로/호스트 스타일에 주의한다. 특히 [SQS QueueUrl 관련 공개 이슈](https://github.com/aws/aws-emulator/issues/25)에서는 반환 URL의 호스트가 실제 AWS로 향해 일부 SDK 호출이 로컬 에뮬레이터를 떠날 수 있다고 보고했다. **이 이슈는 공개 보고이며 본 기록에서 독립 재현한 버그는 아니다.** 실험용 자격 증명과 네트워크 egress 통제를 사용한다.
4. 프로젝트별 AWS 서비스/작업 목록을 추출한 다음 [Fidelity 확인 절차](https://docs.aws.amazon.com/emulator/latest/userguide/check-project.html)로 지원 여부를 평가하고 에뮬레이터 테스트 다음에 격리된 실 AWS 검증을 별도 수행한다. 프로덕션 사용·보안 검증·성능 기준선 대체는 제외한다.

## AI 에이전트 운영 구조에서 얻는 설계 참고점

[AWS 개발 사례](https://www.aboutamazon.com/news/aws/how-autonomous-ai-agents-built-aws-emulator)는 (1) API 모델/실 AWS를 바탕으로 테스트를 만드는 에이전트, (2) 테스트를 재생해 불일치를 찾아 이슈를 만드는 에이전트, (3) 이슈 단위로 고치는 에이전트를 분리한다. 컴파일, 코딩 규약·보안 검토, Fidelity 회귀를 병합 게이트로 사용한다. AWS는 구현 코드를 자율 에이전트로 작성했다고 설명하지만, **에이전트가 작성했다는 사실만으로 코드 정확성이나 일반 프로젝트 재현 가능성이 증명되지는 않는다.**

Java/Spring 백엔드용으로 축소한다면 '명세·계약 정의 → 격리된 재현 테스트 → 한 이슈의 수정 → 테스트·보안·리뷰 Gate → 실환경 승인' 패턴이 학습 가치가 있다. 이는 **미검증 적용 후보**이며 PawCycle·DevPedia 등 어느 프로젝트에도 AWS Emulator를 도입하거나 해당 파이프라인을 구현했다고 주장하지 않는다.

## 대안과 출처의 한계

기존 [LocalStack](https://www.localstack.cloud/pricing)은 상태 영속화와 일부 IAM 정책 검사 같은 기능을 플랜별로 제공한다. 2026-03부터 최신 LocalStack for AWS는 계정·토큰 기반 배포이며 Hobby는 비상업 사용 한정이다. AWS Emulator는 무료 공식 API 에뮬레이터이지만 LocalStack의 완전한 기능 대체로 판단할 수 없다.

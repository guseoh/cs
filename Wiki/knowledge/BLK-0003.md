# Java·Spring·JPA·Spring Security 학습 재시작 운영 가이드

## 2026-11-20 — Spring 전용 교수법 업데이트

Spring Framework·Spring Boot의 학습 형식은 [최신 확정 결정 BLR-0016](../decisions/BLR-0016.md)을 우선한다. **긴 설명글 대신 구조화된 개념 정리**로 진행하고, 문제가 발생하는 코드부터 이유와 개선 과정을 단계별로 보여준 뒤 현행 Spring API로 연결한다. 이 과정은 단순 요약이 아니며 중요한 동작 원리와 실제 코드 호출·결과는 충분히 설명한다. 코드의 버전 차이는 공식 문서로 검증하며, 강의 PDF의 개념 그림은 해당 주제에 필요하면 채팅에서 직접 보여준다. 참고할 한글 개발 기술 블로그·국내 IT 기업 글·확장 개념 링크도 함께 제공한다.

과거 방식의 모든 중간 구현을 재현하지 않으며 **이해가 우선이고 완벽한 필기나 Obsidian 문서 완성은 필수가 아니다.** 이 변경은 현재 **Spring 학습에만 명시적으로 적용**되며 Java·JPA·Spring Security의 개별 규칙과 기존 로드맵은 그대로 보존한다.

## 0. 문서 상태와 적용 범위

이 가이드는 [2026-11-17 학습 운영 결정](../decisions/BLR-0012.md)을 실제 개념 학습에 적용하기 위한 문서다. **Java와 Spring을 처음부터 다시 시작하고, JPA와 Spring Security는 별도 학습 과정으로 운영한다**는 선택과 **핵심 원리의 정확한 이해·실무 활용·선택적 심화·선택적 Obsidian 기록**은 사용자 확정 사항이다.

아래 표의 세부 권장 예시와 분야별 학습 연결은 이를 실행하기 위한 **운영 제안**이다. 모든 강의 상세 목차가 원본 파일과 항목별로 다시 대조되었다거나 학습이 완료되었다는 뜻이 아니다. 특히 Spring의 7과정·34주제·17개 최우선 심화는 [이미 확정된 별도 문서](BLK-0002.md)가 정본이며, 이 문서가 새로 번호를 매기거나 변경하지 않는다. JPA 7단계·43주제, Security 3단계·25주제는 선행 대화에서 사용한 구획을 기반으로 하되, 이 Wiki에 원본 상세 목차가 별도 등록되어 있지는 않으므로 항목 이름·개수의 완전한 원본 대조는 **미검증**으로 남긴다.

## 1. 모든 과정에 공통으로 적용할 원칙

| 구분 | 운영 기준 |
| --- | --- |
| 목표 | 정의 암기나 문서 완성보다 **왜 필요한지·코드의 동작·사용 상황·실수 방지**를 이해 |
| 설명 깊이 | 필수 원리는 충분히 설명, 부수적인 API·내부 구현·역사는 필요할 때만 확장 |
| 설명 분량 | 주제 난이도에 따라 다르게: 짧고 명확한 내용은 짧게, 실행 흐름은 단계별로 |
| 예제 | 작고 대표적인 Java/Spring 코드 위주. 입력·출력·상태 변화 또는 실제 SQL/HTTP 흐름을 연결 |
| 코드 검증 | 설명에 필요하면 결과를 분석. 사용자가 원치 않으면 과제·별도 프로젝트·테스트를 강제하지 않음 |
| 공식 자료 | Spring/JPA/Security 최신 API·버전 차이·보안 조건은 공식 문서 중심으로 확인 |
| 한국어 자료 | 국내 엔지니어링 글은 정확한 이해를 돕는 경우에 선택적으로 참고 |
| 이미지·도식 | 스레드/참조/빈 생성/프록시/요청/영속성/인증 흐름처럼 구조가 핵심일 때만 채택 |
| Obsidian | 이해가 막혔던 부분·혼동·재발 가능 실수·유용한 판단만 선택적으로 기록 |
| 진도 | 완료한 문서 수, 읽은 글 분량, 암기율로 판정하지 않음. 주제별 공부 시간 강제 없음 |
| 심화 | 실무 중요도·안전성·정합성·사용자의 질문에 따라 열되, 주변 주제를 끝없이 확장하지 않음 |

### 한 주제의 기본 진행 방식

1. **핵심 이해:** 정의보다 먼저 사용 맥락과 해결하려는 문제를 파악한다.
2. **동작 확인:** 대표 코드가 어떤 결과를 내는지, 그 이유가 무엇인지 이해한다. 필요하면 객체 상태·호출 순서·SQL·HTTP 교환을 단계별로 추적한다.
3. **사용 판단:** 어떤 상황에 적합하고 어떤 오해·실수를 주의해야 하는지 확인한다.
4. **선택적 확장:** 이해가 막힌 지점, 실무에서 문제가 되는 제약, 흥미가 생긴 내부 원리만 추가 학습한다.
5. **선택적 기록:** 다시 찾을 가치가 있는 내용만 Obsidian에 남긴다. 정리를 안 했어도 이해했다면 다음 주제로 이동한다.

'완료'는 전부 외웠다는 뜻이 아니다. **자기 말로 핵심을 설명하고, 작은 코드를 읽거나 사용할 근거가 생긴 상태**이면 다음으로 넘어갈 수 있다. 까먹으면 다시 찾아보면 되며, 동일 주제를 만날 때 이해를 갱신한다. 별도 퀴즈나 새 실습을 매번 의무화하지 않는다.

### AI에게 기대하는 설명의 기본 형식

- **핵심 개념과 등장 이유:** 필요한 배경만 연결하는 설명형 한국어 문단.
- **동작 흐름과 대표 코드:** 왜 이런 결과가 나오는지 실제 실행을 따라가기. 코드 문법이 이해를 가로막으면 해당 문법만 국소적으로 보충.
- **실무 적용과 주의점:** 흔한 오류·안전성·성능/정합성의 중요 경계.
- **선택적 추가 자료:** 더 읽고 싶은 경우 참고할 공식 문서나 한국어 기술 글. 그림도 이해에 실제 도움이 될 때만.
- '심화'라고 적힌 주제라도 긴 글·여러 그림·다수 외부 링크를 자동 요구하지 않는다. **짧음이 목표도 아니며, 핵심을 누락하는 요약도 금지**한다.

### 로드맵(기존 김영한 Java 7과정 틀 유지)

| 과정 | 학습 핵심 | 깊이 조절 |
| --- | --- | --- |
| 입문편 | 변수, 조건·반복, 배열, 메서드, 기초 실행 흐름 | 알고 있는 문법은 빠르게 확인. 시작을 위한 장문 재정리 불필요 |

| 고급 2편 | I/O, 네트워크, 리플렉션·어노테이션 등 | Spring·실무를 이해할 필요가 있는 사용 맥락 중심 |
| 고급 3편 | 함수형 인터페이스, 람다, 메서드 참조, Stream | 문법·호출 방식·부작용·실무 사용 중심. 필요하면 앞당겨 국소 학습 |

**특별히 정확해야 할 부분:** 값과 참조, 다형성/오버라이딩, equals/hashCode와 컬렉션, 불변성, 예외 전달, 제네릭, 공유 상태·동시성. **코딩 테스트는 별도 알고리즘·문제 풀이 연습이 필요**하며 Java 강의만 완주했다고 준비 완료로 간주하지 않는다.

예: `HashMap`은 해시 기반 조회, 충돌과 동등성, 평균적인 연산 복잡도 및 사용 상황을 먼저 이해한다. 특정 JDK 구현의 트리화 임계값이나 내부 클래스 분석은 기본 완료 조건이 아니다.

## 3. Spring Framework / Spring Boot — 01번부터 재시작

**정본:** [7과정·34주제 커리큘럼 BLK-0002](BLK-0002.md), [확정 결정 BLR-0010](../decisions/BLR-0010.md). 아래는 **주제별 가중치 재해석**이지 새로운 34개 목차가 아니다.

| 과정(기존 번호) | 처음 학습할 때 우선 확보할 능력 |
| --- | --- |
| Spring Core (01~05) | DI가 왜 필요한지, 컨테이너가 Bean을 구성하고 주입하는 과정, 자동 주입 충돌, 싱글톤 무상태 원칙 |
| Spring MVC 1 (06~09) | 요청 → DispatcherServlet → Controller → 응답/JSON 변환의 흐름 |
| Spring MVC 2 (10~15) | DTO 검증, REST 예외 응답, Filter/Interceptor, 외부 HTTP 호출, 테스트 코드 범위 선택 |
| Spring DB 1 (16~18) | JDBC 연결, DataSource/Pool, 트랜잭션 자원과 예외 추상화 |
| Spring DB 2 (19~23) | 데이터 접근 기술 선택, Transactional 프록시·롤백·전파·경계 설계 |
| Spring 고급 (24~28) | ThreadLocal 주의점, 프록시 개념, AOP 제약, 자기 호출과 Transactional의 관계 |
| Spring Boot (29~34) | 실행·자동 구성·설정·Profile·Actuator·메트릭·비동기/스케줄링 이해 |

**원칙적 시작점:** Spring 01 「객체지향 설계와 IoC·DI」. Java는 입문부터 시작하고, 두 과정의 학습 속도를 억지로 맞추지 않는다. Spring Boot의 내부 원리는 후반에 다뤄도 실제 Spring Boot 예제 코드를 읽고 실행하는 것은 초반부터 가능하다.

**깊게 이해할 핵심:** 객체 생성과 DI, Bean 후보 결정과 생명주기, Controller 요청/응답 흐름, 예외·검증, 트랜잭션 경계·프록시·전파, 외부 설정과 운영 상태. 반면 초기 JSP/수제 MVC 구현 반복, XML 설정 실습, Thymeleaf 문법, 저수준 프록시 세부 API는 현재 REST 백엔드 목표에 필요한 맥락만 다룬다. '범위 축소'는 기술이 지원 중단되었다는 의미가 아니다.

**학습 연결:** `@Transactional`을 처음 배울 때 프록시 기본 개념을 미리 설명할 수 있고, 자세한 AOP 구조는 24~28번에서 확장한다. Spring MVC의 Filter는 Security에서 다시 만나되, 보안 필터 체인 상세까지 중복 설명하지 않는다. Spring 테스트(15번)는 분류가 '표준'이어도 직접 테스트를 작성하는 역량의 중요도가 낮다는 의미가 아니다.

**17개 최우선 심화**는 중요 개념에 시간을 우선 쓰기 위한 표식이다. 17개 모두를 동일한 분량의 장문으로 작성한다는 규칙은 없다.

## 4. JPA — 별도 과정으로, 정확한 영속성 이해

기존에 논의한 **7단계·43주제 구획을 보존하는 방향**이다. 아래는 단계별 핵심 범위를 재진술한 것이며 개별 43개 제목의 원본 대조는 후속 과제다.

| 구획 | 기존 요약상 개수 | 핵심 이해 |
| --- | ---: | --- |
| 1. 기본 원리·매핑 | 12 | 엔티티 상태, 영속성 컨텍스트, 1차 캐시, 변경 감지, Flush, 식별자·매핑 |
| 2. 실무 도메인·설계 | 5 | 연관관계 주인, 객체 그래프, 엔티티 책임과 설계 제약 |
| 3. API·조회 최적화 | 5 | 지연 로딩, 프록시, N+1, Fetch Join, 페이징, DTO 조회 |
| 4. Spring Data JPA | 6 | Repository 추상화, 쿼리 메서드, 선언적 조회와 선택 기준 |
| 5. QueryDSL | 5 | 동적 조건, Join, DTO 조회, 페이징/Count Query, 대안 비교 |
| 6. 트랜잭션·정합성 | 5 | 낙관적·비관적 락, 동시 수정, 정합성과 격리 수준의 관계 |
| 7. 성능·운영 | 5 | SQL 실행·쿼리 수·인덱스·배치와 성능 병목 해석 |

**깊이 우선:** 영속성 컨텍스트·Flush/변경 감지, 연관관계, 지연 로딩과 N+1, 트랜잭션/락. 메서드 사용법과 SQL 발생 시점을 설명할 수 있어야 한다. Hibernate 내부 구현 클래스, 특수 힌트, 2차 캐시 세부 구조는 처음부터 전부 분석하지 않는다. QueryDSL은 한 가지 해결 수단으로 배우며 Spring Data JPA Specification 등 다른 동적 쿼리 방법의 선택 조건도 비교한다.

**학습 형식:** JPA는 기존에 합의했던 **이론 중심 방식**을 존중한다. 코드와 SQL 예제로 동작을 이해하되 별도 실습 프로젝트·로그 수집·테스트 과제를 자동 강제하지 않는다. Spring의 트랜잭션 개념은 중복해서 장문 재설명하지 않고 JPA와 연결되는 차이만 다룬다.

## 5. Spring Security — 별도 과정으로, 안전한 사용 기준 확보

기존에 논의한 **3단계·25주제 구획을 보존하는 방향**이다. 역시 개별 25개 제목의 원본 대조는 이 Wiki에 아직 남아 있지 않다.

| 구획 | 기존 요약상 개수 | 핵심 이해 |
| --- | ---: | --- |
| 1. 인증·인가 기초 | 12 | 인증 vs 인가, 세션/쿠키, SecurityFilterChain, Authentication, SecurityContext, 사용자 정보/비밀번호, 인가·예외·테스트 |
| 2. 기능 활용 | 7 | 메서드 보안, CSRF, CORS, API 로그인, 여러 필터 체인, 확장 지점, 세션 보안 |
| 3. 인증 방식 확장 | 6 | JWT, OAuth 2.0, OIDC, Resource Server, Authorization Server, 보안 이벤트 |

**깊이 우선:** 필터 체인의 요청 처리와 인증 상태, 접근 제어의 기준, 안전한 비밀번호 처리, 세션·CSRF, JWT 서명/검증/만료, OAuth2 역할 구분. 필터의 모든 클래스명·순서·내부 구현을 암기할 필요는 없지만 **보안에 중요한 제약과 실수는 절대 생략하지 않는다.**

**학습 연결:** Spring MVC와 Filter에 익숙해진 뒤 시작하면 좋지만 고정된 진입 날짜는 없다. 쿠키 기반 인증, JWT 기반 API 인증, OAuth2 로그인은 동일한 기술이 아니므로 적용 조건과 위험을 나누어 설명한다. Authorization Server는 첫 학습부터 직접 구현 과제로 강제하지 않고 책임과 구조를 먼저 이해한다.

## 6. 네 과정의 관계와 부담 관리

- **현재 집중:** Java·Spring을 기초부터 재시작. 입문 Java에서 충분히 익숙해진 뒤 Spring Core로 연결할 수 있다. 꼭 동일 요일·시간에 번갈아 학습할 필요는 없다.
- **후속 분리:** JPA는 Spring DI·DB·트랜잭션 이해에, Security는 MVC·Filter·HTTP 요청 흐름 이해에 연결한다. 하지만 정확한 개시 시점은 미확정이며 네 과정을 동시에 진행하지 않아도 된다.
- **CS·Linux·시스템 설계:** 이미 확정된 별도 로드맵을 삭제하지 않는다. 현 시점에서는 전부 같은 강도로 병행하기보다 Java/Spring 주제에서 필요할 때 관련 지식을 찾아본다. 인프라·네트워크 전문직 대비를 새 병행 과제로 만들지 않는다.
- **프로젝트:** 배운 원리가 기존 프로젝트의 코드·장애·설계와 만나는 상황에서는 연결 예제를 사용할 수 있다. 다만 매 강의마다 프로젝트 기능 개발을 의무로 만들지 않는다.
- **학습 중단/재개:** 공백 뒤에 돌아오면 전체 복습 계획을 새로 작성하는 대신 **마지막으로 이해한 핵심과 다음 주제 하나**만 확인하여 재개한다.

## 7. Obsidian 기록과 AI 학습 대화의 경계

### 기본적으로 기록하지 않아도 되는 것

단순 정의, 공식 문서에 이미 있는 사용법, 그날 읽은 내용 전체, 강의 이미지·슬라이드 복제, '완벽한 정리'를 위해 만든 긴 글, 매번 반복되는 설명은 의무 기록 대상이 아니다.

### 기록 가치가 있는 것

- 헷갈려서 다시 틀린 개념의 구별: 예를 들어 `==`와 `equals()`, `flush`와 `commit`.
- 코드가 예상과 다르게 동작했던 이유 및 안전한 수정 원리.
- 재사용할 설계 판단: 왜 생성자 주입인지, 언제 Fetch Join/DTO 조회를 택하는지 등.
- 자기만의 언어로 정리해 놓으면 다음번 탐색 비용이 줄어드는 짧은 도식·실수 기록.

권장 메모 형태는 **핵심 2~5문장 + 작은 코드/흐름 + 다시 확인할 한 가지 주의점** 정도이나 분량 제한이나 필수 템플릿은 아니다.

### AI가 학습 진도를 보고할 때

학습 설명 제공, 사용자의 이해 확인, 코드 실행 검증, Obsidian 기록 완료, 프로젝트 반영은 **서로 다른 상태**다. 실제로 수행한 것만 기록한다. 공개 Wiki에는 개인 상태와 비공개 대화의 상세 원문을 게시하지 않는다.

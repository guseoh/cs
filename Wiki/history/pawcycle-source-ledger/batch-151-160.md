## #154 — chore(sre): RDS Single-AZ 전환 저장소 준비

**판정:** Docker기본유지·RDSruntime/read-only Gate·TLS대가 관련 기록: [PWC-0011](../../decisions/PWC-0011.md)。 [원본](https://github.com/guseoh/pawcycle-commerce/pull/154)

Docker mysql:3306/sslDISABLED는기본으로남기고RDSprivate:3306/sslREQUIRED·credential과비민감config분리·Backend-only비internaldatabase-egress를추가했다. base/full preflight·targetidentity/finalconsistency/schema/Flyway/coremanifest를검증한다. REQUIRED는인증서/hostname검증이없어VERIFY_CA/IDENTITYhardening을보류했고실cutover시명시위험수용또는hardening없으면SKIPPED로막는다. 7일retention은ADR후보였고실생성에서확정된다. SourceDocker/volume은즉시삭제하지않는다.

**원본이 보고한 계약·검증·한계 추출:** 아래는 공개 Issue/PR의 당시 진술이다. 이번 Wiki 조사에서 제품/운영 검증을 재실행한 결과가 아니다. 승인·실행·병합 상태는 위 판정 및 manifest의 시각·SHA와 구분한다.

### 원본 진술: 목적과 범위

- 목적: 현재 Production Docker MySQL에 결합된 datasource runtime 계약을 RDS MySQL Single-AZ 전환이 가능한 구조로 확장합니다.
- 변경 범위: 기존 Docker MySQL 기본 경로와 rollback source를 유지하면서 RDS datasource runtime, read-only preflight, migration rehearsal, cutover/rollback readiness 계약, ADR/Runbook, fixture·validator·CI 검증을 저장소에 준비합니다.
- 제외 범위: 실제 RDS·DB Subnet Group·Security Group·IAM·SSM 생성/수정, Production DB dump/import/query/Flyway, datasource 실제 전환, Production deploy, Docker MySQL stop/remove, named volume 삭제, PITR restore, Multi-AZ·Read Replica·RDS Proxy입니다.

### 원본 진술: 결정과 영향

- Docker MySQL은 `mysql:3306`, `sslMode=DISABLED` 기본 경로를 유지하고 RDS는 private endpoint:3306, `sslMode=REQUIRED` 경로로 분리합니다.
- datasource host/port/SSL mode는 비민감 runtime configuration으로 분리하고 DB credential과 구분합니다. RDS와 Docker rollback runtime의 credential 동일성은 요구하지 않고 각 bundle 내부 일관성을 독립 검증합니다.
- Backend에 RDS 접근을 위한 전용 `database-egress` network를 추가합니다. 이 network는 RDS 접근을 위해 non-internal로 유지하되 Backend만 연결되도록 실제 `docker compose config` 구조화 결과로 회귀 검증합니다.
- resource 생성 전 base preflight와 RDS SG 생성 후 full preflight를 분리합니다. AWS 사전 확인은 describe 계열 API만 허용하며 MySQL 8.4, `db.t4g.micro`, gp3 20 GiB, VPC/subnet/AZ와 SG 경계를 검증합니다.
- migration rehearsal과 Production cutover evidence를 분리하고 final consistency, target identity, schema/Flyway/core-table evidence를 fail-closed로 검증합니다.
- 기존 Docker MySQL service와 `pawcycle-production-mysql-data` volume은 cutover 이후에도 rollback source로 보존합니다.
- `sslMode=REQUIRED`는 현재 repository readiness 계약이며 VERIFY_CA/VERIFY_IDENTITY hardening은 deferred입니다. 실제 Production cutover 승인 시 현재 TLS 위험 수용 또는 별도 hardening 완료를 명시적으로 확인하고, 둘 다 확인되지 않으면 cutover를 `SKIPPED`로 중단합니다.
- 제품 API·DB schema/Flyway·Frontend 계약은 변경하지 않으며 실제 AWS/RDS/Production/DB/Secret mutation은 수행하지 않았습니다.

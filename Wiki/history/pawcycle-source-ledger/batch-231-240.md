## #231 — MVP4-DATA-002 — Production Catalog one-shot Import 경로 구축

**판정:** Production空Catalog→明示import要求 관련 기록: [PWC-0024](../../decisions/PWC-0024.md)。 [원본](https://github.com/guseoh/pawcycle-commerce/issues/231)

Applicationdeploy後API total0でlocal-onlybootstrapはProductionで走らないため、startupseed/任意SQLではなくprofile-neutral共通importを要求した。validate/dry-run→confirmapply→postflight、businesskey衝突/在庫保全/cache無効化・実適用別承認を定義した。CSV/API/MD拡張は将来候補である。

**원본이 보고한 계약·검증·한계 추출:** 아래는 공개 Issue/PR의 당시 진술이다. 이번 Wiki 조사에서 제품/운영 검증을 재실행한 결과가 아니다. 승인·실행·병합 상태는 위 판정 및 manifest의 시각·SHA와 구분한다.

### 원본 진술: 배경

#229에서 약 32개 규모의 현실적인 Demo Catalog를 `demo-catalog.json` 기반으로 구축했지만, 현재 `LocalCommerceDemoFixtureService`는 `local-integration` 전용 프로필이라 Production에서는 자동 bootstrap되지 않는다.

실제 Production API 확인 결과 `/api/products`는 `totalElements=0`이다. Application 배포는 정상이나 Production Catalog 데이터는 비어 있다.

수동 SQL 대량 입력이나 Production startup 자동 bootstrap 대신, 운영자가 명시적으로 실행하는 one-shot import 경로가 필요하다.

### 원본 진술: 목적

기존 Demo manifest와 검증된 bootstrap/import 규칙을 재사용해, Production에서 명시적으로 Catalog 데이터를 적재할 수 있는 안전한 one-shot import 경로를 만든다.

이번 작업은 32개 Demo Catalog의 Production 적재를 가능하게 하는 것이 1차 목적이지만, 장기적으로 CSV/Excel/API 기반 Catalog ingestion으로 확장할 수 있도록 manifest import 책임을 local profile에 종속시키지 않는다.

### 원본 진술: One-shot 실행 계약

운영자는 저장소가 제공하는 명시적 command/script로 다음을 수행할 수 있어야 한다.

`validate/dry-run → explicit apply → postflight`

최소 요구:

- 입력 manifest를 명시적으로 선택하거나 승인된 기본 Demo manifest를 사용
- apply 전 manifest 구조/business key 충돌을 검증
- apply 실행은 명시적 opt-in 없이는 동작하지 않음
- 동일 manifest 재실행 시 중복 row 생성 없음
- 이미 존재하는 mutable Inventory 수량을 초기값으로 덮어쓰지 않음
- conflict 시 부분 반영 없이 fail-close
- 성공 후 aggregate 결과만 출력
- Product / SKU / Plan 수와 공개 Product API 결과를 postflight로 확인 가능

구체적인 CLI 형태는 현재 Production Docker/runtime 계약을 확인해 가장 단순하고 안전한 방식을 선택한다. 새 외부 관리 시스템이나 Admin UI를 이번 작업 때문에 추가하지 않는다.

### 원본 진술: 제외 범위

- 실제 공급사 API 연동
- CSV/Excel parser 구현
- Admin Catalog UI 확장
- Product Detail Content 신규 schema
- Review/Rating/Q&A
- S3/CDN
- Redis/Kafka/Queue 신규 도입
- Production DB 직접 SQL seed
- startup Production bootstrap

### 원본 진술: 후속 확장

장기적으로는 동일 ingestion 경계를 다음 입력으로 확장한다.

`MD/Admin 등록 또는 공급사 CSV/Excel/API → validation/dry-run → Catalog Import → Product/SKU/Inventory`

`demo-catalog.json` 자체를 수백~수천 상품의 장기 운영 원본으로 확대하지 않는다.

## #233 — feat(commerce): MVP4 상품 신뢰와 구매 정합성 보완

**판정:** Checkout identity·atomic reorder·Trust domain 관련 기록: [PWC-0083](../../decisions/PWC-0083.md), [PWC-0084](../../decisions/PWC-0084.md)。 [원본](https://github.com/guseoh/pawcycle-commerce/pull/233)

SHA256fingerprint＋初回request_cart_versionでidentityを固定し既存keyは現在Cartstale検査より先に照合する。同一初回requestは後のCart変更/決済消費後もreplay、address/coupon/version差はconflict、legacy欠損はfail-closedだ。実Cart変更のみversion増加しserverReorderのcart/version/idempotencyは同transactionでrollbackする。

Reviewは配送完了購入・会員商品1件・所有/Adminvisibility、Q&Aは回答後編集削除禁止と同rowlock・初回通知1回を守る。V21~23forwardmigration/CI#1311/実DBfailurerollbackを検証し、localJAVA_HOME失敗とCI成功を分離する。Frontend/ProductionDDLは範囲外。

### 원본 진술: 결정과 영향

- Product Detail은 `shortDescription`, visible detail sections와 trust aggregate를 additive하게 제공하며 visible Review가 없으면 `averageRating=null`을 반환합니다.
- Review는 배송 완료 구매 이력·회원/상품당 1개·소유권·Admin visibility를 적용하고 public 응답에서 직접 식별값을 노출하지 않습니다.
- Product Q&A는 작성자 소유권과 답변 후 수정·삭제 금지를 적용하며, 삭제와 Admin 답변이 동일 row lock을 사용해 동시성 경계를 맞췄습니다. 최초 답변 Notification은 한 번만 생성합니다.
- Cart는 실제 내용 변경에서만 version을 증가시킵니다.
- Checkout은 JDK SHA-256 fingerprint와 최초 `request_cart_version`으로 request identity를 보존합니다. 기존 Idempotency-Key는 현재 Cart stale 검증보다 먼저 최초 요청 identity를 확인하므로, Cart가 이후 변경되거나 결제 성공으로 소비되어도 같은 최초 요청은 기존 Order/Payment를 replay합니다. address/coupon/cartVersion이 달라지면 conflict이며 legacy fingerprint/version 누락 row는 fail-close합니다.
- Quick Reorder는 본인 주문의 현재 구매 가능 SKU만 Cart에 추가하고 Inventory reserve/deduct를 수행하지 않으며 동일 key·동일 source order replay에서 Cart를 다시 변경하지 않습니다.
- Quick Reorder의 예상하지 못한 persistence 실패는 동일 transaction에서 Cart mutation, cartVersion, idempotency 결과를 함께 rollback하도록 통합 테스트로 검증했습니다.
- migration은 기존 파일을 수정하지 않고 V21, V22와 review correction용 V23을 forward-only로 추가했습니다.
- API/DB 소비 계약은 `docs/api/API-010-mvp4-product-detail-trust-api.md`, `docs/api/API-011-mvp4-purchase-consistency-api.md`, `docs/handoffs/MVP4-BE-COMPLETE-001/be-to-fe.md`에 기록했습니다.

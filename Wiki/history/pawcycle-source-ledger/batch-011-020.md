## #11 — UX-001: 제안에서 제품 판단으로 넘긴 입력

상품 탐색→SKU/수량/주기→생성→본인 구독 조회의 8개 화면/상태, 로딩·빈 상태·조회 실패·입력 오류·접근성·반응형 후보를 정의했다. 화면 배치·단일 상세 내 입력·제출 중 잠금은 Proposed UX이며 제품 전체의 별도 승인이 아니다. 기본 활성 제출 버튼은 클릭 시 검증하고 잘못된 입력은 전송하지 않으며 필드/요약/포커스로 안내한다. 일시적 조회 실패만 재시도하고 없는 상품/SKU/구독은 대상별 탐색 복구로 나눴다.

초안의 별도 성공 결과 화면, 로그인 후 항상 기본 화면 이동, 상품 탐색 로그인 제한, FE 사전 날짜 계산 대안은 TL/PO 결정 대상으로 전달했다. 비회원 공개 탐색·로그인 후 복귀·성공 이동·사전 예정일의 네 질문은 당시 Open이었다. [#13의 승인/PWC-0027](../../decisions/PWC-0027.md) → #14의 반영으로 연결한다. #11 자체의 모든 제안이 Approved가 된 것은 아니다.

리뷰 3건은 상품 카드 ID 누락, Asia/Seoul·보정 없음 전달 누락, 이미 승인된 보호 화면 로그인 이동까지 차단하는 handoff를 지적했다. 최종 diff와 답변에서 이를 보강한 내용을 확인했다. handoff는 FE 직행 대신 TL 결정 요청으로 전환했다. 문서 validator/인코딩·원격 check 통과는 당시 보고이며 FE 구현·브라우저 E2E는 없다. **판정: 기존 PWC-0027에 선행 제안/리뷰 correction 추가, 독립 UX 결정 ID는 승인 불명인 전체 화면안을 중복 생성하지 않음.**

## #13 — PS-003: 네 제품 결정 승인과 리뷰 근거의 한계
공개 상품 탐색/보호 구독, 안전한 내부 GET 복귀와 fallback·폼/POST replay 제외, 별도 영구 성공 페이지 대신 생성 상세, 생성 전 정확한 예정일 미표시를 Approved Product Decision으로 기록하고 PS-002 AC에 반영했다. 당시 대안과 이유·대가는 [PWC-0027](../../decisions/PWC-0027.md)에 유지한다. DOMAIN·API JSON/HTTP·DB·Security 기술 결정은 바꾸지 않았다.

공개 리뷰는 보고 SHA 불일치와 Learning Record 누락을 지적했다. 그러나 **현재 조회한 PR commit 목록에는 보고서의 `2eb8ee1`이 실제 포함**되어 있다. 과거 리뷰가 언급한 다른 검토 SHA·조상 관계를 현재 사실로 그대로 채택하지 않는다. 최종 diff에 docs/learning 파일이 없는 것은 확인되지만 별도 승인된 예외·후속 보충 여부는 미확인이다. 무조건 당시 DoD 위반 확정 또는 해결 완료라고 하지 않는다. 보고서의 Open/Draft 문구도 보고 시점 상태이며 현재 GitHub는 Merged다. **판정: 기존 결정 보강, 신규 제품 Decision 중복 불필요.**

## #14 — UX-002: 제품 승인 후 화면 규칙 동기화

## #15 — ARCH-001: 책임 경계 제안

**판정: [PWC-0035](../../decisions/PWC-0035.md), status proposed.** 사용자 승인 제품 입력과 이 아키텍처 제안 전체를 구별한다. 최신 고정 main의 원본도 Proposed다. 앱·영속성 구현 없이 3개 문서만 변경했고, 보고된 검사도 추적성/범위/산출물 검사다. 후속 제한 승인은 [PWC-0029](../../decisions/PWC-0029.md)와 별도 연결한다.

## #17 — DATA-001: 네 테이블 후보와 불완전한 전달 정렬
최소 Member/Product/SKU/Subscription 관계, 수량/주기/날짜/FK 제약 후보, 측정 전 index 후보, 표시/구독 가능 여부와 재고 분리, DATE 후보와 감사 시각 구분을 제안했다. 개인정보 필드·결제/재고/배송/상태 모델·범용 정책 테이블은 첫 MVP에서 제외했다. 세부 후보/대가는 [PWC-0036](../../decisions/PWC-0036.md)에 보존한다.

리뷰 5건은 subscribable 추적성, 필수 상품 표시·배송 주기, Accepted 값 객체의 재결정 금지, 필수 입력 누락 오류, 날짜 관계를 지적했다. 최종 본문과 handoff를 대조하면 대부분 보강됐지만 값 객체 채택은 본문에서 유지하면서 handoff에는 “사용 여부”가 남는다. 사용자 지정 최소 반영 보고가 있으므로 전체 리뷰 해결을 주장하지 않는다. **판정: PWC-0036 proposed + [PWL-0011](../../lessons/PWL-0011.md).** migration/Entity/실제 MySQL 제약 검증은 없다. 최신 main에도 설계 Proposed 및 handoff 잔여 표현을 확인했다.

## #18 — API-001: 최초 HTTP·필드·오류 후보의 정합성 correction
상품 2/구독 3 경로, 생성 201·서버 날짜/ID, 빈 목록 200, 본인 조건 조회, 오류 code/message/fieldErrors와 400/401/404/409/500 후보를 정의했다. 타인 구독과 없는 구독을 동일 404로 숨기는 대안 선택, 표시 가격과 결제액 구별, ISO local date 후보를 [PWC-0037](../../decisions/PWC-0037.md)에 남겼다. 삭제 정책/soft delete·검색/정렬/페이지네이션·OpenAPI·인증 구현은 보류했다.

리뷰 6건과 최종 diff에서 정의되지 않은 VALIDATION_FAILED 제거, SKU price를 제외하는 문장 수정, 주 기반 연도 대신 calendar year 설명, PRODUCT_LIST_UNAVAILABLE의 계약/handoff/QA 보강을 확인했다. **판정: PWC-0037 proposed.** 사용자 지정 최소 반영이며 코드/DTO/endpoint/브라우저 테스트는 없다. 후속 [API-002](../../decisions/PWC-0030.md)/[API-003](../../decisions/PWC-0031.md)의 별도 승인을 최초 후보에 소급하지 않는다.

## #19 — AUTH-001: 인증·복귀 후보와 Harness의 작은 구현
인증 컨텍스트 회원/본인 조회, 보호 API 401과 화면 로그인 이동 구별, 내부 GET allowlist·정규화·인코딩 우회/제어 문자 차단·상품 fallback을 설계했다. returnTo/session/cookie/sessionStorage의 비용을 비교했지만 저장 위치·세션/토큰·CSRF·principal·Security·실제 라우트/검증 유틸은 선택하지 않았다([PWC-0038](../../decisions/PWC-0038.md)).

AUTH 3자리 ID를 artifact validator와 양/음성 fixture에 추가한 작은 구현도 기록한다. fixture 통과 보고는 인증 제품 테스트가 아니다. 리뷰는 소유자 복합 조회 의무화와 테스트 미작성 표현의 범위 수정을 요청했다. 최종 handoff는 “항상 함께”지만 ADR 본문은 “가능하면”으로 남는다. **판정: PWC-0038 proposed + PWL-0011, Harness 확장은 기존 PWC-0028의 구현 사건.** sh 부재 후 Git Bash 검사 보고를 보존한다. 실제 인가 우회·운영 취약점은 재현하지 않았다.

## #20 — FOUNDATION-000: 후보의 제목·최소 버전·승인 상태 correction
원래 기술 표·대안·부담은 [PWC-0032](../../decisions/PWC-0032.md)에 유지한다. 리뷰 6건에서 Gradle 9.x를 Java25 지원 최소 9.1+로 좁히고, Proposed를 “지켜야 할 버전”으로 전달하지 않도록 “우선 검토”로 고쳤다. 최종 제목도 “결정안”으로 바뀌었다. 보고 placeholder→실제 Git/PR 정보, Markdown pipe·PowerShell 호출 연산자 교정도 확인했다.

Windows의 python 별칭/파이프 실행 실패, sh 부재, py -3/Git Bash 대체 결과는 당시 보고이며 이 환경에서 재현하지 않았다. Node/Next/TS·JDK/Gradle·JDBC/Flyway 실제 scaffold/build 호환은 후속 중단 조건이다. **판정: 기존 PWC-0032 갱신, 여전히 proposed.** 병합은 후보 전체 승인이나 도구 설치·DB 운용 성공이 아니다.

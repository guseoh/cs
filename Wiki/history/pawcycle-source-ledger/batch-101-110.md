## #105 — reconciliation batch의 transaction 실패 격리

**판정:** 구독별 reconciliation 실패 격리 요구 승인; #106 추적 관련 기록: [PWC-0063](../../decisions/PWC-0063.md)。 [원본](https://github.com/guseoh/pawcycle-commerce/issues/105)

배치 전체 transaction은 한 구독의 실패가 앞선 성공까지 rollback하거나 뒤 구독을 건너뛰게 할 수 있다. catch만 추가하면 rollback-only를 해결하지 못하므로 outer loop transaction 제거와 구독별 독립 REQUIRES_NEW를 요구했다.

self-invocation의 프록시 우회 위험을 명시하고 첫 구독 실패·후속 구독 commit/version 증가·실패 ID 로그를 완료 조건으로 삼았다. command 내부 reconcile은 기존 command transaction을 보존한다. #106으로 종료됐으며 retry/backoff·metric·cadence·운영 실행은 제외했다.

## #106 — fix(be): reconciliation 실패를 구독별로 격리

**판정:** TransactionTemplate 실패 격리 구현과 회귀 검증 관련 기록: [PWC-0063](../../decisions/PWC-0063.md)。 [원본](https://github.com/guseoh/pawcycle-commerce/pull/106)

PlatformTransactionManager 기반 TransactionTemplate(REQUIRES_NEW)을 각 구독에 적용해 프록시 self-invocation을 피했다. outer batch는 transaction이 없고 RuntimeException을 구독 ID와 ERROR로 기록한 뒤 다음 구독으로 진행한다. command transaction 의미는 유지한다.

Java 25+MySQL 8.4 Docker 관련 통합 18개와 동일 DB 강제 재실행, Harness 52개가 보고됐다. transaction 없는 테스트 fixture 잔존과 task ID 전체 경계 리뷰를 함께 조사했다. 운영 scheduler 활성화·재시도·알림 검증은 없다.

### 1. 접근제어자는 왜 필요한가

접근 제어자는 클래스의 필드, 메서드, 생성자 등에 대해 **어디까지 접근을 허용할지 제한하는 기능**이다. 

접근제어자가 중요한 이유는 객체 내부의 상태와 구현을 외부 코드가 마음대로 사용하지 못하게 하여, 객체가 정한 규칙을 지킬 수 있고록 만드기 때문이다.

```java
public class Speaker {

    int volume;

    public Speaker(int volume) {
        this.volume = volume;
    }

    public void volumeUp() {
        if (volume >= 100) {
            System.out.println("최대 음량입니다.");
            return;
        }

        volume += 10;
    }
}
```

`volumeUp()`에서는 음량이 100을 넘지 않도록 검사하고 있다. 그런데 `volume` 필드에 외부 코드가 직접 접근이 가능하다.
```java
Speaker speaker = new Speaker(90);

speaker.volumeUp();
speaker.volume = 200;
```

`Speaker`내부에서는 음량을 통제하려했지만 **외부 코드가 직접 수정하면서 그 규칙을 우회**했다. 이런 상황에서는 `volumeUp()`에 검증 로직을 잘 작성해도 객체의 상태를 안전하게 유지할 수 없다.


```java
public class Speaker {

    private int volume;

    ...
}
```

`volume`필드를 `private`로 제한한다. 이제 `speaker.volume = 200`은 컴파일되지 않는다. 외부에서는 `Speaker`가 허용한 메서드를 통해서만 상태를 다룰 수 있기 때문에, 음량을 변경하는 규칙을 `Speaker` 내부에서 통제할 수 있다.

접근 제어의 목적은 **패키지나 클래스 사용자가 불필요한 구현 세부사항에 의존하지 않도록 막는 것**이다.

### 2. `private`, package-private, `protected`, `public`

Java의 접근 수준은 네 단계로 나뉜다. 접근 범위는 `private → package-private → protected → public` 순서로 넓어진다.

|접근 수준|같은 클래스|같은 패키지|다른 패키지의 자식 클래스|다른 패키지의 일반 클래스|
|---|---|---|---|---|
|`private`|O|X|X|X|
|package-private|O|O|X|X|
|`protected`|O|O|O*|X|
|`public`|O|O|O|O|
#### 2.1 priavate

`private`은 가장 좁은 접근 범위다. 일반적인 경우 해당 **클래스 내부에서만 필드나 메서드를 사용할 수 있기 때문에, 객체 내부에서만 알아야 하는 상태나 보조 기능을 감추는 데 사용**한다.

필드는 특별한 이유가 없다면 `private`으로 두는 경우가 많은 것도 같은 이유다. 외부에서 필드에 직접 의존하기 시작하면 내부 표현을 변경하기 어려워지고, 상태를 바꾸는 규칙도 우회할 수 있기 때문이다.

#### 2.2 package-private

**package-private**은 접근 제어자를 아무것도 작성하지 않았을 때 적용된다.

```java
class OrderValidator {
    void validate() {
    }
}
```
- `default` 접근이라고 부르지만 `default`라는 접근 제어자 키워드가 있는 것은 아니다.
- **같은 패키지 안에서는 접근이 가능하고, 다른 패키지에서는 접근할 수 없다.**

#### 2.3 `protected`

`protected`는 **같은 패키지에서는 상속 여부와 관계없이 접근할 수 있고, 다른 패키지에서는 상속 관계일 때 접근**할 수 있다. 

```java
package parent;

public class Parent {
    protected int value = 10;
}

package child;

import parent.Parent;

public class Child extends Parent {

    void test() {
        System.out.println(this.value);

        Child child = new Child();
        System.out.println(child.value);
    }
}
```
- 다른 패키지의 자식 클래스에서 다음 접근은 가능하다.
- 하지만 같은 `Child` 안이라도 임의의 `Parent` 객체를 만들어 다음처럼 접근하는 것은 허용되지 않는다.

다른 패키지의 자식 클래스가 `protected`멤버를 사용할 수 있다는 것은 부모 타입의 모든 객체 내부를 자유롭게 들여다볼 수 있다는 것은 아니다.

#### 2.4 `public`

`public`은 가장 넓은 범위에서 사용할 수 있다. 하지만 멤버가 `public`이라고 해서 그 멤버가 들어 있는 클래스의 접근 범위를 뛰어넘을 수는 없다.
```java
class InternalService {

    public void execute() {
    }
}
```

`execute()`는 `public`이지만 `InternalService` 자체가 package-private이므로 다른 패키지에서는 `InternalService` 타입에 접근할 수 없다.

> [!note]- 접근 수준
> 접근 범위를 판단할 때는 먼저 클래스 자체에 접근할 수 있는지 보고, 그다음 필드나 메서드의 접근 수준을 확인해야 한다.


### 3. 클래스, 필드, 메서드, 생성자에서의 사용

```java
public class Member {

    private String name;

    public Member(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }

    private void validateName() {
        // 내부에서만 사용하는 기능
    }
}
```
- `name`과 `validateName()`은 클래스 내부 구현
- 생성자와 `getName()`은 외부에 제공하는 기능

파일에 직접 선언하는 클래스에는 `public` 또는 `package-private`만 사용할 수 있다.
```java
public class OrderService { ... }

class OrderValidator { ... }
```
**최상위 클래스에 `private`이나 `protected`를 붙일 수는 없다.** 반면 다른 클래스 안에 들어 있는 중첩 클래스라면 `private`, `protected`도 사용할 수 있다.

생성자가 `public`이면 외부에서 자유롭게 객체를 만들 수 있지만, 생성 범위를 줄이면 객체를 만드는 방식 자체를 통제할 수 있다.
```java
public class Member {

    private Member() {
    }

    public static Member create() {
        return new Member();
    }
}
```
- 외부에서는 `new Member()`를 직접 사용할 수 없다.
- `Member.create()`를 통해서만 객체를 만들 수 있다.
이런 성질은 이후 정적 팩터리 메서드나 싱글턴 같은 설계에서도 사용된다.

### 4. 접근 제어자가 캡슐화와 변경에 어떤 영향을 주는가

접근 제어자는 **캡슐화를 실제 코드에서 지킬 수 있도록 도와주는 도구**다. 

객체가 가진 모든 것을 `public`으로 열어두면 외부 코드는 내부 구조를 자유롭게 사용하게 되고, 프로그램이 개발·확장되고 코드가 계속 추가될수록 그 내부 구조에 많은 코드가 의존하게 된다.

```java
public class Account {

    private int balance;

    public void deposit(int amount) {
        if (amount <= 0) {
            throw new IllegalArgumentException();
        }

        balance += amount;
    }

    public boolean withdraw(int amount) {
        if (amount <= 0 || balance < amount) {
            return false;
        }

        balance -= amount;
        return true;
    }

    public int getBalance() {
        return balance;
    }
}
```
외부 코드는 `balance`라는 내부 데이터가 어떻게 저장되는지보다 `deposit()`과 `withdraw()`라는 사용 방법에 의존한다.

여기서 `private` 필드에 getter와 setter를 만들었다고 자동으로 캡슐화가 잘 된 것은 아니다.

> 접근 제어자를 사용할 때는 단순히 "`private`으로 만들었는가"보다 **외부에 어떤 기능을 공개해야 하는가**를 함께 생각해야 한다.

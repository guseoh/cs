### 1. 상속은 왜 필요한가

상속은 이미 존재하는 클래스의 속성과 기능을 바탕으로 **더 구체적인 클래스를 만들 수 있게 하는 기능**이다. 단순 코드 중복을 줄이는 기능보다 **두 클래스 사이에서 어떤 관계가 있는지**를 먼저 생각하는 것이 중요하다.

```java
public class Car {

    public void move() {
        System.out.println("차를 이동합니다.");
    }
}

public class ElectricCar extends Car {

    public void charge() {
        System.out.println("충전합니다.");
    }
}
```
- `Car`를 **부모 클래스**, `ElectricCar`를 **자식 클래스**라고 한다.
- 상위 클래스와 하위 클래스, 또는 슈퍼 클래스와 서브 클래스라는 표현도 같은 관계를 가리킨다.
- 중요한 점은 **자식이 부모의 기능을 사용**할 수 있다.

```java
class FlyingCar extends Car, Airplane { // 불가능
}
```
- 자바에서는 두 클래스를 동시에 상속할 수는 없다.

### 2. `new ElectricCar()`를 하면 메모리에는 무엇이 만들어질까
```java
ElectricCar electricCar = new ElectricCar();
```

힙에 서로 독립적인 `Car` 객체 하나와 `ElectricCar` 객체 하나가 따로 만들어지는 것으로 이해하면 정확하지 않다. **참조값은 하나이고, 가리키는 것도 하나의 `ElectricCar` 인스턴스**다.

그 인스턴스는 `Car`에서 물려받은 부분과 `ElectricCar`가 새로 정의한 부분을 함께 가지고 있다.

즉, **두 개의 독립적인 객체가 존재한다기보다는 하나의 자식 인스턴스 안에 부모에서 정의한 상태도 포함되어 있다.**
```
electricCar ────────→ ElectricCar 객체 하나
                       ┌───────────────────────┐
                       │ Car에서 물려받은 부분   │
                       │ - speed               │
                       ├───────────────────────┤
                       │ ElectricCar의 부분     │
                       │ - battery             │
                       └───────────────────────┘
```

### 3. 오버라이딩 - 부모 기능 그대로 사용

상속받았다고 해서 부모의 모든 동작을 그대로 사용하지 않아도 된다. 자식 클래스의 성격에 맞게 부모가 제공한 메서드의 동작을 다시 정의할 수 있다. 이것을 **메서드 오버라이딩**이라고 한다.

```java
public class Car {

    public void move() {
        System.out.println("차가 이동합니다.");
    }
}

public class ElectricCar extends Car {

    @Override
    public void move() {
        System.out.println("전기차가 조용히 이동합니다.");
    }

    public void charge() {
        System.out.println("충전합니다.");
    }
}

```

- `@Override`
	- 오버라이딩을 만들어 주는 것이 아니다.
	- **이 메서드는 부모의 메서드를 재정의하려고 작성했다.** 라고 컴파일러에게 알려주는 것이다.

오버라이딩을 하려면 **부모 메서드와 메서드 이름, 매개변수 구성이 맞아야 한다. 접근 범위도 부모보다 좁게 만들 수 없다.**

```java
public final void move() {
}
```

- 부모가 메서드를 `final`로 선언했다면 자식은 이를 오버라이딩할 수 없다.
	- 부모가 "이 동작은 자식이 변경하면 안 된다"고 제한한 것이다.

`private`메서드도 자식이 오버라이딩하는 대상이 아니다.

### 4. 부모의 기능을 직접 사용해야 할 때 `super`를 쓴다
자식 클래스 안에서는 부모로부터 받은 필드와 메서드를 자연스럽게 사용할 수 있다. 그런데 부모와 자식에 같은 이름의 필드나 메서드가 있다면 어느 것을 의미하는지 구분해야 하는 상황이 생긴다.
```java
public class Car {

    protected String name = "Car";

    public void move() {
        System.out.println("Car.move");
    }
}

public class ElectricCar extends Car {

    private String name = "ElectricCar";

    @Override
    public void move() {
        System.out.println("ElectricCar.move");
    }

    public void print() {
        System.out.println(name);
        System.out.println(super.name);

        move();
        super.move();
    }
}
```

- `name`은 현재 `ElectricCar`의 필드를 가리키고, `super.name`은 부모인 `Car`에 정의된 필드를 가리킨다.
- 마찬가지로 `move()`는 현재 클래스에서 오버라이딩한 메서드를 호출하고, `super.move()`를 사용하면 부모의 구현을 직접 호출할 수 있다.

`super`는 **현재 자식 객체 안에서 부모 쪽에 정의된 멤버를 명확하게 선택하기 위한 표현**이다.

### 5. 상속에서는 생성자가 부모부터 실행된다

부모의 생성자를 그대로 물려받아서 사용하는 것이 아니라 **자식 객체를 만들 때 부모 부분도 올바르게 초기화해야 하므로 부모 생성자가 먼저 호출**된다.

자식 클래스가 부모가 준비한 상태와 기능 위에서 동작하기 때문이다. 부모 부분이 제대로 만들어지지 않은 상태에서 자식 부분부터 초기화하면 객체 전체가 정상적인 상태라고 보기 어렵다.

즉, <u>상속 관계를 사용하면 자식 클래스의 생성자에서 부모 클래스의 생성자를 반드시 호출해야 한다.</u>

```java
public class Car {

    protected int speed;

    public Car(int speed) {
        this.speed = speed;
        System.out.println("Car 생성");
    }
}

public class ElectricCar extends Car {

    private int battery;

    public ElectricCar(int speed, int battery) {
        super(speed);
        this.battery = battery;
        System.out.println("ElectricCar 생성");
    }
}

ElectricCar car = new ElectricCar(100, 80);
```
- `ElectricCar`생성자를 호출했지만, `ElectricCar` 객체에는 `Car`에서 정의한 `speed`도 존재해야 한다.
	- 따라서 자식 생성자가 자신의 `battery`를 초기화하기 전에 먼저 `super(speed);`를 통해 `Car`생성자를 호출한다.
- 부모에 매개변수가 없는 생성자가 있다면, 자식 생성자에서 `super()`를 직접 쓰지 않아도 컴파일러가 첫 부분에 호출을 추가해 줄 수 있다.

> [!important] 핵심
> 자식 객체를 생성할 때는 부모에게서 물려받은 부분을 먼저 초기화하기 위해 부모 생성자가 먼저 실행된다.

#### 추가 설명

상속을 배우면 처음에는 편해 보인다. 공통 코드를 부모에 넣고 모든 자식이 가져다 쓰면 중복도 줄어든다. 실제로도 그러한 효과가 있긴 하다.

하지만 부모와 자식은 상당히 강하게 연결된다. 부모 클래스의 동작이나 구조를 바꾸면 자식 클래스들이 영향을 받을 수 있고, 자식 클래스는 부모의 동작을 알아야 자신의 동작을 올바르게 만들 수 있다.

실제 설계에서는 `코드가 겹친다 → 상속한다` 가 아닌, 먼저 **자식이 정말 부모의 한 종류라고 볼 수 있는 관계인지**를 생각해야 한다.

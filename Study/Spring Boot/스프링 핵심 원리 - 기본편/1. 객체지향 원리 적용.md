### 1. 들어가기 전

```java
public class OrderServiceImpl implements OrderService {

    private final MemberRepository memberRepository =
            new MemoryMemberRepository();

    private final DiscountPolicy discountPolicy =
            new FixDiscountPolicy();

    ...
}
```
- `OrderServiceImpl`은 `DiscountPolicy`라는 인터페이스를 사용하고 있지만, 동시에 `new FixDiscountPolicy()`를 직접 실행하고 있다.
- 즉, 주문 서비스는 할인 기능을 사용하는 역할뿐 아니라 어떤 할인 정책을 채택할지 결정하고 그 객체를 생성하는 역할까지 가지고 있다.

### 2. 새로운 할인 정책 추가 자체는 문제가 없다

```java
public interface DiscountPolicy {

    int discount(Member member, int price);
}
```
- 기존 할인 정책 인터페이스이다.

만약 요구사항이 “VIP에게 항상 1,000원 할인”에서 “VIP에게 주문 금액의 10% 할인”으로 변경됐다고 가정하면 존 `DiscountPolicy`나 `FixDiscountPolicy`를 수정하지 않고 새로운 구현체를 추가할 수 있다.

```java
public class RateDiscountPolicy implements DiscountPolicy {

    private int discountPercent = 10;

    @Override
    public int discount(Member member, int price) {
        if (member.getGrade() == Grade.VIP) {
            return price * discountPercent / 100;
        }

        return 0;
    }
}
```

이것이 객체지향 설계가 제공하는 중요한 장점이다. `DiscountPolicy`라는 역할의 계약은 그대로 유지하고, 할인 계산 전략만 새로군 구현으로 추가했다.

> [!more]- Java 수준에서 일어나는 일
> 
> ```java
> DiscountPolicy discountPolicy = new RateDiscountPolicy();
> ```
> - `new RateDiscountPolicy()`에 의해 `RateDiscountPolicy` 객체가 생성되고,
> 	- 그 객체를 가리키는 참조값이 `discountPolicy` 변수에 저장된다.
> - 변수의 선언 타입은 `DiscountPolicy`지만 실제 객체는 `RateDiscountPolicy`다.
> 
> <br>
> 
> ```java
> discountPolicy.discount(member, 10_000);
> ```
> - 실제 객체에 정의된 `RateDiscountPolicy.discount()`로 동적으로 연결
> - 이것이 **다형성**이다.

### 3. 문제는 구현체를 "추가"할 때가 아니라 "적용"할 때 드러난다

```java
public class OrderServiceImpl implements OrderService { 

	// private final DiscountPolicy discountPolicy = new FixDiscountPolicy(); 
	private final DiscountPolicy discountPolicy = new RateDiscountPolicy(); 
}
```
- 정률 할인을 적용하려면 생성 대상만 `RateDiscountPolicy`로 변경해야 한다.
- `OrderServiceImpl`이 `DiscountPolicy`라는 추상 역할뿐 아니라 현재 어떤 구현체가 선택되어야 하는지도 알고 있다.

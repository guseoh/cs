## 1. 객체지향 설계에서 중요한 것은 역할과 구현의 분리

객체지향 프로그램은 여러 객체가 각자의 책임을 수행하면서 서로 협력하여 기능을 완성하는 구조이다.

예를 들어 사용자가 주문을 생성한다고 생각 해보면 주문 서비스는 주문을 처리하는 역할을 담당하지만, 할인 금액을 계산하는 구체적인 방법까지 직접 구현할 필요는 없다.

이러한 설계에서 객체가 **어떤 기능을 제공해야 하는지**와 **그 기능을 내부에서 어떻게 구현하는지를 구분**한다.

```java
public interface DiscountPolicy {
    int discount(int price);
}

public class FixDiscountPolicy implements DiscountPolicy {

    @Override
    public int discount(int price) {
        return 1_000;
    }
}

public class RateDiscountPolicy implements DiscountPolicy {

    @Override
    public int discount(int price) {
        return price * 10 / 100;
    }
}
```
- `DiscountPolicy`는 할인 금액을 계산한다는 역할을 정의하고, `FixDiscountPolicy`와 `RateDiscountPolicy`는 서로 다른 할인 계산 방식을 구현한다.
- 주문 서비스는 구체적인 할인 계산 방식 대신 `DiscountPolicy`의 `discount()`메서드만 알면 된다.
- **인터페이스에 선언된 메서드를 호출하더라도 실제 실행되는 메서드는 연결된 구현 객체에 따라 달라진다.**
	- Java 다형성을 객체의 협력에 활용하는 가장 기본적인 방법이다.

> [!more]- 역할과 구현을 분리하면 아래와 같은 가능성이 생긴다.
> - 주문 서비스와 할인 계산 기능을 독립적으로 개발
> - 새로운 할인 정책을 구현하더라도 기존 역할의 계약을 유지
> - 실행 환경에 따라 서로 다른 할인 정책을 연결
> - 실제 구현체 대신 테스트용 구현체를 전달

## 2. 다형성만으로는 DIP와 OCP를 지킬 수 없는 이유

```java
public class OrderServiceImpl {

    private final DiscountPolicy discountPolicy =
            new FixDiscountPolicy();

    public int calculatePrice(int price) {
        return price - discountPolicy.discount(price);
    }
}
```
`OrderServiceImpl`은 `DiscountPolicy`인터페이스 타입으로 필드를 선언했고, 할인 금액도 인터페이스의 `discount()`메서드를 호출하여 계산한다.

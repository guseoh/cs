## 1. 인터페이스를 사용했는데도 코드 변경이 필요한 이유

주문 서비스가 할인 금액을 계산해야 한다고 생각하면 할인 정책에는 두 가지 구현이 존재한다.
- `FixDiscountPolicy`: 주문 금액과 관계없이 1,000원 할인
- `RateDiscountPolicy`: 주문 금액의 10% 할인

할인 정책이 바뀔 수 있으므로 `DiscountPolicy` 인터페이스를 정의하고 두 구현 클래스가 이를 구현하도록 설계한다.

```java
public interface DiscountPolicy {
    int discount(int price);
}

public class FixDiscountPolicy implements DiscountPolicy {
    @Override
    public int discount(int price) {
        return 1_000;
    }
}

public class RateDiscountPolicy implements DiscountPolicy {
    @Override
    public int discount(int price) {
        return price * 10 / 100;
    }
}
```

- 이 구조에서는 주문 서비스가 `DiscountPolicy`의 `discount()`메서드만 호출하면 된다.
- 실제로 어떤 할인 계산이 수행되는지는 연결된 **구현 객체**에 따라 달라진다.
- 이것이 **인터페이스를 이용한 역할과 구현의 분리**, 그리고 **다형성**이다.


### 1.1 첫 번째 코드 - 구현체를 직접 생성한다.
```java
public class OrderServiceImpl {

    private final DiscountPolicy discountPolicy =
            new FixDiscountPolicy();

    public int calculatePrice(int price) {
        return price - discountPolicy.discount(price);
    }
}
```

- 현재 `OrderServiceImpl`은 `DiscountPolicy`인터페이스를 사용하지만, 내부에서 `FixDiscountPolicy`객체를 직접 생성하고 있다.
- 요구사항이 바뀌어 정률 할인을 적용하려면 `new FixDiscountPolicy()`를 `new RateDiscountPolicy()`로 수정해야 한다.

## 1. AppConfig가 있는데 왜 Spring Container가 필요한가?

```java
AppConfig appConfig = new AppConfig();

MemberService memberService = appConfig.memberService();
OrderService orderService = appConfig.orderService();
```

이 코드를 보면 AppConfig가 `MemberServiceImpl`과 `OrderServiceImple`을 생성하고, 각각 필요한 객체를 연결한다.

이것만으로 DI는 충분히 구현할 수 있지만, **애플리케이션의 규모가 커지면 객체를 생성하고 연결하는 일 외에도 관리해야 할 사항이 늘어난다.**
- **객체의 생성과 재사용**: 매번 새 객체를 만들 것인지, 하나의 객체를 공유할 것인지를 결정해야 한다.
- **의존관계 관리**: 어떤 서비스가 어떤 저장소와 구현체를 사용하는지 연결해야 한다.
- **객체 조회**: 애플리케이션이 구성된 후 필요한 객체를 찾을 수 있어야 한다.
- **생명주기 관리**: 외부 연결이나 리소스를 사용하는 객체의 초기화와 종료를 관리해야 한다.

이러한 공통 책임을 지원하는 것이 **Sprnig Container**이다.


### Spring Container와 Spring Bean

|개념|역할|
|---|---|
|Spring Container|객체를 생성·구성·관리하고 의존관계를 연결하는 주체|
|Spring Bean|Spring Container가 관리하는 Java 객체|
|ApplicationContext|Spring Container의 대표적인 인터페이스|
|AppConfig|컨테이너에 어떤 객체를 어떻게 구성할지 알려주는 설정 정보|
Spring Bean이 특별한 종류의 Java 객체인 것은 아니다. 일반 Java 객체라도 Spring 컨테이너에 등록되어 관리된다면 Spring Bean이다.

반대로 JPA로 조회한 엔티티. 요청을 전달하는 DTO, 메서드 내부에서 생성한 임시 객체는 Spring 애플리케이션 안에서 사용하더라도 일반적으로 Spring Bean이 아니다.
- `@Service`, `@Repository`, `@Bean`으로 선언되어야 Spring Bean으로 등록된다.

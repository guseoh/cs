## 1. Database, DBMS, RDBMS

| 용어       | 의미                            | 예                                     |
| -------- | ----------------------------- | ------------------------------------- |
| Database | 조직화해서 저장한 데이터의 집합             | 쇼핑몰 회원·주문·상품 데이터                      |
| DBMS     | Database를 생성·조회·변경·관리하는 소프트웨어 | 여러 종류의 DB 관리 시스템                      |
| RDBMS    | **관계형 데이터 모델**을 사용하는 DBMS     | MySQL, PostgreSQL, Oracle, SQL Server |
```sql
CREATE DATABASE shop;
```

- `shop`은 데이터베이스이고, 이를 생성하고 SQL을 받아 처리하는 MySQL Server는 DBMS다.

## 2. 관계형 데이터베이스의 '관계형'은 무엇인가?

[](https://www.postgresql.org/docs/16/tutorial-concepts.html) 에서 RDBMS를 "relation에 저장된 데이터를 관리하는 시스템"
이라고 설명한다. 여기서 relation은 본질적으로 수학적 의미의 table이라고 설명한다.

```
MEMBER

id   email              nickname
---------------------------------
1    a@test.com         지훈
2    b@test.com         민수
3    c@test.com         영희
```
- `id`, `email`, `nickname`은 **Column(열**)
- 회원 한 명에 해당하는 한 줄은 **Row(행)**

## 3. 데이터를 하나의 거대한 테이블에 넣지 않는 이유

쇼핑물을 예로 보면 회원이 주문을 하면 모든 정보를 하나의 테이블에 넣을 수도 있을 것 같다. 그런데 회원이 주문을 100번 하면 이메일과 닉네임이 100번 반복된다.(중복) 그리고 닉네임이 변경되면 과거에 저장해둔 100개의 행을 어떻게 처리할지도 문제가 된다.

```
MEMBERS

id | email | nickname

ORDERS

id | member_id | order_date | total_amount
```
- 두 테이블을 완전히 독립적으로 두지 않고 `ORDERS.member_id`가 어느 회원의 주문인지를 표현

이렇게 데이터를 나누면 회원 자체의 정보와 주문 자체의 정보를 각각 자신의 테이블에서 관리하면서 필요할 때 다시 결합할 수 있다.

여기서 데이터를 어떻게 나누는지가 **데이터 모델링**과 정규화이고, 서로 다른 테이블을 다식 결합하는 것이 **JOIN**이며, 두 테이블의 관계가 깨지지 않도록 보호하는 것이 **Foreign Key**와 참조 무결성이다.

## 4. Key가 필요한 이유

```
MEMBERS
1 | kim@test.com
2 | lee@test.com

ORDERS
100 | 1
101 | 1
102 | 2
```
- `ORDERS`에서 두 번째 값인 `member_id`가 어떤 회원을 의미하는지 알아야 한다.  여기서 **Key(키)** 가 등장한다.
- `MEMBERS.id`처럼 각 Row를 식별할 수 있는 값을 **Primary Key(PK, 기본 키)**로 사용할 수 있다.
- `ORDERS.member_id`처럼 다른 테이블의 특정 Row를 가리키기 위해 사용하는 값을 **Foreign Key(FK, 외래 키)**라고 한다.

FK는 Java의 객체 참조처럼 메모리 주소를 저장하는 것이 아닌 값을 저장한다.

## 5. 관계는 데이터를 물리적으로 붙여놓는다는 뜻이 아니다

`Member 1 : N Order` 관계가 있다고 해서 데이터베이스 내부에서도  `Member 객체 - List<Order>` 같은 구조로 저장되는 것은 아니다.

관계형 데이터베이스에서는 Column 값의 대응으로 관계를 표현한다. 즉, 데이터는 각각의 테이블에 존재하고, 필요할 때 SQL이 그 관계를 이용한다.

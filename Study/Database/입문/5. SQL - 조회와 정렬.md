## 1. SELECT는 테이블을 출력하는 명렁어가 아니라 원하는 결과 집합을 만드는 명령이다

"판매 중인 상품 가운데 가격이 10,000원 이상인 상품을 비싼 순서대로 3개만 보여주세요."

이 요청을 처리하려면 데이터베이스에 저장된 모든 상품을 그대로 보여주는 것이 아니라, 판매 상태와 가격을 확인해 필요한 행을 고르고, 가격순으로 정렬한 뒤 세 개만 선택해야 한다.

이처럼 **조건에 맞는 데이터를 골라 새로운 조회 결과를 만드는 역할**을 하는 SQL이 `SELECT`이다.

| id  | name    | price | stock | status   | category |
| --- | ------- | ----: | ----: | -------- | -------- |
| 1   | 텀블러     | 15000 |     5 | SALE     | 생활       |
| 2   | 머그컵     |  9000 |    12 | SALE     | 생활       |
| 3   | 키보드     | 45000 |     3 | SALE     | 전자       |
| 4   | 마우스     | 25000 |     0 | SOLD_OUT | 전자       |
| 5   | 노트북 거치대 | 30000 |     7 | SALE     | NULL     |
| 6   | USB 허브  | 15000 |    10 | SALE     | 전자       |

```sql
SELECT id, name, price
FROM products
WHERE status = 'SALE'
  AND price >= 10000
ORDER BY price DESC, id ASC
LIMIT 3;
```
- `FROM products`는 어떤 테이블의 데이터를 대상으로 할지 지정
- `WHERE`는 판매 중이면서 가격이 10,000원 이상인 행을 선택
- `SELECT id, name, price`는 결과에 포함할 컬럼을 정한다
- `ORDER BY`가 순서를 결정
- `LIMIT`이 반환할 행의 개수를 제한

SELECT의 결과는 **원본 테이블 자체가 아니다.** `SELECT`는 다른 데이터를 변경하지 않고, 현재 요청에 필요한 행과 컬럼만 골라 **결과 집합(Result Set)** 을 반환한다.

결과 집합은 테이블처럼 행과 열로 표현되지만, 실제 저장된 테이블과 동일한 객체는 아니다. SQL 실행 과정에서 만들어지는 논리적인 결과이며, 클라이언트는 이를 받아 화면에 표시하거나 애플리케이션에서 사용할 수 있다.

### ❓ MySQL은 실제로 어떤 방법으로 데이터를 찾아올까?

MySQL이 반드시 모든 상품을 하나씩 읽으면서 조건을 검사한다고 생각하면 정확하지 않다. 데이터가 적다면 괜찮지만, 상품이 수백만 건이라면 다른 접근 방법이 필요하다.

여기서 **스토리지 엔진(Storage Engine)** 과 **InnoDB**라는 개념이 등장한다.

MySQL은 크게 두 가지로 나눈다.
- SQL을 해석하고 실행 방법을 결정하는 서버 영역
- 실제 데이터를 저장하고 읽는 스토리지 엔진 영역

스토리지 엔진은 데이터를 디스크와 메모리에서 어떻게 관리할지 담당하는 구성요소이고, **InnoDB는 MySQL에서 기본으로 사용하는 스토리지 엔진**이다.

InnoDB는 단순히 데이터를 보관하는 역할뿐 아니라 인덱스, 트랜잭션, 행 단위 잠금, 장애 복구 등에도 관여한다.

## 2. WHERE는 어떤 행의 결과에 포함할지 결정한다

앞의 구문에서 중요한 조건은 `WHERE status = 'SALE' AND price >= 10000`이다. 여기서 `WHERE`는 테이블에 있는 행 가운데 주어진 조건이 참인 행만 결과에 포함하도록 지정한다.

조건을 표현하기 위해 `=` `<>` ,<, >, ≤, ≥ 같은 비교 연산자를 사용한다. 그리고 조건이 여러 개라면 `AND`, `OR`, `NOT`을 이용해 결합할 수 있다.

AND가 OR보다 우선해서 평가되는 연산자이다.

```sql
WHERE status = 'SALE'
  AND price >= 30000
  OR stock = 0
```
- 작성자는 판매 중이면서 비싸거나 품절된 상품을 찾으려 했을 수도 있지만, 실제 조건은 `(status = 'SALE' AND price >= 30000) OR stock = 0` 으로 해석된다.
- 따라서 판매 중이 아니더라도 재고가 0인 상품은 결과에 포함될 수 있다.

```sql
WHERE status = 'SALE'
  AND (price >= 30000 OR stock = 0)
```
- 정말로 판매 중인 상품에 한정해서 가격 또는 재고 조건을 적용하려면 괄호를 사용해야 한다.

실무에서 검색 조건이 복잡해지면 조건식의 의미가 모호해지기 쉽다.. 특히 여러 검색 필터를 조합하는 API를 만든다면 괄호 하나의 차이가 의도하지 않은 데이터를 조회하는 오류로 이어질 수 있다.

### 여러 값, 범위, 문자열을 검색하는 방법

| SQL 조건                          | 의미                   |
| ------------------------------- | -------------------- |
| `price >= 10000`                | 가격이 10,000 이상        |
| `category IN ('생활', '전자')`      | 두 분류 중 하나            |
| `price BETWEEN 10000 AND 30000` | 양쪽 경계를 포함한 범위        |
| `name LIKE 'USB%'`              | USB로 시작하는 문자열        |
| `name LIKE '%컵%'`               | 컵을 포함하는 문자열          |
| `name LIKE 'USB_'`              | USB 다음에 한 글자가 있는 문자열 |
`IN`은 여러 값 중 하나와 일치하는지 검사한다. 예를 들어 `category IN ('생활', '전자')`는 분류가 생활이거나 전자인 상품을 찾는다.

`BETWEEN`은 양 끝 값을 모두 포함하기 때문에 `price BETWEEN 10000 AND 30000`은 가격이 정확히 10,000이거나 30,000이어도 참이 된다.
- 특히 날짜 검색에서 중요하다.
- `DATETIME` 컬럼에서 특정 날짜 전체를 조회할 때 종료 시각을 `2026-10-11 00:00:00`으로 지정하고 `BETWEEN`을 사용하면 다음 날 자정의 데이터까지 포함된다.
- 따라서 시각 범위를 조회할 때는 시작 시각을 포함하고 종료 시각은 제외하는 형태인 `created_at >= '2026-10-10' AND created_at < '2026-10-11'`이 더 명확한 경우가 많다.

`LIKE`는 특정 문자열 형태와 일치하는지 검사하는 연산자이다. 
- `%`는 0개 이상의 문자
- `_`는 정확히 한 문자

## 3. NULL을 이해해야 WHERE 결과를 정확하게 예측할 수 있다

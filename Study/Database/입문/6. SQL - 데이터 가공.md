## 1. 산술 연산 - 저장된 값으로 새로운 정보를 계산한다

| id  | name    | price | stock | category |
| --- | ------- | ----- | ----- | -------- |
| 1   | 텀블러     | 15000 | 5     | 생활       |
| 2   | 머그컵     | 9000  | 12    | 생활       |
| 3   | 키보드     | 45000 | 3     | 전자       |
| 4   | 마우스     | 25000 | 0     | 전자       |
| 5   | 노트북 거치대 | 30000 | 7     | `NULL`   |
| 6   | USB 허브  | 15000 | 10    | 전자       |
- 상품마다 가격과 재고 수량은 저장되어 있지만, 현재 보유한 상품의 재고 금액은 별도로 저장하지 않았다.
- 예를 들어 텀블러는 가격이 15,000원이고 재고가 5개이므로 `15000 x 5 = 75000`원이라는 값을 계산할 수 있다.

```sql
SELECT
    id,
    name,
    price,
    stock,
    price * stock AS stock_value
FROM products
WHERE id IN (1, 2, 5);
```
- 각 상품의 가격과 재고 수량을 곱해서 `stock_value`라는 결과 컬럼을 만든다.

여기서 `price * stock`을 **표현식(Expression)** 이라고 한다. 컬럼이나 상수에 연산자를 적용해 새로운 값을 만들어내는 구문이다.

`AS stock_value`는 표현식의 결과에 붙이는 별칭(Alias)이다. 이 별칭을 붙이지 않아도 계산은 되지만, 조회 결과를 받는 개발자에게 해당 값이 어떤 의미인지 명확하게 알려줄 수 있다.

**계산된 `stock_value`는 조회 결과에만 존재하는 값이지, 실제 `products` 테이블에 새로운 컬럼이 생긴 것이 아니다.**

#### 숫자를 계산할 때 알아두면 좋은 함수

| 함수 또는 연산자 | 의미 | 사용 예와 결과 |
|---|---|---|
| `+`, `-`, `*` | 덧셈·뺄셈·곱셈 | `100 * 3` → `300` |
| `/` | 나눗셈 | `5 / 2` → `2.5000` |
| `DIV` | 정수 나눗셈 | `5 DIV 2` → `2` |
| `MOD(a, b)` | 나머지 | `MOD(5, 2)` → `1` |
| `ROUND(n, d)` | 지정 자릿수로 반올림 | `ROUND(12.345, 2)` → `12.35` |
| `TRUNCATE(n, d)` | 지정 자릿수 아래를 버림 | `TRUNCATE(12.345, 2)` → `12.34` |
| `CEIL(n)` | 크거나 같은 가장 가까운 정수 | `CEIL(12.1)` → `13` |
| `FLOOR(n)` | 작거나 같은 가장 가까운 정수 | `FLOOR(12.9)` → `12` |
| `ABS(n)` | 절댓값 | `ABS(-5)` → `5` |

#### 실무에서는 반올림 방식과 숫자 타입을 함께 생각해야 한다

```sql
SELECT
    name,
    price,
    ROUND(price * 0.9, 0) AS discounted_price
FROM products;
```
- 모든 상품 가격에 10% 할인율을 적용한 예상 가격을 조회
- `price * 0.9`로 할인 가격을 계산하고, `ROUND(…, 0)`으로 소수점 이하를 반올림한다.

예를 들어 `ROUND(2.5)`와 `ROUND(25E-1)`은 표현식의 숫자 유형에 따라 서로 다른 결과를 낼 수 있다. `25E-1`은 과학적 표기법으로 작성된 근삿값 숫자이기 때문이다.

상품 가격이나 정산 금액을 계산할 때는 **금액 타입, 할인율의 표현 방식, 반올림 시점과 규칙을 함께 결정**해야 한다. 특히 여러 항목에 각각 반올림을 적용한 후 합산한 금액과, 먼저 합산한 뒤 반올림한 금액은 달라질 수 있다.

즉, **계산 결과의 정확성도 데이터 타입과 비즈니스 규칙의 영향을 받는다는 사실**을 알아야 한다.

## 2. 문자열 함수 - 데이터를 저장하는 형태와 보여주는 형태는 다를 수 있다

테이블에는 `name`과 `category`가 서로 다른 컬럼에 저장되어 있지만, 관리자 화면에서는 `텀블러 (생활)` 또는 `키보드 (전자)`처럼 출력하고 싶은 상황이다.

물론 Java 코드에서 문자열을 합칠수 있다. 하지만 조회 결과 자체를 원하는 형태로 반환하고 싶다면 MySQL의 `CONCAT()`을 이용할 수 있다.

```sql
SELECT
    name,
    category,
    CONCAT(name, ' (', category, ')') AS display_name
FROM products
WHERE id IN (1, 3, 5);
```
- `CONCAT()`은 전달된 문자열들을 왼쪽부터 순서대로 연결한다. 
- 따라서 ID가 1인 텀블러는 `텀블러 (생활)`, ID가 3인 키보드는 `키보드 (전자)`라는 결과가 만들어진다.

그런데 `category`가 `NULL`인 경우에는 `CONCAT()` 의 결과도 `NULL`이 된다. MySQL의 `CONCAT()`은 **인자 중 하나라도 `NULL`이면 전체 결과가 `NULL`** 이기 때문이다.

| name    | category | display_name |
| ------- | -------- | ------------ |
| 텀블러     | 생활       | 텀블러 (생활)     |
| 키보드     | 전자       | 키보드 (전자)     |
| 노트북 거치대 | `NULL`   | `NULL`       |

`CONCAT_WS()`는 구분자를 지정해서 문자열을 연결하는 함수다. 예를 들어 `CONCAT_WS(' / ', name, category)`는 `텀블러 / 생활`처럼 만든다.


#### 문자열을 가공하는 대표적인 함수

| 함수                    | 의미              | 활용        |
| --------------------- | --------------- | --------- |
| `CONCAT()`            | 문자열 연결          | 이름과 분류 조합 |
| `CONCAT_WS()`         | 구분자를 이용한 문자열 연결 | 주소·태그 표시  |
| `UPPER()` / `LOWER()` | 대문자·소문자로 변환     | 검색·표시값 정리 |
| `SUBSTRING()`         | 문자열의 일부 추출      | 문자열 일부 표시 |
| `TRIM()`              | 앞뒤 공백 제거        | 입력값 정리    |
| `REPLACE()`           | 특정 문자열 치환       | 문자 교체     |
| `CHAR_LENGTH()`       | 문자 수 확인         | 문자열 길이 검사 |
| `LENGTH()`            | 바이트 수 확인        | 저장 크기 확인  |
`SUBSTRING('DATABASE', 1, 4)`의 결과는 `DATA`이다. MySQL에서는 문자열 위치를 0이 아닌 1부터 세기 때문이다. Java의 `substring()`과 시작 인덱스 기준이 다르다.

`TRIM(' MySQL ')`은 앞뒤 공백을 제거하고, `REPLACE('hello world', 'world', 'SQL')`은 `hello SQL`을 반환한다.


##### LENGTH와 CHAR_LENGTH는 왜 다른가?

MySQL에서 `LENGTH()`는 문자열의 바이트 수를 반환하고, `CHAR_LENGTH()`는 문자 수를 반환한다.

```sql
SELECT
    CHAR_LENGTH('가나다') AS char_count,
    LENGTH('가나다') AS byte_count;
```
- char_count: 3
- byte_count: 9

`가나다`는 세 글자이지만 UTF-8에서 각 글자가 3바이트이므로 총 9바이트를 차지하기 때문이다.

이전에 배운 `VARCHAR(100)`의 의미와도 연결된다. 
- MySQL의 `VARCHAR(100)`은 일반적으로 100바이트가 아니라 최대 100문자를 의미한다.
- 실제 필요한 저장 공간은 문자 집합과 저장된 문자열의 내용에 따라 달라질 수 있다.


## 3. NULL 함수 - 값이 없을 때 무엇을 보여주거나 계산할 것인가?

`NULL + 100`은 100이 아니라 `NULL`이다. 값을 알 수 없으므로 계산 결과도 알 수 없다는 의미이다. `CONCAT('상품: ', NULL)` 역시 `NULL`을 반환한다.

실제 서비스에서는 `NULL`을 그대로 반환하기보다 다른 값으로 대체해야 하는 상황이 많다.

```sql
SELECT
    id,
    name,
    IFNULL(category, '미분류') AS display_category
FROM products
WHERE id = 5;
```
- 노트북 거치대의 `category`가 `NULL`일 때 관리자 화면에 ‘미분류’라는 문구를 표시하고 싶다면 `IFNULL()`을 사용할 수 있다.

`IFNULL(category, '미분류')`는 category가 `NULL`이 아니라면 원래 값을 반환하고, `NULL`이면 '미분류'를 반환한다.

#### COALESCE는 여러 후보 중 사용할 값을 결정한다

`IFNULL()`은 두 인자 중 하나가 `NULL`인지 판단한다. 그런데 사용할 수 있는 후보가 여러 개라면 어떻게 해야 할까?

상품에 짧은 설명(`short_description`)과 긴 설명(`description`)이 모두 있다고 가정해보자. 짧은 설명이 있으면 이를 우선 사용하고, 없으면 긴 설명을 사용하며, 둘 다 없다면 '설명 없음'을 반환하고 싶은 상황이다.

이럴 때 `COALESCE(short_description, description, '설명 없음')`을 사용하면 된다.

![[Pasted image 20261012173301.png|300]]
`COALESCE()`는 왼쪽부터 인자를 확인해서 처음으로 `NULL`이 아닌 값을 반환한다. 모든 값이 `NULL`이라면 결과 역시 `NULL`이다. `COALESCE`는 `NULL`의 의미를 없애는 함수가 아니라 조회 목적에 맞게 대체값을 선택하는 함수이다. 값이 없는 상태와 실제로 0인 상태를 구분해야 하는지 먼저 판단해야 한다.

`NULLIF(a, b)`는 두 표현식이 같으면 `NULL`을, 다르면 첫 번째 값을 반환한다. 예를 들어 분모가 0인 계산을 피하기 위해 `NULLIF(denominator, 0)`을 사용하는 방식이 있다. 이 경우 0인 분모가 `NULL`로 바뀌므로 나눗셈 결과가 `NULL`이 될 수 있다.

## 4. 날짜·시간 함수와 형 변환 - 데이터의 표현과 의미를 구분한다

| 함수                   | 역할             | 활용           |
| -------------------- | -------------- | ------------ |
| `NOW()`              | 현재 날짜와 시간      | 현재 시각 확인     |
| `CURRENT_DATE()`     | 현재 날짜          | 오늘 날짜 기준 조회  |
| `DATE_ADD()`         | 날짜에 기간 더하기     | 만료일 계산       |
| `DATE_SUB()`         | 날짜에서 기간 빼기     | 이전 기간 계산     |
| `DATEDIFF()`         | 두 날짜의 일수 차이    | 날짜 간격 확인     |
| `DATE_FORMAT()`      | 날짜를 문자열로 변환    | 날짜 표시 형식 변경  |
| `YEAR()` / `MONTH()` | 연도·월 추출        | 날짜 구성요소 확인   |
| `STR_TO_DATE()`      | 문자열을 날짜 값으로 해석 | 외부 날짜 문자열 변환 |

```sql
SELECT
    DATE_ADD('2026-10-10', INTERVAL 7 DAY) AS expires_on,
    DATEDIFF('2026-10-12', '2026-10-10') AS days_diff,
    DATE_FORMAT('2026-10-12', '%Y년 %m월 %d일') AS display_date;
```
- 2026년 10월 10일에 7일을 더한 날짜
- 두 날짜 사이의 일수 차이
- 날짜를 문자열로 표현


#### 날짜를 표현하는 문자열과 실제 날짜 값은 다르다

`DATE_FORMAT(created_at, '%Y-%m-%d')`는 보기 좋은 날짜 문자열을 만들어주지만, 반환된 결과가 여전히 `DATETIME` 타입인 것은 아니다.

예를 들어 API가 정확한 생성 시각을 제공해야 한다면, DB에서 미리 `2026년 10월 12일` 이라는 표시용 문자열을 만들어 반환하는 것보다 실제 날짜·시간 값으로 제공하고 화면에서 형식을 결정하는 편이 유연할 수 있다.

`NOW()`와 `CURRENT_DATE()`의 결과는 MySQL 세션의 시간대 설정 영향을 받는다. MySQL 서버, 애플리케이션, 사용자가 서로 다른 시간대를 사용하는 서비스라면 단순히 `NOW()`를 사용했다는 사실만으로 모든 환경에서 동일한 시각 표현을 얻는다고 생각하면 안 된다.
- 운영 서버가 UTC를 사용하고 사용자는 한국 시간으로 서비스를 이용한다면, "오늘"이라는 조건이 어느 시간대를 기준으로 하는지부터 정해야 한다.

#### 날짜 함수가 검색 성능에도 영향을 줄 수 있다

```sql
SELECT *
FROM orders
WHERE DATE(created_at) = '2026-10-12';

SELECT *
FROM orders
WHERE created_at >= '2026-10-12'
  AND created_at < '2026-10-13';
```
- 둘 다 2026년 10월 12일에 생성된 주문을 조회하려는 SQL

첫 번째는 `created_at`에 `DATE()` 함수를 적용하여 날짜 부분을 추출한 뒤 비교한다. 반면 두 번째는 컬럼 자체를 일정 범위와 비교한다.

만약 `created_at`에 일반적인 B-Tree 인덱스가 존재한다면 두 번째 형태가 인덱스의 정렬 구조를 활용해 날짜 범위를 탐색하기 더 자연스럽다.

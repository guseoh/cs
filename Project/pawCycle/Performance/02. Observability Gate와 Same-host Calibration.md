# Observability Gate와 Same-host Calibration

일반 개념은 [[../../../Study/Performance/03. Observability와 계층별 병목 분리|Observability와 계층별 병목 분리]]와 [[../../../Study/Performance/08. Observer Effect와 Same-host Calibration|Observer Effect와 Same-host Calibration]]에서 다룬다.

이 문서는 PawCycle OCI Production에서 실제로 수행한 Gate와 측정 결과만 기록한다.

## 목표

## 시작 상태

Production:

~~~text
production_assessment=READY
release_coordination=stable
docker_query=ok
backend=healthy
api_products_http=200
metrics_proxy_http=200
~~~

Observability:

~~~text
status=NORMAL
production_assessment=READY
prometheus_target=up
~~~

Initial ON runtime source는 historical approved SHA였지만 관련 configuration checksum drift는 없었다.

최종 Restored ON은 exact latest approved SHA source로 다시 올려 provenance를 정렬했다.

## 실행 순서

~~~text
1. Initial ON 60초
2. Prometheus/Grafana OFF
3. metrics-proxy OFF
4. Application identity 확인
5. OFF 60초
6. latest-SHA metrics-proxy 복구
7. latest-SHA Prometheus/Grafana 복구
8. READY / NORMAL / target up 확인
9. runtime provenance 확인
10. Restored ON 60초
~~~

각 window:

- GET /api/products
- 30 samples
- 2초 간격
- vmstat 1 60
- free -b
- df -P /
- docker stats --no-stream
- restart/OOM 확인

## Provenance

복구 후 metrics-proxy, Prometheus, Grafana Compose working directory가 승인 SHA exact source 하위 경로인지 확인했다.

~~~text
latest_sha_runtime_provenance=PASS
~~~

Application Backend/Frontend/Nginx container identity도 OFF/ON 전후 동일했다.

## 판정

~~~text
same-host Observability = KEEP
separate Observability Compute = DEFER
same-host overhead calibration = PASS
runtime 측면 Performance Measurement Ready = PASS
~~~

근거:

- HTTP 90/90 성공
- OFF 대비 Restored ON p50 +0.426ms
- p95 +1.167ms
- CPU user+system 약 +0.73%p
- I/O wait 증가 없음
- OOM/restart 없음
- Application identity 불변
- latest SHA provenance 정렬

Memory 비용은 실제로 존재하지만 이번 calibration에서 baseline을 사용할 수 없을 정도의 latency/error/CPU 왜곡은 확인되지 않았다.

## Calibration 해석 경계

이 실험은 capacity test가 아니다.

30 samples × 3구간의 짧은 calibration이므로 p99/max는 outlier 영향을 크게 받는다. 따라서 이번 판정은 다음 증거를 함께 사용했다.

~~~text
HTTP error 0
p50/p95 방향
CPU headroom
iowait
swap in/out
OOM/restart
Application identity
Observability runtime stability
~~~

이 결과로 “OCI 최대 처리량”이나 “Production capacity”를 주장하지 않는다.

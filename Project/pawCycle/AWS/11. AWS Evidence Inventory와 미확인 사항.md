## 확정하지 않은 내용

근거가 충돌하거나 부족한 항목은 다음처럼 남긴다.

- 초기 `t3.small`에서 RDS 검토 시점 `t3.medium`으로 변경된 정확한 날짜와 원인은 확인하지 못했다.
- RDS cutover의 exact timestamp, downtime과 final consistency import 전체를 한 문서에서 증명하는 실행 보고서는 찾지 못했다. Issue #158도 Open이다.
- 다만 2026-08-22 Production capacity test의 RDS CloudWatch evidence로 그 시점의 active RDS 사용은 확인된다.
- RDS automated backup retention 7일 적용은 resource 생성 Issue에 기록됐지만 별도 PITR restore exercise evidence는 찾지 못했다.
- Multi-AZ, read replica, RDS Proxy와 Application multi-instance는 실제 도입하지 않았다.
- HTTPS 자동 갱신 schedule, certificate backup, backup automation/cross-region/장기 보존과 실제 Production DB restore는 당시 미검증이었다.
- PR #277과 PR #284 시점 이후 OCI Production을 전제로 한 운영 근거가 이어졌으므로 “현재 active Production 없음”도 “현재 전체가 Production Verified”도 이 AWS 문서에서 확정하지 않는다.
- AWS resource ID, IP, endpoint, credential, raw row, backup ID와 account 정보는 조사 중 보였더라도 이 저장소에 옮기지 않았다.

## 사실과 재평가를 읽는 방법

각 문서에서 날짜와 GitHub link가 붙은 내용은 역사적 사실이다. “현재 다시 한다면”이나 provider 비교는 그 사실을 바탕으로 한 현재 관점의 재평가다. AWS 공식 문서는 서비스 일반 동작을 설명하지만 PawCycle에서 실제 실행했음을 증명하지 않는다. 반대로 Issue와 PR의 계획은 저장소 준비 또는 승인 범위를 설명할 뿐, 실행 보고나 운영 metric이 없으면 Production Verified로 올리지 않는다.

## 3. 패키지 기본 구조 — 도메인 중심

```text
src/main/java/guseoh/devpedia/
├── DevpediaApplication.java
├── member/              # 회원, 공개 프로필
├── auth/                # 세션 인증 및 보안 구성
├── reference/           # Role, TechStack 기준정보
├── recruitment/         # 모집글, 모집 역할, 마감
├── application/         # 지원·철회·승인·거절
├── comment/             # 댓글/답글
├── bookmark/            # 북마크
└── global/              # 공통 설정, API 오류, 시간
```

도메인 안에서는 필요할 때 `controller/`, `service/`, `repository/`, `domain/`, `dto/request/`, `dto/response/`로 분리한다. 공통 설정만 `global/`에 둔다. 빈 폴더는 선제적으로 생성하지 않는다.

## 4. 환경별 설정

### `application.yml`

```yaml
spring:
  application:
    name: devpedia
  profiles:
    default: local
  jpa:
    open-in-view: false
    hibernate:
      ddl-auto: validate
    properties:
      hibernate:
        jdbc:
          time_zone: UTC
  sql:
    init:
      mode: never
server:
  servlet:
    session:
      timeout: 30m
      tracking-modes: cookie
      cookie:
        http-only: true
        same-site: lax
```

### `application-local.yml`

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/devpedia?connectionTimeZone=UTC
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  jpa:
    show-sql: false
logging:
  level:
    org.hibernate.SQL: DEBUG
```

### `application-prod.yml`

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
server:
  servlet:
    session:
      cookie:
        secure: true
        http-only: true
        same-site: lax
```

**주의:** 로컬 개발에서 HTTP를 사용하면 `Secure` 세션 쿠키를 강제하지 않는다. 운영은 HTTPS가 필수다. MySQL 사용자/비밀번호를 YAML이나 Git에 하드코딩하지 않는다. Spring Boot가 일반 `.env` 파일을 자동으로 읽는다고 가정하지 않는다.

## 5. DB 최초 구성

03 문서의 CREATE DATABASE 두 문장을 실행한다. devpedia를 선택하고 CREATE TABLE 블록과 기준 데이터 INSERT를 순서대로 실행한다. devpedia_test에도 동일한 테이블·기준 데이터를 적용한다. 애플리케이션 계정에는 해당 DB의 SELECT/INSERT/UPDATE/DELETE만 부여하고 스키마 생성은 별도 개발용 관리 연결에서 수행한다.

IntelliJ 실행 구성에 DB_USERNAME, DB_PASSWORD를 설정하고 local 프로필로 기동한다. Spring Boot는 일반 .env 파일을 자동 로딩하지 않는다. 테스트는 application-test.yml에서 devpedia_test만 연결하며 개발 DB를 사용하지 않는다. ddl-auto=validate는 스키마를 생성하지 않는다.

## 6. 공통 기준

| 주제 | 규칙 |
|---|---|
| 운영 날짜 | `Asia/Seoul` 기준 `LocalDate`, 주입 가능한 `Clock` 사용 |
| 저장 시각 | `DATETIME(6)` + Java `LocalDateTime`에 UTC 값을 저장; 변환 로직 일관화 |
| PK | 단독 엔티티 `BIGINT AUTO_INCREMENT` / Java `Long` |
| 엔티티 관계 | `@ManyToOne(fetch = LAZY)` 명시, 공개 DTO에 엔티티 직접 반환 금지 |
| 생성/수정 시각 | 필요한 엔티티에 `createdAt`, `updatedAt`; JPA Auditing 활성화 |
| 생성자/수정자 | 공통 `createdBy` 감사 필드 추가하지 않음; 작성자/지원자 관계로 표현 |
| 프로필 | 별도 `public_profiles` 테이블이 아닌 `members`의 공개 필드 + 연결 관계 |
| 연관관계 직렬화 | 요청/응답 DTO를 통해 필드 선택; OSIV 비활성화 |
| SQL 관찰 | Hibernate SQL 로그 + MySQL 실제 결과/실행 계획으로 검증 |

## 8. Gradle 의존성과 실행

```groovy
plugins {
    id 'java'
    id 'org.springframework.boot' version '4.1.1'
    id 'io.spring.dependency-management' version '1.1.7'
}
group = 'guseoh'
version = '0.0.1-SNAPSHOT'
java { toolchain { languageVersion = JavaLanguageVersion.of(21) } }
repositories { mavenCentral() }
dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    implementation 'org.springframework.boot:spring-boot-starter-data-jpa'
    implementation 'org.springframework.boot:spring-boot-starter-validation'
    implementation 'org.springframework.boot:spring-boot-starter-security'
    runtimeOnly 'com.mysql:mysql-connector-j'
    compileOnly 'org.projectlombok:lombok'
    annotationProcessor 'org.projectlombok:lombok'
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
    testImplementation 'org.springframework.boot:spring-boot-starter-data-jpa-test'
    testImplementation 'org.springframework.boot:spring-boot-starter-security-test'
    testRuntimeOnly 'org.junit.platform:junit-platform-launcher'
}
tasks.named('test') { useJUnitPlatform() }
```

Gradle Wrapper 9.x를 저장소에 포함한다. JDK와 Gradle JVM을 모두 21로 설정한다. Windows PowerShell에서 프로젝트 루트 기준 실행한다.

```powershell
$env:DB_USERNAME="devpedia_app"
$env:DB_PASSWORD="실제 로컬 비밀번호"
.\gradlew.bat --version
.\gradlew.bat test
.\gradlew.bat bootRun --args="--spring.profiles.active=local"
```

테스트의 datasource URL은 `jdbc:mysql://localhost:3306/devpedia_test?connectionTimeZone=UTC`다. 테스트 전용 DB_USERNAME/DB_PASSWORD를 테스트 실행 구성에 설정한다. 서버 포트는 8080이다. API 확인은 `/api/v1/auth/csrf`부터 시작한다.

## 9. 시간·감사 필드·직렬화

Clock 빈은 Clock.systemUTC()로 만들고 업무 날짜가 필요한 입력 검증에서 Asia/Seoul로 변환한다. createdAt/updatedAt은 UTC LocalDateTime으로 기록한다. JPA Auditing의 DateTimeProvider도 같은 Clock을 사용한다. 댓글은 생성 시 createdAt, 내용 수정 시 editedAt을 직접 기록한다. 지원서는 submittedAt/decidedAt을 명령 시점에 기록한다.

Jackson 응답 시간은 `2026-10-20T07:00:00Z` 형태다. LocalDateTime에 무조건 Z 문자를 덧붙이지 않고 UTC OffsetDateTime으로 변환한다. DTO의 enum은 대문자다. JSON에 정의되지 않은 필드는 400으로 거절하도록 역직렬화 설정을 적용한다. 설정 속성은 사용하는 Boot/Jackson 버전의 실제 동작을 API 테스트로 확인한다.

## 10. 로컬 프런트 연결

React 개발 서버는 `/api` 요청을 `http://localhost:8080`으로 프록시한다. 브라우저는 프런트 주소에 상대경로로 요청한다. API 서버를 브라우저에서 다른 origin으로 직접 호출하는 CORS 구성은 이 개발 흐름에 필요하지 않다. 운영도 UI와 API를 같은 origin으로 노출한다.

## 재현 가능한 테스트 실행

사용한 JDK 배포판/패치, MySQL 서버 버전, Gradle Wrapper 정확한 버전은 최초 기동 시 기록한다. 확인하지 않은 버전을 실행 검증 완료로 표시하지 않는다. 테스트 클래스에 @ActiveProfiles("test")를 지정한다.

```yaml
# src/test/resources/application-test.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/devpedia_test?connectionTimeZone=UTC
    username: ${TEST_DB_USERNAME}
    password: ${TEST_DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate
```

MySQL 통합 테스트의 연결 대상은 devpedia_test인지 시작 시 확인한다. 기본 local 프로필로 통합 테스트가 실행되지 않도록 한다.

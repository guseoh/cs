# DevPedia V1 — 도메인 순서와 Slice 완료 조건

도메인 순서: 기반 → 회원/인증 → 기준정보 → 프로필 → 모집 → 지원 → 선발/종료 → 공개 제거 → 댓글 → 북마크 → 통합.

Slice는 한 사용자 행동의 입력·업무 처리·DB 저장·응답·테스트까지 이어지는 작업 단위다. 각 Slice에 필요한 Entity → Repository → Service → Controller/DTO와 최소 화면 연결을 함께 진행한다. 모든 엔티티를 먼저 완성하지 않는다. S06의 지원 이력 제한은 S07에서 실제 지원 데이터로 추가 검증한다. S08의 역할 충족 처리와 S09의 전체 마감은 함께 완료되어야 선발 기능을 완료로 본다.

| Slice | 도메인 | 작업 | API | 완료 증거 |
|---|---|---|---|---|
| S00 | 기반 | 환경·스키마·Clock·Problem·최소 Security/CSRF | A01 | test DB validate 기동, CSRF 발급과 오류 JSON |
| S01 | 회원/인증 | 가입·로그인·내 계정·로그아웃 | A02–A05 | 중복 409, 세션 교체, 로그아웃/재로그인 실패 검증 |
| S02 | 기준정보 | 역할·기술 초기 데이터와 조회 | R01–R02 | 고정 순서, 쓰기 API 없음 |
| S03 | 회원/프로필 | 공개/내 프로필 조회·전체 교체 | P01–P03 | 공개 개인정보 차단, 배열/참조 검증 |

| S12 | 북마크 | 추가·해제·목록 | K01–K03 | 중복 204, 제거 글 제외/count 일치 |
| S13 | 통합 | 브라우저 흐름·접근성·회귀 | 전체 | A 모집 → B 지원 → A 선발 → B 결과 확인 |

## 공통 완료 조건

정상 요청, 입력 오류, 미인증/타인 접근, DB 반영과 롤백을 기능에 맞게 검증한다. 업무 규칙 단위 테스트, API 계약 테스트, MySQL 통합 테스트를 구분한다. 동시성 테스트는 09에 명시한 관련 Slice에서 수행한다. 테스트마다 독립 데이터를 준비하고 실제 실행 결과를 기록한다. 날짜는 고정 Clock을 사용한다.

## V1과 V2

V1은 모집부터 지원 결과 확인까지 완료한다. 날짜·무결성·삭제 후 이력은 V1이다. V2 후보는 승인 후 연락/합류, 알림, 계정 복구·소셜 로그인, 모집 재개·충원이다. 팀 운영·추천·관리자 기능은 실제 필요를 확인한 뒤 별도 범위를 정한다.

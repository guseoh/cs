## 1. 공통 타입

| 타입 | JSON | 규칙 |
|---|---|---|
| `id` | number | Java Long, 양수 |
| `date` | `YYYY-MM-DD` | 업무 날짜, 서울 시간 기준 |
| `dateTime` | ISO 8601 `Z` | DB UTC LocalDateTime을 응답에서 UTC 오프셋 시각으로 직렬화 |
| enum | 대문자 문자열 | 명시된 값 외 400 |
| URL | string/null | `http`/`https`, 2048자 이내 |
| nullable | `null` | 지정 필드에 한하여 허용 |
| `Page<T>` | object | 아래 공통 페이지 |

### `Page<T>`

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0,
  "sort": "CREATED_DESC"
}
```

결과를 `{success,data}`로 재포장하지 않는다. 생성/조회 응답은 직접 리소스 JSON으로 반환한다.

## 2. 인증·회원

### `SignupRequest` (`POST /auth/signup`)

| 필드 | 조건 |
|---|---|
| `email` | 필수, 이메일 형식, 1..254자, 소문자 정규화 |
| `password` | 필수, 8..72자, BCrypt 입력 제한을 고려해 UTF-8 72바이트 이하 검사 |
| `nickname` | 필수, trim 후 2..30자 |

```json
{"email":"dev@example.com","password":"sample-password-123","nickname":"backendDev"}
```

### `MyAccountResponse`

```json
{"memberId":1,"email":"dev@example.com","nickname":"backendDev"}
```

### `CsrfResponse`

```json
{"headerName":"X-CSRF-TOKEN","token":"csrf-token-issued-for-current-session"}
```

CSRF 토큰 예시는 실제 토큰 값이 아니다. 브라우저는 `GET /auth/csrf`로 받은 토큰을 이후 변경 요청의 `X-CSRF-TOKEN` 헤더에 설정한다. 로그인/로그아웃 후 재조회한다.

### `PublicProfileResponse`

```json
{
  "memberId":1,
  "nickname":"backendDev",
  "bio":"Spring과 MySQL을 공부합니다.",
  "githubUrl":"https://github.com/example",
  "portfolioUrl":null,
  "interestRoles":[{"id":1,"name":"백엔드"}],
  "techStacks":[{"id":1,"name":"Java"}]
}
```

### `ProfileReplaceRequest` (`PUT /me/profile`)

`nickname` 필수 2..30자, `bio` nullable 최대 500자, 두 URL nullable 최대 2048자, `interestRoleIds` 배열 0..20개, `techStackIds` 배열 0..50개 (각각 중복 ID 불가). **전체 교체**이므로 생략한 nullable 필드는 NULL, 생략한 ID 배열은 오류(필수 배열).

```json
{
  "nickname":"backendDev",
  "bio":"Java/Spring",
  "githubUrl":"https://github.com/example",
  "portfolioUrl":null,
  "interestRoleIds":[1],
  "techStackIds":[1,2]
}
```

`MyProfileResponse`는 `PublicProfileResponse` 필드에 `email`을 추가한 형태다. 다른 회원 공개 응답에는 `email`을 절대 추가하지 않는다.

`ReferenceListResponse = {"items":[{"id":1,"name":"백엔드"}]}`.

## 4. 모집글

### `RecruitmentPostCreateRequest`

| 필드 | 필수·검증 |
|---|---|
| `type` | 필수 `PROJECT / STUDY` |
| `title` | 필수, trim 후 1..100자 |
| `content` | 필수, trim 후 1..10000자, HTML 태그 미지원(문자열로 취급·출력 escaping) |
| `startDate` | 필수 LocalDate, 오늘 이후 |
| `applicationDeadlineDate` | nullable, 오늘 이상·시작일 이전 |
| `workMode` | 필수 `ONLINE / OFFLINE / HYBRID` |
| `region` | nullable, 1..100자 |
| `expectedDuration` | nullable, 1..50자 |
| `slots` | 필수 1..20개, `roleId` 중복 불가 |
| `techStackIds` | 필수 배열(빈 배열 허용), 0..50개, 중복 불가 |

각 slot 입력: `{"roleId":1,"capacity":2}`. roleId와 capacity는 필수 정수다. capacity 누락·null·잘못된 타입은 400, 정수이지만 1..20 범위 밖이면 INVALID_POST_SLOTS(422)다.

```json
{
  "type":"PROJECT",
  "title":"백엔드 팀원 모집",
  "content":"Spring Boot 프로젝트를 함께 만듭니다.",
  "startDate":"2026-12-01",
  "applicationDeadlineDate":"2026-11-25",
  "workMode":"ONLINE",
  "region":null,
  "expectedDuration":"3개월",
  "slots":[{"roleId":1,"capacity":2},{"roleId":2,"capacity":1}],
  "techStackIds":[1,2]
}
```

### `RecruitmentPostPatchRequest`

전달된 필드만 수정. 허용 필드: `title`, `content`, `workMode`, `region`, `expectedDuration`, `startDate`, `applicationDeadlineDate`, `slots`, `techStackIds`. `type`은 생성 이후 변경할 수 없다. `startDate`, `applicationDeadlineDate`, `slots`는 **해당 글에 지원 이력이 없을 때만** 수정한다. `region`, `expectedDuration`, `applicationDeadlineDate`에 `null`을 보내면 값을 제거한다. `slots`는 제출 시 항상 **전체 목록 교체**이다. `{}`와 허용되지 않은 필드는 400/422 계약에 따라 거절한다(알 수 없는 JSON 필드는 400, 빈 변경은 422).

```json
{"title":"Java 백엔드 팀원 모집","techStackIds":[1,2,3]}
```

### `RecruitmentPostSummary`

```json
{
  "id":10,
  "type":"PROJECT",
  "title":"백엔드 팀원 모집",
  "status":"OPEN",
  "closeReason":null,"acceptingApplications":true,
  "startDate":"2026-12-01",
  "applicationDeadlineDate":"2026-11-25",
  "workMode":"ONLINE",
  "author":{"memberId":1,"nickname":"backendDev"},
  "roles":[{"id":1,"name":"백엔드"}],
  "techStacks":[{"id":1,"name":"Java"}],
  "createdAt":"2026-10-20T05:00:00Z"
}
```

### `RecruitmentPostDetail`

Summary의 모든 필드에 `content`, `region`, `expectedDuration`, `slots`, `bookmarkedByMe`, `updatedAt` 추가. 비회원 `bookmarkedByMe=null`, 로그인 회원 true/false.

```json
{
  "id":10,"type":"PROJECT","title":"백엔드 팀원 모집","status":"OPEN","closeReason":null,"acceptingApplications":true,
  "startDate":"2026-12-01","applicationDeadlineDate":"2026-11-25","workMode":"ONLINE",
  "author":{"memberId":1,"nickname":"backendDev"},
  "roles":[{"id":1,"name":"백엔드"}],"techStacks":[{"id":1,"name":"Java"}],
  "createdAt":"2026-10-20T05:00:00Z",
  "content":"Spring Boot 프로젝트를 함께 만듭니다.","region":null,"expectedDuration":"3개월",
  "slots":[{"slotId":30,"role":{"id":1,"name":"백엔드"},"capacity":2,"approvedCount":0,"status":"OPEN"}],
  "bookmarkedByMe":false,"updatedAt":"2026-10-20T05:00:00Z"
}
```

## 5. 지원·선발

### `ApplicationCreateRequest`

`motivation` 필수 1..3000자. `githubUrl`, `portfolioUrl` nullable URL. **서버는 요청에 없는 값을 회원 프로필에서 암묵적으로 채우지 않는다.** UI가 기본값을 보여주고 최종 제출값을 보낸다.

```json
{"motivation":"JPA와 테스트에 기여하겠습니다.","githubUrl":"https://github.com/example","portfolioUrl":null}
```

### `MyApplicationSummary`

```json
{
  "applicationId":80,"postId":10,"postTitle":"백엔드 팀원 모집",
  "postStatus":"OPEN","slotId":30,"role":{"id":1,"name":"백엔드"},
  "status":"UNDER_REVIEW","submittedAt":"2026-10-20T06:00:00Z","decidedAt":null,
  "autoCloseReason":null
}
```

### `MyApplicationDetail`

Summary 필드 전부 + `motivation`, `githubUrlSnapshot`, `portfolioUrlSnapshot`. 자기 지원은 본인이 제출한 정보 전체를 볼 수 있다.

### `OwnerApplicationSummary`

`applicationId`, `slotId`, `role`(ReferenceItem), `applicant`(공개 MemberSummary), `status`, `submittedAt`, `decidedAt`.

### `OwnerApplicationDetail`

Owner Summary + `motivation`, `githubUrlSnapshot`, `portfolioUrlSnapshot`, `autoCloseReason`, `decidedByMemberId`. 다른 모집글의 지원서에는 접근할 수 없다.

```json
{
  "applicationId":80,"slotId":30,"role":{"id":1,"name":"백엔드"},
  "applicant":{"memberId":2,"nickname":"javaUser"},
  "status":"APPROVED","submittedAt":"2026-10-20T06:00:00Z",
  "decidedAt":"2026-10-21T08:00:00Z","motivation":"JPA와 테스트에 기여하겠습니다.",
  "githubUrlSnapshot":"https://github.com/example","portfolioUrlSnapshot":null,
  "autoCloseReason":null,"decidedByMemberId":1
}
```

`ApplicationStatus`는 `UNDER_REVIEW | APPROVED | REJECTED | WITHDRAWN | AUTO_CLOSED`. 자동 종료 원인은 `ROLE_FILLED | POST_CLOSED | POST_REMOVED`.

## 6. 댓글

### `CommentCreateRequest`

`content` 1..1000자 필수, `parentCommentId` nullable (null이면 루트). `postId`와 부모의 글 ID는 일치해야 한다.

```json
{"content":"참여 조건이 있나요?","parentCommentId":null}
```

### `CommentUpdateRequest`

```json
{"content":"주 2회 참여 가능한가요?"}
```

### `CommentResponse`

```json
{
  "commentId":55,"postId":10,"parentCommentId":null,
  "author":{"memberId":2,"nickname":"javaUser"},
  "content":"참여 조건이 있나요?","isContentRemoved":false,"parentPreview":null,
  "createdAt":"2026-10-20T07:00:00Z","editedAt":null
}
```

부모가 tombstone이면 `content=null`, `isContentRemoved=true`. 작성자 정보는 남기되 내용은 공개하지 않는다.

## 8. Validation 에러 필드 이름

DTO 필드 오류는 `errors` 배열에 `field`, `reason` 두 문자열로 반환한다. DB 중복·상태 충돌은 필드 오류 대신 단일 `code`로 반환한다. 정확한 Problem Details 예시는 [06_예외처리_규약.md](06_예외처리_규약.md)에 정의한다.

## 9. 필드 처리 규칙

| 입력 | 생략 | null | 빈 문자열·빈 배열 |
|---|---|---|---|
| 생성 필수 스칼라 | 400 | 400 | 문자열 공백만이면 400 |
| 생성 선택 문자열 | null 저장 | null 저장 | trim 후 빈 값은 null |
| 필수 ID 배열 | 400 | 400 | 빈 배열은 허용 범위에 따라 처리 |
| PATCH title/content/workMode/startDate | 유지 | 400 | 필드 규칙 적용 |
| PATCH region/expectedDuration/applicationDeadlineDate | 유지 | 제거 | 선택 문자열 빈 값은 null |
| PATCH slots | 유지 | 400 | 0개이면 INVALID_POST_SLOTS |
| PATCH techStackIds | 유지 | 400 | 빈 배열이면 전체 기술 해제 |

PATCH는 필드 존재 여부와 값을 구분한다. 단순 nullable DTO 필드만으로 생략과 명시적 null을 합치지 않는다. 필드별 presence를 추적하는 DTO 또는 허용 필드를 검사한 JSON 객체에서 typed DTO로 변환한다. `{}`는 EMPTY_PATCH(422)다. type·authorMemberId·status·approvedCount 같은 서버 관리 필드는 요청할 수 없다. 날짜 변경 시 변경된 값과 기존 값을 합친 일정 조합을 검사한다. 변경하지 않은 날짜를 생성 시의 오늘 기준으로 재검증하지 않는다.

문자열은 비밀번호를 제외하고 양끝 공백을 제거한 뒤 길이를 검사한다. 비밀번호는 8..72자와 UTF-8 72바이트 이하를 모두 만족해야 한다. URL은 절대 http/https URL이며 host가 있어야 하고 userinfo는 허용하지 않는다. 서버가 URL을 방문하거나 다운로드하지 않는다. 링크는 프런트에서 외부 링크로 렌더링한다. content는 HTML로 실행하지 않는 텍스트다.

ID 배열의 원소 null·음수·문자열은 400, 중복 ID·개수 범위 초과는 INVALID_REFERENCE_SELECTION(422)이다. slots의 빈 목록·개수 초과·역할 중복·정원 범위 위반은 INVALID_POST_SLOTS(422)이다. roleId 자체의 누락·음수는 필드 오류 400, 존재하지 않는 기준 ID는 REFERENCE_NOT_FOUND(422)다.

## 10. 응답 타입 사전

아래에 nullable로 표시한 필드는 값이 없을 때 JSON null을 반환한다. 배열은 null 대신 []다. 응답에 선언하지 않은 내부 필드는 추가하지 않는다.

| 타입 | 필드와 타입 |
|---|---|
| MemberSummary | memberId: Long, nickname: String |
| ReferenceItem | id: Long, name: String |
| ReferenceListResponse | items: ReferenceItem[] |
| CsrfResponse | headerName: String, token: String |
| MyAccountResponse | memberId: Long, email: String, nickname: String |
| PublicProfileResponse | memberId: Long, nickname: String, bio: String?, githubUrl: String?, portfolioUrl: String?, interestRoles: ReferenceItem[], techStacks: ReferenceItem[] |
| MyProfileResponse | PublicProfileResponse의 모든 필드 + email: String |
| RecruitmentPostSummary | id: Long, type: PostType, title: String, status: PostStatus, closeReason: CloseReason?, acceptingApplications: boolean, startDate: Date, applicationDeadlineDate: Date?, workMode: WorkMode, author: MemberSummary, roles: ReferenceItem[], techStacks: ReferenceItem[], createdAt: DateTime |
| RecruitmentSlotResponse | slotId: Long, role: ReferenceItem, capacity: int, approvedCount: long, status: OPEN/FILLED |
| RecruitmentPostDetail | Summary + content: String, region: String?, expectedDuration: String?, slots: RecruitmentSlotResponse[], bookmarkedByMe: Boolean?, updatedAt: DateTime |
| MyApplicationSummary | applicationId: Long, postId: Long, postTitle: String, postStatus: PostStatus, slotId: Long, role: ReferenceItem, status: ApplicationStatus, submittedAt: DateTime, decidedAt: DateTime?, autoCloseReason: AutoCloseReason? |
| MyApplicationDetail | MyApplicationSummary + motivation: String, githubUrlSnapshot: String?, portfolioUrlSnapshot: String? |
| OwnerApplicationSummary | applicationId: Long, slotId: Long, role: ReferenceItem, applicant: MemberSummary, status: ApplicationStatus, submittedAt: DateTime, decidedAt: DateTime? |
| OwnerApplicationDetail | OwnerApplicationSummary + motivation: String, githubUrlSnapshot: String?, portfolioUrlSnapshot: String?, autoCloseReason: AutoCloseReason?, decidedByMemberId: Long? |
| CommentResponse | commentId: Long, postId: Long, parentCommentId: Long?, author: MemberSummary, content: String?, isContentRemoved: boolean, parentPreview: ParentPreview?, createdAt: DateTime, editedAt: DateTime? |
| BookmarkResponse | postId: Long, postStatus: PostStatus, postTitle: String, createdAt: DateTime |
| Page<T> | items: T[], page: int, size: int, totalElements: long, totalPages: int, sort: String |

프로필 관심 역할·기술과 글의 roles/techStacks는 기준정보 displayOrder,id 순으로 정렬한다. slots도 role의 동일 순서를 따른다. approvedCount는 APPROVED 지원 수다. FILLED는 approvedCount>=capacity이며, 슬롯이 OPEN이어도 글이 CLOSED면 지원 불가다.

PostType=PROJECT/STUDY, WorkMode=ONLINE/OFFLINE/HYBRID, PostStatus=OPEN/CLOSED/REMOVED다. 기본 마감 사유는 OWNER/ALL_ROLES_FILLED이고 미마감은 null이다. 페이지 sort는 모집·내 모집 CREATED_DESC 또는 모집 DEADLINE_ASC, 지원 SUBMITTED_DESC, 댓글 CREATED_ASC, 북마크 CREATED_DESC다. totalPages는 totalElements=0이면 0, 그 외 ceil(totalElements/size)다.

## 11. 목록과 명령 요청 예시

```http
GET /api/v1/recruitment-posts?type=PROJECT&roleId=1&techStackIds=1,2&page=0&size=20&sort=CREATED_DESC
GET /api/v1/me/applications?status=UNDER_REVIEW&page=0&size=20
GET /api/v1/recruitment-posts/10/applications?slotId=30&status=UNDER_REVIEW
GET /api/v1/recruitment-posts/10/comments?page=0&size=20
```

```json
{
  "items":[
    {"postId":10,"postStatus":"OPEN","postTitle":"백엔드 팀원 모집","createdAt":"2026-10-20T09:00:00Z"}
  ],
  "page":0,"size":20,"totalElements":1,"totalPages":1,"sort":"CREATED_DESC"
}
```

로그인 요청은 JSON이 아니다. 실제 클라이언트에서 URL 인코딩한다.

```http
POST /api/v1/auth/login
Content-Type: application/x-www-form-urlencoded
X-CSRF-TOKEN: 발급받은-토큰
Cookie: JSESSIONID=현재-세션

email=dev%40example.com&password=sample-password-123
```

승인·거절·철회·마감·북마크 요청에는 JSON 본문을 넣지 않는다. 토큰과 세션 쿠키를 보내며 204 응답을 JSON으로 파싱하지 않는다. 200/201 응답은 위 타입 사전과 앞 절의 리소스 예시를 사용한다. 예시 날짜는 고정 형식 예시이므로 테스트에서는 미래 날짜로 교체한다.

## 보완 응답 타입

ParentPreview = {commentId: Long, authorNickname: String, contentPreview: String?, isContentRemoved: boolean}. 루트 댓글은 parentPreview=null이다. 미리보기와 접수 가능 여부의 계산 기준은 09를 따른다. ID의 JSON number 계약은 V1에서 유지하며 JavaScript 안전 정수 범위를 넘는 ID 체계 도입 전 문자열 계약으로 전환한다.

# DevPedia V1 — 확정 정책과 경계 조건

이 문서는 보완본의 공통 정책이다. 업무 규칙은 02, HTTP는 04, 필드는 05, 오류는 06을 함께 적용한다. 기존 기능의 정합성은 V1에 포함하며 알림·팀 운영·모집 재개는 V2 후보로 둔다.

## 1. 날짜와 접수

서울 기준 오늘을 주입된 Clock으로 계산한다. 신규 지원은 저장 상태 OPEN, 오늘 < startDate, 마감일이 없거나 오늘 <= applicationDeadlineDate, 역할 여유가 있을 때만 가능하다. 마감일 당일까지 접수하며 시작일 당일부터 신규 접수하지 않는다.

날짜 경과 자체는 저장 상태를 바꾸지 않는다. 기존 지원의 승인·거절과 직접 마감은 OPEN이면 가능하다. 글의 OPEN은 관리상 미마감 상태이며 접수 가능 여부와 다르다. 응답의 acceptingApplications는 글 상태와 날짜만으로 계산하며, 슬롯 정원·본인 이력은 별도 검사한다. 실제 검토 중인 지원 건수는 모집자 화면에서 별도로 표시한다. 화면은 OPEN이면서 acceptingApplications=false일 때 ‘접수 종료’을 표시한다. 자동 마감 스케줄러는 V2 후보다.

## 2. 공개 제거

소유자만 OPEN/CLOSED → REMOVED로 변경한다. removedAt을 기록하고 기존 closedAt/closeReason은 보존한다. 모든 UNDER_REVIEW 지원은 같은 트랜잭션에서 AUTO_CLOSED/POST_REMOVED로 전환한다. 최종 결과는 유지한다. 자동 종료의 decidedByMemberId는 null이다.

공개 글 상세·댓글 목록·신규 댓글·북마크 추가는 404다. 내 모집 목록은 기본적으로 공개 중인 글을 표시하며, 공개 범위 필터로 공개 제거된 본인 글을 조회할 수 있다. 내 북마크 목록은 REMOVED를 제외한다. 각 목록의 전체 건수도 동일한 조회 조건을 적용한다. 북마크 연결 행은 보존하며 해제는 항상 가능하다. 내 지원 목록/상세는 제거된 글의 제목·상태와 제출 기록을 계속 반환한다. 모집자도 자기 글의 지원 이력을 계속 조회할 수 있지만 선발은 불가하다. 제거된 글의 댓글 수정은 404, 본인 댓글 삭제는 허용한다. 글 제거 재요청은 소유자 확인 후 204다.

## 3. 동시 실행과 원자성

지원 제출·철회·승인·거절, 모집글 수정·마감·제거는 동일한 모집글 행의 비관적 쓰기 잠금을 트랜잭션 초기에 획득한다. 잠금 순서는 글 → 슬롯/지원서이며 다중 글 작업은 V1에서 하지 않는다. 모든 관련 경로가 이 규칙을 지킨다. 잠금 전 읽은 상태/집계는 판단에 사용하지 않는다.

해당 명령 트랜잭션은 READ_COMMITTED로 실행하고 잠금 이후 최신 상태·지원 이력·승인 수를 다시 조회한다. 역할 충족에 따른 자동 종료와 전체 정원 충족 마감도 같은 트랜잭션에 포함한다. 단순 @Transactional 선언만으로 정원과 중복 지원이 보장된다고 가정하지 않는다. 잠금 실패는 409 CONCURRENT_MODIFICATION이며 서버/클라이언트가 쓰기를 자동 재전송하지 않는다.

댓글 작성·삭제도 글 → 부모 댓글 순서로 잠그고 부모 존재·삭제 표시·답글 수를 재검사한다. 마지막 답글을 지워도 이미 내용 제거된 루트는 유지한다. 북마크 추가는 글을 잠근 뒤 공개 여부와 기존 연결을 검사하고 저장한다. 중복 추가는 204이며 해제는 회원·글 조건 DELETE의 영향 행 수와 관계없이 204다.

## 4. 오류 우선순위

CSRF/인증 → 입력 바인딩 → 리소스 존재 → 소유권 → 명령별 상태 → 업무 조건 순서다. 지원 승인·거절은 글과 소유권 및 지원 소속을 확인한 후 지원 최종 상태를 먼저 검사한다. 최종 상태면 APPLICATION_STATE_CONFLICT, 검토 중이면서 글이 CLOSED면 POST_ALREADY_CLOSED, REMOVED면 POST_NOT_FOUND다. 같은 순서로 재요청 테스트를 작성한다.

지원 제출은 글/슬롯 → OPEN → 날짜 → 자기 글 → 동일 글 검토 중 → 승인 이력 → 동일 역할 거절 이력 → 정원 순서로 검사한다. 날짜 경과는 APPLICATION_PERIOD_ENDED(409)다. 철회는 본인 조건 조회 후 UNDER_REVIEW 여부를 검사한다.

## 5. 인증과 입력

로그인 폼은 email/password 각 하나만 받는다. 누락·중복·알 수 없는 필드는 INVALID_LOGIN_REQUEST(400), 자격 증명 불일치는 BAD_CREDENTIALS(401)다. 필터에서 폼 계약을 검사하고 공통 Problem 응답으로 작성한다. 가입과 같은 비밀번호 길이·UTF-8 바이트 제한을 로그인 입력에도 적용한다. 이미 로그인된 세션의 재로그인은 성공 시 계정을 교체하고 실패 시 기존 인증도 제거한다. 실패 이후 보호 GET은 401이어야 한다.

JSON 정수 필드는 정수 숫자만 허용한다. 문자열 숫자·소수·boolean을 정수로 강제 변환하지 않는다. JSON 타입 오류는 INVALID_JSON, 바인딩된 필드의 누락/null/범위 오류는 VALIDATION_FAILED 또는 명시된 업무 코드다. 세션 만료나 다른 탭의 로그아웃은 다음 요청의 401/CSRF_INVALID로 감지하고 상태를 다시 조회한다. 쓰기는 재전송하지 않는다.

## 6. 화면 접근성

폼은 label과 입력을 연결하고 오류를 aria-describedby로 연결한다. 키보드만으로 탐색·제출·모달 닫기가 가능해야 한다. 포커스를 눈에 보이게 표시한다. 모집/지원 상태는 색상과 함께 텍스트로 표시한다. 비활성 지원 버튼 주변에 마감·정원·로그인 등 사유를 표시한다. 로딩·빈 결과·오류 상태를 구분한다.

댓글은 V1에서 평탄한 시간순 목록을 유지한다. 답글 응답에는 parentPreview={commentId, authorNickname, contentPreview, isContentRemoved}를 제공한다. 부모 내용 미리보기는 최대 80자이며 제거된 내용은 null이다. 삭제된 부모는 ‘삭제된 댓글에 대한 답글’로 표시한다. 부모가 다른 페이지에 있어도 답글 맥락을 확인할 수 있어야 한다.

## 7. 검증 기준

동일 회원 동시 지원 2건 중 1건만 생성, 마지막 자리 동시 승인 중 1건만 승인, 승인/철회 경합 시 하나의 최종 상태, 마감/지원 경합 후 검토 중 지원 잔류 없음, 제거 후 이력 보존·공개 차단을 검증한다. 각각 독립 연결/트랜잭션과 동시 시작 장벽을 사용한다. 테스트 본체의 단일 트랜잭션으로 경합을 흉내 내지 않는다.

Clock 고정 테스트로 마감일 23:59:59와 다음날 00:00:00 서울 경계, 시작일 경계, 마감일 null을 검사한다. 테스트용 DB만 사용한다.

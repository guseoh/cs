# “우리가 직접 만들겠습니다” — 무신사의 POS 내재화 여정

> [!abstract] 한 줄 정리
> 외부 솔루션과 자체 개발의 선택은 기술 선호가 아니라 변경 속도, 비용, 데이터 통제권과 운영 책임의 균형 문제입니다.

> techblog.musinsa.com

## 핵심 내용

오프라인 매장 확대와 함께 기존 외부 POS 솔루션의 기능 추가 속도, 비용, 시스템 연동과 데이터 활용 한계가 커지자 자체 MPOS를 개발한 사례입니다. Electron 기반 시스템을 내재화해 외부 업체 일정 조율 없이 기능을 배포하고 유지보수와 로그·데이터 활용 권한을 내부에 확보했습니다.

POS를 직접 소유하면 기능 배포 속도와 데이터 활용도가 높아질 수 있지만, 그만큼 매장 운영 중 장애·오프라인 연결·단말 업데이트·결제 승인 흐름을 내부 팀이 책임져야 한다. 기존 외부 솔루션을 내재화할 때 **기술 종속성 제거**만 목표로 두면 오히려 운영 책임이 더 커지는 비용을 간과하기 쉽다.

| 기존 외부 POS 의존 | MPOS 내재화로 달라지는 책임 |
| --- | --- |
| 요구사항별 벤더 일정 조율 | 기능 우선순위·릴리스 자체 결정 |
| 제한된 로그·데이터 연동 | 매장 이벤트·장애 진단 직접 소유 |
| 패키지 단위 변경·배포 | Electron 앱·단말 버전 관리 |
| 외부 장애 대응 의존 | 모니터링·운영 대응 체계 구축 |

전자상거래와 오프라인 주문·재고의 식별자를 일치시키고 네트워크가 끊긴 매장의 처리 기준을 명확히 하는 것도 POS 내재화 이후에 다뤄야 할 대표적인 설계 질문이다. 이 마지막 항목은 원문의 결과가 아닌 일반적인 적용 검토 사항이다.

## 왜 읽을까

직접 개발이 무조건 우수하다고 말하지 않고 사업의 변경 속도와 통제권이 외부 의존 비용을 넘어선 시점에 내재화를 선택했다는 점이 중요합니다.

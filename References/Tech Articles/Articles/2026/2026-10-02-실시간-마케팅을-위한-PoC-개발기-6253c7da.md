# 실시간 마케팅을 위한 PoC 개발기

> [!abstract] 한 줄 정리
> 일 단위 배치 데이터를 실시간 파이프라인으로 바꾸려면 기술을 먼저 확정하기보다, 실제 마케팅 요구를 만족하는 지연 시간·정합성·운영 복잡도를 PoC로 검증해 아키텍처 선택의 근거를 만들어야 한다.

> 우아한형제들 기술블로그 · 2025-05-20

## 핵심 내용

- **문제:** 사용자 타깃 데이터를 일 단위로 갱신하던 구조로는 행동 직후 반응해야 하는 실시간 마케팅 요구를 만족하기 어려웠다.
- **접근:** 기존 시스템을 바로 교체하지 않고 실시간 데이터 갱신 파이프라인을 별도 PoC로 구성해 실제 요구와 기술 적합성을 검증했다.
- **구조:** 이벤트가 발생한 뒤 타깃 데이터가 갱신되는 흐름을 파이프라인으로 분리하고, 각 구간의 처리 책임과 데이터 전달 방식을 검토했다.
- **트레이드오프:** 실시간성은 배치보다 빠른 반응을 주지만 메시징·스트림 처리와 운영 지점이 늘어난다. 따라서 ‘실시간’ 자체보다 필요한 지연 수준과 운영 비용을 함께 봐야 한다.

## 왜 읽을까

Kafka나 스트림 처리 기술을 도입했다는 결과보다 PoC를 통해 아키텍처 가정을 먼저 검증하는 과정이 가치 있다. 새로운 분산 구조는 기능 요구를 해결하는 동시에 장애 지점과 운영 비용을 늘리므로, 본 구현 전에 어떤 것을 측정해야 하는지 생각하기 좋다.

**프로젝트에 적용 — FutMatch**

- [ ] 경기 모집·신청·알림 중 즉시성이 실제 필요한 이벤트와 지연을 허용할 수 있는 작업을 먼저 구분한다.
- [ ] 이벤트 기반 구조를 검토할 때 중복 이벤트, 순서 역전, Consumer 재처리 시나리오를 PoC에 포함한다.
- [ ] 단순 동기 호출과 메시징 구조의 복잡도·지연·복구 방식을 비교한 뒤 도입 여부를 결정한다.

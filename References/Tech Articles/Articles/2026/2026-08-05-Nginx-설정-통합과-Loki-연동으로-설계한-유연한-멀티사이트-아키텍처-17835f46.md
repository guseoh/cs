# Nginx 설정 통합과 Loki 연동으로 설계한 유연한 멀티사이트 아키텍처

> [!abstract] 한 줄 정리
> 서비스가 늘수록 반복되는 Nginx 설정을 중앙화하되 공통 장애 범위가 커지는 비용까지 함께 관리해야 합니다.

> techblog.lycorp.co.jp

## 핵심 내용

새 서비스를 열 때마다 별도 서버·로드밸런서 발급과 Nginx 수동 설정 때문에 최소 2주가 걸리던 구조를 개선합니다. 약 100개 도메인의 설정을 Ingress Nginx와 공통 멀티사이트 구조로 통합하고 인증서, GeoIP, 점검 페이지, Loki 로그 수집 같은 공통 기능을 중앙 관리합니다. 동시에 중앙화된 공통 Nginx 장애가 여러 서비스로 번질 위험도 고려하며 점진적으로 전환합니다.

웹 서버 구성을 공통화하면 신설 서비스마다 서버와 로드밸런서를 발급받아 수동 설정하던 비용이 줄지만, 공통 Nginx 계층의 잘못된 설정이 여러 서비스를 동시에 영향을 줄 수 있다. 원문은 기존 PMC, Ingress Nginx, 네이티브 Nginx를 비교하면서 **remote address·GeoIP·Loki 수집·설정 자유도**를 함께 판단했다. 따라서 Kubernetes로 옮긴다고 모든 요구를 Ingress 어노테이션만으로 충족할 수 있다고 가정하지 않았다.

| --- | --- | --- |
| 개별 Nginx | 서비스별 제어 독립 | 설정·인증서 중복 |
| Ingress Nginx | Kubernetes 배포 자동화 | 고급 기능 제약 |
| 공통 네이티브 Nginx | 템플릿·모듈 통제 | 공통 설정 변경의 영향 확대 |

실제 배포에서는 `nginx -t`에 해당하는 설정 검증과 프로세스 상태 확인, 롤링 반영·중단 조건을 함께 두어 설정 오류의 범위를 제한해야 한다.

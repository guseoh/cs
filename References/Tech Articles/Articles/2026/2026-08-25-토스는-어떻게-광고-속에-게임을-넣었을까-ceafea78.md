# 토스는 어떻게 광고 속에 게임을 넣었을까

> [!abstract] 한 줄 정리
> 외부 HTML 코드를 앱 안에서 실행해야 하는 문제를 표준 API, 상태 소유권, 실패 격리, 신뢰하지 않는 입력이라는 경계 설계로 풀어낸 사례입니다.

> Toss Tech · 2026-08-18

## 핵심 내용

토스 광고 지면은 플레이어블 광고를 지원하지 않았고, 기존 상용 광고 SDK를 붙이면 자체 광고 시스템과 통제 경계가 어긋났습니다. 업계 표준인 MRAID를 채택하되 실제 소재가 호출하는 API만 구현해 표면적과 유지 비용을 줄였습니다.

JavaScript와 네이티브 사이 메시지는 하나의 규약으로 통일하고, 실제 화면 상태의 소유권은 네이티브에 두었습니다. 표준 MRAID와 토스 전용 확장 API도 분리했습니다. 외부 소재 코드는 검사를 통과해도 신뢰하지 않고, SDK 전역 객체를 freeze해 덮어쓰기와 재정의를 막았습니다.

실제 렌더 완료는 폰트·이미지 디코드·paint·DOM 안정·requestAnimationFrame을 조합하고 2.3초 안전망 타이머까지 둬 감지 실패가 광고 노출 자체를 막지 않게 했습니다.

MRAID 표준을 채택했다고 해서 외부 광고 소재를 앱 내부의 신뢰할 수 있는 코드로 취급해서는 안 된다. JavaScript는 이벤트와 명령을 요청할 수 있어도 실제 화면 상태와 네이티브 권한은 앱 쪽에서 검증해야 한다. 업계 규약을 필요한 API까지만 구현한 것은 호환성 확보와 공격 표면 최소화를 함께 고려한 결정이다.

렌더 완료 신호를 단순한 페이지 load 이벤트에만 의존하지 않고 폰트·이미지·paint 상태를 결합하는 것도 실제 사용자에게 보이는 완료 시점을 구별하기 위해서다. 안전망 타이머는 감지가 실패했을 때 광고 노출이 영구 대기 상태에 빠지는 것을 방지한다.

## 왜 읽을까

표준을 어디까지 따르고 어디서 확장할지, 상태의 진짜 소유자가 누구인지, 외부 코드를 어느 정도 신뢰할지 같은 경계 설계가 선명합니다. 프런트엔드 글이지만 외부 API·Webhook·플러그인 연동에도 그대로 적용할 수 있습니다.

# 토스는 어떻게 광고 속에 게임을 넣었을까

> [!abstract] 한 줄 정리
> 외부 HTML 코드를 앱 안에서 실행해야 하는 문제를 표준 API, 상태 소유권, 실패 격리, 신뢰하지 않는 입력이라는 경계 설계로 풀어낸 사례입니다.

> Toss Tech · 2026-08-18

## 핵심 내용

- **문제:** 토스 광고 지면은 플레이어블 광고를 지원하지 않았고, 기존 상용 광고 SDK를 붙이면 자체 광고 시스템과 통제 경계가 어긋났습니다.
- **접근:** 업계 표준인 MRAID를 채택하되 실제 소재가 호출하는 API만 구현해 표면적과 유지 비용을 줄였습니다.
- **구조:** JavaScript와 네이티브 사이 메시지는 하나의 규약으로 통일하고, 실제 화면 상태의 소유권은 네이티브에 두었습니다. 표준 MRAID와 토스 전용 확장 API도 분리했습니다.
- **주의점:** 외부 소재 코드는 검사를 통과해도 신뢰하지 않고, SDK 전역 객체를 freeze해 덮어쓰기와 재정의를 막았습니다.
- **구조:** 실제 렌더 완료는 폰트·이미지 디코드·paint·DOM 안정·requestAnimationFrame을 조합하고 2.3초 안전망 타이머까지 둬 감지 실패가 광고 노출 자체를 막지 않게 했습니다.

## 왜 읽을까

표준을 어디까지 따르고 어디서 확장할지, 상태의 진짜 소유자가 누구인지, 외부 코드를 어느 정도 신뢰할지 같은 경계 설계가 선명합니다. 프런트엔드 글이지만 외부 API·Webhook·플러그인 연동에도 그대로 적용할 수 있습니다.

# 모두가 데이터를 다루는 AI 시대, 지난 1년간 데이터 팀은 어떻게 달라졌을까?

> [!abstract] 한 줄 정리
> 자연어로 데이터를 쉽게 조회하게 만드는 것보다 더 중요한 것은 AI가 신뢰할 수 있는 지표 정의·리니지·권한·최신성·검증 체계를 플랫폼의 기본 동작으로 만드는 것이다.

> 당근 기술 블로그 · 2026-04-22

## 핵심 내용

- **변화:** AI가 SQL 초안, 데이터 품질 영향 범위 파악, 파이프라인 장애 원인 탐색 등 구현 작업을 보조하면서 데이터 엔지니어의 무게중심이 구현에서 구조 설계·운영 판단·검증으로 이동하고 있다.
- **구조:** 당근은 BigQuery, Lineage, KarrotMetrics, Superset, Event, Experiment 등을 MCP 서버로 연결한 `data-mcp`를 운영해 LLM이 데이터 도구에 직접 접근할 수 있게 만들고 있다.
- **주의점:** 자연어 질의가 쉬워져도 지표 정의가 일관되지 않거나 최신성·권한·리니지가 관리되지 않으면 그럴듯하지만 틀린 답을 더 빠르게 만들 수 있다. 그래서 KarrotMetrics의 코드 기반 지표 정의와 컬럼 레벨 리니지가 AI의 근거가 된다.
- **접근:** MCP 계층에서 어떤 데이터 소스로 라우팅할지 결정하고, 사용자 권한 밖의 데이터는 AI가 추정하지 못하도록 차단한다. 지표 정의·오너·최신성 같은 도메인 정보도 함께 제공한다.
- **트레이드오프:** 데이터 민주화와 의사결정의 신뢰는 별개다. UI뿐 아니라 LLM 인터페이스도 제품 표면으로 설계하되, 수정 기능에는 검증·승인 레이어를 같이 두는 방향을 택했다.

## 왜 읽을까

AI를 데이터 조직의 생산성 도구로만 보는 대신 **데이터 거버넌스와 플랫폼 설계 문제**로 확장해 볼 수 있다. 특히 “답이 없는 것이 틀린 답보다 안전하다”는 기준은 AI가 사내 데이터에 접근할 때 좋은 안전 원칙이 된다.

**프로젝트에 적용 — DevPedia**

- [ ] AI가 사용하는 프로젝트 지표·통계를 코드 또는 명시적 정의에서만 가져오도록 근거 소스를 고정한다.
- [ ] 통계 응답에 정의, 계산 기준, 최신 시점 같은 메타데이터를 함께 제공할 수 있는지 검토한다.
- [ ] AI가 접근할 수 없는 정보는 추론으로 채우지 않고 명시적으로 실패하도록 권한 경계를 둔다.

# 현관문에도 얼굴이 있다: 배송 완료 사진 기반 On-device 오배송 탐지 시스템

> [!abstract] 한 줄 정리
> 희소하지만 비용이 큰 오배송 문제를 단순 이미지 분류가 아니라 장소 재인식 문제로 바꾸고, 임베딩 중심점 비교와 On-device 추론으로 실시간 판별 가능한 구조를 만든 사례입니다.

> 컬리 기술 블로그 · 2026-04-28

## 핵심 내용

오배송은 전체 건수에서 매우 드물기 때문에 이진 분류기를 만들면 높은 정확도를 얻더라도 실제 오배송을 잘 찾는지 판단하기 어렵다. 컬리는 주소지 사진에 흔들림·무관한 물체가 섞이는 문제를 먼저 정상/비정상 품질 모델로 제거하고, 정제된 배송 사진을 동일 장소의 재인식 문제로 바꾸었다.

![원문 사진 인코더와 Gallery·Query Embedding 간 거리 기반 오배송 판정 설명 그림](https://helloworld.kurly.com/_astro/extract_embedding_and_get_distaence.DOPFud6p_Z15YyKr.webp)

*그림 1. 원문 사진 인코더와 Gallery·Query Embedding 간 거리 기반 오배송 판정 설명 그림 — [출처: 원문 기술 블로그](https://helloworld.kurly.com/blog/image-based-misdelivery-detection)*

사진을 이미지 인코더에 통과시켜 특징 벡터로 만들고, 동일 주소의 사진 벡터끼리는 가까워지고 다른 주소와는 멀어지도록 학습한다. 모바일에서 과거 사진 10장을 모두 로딩해 비교하면 저장·연산이 크므로 주소마다 Gallery Embedding 중심점 하나를 보관하고 새 Query Embedding과 유클리디안 거리를 비교했다. 거리가 임계값보다 크면 새로운 장소일 가능성이 높다고 판단한다.

| 설계 요소 | 선택 | 필요한 검증 |
| --- | --- | --- |
| 이미지 품질 | 정상·비정상 사전 분류 | 흐림·무관한 사진 제거 |
| 장소 인식 | 사진 임베딩 거리 | 학습/평가 주소 누출 방지 |
| 모바일 저장 | 주소별 Gallery 중심 벡터 | 메모리·지연 감소 |
| 거리 임계값 | 18.0 | 오탐/미탐과 실제 클래스 비율 |
| 분할 | 주소 중복 없는 8:1:1 | Zero-shot 일반화 |

주소가 겹치지 않게 Train:Val:Test를 8:1:1로 나눠 학습에서 보지 못한 주소에 대한 Zero-shot 성능을 확인했다. 거리 임계값 18.0에서 Accuracy 99.95%, Precision·Recall 각각 99.97%라는 테스트 수치를 얻었다. 하지만 극히 낮은 실제 오배송 비율에서는 Precision의 기준 집단과 오탐 건수가 중요하며 실운영에서도 같은 수치가 난다는 보장은 없다.

## 왜 읽을까

AI 모델의 성능만 다루지 않고 데이터 품질, 학습 문제 정의, 모바일 저장·연산 제약, 신규 주소에 대한 일반화까지 하나의 서비스 설계로 연결합니다. 모델 선택보다 먼저 ‘무엇을 비교하면 실제 문제를 풀 수 있는가’를 재정의하는 과정이 특히 좋습니다.

또한 서버 추론이 아닌 On-device 구조를 선택하면서 중심점 표현으로 계산량과 저장 비용을 줄인 사례라, AI 기능도 결국 시스템 제약과 함께 설계해야 한다는 관점을 얻을 수 있습니다.

**프로젝트에 적용 — 공통**

- [ ] 향후 AI 기능을 붙일 때 모델부터 고르기보다 오탐·미탐 비용과 실제 서비스 실패 조건을 먼저 정의합니다.
- [ ] 서버와 클라이언트 중 어디에서 추론할지 결정할 때 지연 시간뿐 아니라 네트워크 의존성, 저장 공간, 배터리·연산 비용을 함께 비교합니다.
- [ ] 정확도 하나만 보지 않고 실제 클래스 불균형에 맞춰 Precision·Recall과 실패 사례를 따로 검증합니다.

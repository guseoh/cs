# 프롬프트를 쓰는 PM과 AI를 이해시키려는 개발자

> [!abstract] 한 줄 정리
> MCP 도구가 정상 동작해도 LLM이 파라미터를 잘못 해석하거나 도구 호출 순서를 생략할 수 있습니다. 실제 발화 기반 테스트와 도구 설명·응답 계약 개선을 함께 적용해야 합니다.

> 올리브영 테크블로그 · 2026-08-28

## 핵심 내용

- **문제:** ‘2000만원대’ 가격을 ‘2만원대’로 해석하거나, 브랜드·카테고리 조회 도구를 건너뛰고 최종 검색 도구만 호출하는 문제가 발생했습니다. - **접근:** PM은 한국어 가격 표현의 Few-shot 예시를, 개발자는 수식 기반 범위 규칙을 실험했습니다. 54개 테스트에서 초기 32/54(59%), 수식 48/54(89%), Few-shot 52/54(96%)였습니다. - **구조:** 도구 호출 순서를 description에 명시하고 이전 도구의 결과를 다음 도구 파라미터에 연결하는 규칙을 구체화했습니다. 카테고리 결과는 재해석을 유도하는 이름을 제거하고 ID 중심으로 단순화했습니다.

- **결과:** 브랜드·카테고리 조합별 테스트에서 도구 체이닝 완성률이 전체 평균 약 73%에서 약 93%로 개선됐습니다. 브랜드만 80→약 95%, 카테고리만 75→약 95%, 둘 다 65→약 90%였습니다. - **교훈:** 동일한 실패에도 호출 순서와 반환 데이터의 해석이라는 서로 다른 원인이 겹칠 수 있습니다. 툴 자체의 정상 동작과 에이전트의 올바른 사용은 별도로 검증해야 합니다.

도구를 올바르게 호출하는지 확인하지 않고 프롬프트만 고치면 실패 원인을 찾기 어렵다. 원문은 '2000만원대'를 숫자로 해석하는 문제와 브랜드·카테고리 조회를 생략한 채 최종 검색을 호출하는 문제를 분리해 실험했다. 가격 표현은 Few-shot과 수식 규칙을 비교했고, 도구 순서는 Description과 결과 데이터의 식별자 구조를 조정해 개선했다.

| 가격 해석 실험 | 54개 중 성공 |
| --- | ---: |
| 초기 | 32 |
| 수식 기반 | 48 |
| Few-shot 예시 | 52 |

도구 체이닝 평균 약 73%→93%는 도구 자체의 정확도와 구별해야 한다. API가 정상 응답해도 에이전트가 호출 순서를 어기거나 앞선 결과의 ID를 무시하면 전체 검색은 실패한다.

## 왜 읽을까

MCP 도입 시 API의 성공 여부만 테스트하는 것으로는 충분하지 않다는 것을 실제 측정으로 보여줍니다. 사람이 작성한 예시, 수학 규칙, 데이터 계약을 비교하는 실험 설계도 배울 만합니다.

**프로젝트에 적용 — 공통**

- [ ] Codex·에이전트가 도구를 호출하는 업무에서 정상·경계·모호한 입력의 회귀 테스트 세트를 만듭니다.
- [ ] 도구 설명과 반환 JSON의 필드가 다음 단계에 어떻게 전달되는지 계약을 명시합니다.
- [ ] 정확도뿐 아니라 도구 호출 순서, 잘못된 인자, 누락된 호출을 별도 지표로 측정합니다.

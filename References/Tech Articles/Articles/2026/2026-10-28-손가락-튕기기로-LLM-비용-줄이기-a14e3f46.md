# 손가락 튕기기로 LLM 비용 줄이기

> [!abstract] 한 줄 정리
> 고비용 LLM을 전부 대체하기보다 소형 모델이 높은 신뢰도로 처리할 수 있는 요청만 먼저 맡기고 나머지는 기존 LLM으로 보내면, 품질 기준을 유지하면서 비용과 지연을 줄일 수 있다.

> 토스 기술 블로그 · 김형찬/박민우/임민섭 · 2026-10-27

## 핵심 내용

- **문제:** 동일한 LLM API에 서로 다른 작업이 섞여 있어 어떤 작업을 소형 모델로 전환할지 찾기 어려웠다. System Prompt 앞부분의 역할·작업 정의를 해시한 Task Fingerprint로 로그를 분류했다. - **구조:** 매일 호출량·토큰·추정 비용을 집계해 후보를 선정하고, 레이블 추출과 학습·평가 데이터 분리를 검증한 뒤 Airflow로 학습·등록 과정을 자동화했다. 클라이언트는 소형 모델 Confidence가 임계치 이상이면 결과를 사용하고 아니면 LLM으로 fallback한다. - **수치:** 동일 상품 판별의 오프라인 검증 100,648건 중 34,963건(34.74%)을 채택했다. 기존 LLM 판단과 불일치 34건, 선택적 일치율 99.9028%로 목표 99.9%를 충족했다. 이는 정답 레이블에 대한 절대 정확도가 아니라 기존 LLM과의 일치율이다.

- **운영 결과:** 첫 배포 약 6일 동안 일별 요청의 33~37%를 소형 모델이 처리했고 입력 토큰 약 76억 개, 출력 토큰 약 4,520만 개를 줄였다. L4 GPU 1장 부하 테스트에서 1,203 RPS, p50 9.02ms, p99 15.23ms였으며 테스트 중 실패·드롭 요청은 없었다. - **트레이드오프:** 목표 일치율을 99%로 완화하면 Coverage 51.59%, 95%로 완화하면 72.35%까지 늘어난다. 품질 목표가 엄격할수록 기존 LLM에 넘기는 요청이 많아진다.

비용 최적화에서 소형 모델을 전면 교체 모델로 보기보다 **고신뢰 사례만 먼저 처리하는 선택적 분류기**로 두면 품질 저하 위험을 관리하기 쉽다. Task Fingerprint는 역할·작업 정의를 기준으로 동일한 호출을 분류해 소형 모델로 옮길 후보를 찾는다. 소형 모델의 Confidence가 충분히 높을 때만 결과를 채택하고 나머지는 기존 LLM으로 보내는 구조이므로 목표 일치율을 높일수록 절감할 수 있는 요청 비중은 낮아진다.

| 선택 일치율 목표 | 선택적 처리 비중 |
| --- | ---: |
| 99.9% | 34.74% |
| 99% | 51.59% |
| 95% | 72.35% |

34,963건 중 기존 LLM 결과와 불일치한 34건으로 계산된 **99.9028%**는 모델 간 일치율이지 외부 정답과 비교한 절대 정확도가 아니다. 오프라인에서의 Confidence 분포가 배포 뒤에도 유지되는지, 시간이 지나며 분포가 변하지 않는지를 모니터링해야 운영 품질을 판단할 수 있다.

## 왜 읽을까

모델 성능을 단일 정확도 점수로 비교하지 않고, **선택적 정확도와 Coverage의 관계**로 배포 기준을 정하는 방법을 배울 수 있다. Confidence 자체를 정답 확률로 오해하지 않고 오프라인 검증으로 Threshold를 정했다는 점이 중요하다.

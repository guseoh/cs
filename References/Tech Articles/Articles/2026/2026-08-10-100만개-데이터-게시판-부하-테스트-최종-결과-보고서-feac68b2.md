# \[100만개 데이터 게시판\] 부하 테스트 최종 결과 보고서

> [!abstract] 한 줄 정리
> 인덱스와 쿼리 튜닝은 데이터 분포가 현실적이지 않으면 오히려 잘못된 결론을 낼 수 있으므로 가설과 테스트 데이터를 함께 검증해야 합니다.

> velog.io

## 핵심 내용

Java 17, Spring Boot, MySQL 8.0, QueryDSL, k6 환경에서 100건부터 100만 건까지 늘리며 Full Table Scan → 단일 인덱스 → 데이터 분포 수정 → No-Offset → Full-text Search 순으로 개선합니다. 인덱스를 처음 넣었을 때 P95가 3.36초에서 9.47초로 오히려 악화됐는데 낮은 카디널리티 때문에 인덱스가 필터 역할을 하지 못한 것이 원인이었습니다. 이후 오류율을 71.34%에서 0%로 낮추고 No-Offset 전환으로 P95를 1.56초에서 12.91ms까지 개선합니다.

## 왜 읽을까

인덱스를 넣어서 빨라졌다는 성공담이 아니라 가설이 틀린 결과를 그대로 남기고 데이터 분포를 다시 설계하는 과정이 좋습니다.

# 장애를 스스로 복구하는 AI 에이전트

> [!abstract] 한 줄 정리
> 외부 웹 변경으로 반복되던 장애를 AI 에이전트로 복구하되, 상태·라우팅·검증·배포 권한은 코드와 사람이 통제하는 구조로 만든 실전 사례다. 핵심은 LLM을 더 믿는 것이 아니라, 틀려도 사고가 나지 않도록 작게 가두는 데 있다.

> 쏘카 테크 블로그 · 2026-07-22

## 핵심 내용

- **문제:** 2025년 할인권 적용 실패가 약 30만 건 발생했고 16.5만 건이 환불로 이어졌다. 장애 인지부터 코드 수정·배포까지 평균 4시간이 걸렸다.
- **구조:** LangGraph StateGraph로 `접근 → 로그인 → 차량 조회 → 할인 적용 → 검증 → 변경점 비교 → Draft PR` 흐름을 고정하고, LLM은 각 단계 내부의 판단만 맡겼다.
- **접근:** 자유 텍스트 대신 Zod Structured Output, Few-shot 기준, 단계별 컨텍스트 격리와 상한을 사용했다. 잘못된 행동은 도구 레벨에서 막고, 결과는 별도 검증으로 다시 확인했다.
- **결과:** 2주 PoC에서 실제 장애 로그 186건을 오프라인 평가한 뒤 약 50개 장비사로 확대했고, 확대 배포 후 두 달여 동안 7,267건을 실제 자동 복구했다.
- **트레이드오프:** 복구는 자동 실행하지만 코드 변경은 Draft PR까지만 허용한다. 복구 속도와 전체 시스템 변경 위험을 같은 자동화 수준으로 취급하지 않은 것이 핵심이다.

## 왜 읽을까

AI 에이전트의 데모가 아니라 운영 시스템에 넣을 때 필요한 경계가 구체적이다. `프롬프트로 하지 말라고 지시`하는 대신 권한·출력·실행 횟수·컨텍스트 범위를 코드로 제한하는 관점을 배울 수 있다.

특히 자동화 뒤에 기존 배치 코드의 결함이 더 많이 드러났다는 결론이 좋다. AI 도입이 기존 시스템 품질 문제를 덮는 수단이 아니라, 오히려 관측하고 수정하는 계기가 될 수 있음을 보여준다.

**프로젝트에 적용 — PawCycle**

- [ ] 향후 장애 자동화는 원인 분석과 조치 권한을 분리하고, 코드 변경은 PR까지만 자동화한다.
- [ ] k6·운영 장애 기록을 에이전트 평가용 고정 데이터셋으로 사용할 수 있는지 검토한다.
- [ ] LLM 출력은 자유 문장 대신 상태·분류·확신도 같은 구조화 결과로 받는 방식을 우선 검토한다.

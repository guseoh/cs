# AI가 팀 규칙을 지키도록 하는 방법

> [!abstract] 한 줄 정리
> AI에게 팀 규칙을 한 번에 많이 주는 것보다, 코드를 작성한 직후 관련 규칙만 다시 주입하는 피드백 루프가 더 효과적이다. 규칙 역시 로그와 PR 리뷰를 통해 지속적으로 개선해야 한다.

> Toss Tech · 2026-09-08

## 핵심 내용

- **문제:** `AGENTS.md` 같은 전역 지침은 긴 Coding Agent 세션에서 앞부분의 규칙이 점점 묻히고, 세세한 팀 규칙을 모두 넣으면 Context 자체가 비대해지는 문제가 있었다.
- **접근:** 파일 작성 직후 Hook이 코드 패턴과 파일명을 기준으로 관련 규칙을 최대 2개만 골라 에이전트에게 다시 주입하는 `Stylepack`을 만들었다. AI로 규칙 관련성을 판정하는 방식도 시험했지만 요청당 약 10초가 추가돼 정규식 기반 후보 선별로 바꿨다.
- **구조:** 파일 단위 Hook은 즉시 피드백을 담당하고, 작업 종료 직전에는 전체 `git diff`를 보며 최대 4개 규칙을 다시 확인한다. 각 저장소에 규칙을 복제하지 않고 중앙 저장소에서 세션 시작 때 최신 규칙을 가져온다.
- **결과:** 한 정규식 규칙은 21개 세션에서 발동했지만 실제 코드 변경은 0건이어서 오탐임을 확인했고 조건을 수정했다. N+1처럼 코드 모양만으로 판정하기 어려운 규칙은 발동형 규칙에서 상시 Context로 옮겼다.
- **개선:** 반복되는 PR 리뷰 코멘트를 새 규칙 후보로 수집해 사람의 리뷰 경험이 다시 Stylepack으로 들어가는 피드백 루프를 만들었다.

## 왜 읽을까

AI 코딩 규칙을 문서에 더 많이 적는 것이 정답이 아니라, **언제 어떤 규칙을 다시 보여줄 것인지**가 중요하다는 관점을 얻을 수 있다. 특히 규칙 시스템 자체의 오탐·미탐을 로그로 측정하고 개선한다는 점이 실무적이다.

**프로젝트에 적용 — DevPedia**

- [ ] Codex가 자주 놓치는 규칙을 전역 지침과 작업 직후 피드백 규칙으로 구분한다.
- [ ] 반복되는 PR 리뷰 지적을 모아 실제로 재발하는 항목만 프로젝트 규칙 후보로 승격한다.
- [ ] 규칙별 발동 횟수와 실제 수정 여부를 기록해 쓸모없는 규칙을 제거한다.

# 기기 없이 앱을 테스트하는 법, 멀티버스가 알려드립니다

> [!abstract] 한 줄 정리
> 테스트 품질을 높이려면 테스트 방법만 가르칠 것이 아니라 환경 준비와 도구 사용의 마찰을 줄여 누구나 반복 검증할 수 있게 만들어야 한다는 플랫폼 사례다.

> 카카오페이 기술 블로그 · 2025-10-23

## 핵심 내용

- **문제:** 여러 OS·기기 조합 검증에는 실기기 확보와 개발 환경 설정이 필요했고, 서버·FE·기획·디자인처럼 모바일 개발자가 아닌 직군에는 테스트 진입 장벽이 특히 높았다.
- **접근:** macOS 앱에서 필요한 개발 도구 설치, iOS/Android 가상 기기 생성·실행·삭제, 원하는 앱 버전 설치를 한 흐름으로 제공해 환경 구축 절차를 감췄다.
- **구조:** 특정 브랜치·태그 빌드 설치뿐 아니라 딥링크 실행, 화면 캡처·녹화, 사용자 행동 로그 실시간 확인까지 테스트에 반복되는 작업을 같은 도구 안에 묶었다.
- **결과:** FE 개발자는 보유하지 않은 플랫폼을 확인하고, 기획자는 서버 배포 뒤 여러 앱 버전을 검증하며, 디자이너는 여러 해상도를 동시에 비교하는 식으로 개발자 밖의 직군까지 같은 검증 환경을 사용할 수 있게 됐다.
- **트레이드오프:** 가상 기기가 모든 실기기 검증을 대체하는 것이 아니라 반복 확인의 접근 비용을 낮추는 공통 기반으로 사용하며, OS·네트워크·RUM 로그와 다른 사내 테스트 도구까지 연결하는 방향으로 확장하고 있다.

## 왜 읽을까

테스트 자동화의 가치가 테스트 코드 개수에만 있지 않다는 점이 좋다. 환경 준비가 느리고 복잡하면 사람은 검증을 덜 하게 되므로, 빠르고 재현 가능한 테스트 환경 자체가 품질 시스템의 일부라는 관점을 얻을 수 있다.

**프로젝트에 적용 — 공통**

- [ ] DevPedia·PawCycle·FutMatch에서 새 환경을 띄운 뒤 대표 기능을 검증하는 절차를 한 명령 또는 짧은 스크립트로 묶는다.
- [ ] 로컬과 CI에서 사용하는 DB·환경 변수·검증 명령 차이를 줄여 동일한 실패를 재현할 수 있게 한다.
- [ ] 반복 수동 검증이 생기면 문서에 절차를 추가하기 전에 자동화하거나 공통 명령으로 만들 수 있는지 먼저 본다.

# 기기 없이 앱을 테스트하는 법, 멀티버스가 알려드립니다

> [!abstract] 한 줄 정리
> 테스트 품질을 높이려면 테스트 방법만 가르칠 것이 아니라 환경 준비와 도구 사용의 마찰을 줄여 누구나 반복 검증할 수 있게 만들어야 한다는 플랫폼 사례다.

> 카카오페이 기술 블로그 · 2025-10-23

## 핵심 내용

여러 OS·해상도와 앱 빌드를 테스트하려면 기기 자체뿐 아니라 SDK·에뮬레이터·서명된 빌드·딥링크 환경 설정이 필요하다. 이 과정은 서버 개발자·디자이너·기획자처럼 모바일 전문 환경이 없는 팀원의 테스트 참여를 막는 장벽이 되기 쉽다.

카카오페이의 멀티버스는 macOS 도구에서 필요한 개발 툴 설치, iOS/Android 가상 기기 생성·실행·삭제, 특정 브랜치/태그 버전의 앱 설치를 하나로 묶었다. 반복적인 딥링크 실행과 화면 캡처·녹화·행동 로그 확인도 도구 안에 통합해 사용자가 에뮬레이터 명령을 일일이 외우지 않아도 검증할 수 있게 했다.

| 반복 작업 | 통합한 지원 | 남는 실기기 검증 |
| --- | --- | --- |
| 개발 환경 | SDK·시뮬레이터 설치 | 기기별 제조사 차이 |
| 테스트 기기 | OS·해상도별 가상 기기 | 센서·하드웨어 성능 |
| 앱 빌드 | 브랜치/태그 버전 설치 | 실제 배포 서명·업데이트 |
| 디버깅 | 딥링크·화면·행동 로그 | 실제 네트워크·푸시 환경 |

이로써 개발자 밖의 직군도 여러 앱 버전과 해상도를 비교하고 백엔드 배포 직후 기능을 확인할 수 있게 됐다. 다만 가상 기기는 실제 단말의 센서·앱 스토어·배터리·네트워크·OS 제조사별 변형까지 모두 재현하지 못하므로 실기기 회귀와 함께 사용해야 한다. 원문은 사용자 경험 개선을 설명하지만 정량적인 설정 시간 감소율은 제시하지 않는다.

## 왜 읽을까

테스트 자동화의 가치가 테스트 코드 개수에만 있지 않다는 점이 좋다. 환경 준비가 느리고 복잡하면 사람은 검증을 덜 하게 되므로, 빠르고 재현 가능한 테스트 환경 자체가 품질 시스템의 일부라는 관점을 얻을 수 있다.

**프로젝트에 적용 — 공통**

- [ ] DevPedia·PawCycle·FutMatch에서 새 환경을 띄운 뒤 대표 기능을 검증하는 절차를 한 명령 또는 짧은 스크립트로 묶는다.
- [ ] 로컬과 CI에서 사용하는 DB·환경 변수·검증 명령 차이를 줄여 동일한 실패를 재현할 수 있게 한다.
- [ ] 반복 수동 검증이 생기면 문서에 절차를 추가하기 전에 자동화하거나 공통 명령으로 만들 수 있는지 먼저 본다.

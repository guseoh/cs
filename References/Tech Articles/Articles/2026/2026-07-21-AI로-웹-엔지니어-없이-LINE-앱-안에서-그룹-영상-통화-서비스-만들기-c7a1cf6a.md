# AI로 웹 엔지니어 없이 LINE 앱 안에서 그룹 영상 통화 서비스 만들기

> [!abstract] 한 줄 정리
> AI가 낯선 기술의 구현 속도를 높일 수는 있지만, 성공 여부는 요구사항을 작은 시스템 경계로 나누고 검증 가능한 플랫폼을 선택하는 데 달려 있습니다.

> techblog.lycorp.co.jp

## 핵심 내용

PM과 Android 엔지니어가 별도의 웹 엔지니어 없이 LINE 앱 내부의 그룹 영상 통화 기능을 구현한 사례입니다. LIFF·LINE Official Account·LINE Planet SDK를 조합하고 React/Vite와 Firebase Cloud Functions를 사용해 웹 앱과 애플리케이션 서버에 집중했습니다.

WebRTC와 글로벌 네트워크 같은 어려운 영역은 LINE Planet이 추상화하고, AI는 익숙하지 않은 웹 영역의 구현을 보조했습니다. 모든 것을 직접 만드는 대신 책임을 나누는 선택이 핵심입니다.

PM과 Android 엔지니어가 별도 웹 개발자 없이 기능을 완성한 이유를 AI 코드 생성만으로 설명하면 중요한 설계 선택을 놓친다. 영상 통화의 WebRTC 연결·글로벌 미디어 전송은 LINE Planet SDK에 맡기고, LIFF·Official Account로 기존 LINE 앱의 사용자 진입을 연결했다. React/Vite와 Firebase Cloud Functions는 팀이 직접 구현할 범위를 작은 웹 화면과 기능 서버에 집중시키는 수단이었다.

```mermaid
flowchart LR
 A["LINE 앱 사용자"] --> B["LIFF 웹 화면"]
 B --> C["React/Vite 앱"]
 C --> D["Cloud Functions"]
 C --> E["LINE Planet SDK"]
 E --> F["그룹 영상 통화"]
```

*자체 재구성. SDK가 책임지는 실시간 미디어와 직접 구현한 웹·서버 계층을 구분했다.*

외부 SDK가 복잡성을 줄여도 인증·권한·SDK 오류·비용과 서비스 종속성은 남는다. AI 보조 구현의 생산성은 이러한 책임 경계가 명확할수록 높아진다.

## 왜 읽을까

AI 코딩 성공 사례를 '프롬프트를 잘 썼다'로 설명하지 않고, 플랫폼 선택·구조 분해·검증 가능한 범위 설정과 연결해 보여줍니다.

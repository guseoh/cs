# 카카오페이 성능 테스트 존을 소개합니다.

> [!abstract] 한 줄 정리
> 성능 테스트는 k6 스크립트보다 재현 가능한 격리 환경과 지표 수집, 테스트 이력 관리가 갖춰져야 반복 가능한 엔지니어링이 됩니다.

> tech.kakaopay.com

## 핵심 내용

성능 테스트 준비에 길게는 한 달이 걸리던 문제를 줄이기 위해 Kubernetes 기반 격리 환경과 Testcraft, Prometheus/Grafana, k6를 연결한 성능 테스트 존을 구축합니다. 테스트 실행 이력과 모니터링을 표준화해 팀마다 환경을 다시 만드는 비용을 줄였습니다.

다만 개발 GCP와 운영 IDC, 단일/다중 클러스터 차이처럼 테스트 환경과 production의 차이는 명시적으로 한계로 남깁니다.

성능 테스트 환경을 만들 때마다 별도 서버를 신청하고 모니터링을 연결하면 테스트 자체보다 준비 과정이 더 큰 비용이 된다. 카카오페이의 성능 테스트 존은 Kubernetes 격리 환경과 k6·Prometheus/Grafana·테스트 실행 도구를 공통화해 팀이 **같은 측정 절차를 반복할 수 있게** 만든 것이다.

| 구성 요소 | 검증에 주는 이점 |
| --- | --- |
| Kubernetes 테스트 네임스페이스 | 실행 환경·자원 분리 |
| k6·Testcraft | 부하 시나리오 반복 |
| Prometheus·Grafana | 애플리케이션·인프라 병목 관찰 |
| 테스트 이력 관리 | 전후 지표·조건 대조 |

운영 IDC와 개발 GCP가 다르거나 단일/다중 클러스터 차이가 있으면 네트워크 왕복·장애 복구·컴퓨팅 성능이 달라질 수 있다. 따라서 테스트 존의 결과는 용량 판단 근거가 되지만 운영 트래픽의 절대적인 재현이라고 단정할 수 없다.

## 왜 읽을까

부하 테스트 숫자가 의미 있으려면 환경 차이를 설명할 수 있어야 한다는 점을 잘 보여줍니다.

**프로젝트에 적용**

**PawCycle** — k6 기준선을 만들 때 서버 스펙·DB 데이터량·네트워크·캐시 상태를 함께 기록하고, production과 다른 조건은 결과 보고서에 한계로 명시할 수 있습니다.

# Hive에서 Iceberg로: 데이터 반영 속도 12배 향상의 비밀

> [!abstract] 한 줄 정리
> 전체 재처리 대신 증분 처리로 전환하려면 속도뿐 아니라 최신성, 중복·유실, 장애 복구까지 함께 설계해야 합니다.

> techblog.lycorp.co.jp

## 핵심 내용

수억 건 상품 데이터를 변경 때마다 전체 재작성하던 Hive 기반 ETL을 Apache Iceberg와 Flink 기반 증분 처리 구조로 바꾼 사례입니다. 기존 60분 주기의 반영을 5분으로 줄였고, 늦게 도착한 과거 데이터가 최신 데이터를 덮지 않도록 이벤트 시각을 상태로 관리했습니다. 체크포인트와 2단계 커밋으로 Iceberg 저장과 Kafka 상태 메시지 사이 부분 성공도 방지했습니다.

## 왜 읽을까

기술이 빠르다는 설명보다 데이터 최신성·중복·유실·장애 복구 요구사항을 먼저 정의하고 Spark와 Flink를 비교한 과정이 좋습니다. 운영 복잡도와 러닝 커브 증가도 비용으로 인정합니다.

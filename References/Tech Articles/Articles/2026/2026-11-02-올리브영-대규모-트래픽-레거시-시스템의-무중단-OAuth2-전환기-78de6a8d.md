# 올리브영 대규모 트래픽 레거시 시스템의 무중단 OAuth2 전환기

> [!abstract] 한 줄 정리
> 인증 체계 교체의 우선순위는 표준 도입 자체보다 로그인 연속성과 장애 격리입니다. 기능 플래그·토큰 선발급·점진적 확대·부하 분산으로 레거시에서 새 인증으로 안전하게 옮겼습니다.

> 올리브영 테크블로그 · 2026-01-30

## 핵심 내용

세션 기반 로그인에서 OAuth2로 바꿀 때 가장 먼저 지켜야 하는 것은 새 표준의 도입보다 사용자 로그인 연속성이다. 올리브영은 Spring Session과 자동 로그인 쿠키의 제약을 해결하되 세일 직전 대규모 사용자에게 영향을 주지 않도록 Feature Flag로 기존·신규 인증 경로를 함께 운영했다.

Spring Session과 자동 로그인 쿠키가 혼재해 로그아웃·기기별 제어·마이크로서비스 독립 인증에 한계가 있었습니다. 대규모 세일 트래픽을 앞두고 OAuth2 전환을 추진했습니다.

FeatureFlagDelegatingInterceptor에서 기존 세션 경로와 새 토큰 경로를 분기하고, 오류 시 기존 방식으로 돌아가게 했습니다. 새 토큰을 먼저 발급하되 실제 인증에는 사용하지 않는 Shadow Mode도 적용했습니다.

*그림 2. 동일 만료 시각이 Refresh 요청 스파이크를 만드는 과정 — [출처: 원문 기술 블로그](https://oliveyoung.tech/2025-10-28/oliveyoung-zero-downtime-oauth2-migration/)*

`FeatureFlagDelegatingInterceptor`는 단일 진입점에서 요청별 활성화 여부를 확인하고 레거시 인증 체인 또는 JWT 체인으로 위임한다. 토큰만 먼저 발급하고 실제 인증에는 사용하지 않는 Shadow Mode로 새 경로를 검증한 다음, 임직원 테스트를 거쳐 사용자 비중을 10→20→50→75→100%로 늘렸다. 각 요청에 Phase 정보를 남겨 어떤 경로의 실패인지 구분할 수 있게 했다.

```java
// 원문 인터셉터의 Phase 분기를 축약해 재구성
boolean next = flagService.activatePhase2(request, response);
request.setAttribute("oauth.phase.version", next ? "2.0" : "1.0");
return next ? executeJwtChain(request, response, handler)
            : executeLegacyChain(request, response, handler);
```

Phase 분기를 한 진입점으로 모으면 새 경로에서 문제를 발견했을 때 기존 경로로 되돌릴 수 있지만, 세션·토큰의 호환성은 별도 검증이 필요하다.

임직원 검증 뒤 사용자 비중을 10%→20%→50%→75%→100%로 늘렸고, 단계별 오류율과 지연을 관찰했습니다. 전체 전환 후 약 2주 안정화 기간을 두었습니다.

토큰 만료에 ±30초 Jitter를 넣어 Refresh API 피크를 5,000→3,000 TPS로 약 40% 줄였습니다. 세일 기간 평시 약 10배 트래픽에서 P95 약 50ms, CPU·메모리 사용률 30~35%를 보고했습니다.

Authorization Server의 지연·실패가 전체 요청을 묶지 않도록 Resilience4j Circuit Breaker를 도입했습니다. 전환 성공의 핵심은 문제가 생겼을 때 되돌릴 수 있는 실행 경로였습니다.

| 단계·기법 | 확인할 대상 | 관측 결과·의의 |
| --- | --- | --- |
| Shadow Mode | 실제 로그인과 분리한 새 토큰 발급 | 새 경로 오류를 사전 확인 |
| 단계별 확대 | 10 → 20 → 50 → 75 → 100% | 사용자 영향과 오류율을 점진 검증 |
| Token Jitter | 고정 만료 시간에 ±30초 적용 | Refresh 최대 약 5,000 → 3,000 TPS |
| Circuit Breaker | 인증 서버 지연·오류 | 연쇄 장애를 요청 경계에서 차단 |

*세일 기간의 지표는 해당 운영 기간에 한정된 측정값이며 OAuth2 자체의 일반 성능을 뜻하지 않는다.*

Access Token 만료가 5분 간격으로 정렬되면 대규모 로그인 직후 토큰 갱신이 같은 순간 집중된다. 만료 시간에 ±30초의 Jitter를 주어 Refresh 피크를 약 5,000에서 3,000 TPS로 낮췄고, 인증 서버 장애의 연쇄 전파는 Circuit Breaker로 제한했다. 기능 플래그·Shadow Mode·Jitter·Circuit Breaker는 서로 다른 실패를 차단하는 보완적 수단이다.

## 왜 읽을까

인증 보안 개선과 운영 안정성이 충돌할 때 어떤 순서로 위험을 줄이는지 확인할 수 있습니다. 기능 플래그, Shadow Mode, Jitter, Circuit Breaker를 따로 설명하는 글보다 실제 전환 시나리오로 함께 이해하기 좋습니다.

# 음성 AI 모델을 프로덕션에 올리기까지: Kanana-O 서빙 최적화 여정

> [!abstract] 한 줄 정리
> 좋은 AI 모델을 만드는 일과 사용자가 기다릴 수 있는 비용·지연으로 안정적으로 서빙하는 일은 별개의 엔지니어링 문제입니다.

> tech.kakao.com

## 핵심 내용

음성 AI 모델 Kanana-O를 실제 서비스 환경에 올리기 위해 추론 지연, GPU 자원, 처리량 등 serving 병목을 최적화한 과정을 다룹니다. 연구 단계의 모델 품질만으로는 프로덕션 요구를 만족할 수 없고, 요청 패턴과 인프라 제약에 맞게 실행 경로를 다듬어야 합니다.

음성 AI 모델의 프로덕션 서빙에서는 모델이 음성 품질 벤치마크에서 좋은 결과를 냈다는 사실과 실시간 요청을 안정적으로 처리한다는 사실을 구분해야 한다. 음성 입력 길이와 동시 요청 수가 변하면 GPU 메모리, 첫 출력 지연, 후속 스트리밍 속도와 처리량이 모두 달라질 수 있기 때문이다. 모델 실행 경로와 시스템의 자원 예약을 동시에 다듬는 최적화가 필요하다.

| 실서비스 평가 축 | 확인할 질문 |
| --- | --- |
| 시작 지연 | 사용자에게 첫 음성·응답이 언제 전달되는가? |
| 스트리밍 처리 | 생성 속도가 소비 속도를 따라가는가? |
| GPU 메모리 | 동시 요청·입력 길이 변화에 안전한가? |
| 처리량 | 지연 상한을 지키면서 몇 요청을 처리하는가? |
| 장애 복구 | 추론 실패 때 재시도·대체 경로가 있는가? |

이 표는 원문의 실서비스 문제를 이해하기 위한 검증 관점이며 구체적인 성능 수치는 원문에서 재확인하지 않은 경우 임의로 작성하지 않았다.

## 왜 읽을까

AI 프로젝트를 모델 성능 수치에서 끝내지 않고 운영 가능한 시스템으로 만드는 관점을 얻기 좋습니다.

**프로젝트에 적용**

**PawCycle** — AI 기능을 붙이게 된다면 모델 정확도와 함께 p95 latency, 요청당 비용, 메모리/GPU 사용량, 장애 시 fallback까지 운영 지표로 정의할 수 있습니다.

# 더 중요한 고민에 집중하는 올리브영 PM이 AI로 일하는 방식

> [!abstract] 한 줄 정리
> AI를 문서와 화면의 초안·동기화에 사용하고, 정책 결정과 검수는 담당자가 유지하면 여러 기획서의 불일치를 줄일 수 있다.

> 올리브영 테크블로그 · 2026-10-29

## 핵심 내용

- **문제:** 반복적인 트렌드 수집, 지표 집계, 서로 연결된 7개 기획서의 수동 갱신으로 판단보다 정리에 시간이 들었다. - **접근:** AI 에이전트로 출처별 브리핑을 자동화하고, 지표 집계 규칙을 스킬로 정의해 Apps Script로 시트에 반영했다. - **수치:** 아침 정보 수집 30분이 브리핑 확인 10분으로, 도메인별 최대 1시간의 주간 집계가 5분으로 단축됐다.

- **구조:** 기존 화면 캡처와 새 화면의 스타일을 결합해 클릭 가능한 프로토타입을 만들고, 정책 설명 번호를 기준으로 7개 기획서를 연동했다. - **주의점:** AI가 생성·정리하더라도 무엇을 바꾸고 어떤 정책을 적용할지는 PM이 직접 결정하고 검토했다.

PM이 AI를 활용하는 사례의 목적은 기획을 AI에게 넘기는 것이 아니라 반복적인 자료 수집·집계·문서 동기화 비용을 줄여 사람이 정책 결정을 내릴 시간을 확보하는 것이다. 출처별 브리핑, 스킬에 정의된 지표 집계, Apps Script를 통한 시트 반영은 별도 자동화 단계이며 각 단계의 최신성과 정확성을 확인해야 한다.

| 자동화 업무 | 관측된 변화 | 확인할 위험 |
| --- | --- | --- |
| 아침 자료 수집 | 30분→10분 | 출처·누락 |
| 주간 집계 | 최대 1시간→5분 | 계산식·기간 |
| 기획서 7개 연동 | 수동 수정 감소 | 정책 번호 불일치 |
| 클릭형 프로토타입 | 소통 효율 개선 | 구현·접근성 검증 |

AI가 여러 기획서를 동시에 고쳐도 최초 정책 해석이 틀리면 오류도 일관되게 전파된다. 최종 정책 결정과 승인 책임은 사람에게 남는다.

## 왜 읽을까

문서 정합성을 개인의 주의력에 의존하지 않고 구조로 해결하는 사례다. AI를 단순 생성 도구가 아니라 반복 작업과 산출물 간 연결을 담당하는 도구로 활용하는 판단을 배울 수 있다.

**프로젝트에 적용 — DevPedia**

- [ ] 모집·지원·승인 요구사항의 정책 정본과 화면별 설명을 연결한다.
- [ ] 정책 하나를 수정했을 때 API 명세·테스트 조건·화면 설명에 반영되는지 확인한다.
- [ ] AI가 만든 초안은 도메인 불변식과 권한 규칙을 직접 검수한다.

# 플랫폼 행성에 떨어진 서비스 개발자

> [!abstract] 한 줄 정리
> 익숙하지 않은 플랫폼의 개선 우선순위를 감으로 정하지 않고 공통 행동 로그와 사용 지표로 찾았다. 자주 반복되는 작업의 마찰을 줄이고 결과를 재측정하는 접근이다.

> 우아한형제들 기술블로그 · 2026-10-06

## 핵심 내용

- **문제:** 전시 운영 어드민에 약 50개 메뉴가 있었지만 누가 어떤 기능을 얼마나 쓰는지 알 수 없어, 프론트엔드 개발자 2명이 무엇부터 개선할지 결정하기 어려웠다.
- **접근:** 페이지 조회·검색·생성·수정 이벤트를 공통 Tracker로 수집하고, 메뉴·조직별 사용량을 대시보드로 만들어 여러 플랫폼 조직에서 재사용할 수 있게 했다.
- **수치:** 조회 페이지 방문 세션의 80% 이상에서 필터 조작과 직접 검색이 발생했다. 조건 자동 복원에 이어 필터 탭 저장·재사용을 도입했다.
- **결과:** 필터 조작·검색 없이 상세 페이지로 바로 이동한 비율은 5.8%→22.6%(약 3.9배), 상세 진입 중앙값은 10.4초→8.3초(20% 이상 감소)였다. 사용량을 고려한 개선 범위 커버리지는 82%에 도달했다.
- **검증:** BigQuery/MCP/Skill로 지표 분석을 돕고, AI가 변경분과 정책을 바탕으로 TC를 생성해 Playwright로 96건을 실행했다. 중요한 시나리오와 AI 결과는 사람이 재검토했다.

## 왜 읽을까

공통 컴포넌트의 가치는 적용 메뉴 수만이 아니라 실제 사용 빈도와 반복되는 불편으로 판단해야 한다. 단순 화면 개선이 아니라 측정 가능한 사용자 작업 흐름의 개선을 설계하는 방법을 배울 수 있다.

**프로젝트에 적용 — PawCycle**

- [ ] 상품 관리·검색 화면에서 필터 조작, 검색, 상세 진입 이벤트를 공통 규격으로 기록한다.
- [ ] 최근 검색 조건 복원 전후로 상세 진입 시간 중앙값과 반복 입력 횟수를 비교한다.
- [ ] AI 기반 브라우저 QA를 사용하더라도 주문·재고 같은 핵심 시나리오는 사람이 검증한다.

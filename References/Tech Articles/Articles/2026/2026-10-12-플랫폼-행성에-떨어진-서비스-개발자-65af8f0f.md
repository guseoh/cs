# 플랫폼 행성에 떨어진 서비스 개발자

> [!abstract] 한 줄 정리
> 익숙하지 않은 플랫폼의 개선 우선순위를 감으로 정하지 않고 공통 행동 로그와 사용 지표로 찾았다. 자주 반복되는 작업의 마찰을 줄이고 결과를 재측정하는 접근이다.

> 우아한형제들 기술블로그 · 2026-10-06

## 핵심 내용

운영 어드민에 메뉴가 약 50개 있어도 누가 어떤 메뉴를 실제 업무에서 얼마나 사용하는지 모른다면 개발자가 보기에 불편한 화면부터 손대기 쉽다. 우아한형제들 플랫폼 팀은 두 명의 프런트엔드 개발자가 페이지·검색·생성·수정 이벤트를 공통 Tracker로 모으고 사용 조직·메뉴별 행동을 관측해 개선 순서를 정했다.

![플랫폼 전시 어드민의 필터 개선 단계별 상세 진입 성과 그래프](https://techblog.woowahan.com/wp-content/uploads/2026/09/3_filter_result.png)

*그림 1. 원문의 v1·조건 복원 v2·필터 탭 v3 그래프: 상세 진입 비율과 소요 시간 변화 — [출처: 원문 기술 블로그](https://techblog.woowahan.com/27821/)*

로그를 수집해 보니 조회 페이지에 방문한 세션의 80% 이상에서 필터 조작과 직접 검색을 수행했다. 같은 조건을 매번 다시 설정해야 하는 비용을 줄이기 위해 우선 최근 조건 자동 복원을 적용했고, 자주 사용하는 조건을 탭으로 저장·전환하는 기능을 추가했다. 이 변화는 사용자 행동의 빈도를 기준으로 진행되었으며 단순히 UI 컴포넌트 수를 늘리는 작업과 달랐다.

| 사용성 지표 | v1(기존) | v3(필터 탭) |
| --- | ---: | ---: |
| 필터·검색 없이 상세로 이동 | 5.8% | 22.6% |
| 상세 진입 중앙값 | 10.4초 | 8.3초 |
| 개선 커버리지 | — | 사용량 가중 약 82% |

*단순 방문 횟수가 아닌 행동 단계의 변경 여부까지 관찰해야 실제 사용성 개선을 해석할 수 있다.*

필터 조작이나 검색 없이 상세 페이지로 바로 이동한 비율은 5.8%→22.6%로 약 3.9배 증가했고 상세 항목 진입 시간 중앙값은 10.4초→8.3초로 20% 넘게 단축됐다. 메뉴별 사용량으로 계산한 개선 범위의 커버리지는 82%였다. AI로 테스트 케이스를 생성해 Playwright 96건을 수행했지만 중요한 시나리오의 기대 결과와 서비스 정책은 사람이 다시 검토했다.

## 왜 읽을까

공통 컴포넌트의 가치는 적용 메뉴 수만이 아니라 실제 사용 빈도와 반복되는 불편으로 판단해야 한다. 단순 화면 개선이 아니라 측정 가능한 사용자 작업 흐름의 개선을 설계하는 방법을 배울 수 있다.

**프로젝트에 적용 — PawCycle**

- [ ] 상품 관리·검색 화면에서 필터 조작, 검색, 상세 진입 이벤트를 공통 규격으로 기록한다.
- [ ] 최근 검색 조건 복원 전후로 상세 진입 시간 중앙값과 반복 입력 횟수를 비교한다.
- [ ] AI 기반 브라우저 QA를 사용하더라도 주문·재고 같은 핵심 시나리오는 사람이 검증한다.

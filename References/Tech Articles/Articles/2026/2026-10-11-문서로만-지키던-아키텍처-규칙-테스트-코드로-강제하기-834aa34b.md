# 문서로만 지키던 아키텍처 규칙, 테스트 코드로 강제하기

> [!abstract] 한 줄 정리
> 아키텍처 규칙을 위키나 AI 지침에만 두면 리뷰 누락과 에이전트의 규칙 위반을 막기 어렵다. ArchUnit 테스트와 CI로 신규 위반을 차단하면서 기존 레거시는 동결해 점진적으로 줄일 수 있다.

> 우아한형제들 기술블로그 · 2026-09-07

## 핵심 내용

- **문제:** 레이어 의존성·네이밍·주입 방식 등 팀 규칙이 위키와 .claude/rules/에 있었지만 코드 리뷰에서 반복적으로 위반을 발견했다. AI 에이전트도 세션 컨텍스트에 따라 규칙을 놓쳤다.
- **접근:** ArchUnit 1.3.0과 JUnit을 독립 테스트 모듈에 구성하고 CI verification 단계에 연결했다. 도메인→웹/인프라 의존 금지, 필드 주입 금지, 네이밍 등을 단계별로 검사한다.
- **레거시:** 웹계층→outport 직접 의존 위반만 수천 건이라 일괄 수정 대신 FreezingArchRule로 기존 위반을 Git 추적 파일에 동결했다. 신규 위반은 CI 실패, 기존 위반 감소는 점진적 리팩터링 성과로 확인한다.
- **트레이드오프:** 동결 파일을 무조건 늘리면 신규 위반을 숨길 수 있으므로 MR에서 동결 파일 diff를 검토해야 한다. 규칙이 실제 팀 구조에 맞는지도 검증하고, 모든 규칙을 한꺼번에 강제하지 않는다.

## 왜 읽을까

‘아키텍처를 문서화했다’와 ‘아키텍처가 유지된다’ 사이의 차이를 보여준다. 코드 리뷰어의 기억과 AI 프롬프트에 의존하는 규칙을 실행 가능한 회귀 테스트로 옮기면서도 기존 코드 전체를 즉시 수정하지 않는 현실적인 도입 전략을 얻을 수 있다.

**프로젝트에 적용 — DevPedia**

- [ ] 현재 패키지·모듈 의존성 규칙(Controller→Service→Repository 등) 중 실제 지켜야 할 것만 명문화한다.
- [ ] ArchUnit으로 도메인 계층이 웹·인프라 구현에 직접 의존하지 않는지 테스트하고 CI에 연결한다.
- [ ] 기존 위반은 필요 시 baseline으로 동결하되 신규 위반 0건을 유지하고 동결 목록의 증가를 리뷰한다.

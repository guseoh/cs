# 쿠키런: 킹덤의 전투 데이터, JSON Schema로 검증하고 자동완성하기

> [!abstract] 한 줄 정리
> 형식상 올바른 JSON도 도메인에서는 잘못된 데이터일 수 있다. 역직렬화 대상 코드에서 스키마를 만들고 실제 입력 계약에 맞게 보정해 작성 시점의 자동완성과 테스트 시점의 검증을 연결했다.

> 데브시스터즈 DEVTECH · 2026-05-19

## 핵심 내용

- **문제:** 기획자가 전투 데이터를 JSON으로 수기 작성했지만 Unity의 관대한 역직렬화는 존재하지 않는 필드나 잘못된 타입을 조용히 무시해 오류를 찾기 어려웠다.
- **접근:** JSON Schema로 허용 필드·타입·필수 여부를 정의하고, 클래스에서 자동 생성한 스키마를 기반으로 검증하도록 했다. 스키마를 전부 수작업으로 관리하는 부담을 줄이려는 선택이다.
- **시행착오:** 기본 생성기는 실제 입력의 camelCase 대신 PascalCase 공개 프로퍼티를 사용하고 enum을 숫자로 출력했다. Contract Resolver를 커스터마이징하고 스키마 후처리로 enum 문자열·`additionalProperties=false` 등을 반영했다.
- **구조:** 전투 테스트마다 별도 스레드에서 스키마를 검증해 Unity 로그로 오류를 보고한다. VS Code의 `json.schemas` 설정과 스키마 파일을 패키지로 제공해 기획자·QA도 자동완성과 즉시 검증을 이용한다.
- **결과·주의점:** 2023년부터 개선해 여러 직군이 사용하는 도구로 발전했고 오류를 줄였다고 보고한다. 다만 오류율·작업시간의 정량적 Before/After는 공개하지 않았다.

## 왜 읽을까

런타임에서 오류를 발견하는 대신 데이터를 작성하는 시점으로 검증을 당기는 설계다. 특히 코드 타입과 외부 입력 형식이 일치하지 않을 때 생성기 출력을 그대로 믿지 않고 실제 계약에 맞게 수정하는 판단이 중요하다.

도구 선택도 무조건 새 시스템을 만드는 것이 아니라 VS Code의 기존 JSON Schema 지원을 활용해 유지보수 부담을 낮췄다는 점이 좋다.

**프로젝트에 적용 — 공통**

- [ ] JSON 요청·설정 데이터의 허용 필드, enum, 필수값과 미지정값 처리 규칙을 명확히 한다.
- [ ] DTO 검증과 실제 역직렬화 결과가 어긋나는 경계 입력을 테스트한다.
- [ ] 설정용 JSON 파일이 있다면 IDE의 스키마 검증을 활용할 수 있는지 검토하되, 필요하지 않은 스키마 관리 체계는 새로 도입하지 않는다.

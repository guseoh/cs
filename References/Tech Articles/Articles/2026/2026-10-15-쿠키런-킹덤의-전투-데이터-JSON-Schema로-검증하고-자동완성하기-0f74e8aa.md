# 쿠키런: 킹덤의 전투 데이터, JSON Schema로 검증하고 자동완성하기

> [!abstract] 한 줄 정리
> 형식상 올바른 JSON도 도메인에서는 잘못된 데이터일 수 있다. 역직렬화 대상 코드에서 스키마를 만들고 실제 입력 계약에 맞게 보정해 작성 시점의 자동완성과 테스트 시점의 검증을 연결했다.

> 데브시스터즈 DEVTECH · 2026-05-19

## 핵심 내용

게임 기획 데이터가 JSON으로 입력될 때, 잘못된 필드 이름이나 타입을 관대한 역직렬화기가 조용히 무시하면 게임 실행 단계에 이르러서야 오류가 발견될 수 있다. 데브시스터즈는 기획자가 데이터 편집 시점에 유효성 검사를 받고 자동완성도 활용할 수 있도록 JSON Schema를 중심 계약으로 도입했다.

클래스 모델에서 JSON Schema를 생성해 필수 필드·타입·열거형과 추가 필드 허용 여부를 검증했다. 기본 생성기가 공개 프로퍼티를 PascalCase로 출력하거나 enum을 숫자로 나타내는 문제는 Contract Resolver와 스키마 후처리로 수정했다. `additionalProperties=false`를 사용하면 오타로 만들어진 미정의 필드를 유효한 필드처럼 무시하지 않고 오류로 검출할 수 있다.

```json
{
  "type": "object",
  "properties": {"id": {"type":"string"}, "damage": {"type":"number"}},
  "required": ["id", "damage"],
  "additionalProperties": false
}
```

*원문 방법을 설명하기 위한 학습용 간소화 스키마다. 실제 게임 데이터 필드와 필수 규칙은 별도로 정의된다.*

| 데이터 오류 | 관대한 역직렬화의 위험 | Schema 검증 |
| --- | --- | --- |
| 필드명 오타 | 알 수 없는 값이 조용히 사라짐 | 추가 필드 거절 |
| 필수 필드 누락 | 런타임 기본값으로 진행 가능 | required 위반 보고 |
| enum 표현 불일치 | 숫자·문자열 변환 오류 | 허용 문자열 집합 명시 |
| 에디터 입력 중 오류 | 실행 전까지 발견 지연 | VS Code 자동완성·즉시 검사 |

검증은 전투 테스트를 실행하기 전에 별도 스레드에서 수행해 Unity 로그에 문제가 있는 필드와 위치를 보고한다. 스키마 파일을 VS Code의 `json.schemas` 설정과 함께 제공하자 데이터 담당자와 QA가 입력 중 자동완성·오류 검출을 활용할 수 있게 됐다. 이런 계약 자동화는 기획 데이터와 코드 모델이 서로 어긋나는 비용을 줄이지만 실제 오류율·작업 시간 개선 수치는 원문에 공개되지 않았다.

## 왜 읽을까

런타임에서 오류를 발견하는 대신 데이터를 작성하는 시점으로 검증을 당기는 설계다. 특히 코드 타입과 외부 입력 형식이 일치하지 않을 때 생성기 출력을 그대로 믿지 않고 실제 계약에 맞게 수정하는 판단이 중요하다.

도구 선택도 무조건 새 시스템을 만드는 것이 아니라 VS Code의 기존 JSON Schema 지원을 활용해 유지보수 부담을 낮췄다는 점이 좋다.

**프로젝트에 적용 — 공통**

- [ ] JSON 요청·설정 데이터의 허용 필드, enum, 필수값과 미지정값 처리 규칙을 명확히 한다.
- [ ] DTO 검증과 실제 역직렬화 결과가 어긋나는 경계 입력을 테스트한다.
- [ ] 설정용 JSON 파일이 있다면 IDE의 스키마 검증을 활용할 수 있는지 검토하되, 필요하지 않은 스키마 관리 체계는 새로 도입하지 않는다.

# 프레임워크에 구애받지 않는 통합 백오피스 구축하기

> [!abstract] 한 줄 정리
> 같은 상품정보 화면을 React·Vue·JSP 시스템마다 만들던 중복을 없애기 위해 올리브영은 Vue의 `defineCustomElement`로 프레임워크 독립적인 웹 컴포넌트를 만들었다. 모노레포에서 빌드한 공통 화면을 S3·CDN으로 공급하되, 스타일 격리와 인증 전달, 캐시 무효화 문제를 별도 계약으로 해결했다.

## 핵심 내용

올리브영은 협력사 상품 관리 시스템(Vue·React)과 품질 관리 시스템(JSP)에 동일한 상품정보 화면을 제공해야 했다. 세 시스템은 같은 목적과 API를 사용하지만 화면 구현 기술이 달라 UI와 로직을 최대 세 벌 유지해야 했다. 모든 시스템을 Vue 등 하나의 프레임워크로 전환하는 방법은 안정적으로 운영되는 레거시까지 장기간 재작성해야 하므로 비용과 전환 위험이 컸다. iframe은 화면을 독립적으로 포함하기 쉽지만 다른 오리진의 쿠키·세션 연동과 로그인 경험이 제약이어서 요구사항에 맞지 않았다.

대안으로 Vue 3의 `defineCustomElement`를 사용해 공통 화면을 브라우저 표준 커스텀 요소로 빌드했다. 모노레포에 공통 화면을 패키지화하고 JS 빌드 결과물을 S3와 CDN에 배포한 후, 각 백오피스가 `script`로 불러와 HTML 커스텀 태그로 렌더링하는 방식이다. React·Vue·JSP 각각에 공통 비즈니스 화면을 복제할 필요가 없으며, 부모 시스템을 재배포하지 않고 공통 화면 자산을 교체할 수 있다. 다만 브라우저의 CDN 캐시가 만료되기 전까지 이전 JS가 남을 수 있어, 원문 구현은 날짜·시간 쿼리 파라미터로 캐시 버스팅을 적용했고 내용 해시 파일명 또는 CDN Invalidation도 대안으로 제시한다.

가장 까다로운 구현 이슈 중 하나는 스타일이었다. Shadow DOM은 외부 스타일과의 충돌을 막지만, Vue가 전역 문서에 주입한 스타일이나 CDN에서 내려받은 CSS가 자동으로 그 내부에 적용되지는 않는다. 작성자는 React 쪽 커스텀 훅에서 `customElements.whenDefined`로 요소 등록을 기다린 뒤 `shadowRoot`를 확인하고, `[data-v-` 표시가 있는 Vue 스타일을 복제하는 동시에 CDN CSS를 별도로 가져와 주입했다. 모든 준비가 끝난 뒤 로딩 상태를 해제해 초기 화면 깜빡임을 줄이는 순서로 구성했다.

인증은 웹 컴포넌트가 부모 페이지의 브라우저 실행 맥락에서 동작한다는 성질을 이용한다. 같은 오리진이라면 기존 쿠키·헤더 체계를 사용할 수 있고, 부모가 사용하는 Axios 인스턴스를 컴포넌트의 프로퍼티로 넘기는 방법도 있다. 이종 도메인 API에서는 필요한 토큰·설정을 부모에서 런타임에 주입하는 방식을 설명한다. 그러나 **부모의 자원을 공유한다는 것은 자동으로 안전하다는 뜻이 아니다.** 쿠키 인증에는 CSRF 방어가 필요하고, 토큰을 주입하는 경우 권한 범위와 노출 경계도 설계해야 한다. 또한 웹 컴포넌트는 초기 JS 로딩 및 커스텀 요소 등록을 기다려야 하므로, 서버 렌더링·검색 노출이 중요한 공개 화면보다 로그인 후 백오피스 화면에 더 적합하다. 원문은 구체적인 아키텍처 구현과 운영 고려 사항을 제시하지만, 정량적인 개발 시간 절감이나 성능 지표는 공개하지 않았다.

## 왜 읽을까

설계의 핵심은 '모든 기술을 통일할 것인가'가 아니라 어느 변경 단위를 독립적으로 관리·배포할 것인가를 결정하는 데 있다. 시스템 전체 마이그레이션의 비용과 기존 시스템을 유지하며 공유 기능만 분리하는 비용을 비교하면, 작은 통합 경계가 전체 재작성보다 위험을 낮출 수 있다. 반면 독립 배포에는 버전 호환성·캐시 전략·인증 책임·스타일 로딩이라는 새로운 운영 계약이 생긴다.

**설계 연습 아이디어(제안·미검증):** 관리자 화면과 일반 화면에서 중복되는 기능이 실제로 존재한다면 먼저 중복의 범위와 변경 빈도를 측정하고, 공통 라이브러리·iframe·웹 컴포넌트·재작성 중 어떤 경계가 적합한지 비교해 볼 수 있다. 이 사례만으로 특정 프로젝트에 웹 컴포넌트를 바로 도입해야 한다고 결론 내리지는 않는다.

# 공공데이터포털 화재에서 살아남기

> [!abstract] 한 줄 정리
> 외부 API는 정상일 때 편리하지만 중요한 기능을 전적으로 의존하면 상대 시스템의 장애가 곧 내 서비스 장애가 되므로 fallback 데이터와 degraded mode가 필요합니다.

> velog.io

## 핵심 내용

발표 이틀 전 공공데이터포털 장애가 발생하자 KRX CSV의 2,879개 종목과 약 5년치 110만 행 데이터를 이용해 대체 경로를 구축합니다. 테스트 결과 200번의 backtest 호출 중 약 83%가 상위 100개 종목에 집중된다는 점을 확인하고 on-demand 저장 방식을 선택합니다.

50개 사례 환경에서 API 호출은 약 201회에서 58회 수준으로 줄었지만 외부 의존성을 완전히 없앤 것은 아니며, production이라면 multi-source가 필요하다는 한계도 남깁니다.

## 왜 읽을까

외부 API 장애를 경험한 뒤 캐시·소유 데이터·fallback 범위를 실제 사용 패턴으로 결정하는 과정이 구체적입니다.

**프로젝트에 적용**

**FutMatch** — 지도·구장·알림 같은 외부 API를 붙일 때 장애 시 기능 전체를 500으로 만들지 말고 최근 데이터·재시도·읽기 전용 degraded mode 중 무엇을 제공할지 미리 정할 수 있습니다.

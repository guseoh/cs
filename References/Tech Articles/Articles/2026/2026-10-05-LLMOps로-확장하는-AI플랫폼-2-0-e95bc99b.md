# LLMOps로 확장하는 AI플랫폼 2.0

> [!abstract] 한 줄 정리
> LLM을 프로덕션에 넣으면 모델 호출보다 프롬프트 버전, 외부 API 장애, 비용, 평가, 자격 증명과 개인정보가 운영 문제로 떠오른다. 이를 개별 서비스가 반복 구현하지 않도록 플랫폼 책임으로 끌어올린 사례다.

> 우아한형제들 기술블로그 · 2025-09-29

## 핵심 내용

우아한형제들 사내 AI 제품이 10개 이상으로 늘어나자 특정 모델 API를 호출하는 코드보다 프롬프트 버전, 비용, 모델 장애, 권한과 반복 실험을 공통으로 운영하는 일이 어려워졌다. 기존 MLOps의 학습·배포 관리에 더해 호출형 모델의 요청 단위 Trace·토큰 비용·벤더 대체가 필요해진 것이다.

AI 플랫폼 2.0은 GenAI Studio에서 프롬프트 버전·Golden Dataset·평가·키를 관리하고 SDK/LiteLLM에서 모델 라우팅·Retry·Fallback을 제공한다. API Gateway는 동일 기능을 OpenAI 호환 REST 인터페이스로 노출해 Python 외 애플리케이션도 접근하도록 했다. GenAI Labs는 모델과 프롬프트를 동일 데이터셋으로 반복 실험하는 환경이고, Langfuse Trace와 ClickHouse·Prometheus·Grafana를 연결해 비용·에러·지연의 원인을 추적한다.

| 컴포넌트 | 핵심 책임 | 함께 검증할 운영 제약 |
| --- | --- | --- |
| GenAI Studio | 프롬프트·데이터셋·Trace·키 | 버전/권한/개인정보 |
| GenAI SDK | 모델 호출·Fallback | 벤더·리전 실패 |
| API Gateway | 표준 REST 진입점 | 인증·요청량·모델 선택 |
| GenAI Labs | 프롬프트·평가 실험 | 동일 데이터셋 비교 |
| 자체 Langfuse | 추적·평가 | ClickHouse·Redis 등 운영 부담 |

2025년 4월 Azure OpenAI East US 장애처럼 특정 리전이 길게 실패하면 같은 모델의 다른 리전으로 우회할 수 있어야 한다. Langfuse를 직접 운영하면서 ClickHouse·Redis 등 관리 책임이 증가하지만 여러 팀의 재현성·보안 정책을 한곳에서 검증할 수 있다. 원문은 2025년 기준 플랫폼 이용자 수가 전년 대비 50% 늘었다고 보고했으며 이는 플랫폼의 개별 성능 개선율은 아니다.

## 왜 읽을까

AI 기능 자체보다 AI를 운영 서비스로 만들 때 생기는 백엔드 문제를 보기 좋다. 외부 의존성의 timeout·fallback, 관측 가능성, 비밀정보 관리, 비용 추적, 회귀 평가를 하나의 플랫폼 문제로 연결한다.

**프로젝트에 적용 — DevPedia**

- [ ] 향후 AI 기능을 붙인다면 모델명·프롬프트·응답시간·실패 원인을 요청 단위로 추적할 수 있게 한다.
- [ ] 외부 모델 장애 시 timeout·재시도·fallback의 책임 위치를 명시한다.
- [ ] 프롬프트를 코드 밖 임시 텍스트로 두지 말고 버전과 평가 데이터셋을 함께 관리한다.

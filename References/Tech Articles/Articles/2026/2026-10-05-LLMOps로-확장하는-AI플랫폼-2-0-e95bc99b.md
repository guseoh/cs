# LLMOps로 확장하는 AI플랫폼 2.0

> [!abstract] 한 줄 정리
> LLM을 프로덕션에 넣으면 모델 호출보다 프롬프트 버전, 외부 API 장애, 비용, 평가, 자격 증명과 개인정보가 운영 문제로 떠오른다. 이를 개별 서비스가 반복 구현하지 않도록 플랫폼 책임으로 끌어올린 사례다.

> 우아한형제들 기술블로그 · 2025-09-29

## 핵심 내용

- **문제:** 사내 AI 프로덕트가 10개 이상으로 늘면서 멀티 Provider, 프롬프트 버전, 외부 API 장애, 비용, 실험 재현성, 자격 증명과 개인정보 보호가 공통 운영 문제로 나타났다.
- **접근:** Studio·SDK·API Gateway·Labs로 책임을 나눠 프롬프트 버전과 Trace, Evaluation Dataset, 크레덴셜, 라우팅·Retry·Fallback을 공통화했다.
- **장애·운영:** 2025년 4월 Azure OpenAI East US 장애처럼 외부 모델 API가 장시간 불능이 될 수 있어 동일 모델의 다른 리전이나 Provider로 우회할 수 있는 전략을 SDK에 넣었다.
- **트레이드오프:** Langfuse를 self-hosted로 선택하면서 ClickHouse·Redis 등 운영 컴포넌트가 늘어나는 부담을 감수했지만, 프롬프트 관리·Trace·평가·대규모 확장성을 하나의 운영 기반으로 가져가는 이점을 택했다.
- **결과:** 2025년 기준 플랫폼 사용자 수가 전년 대비 50% 증가했고 신규 LLM 프로젝트도 크게 늘었다. 요청 단위 Trace와 프로젝트별 비용 관측 체계도 확보했다.

## 왜 읽을까

AI 기능 자체보다 AI를 운영 서비스로 만들 때 생기는 백엔드 문제를 보기 좋다. 외부 의존성의 timeout·fallback, 관측 가능성, 비밀정보 관리, 비용 추적, 회귀 평가를 하나의 플랫폼 문제로 연결한다.

**프로젝트에 적용 — DevPedia**

- [ ] 향후 AI 기능을 붙인다면 모델명·프롬프트·응답시간·실패 원인을 요청 단위로 추적할 수 있게 한다.
- [ ] 외부 모델 장애 시 timeout·재시도·fallback의 책임 위치를 명시한다.
- [ ] 프롬프트를 코드 밖 임시 텍스트로 두지 말고 버전과 평가 데이터셋을 함께 관리한다.

# ELK와 Grafana를 이용해 테스트 자동화 시각화하기

> [!abstract] 한 줄 정리
> 테스트를 자동으로 실행하는 것만으로는 품질 관리가 완성되지 않습니다. 실행 과정·결과를 표준 이벤트로 수집하고 누구나 상태를 확인할 수 있게 해야 테스트 자동화가 지속적으로 사용됩니다.

> LINE Engineering · 2023-07-14

## 핵심 내용

- **문제:** 서비스마다 여러 회귀·퀵 테스트 잡이 돌았지만 결과 메일이 쌓이고, 테스트 진행률·완료 시점·실패 원인을 한눈에 파악하기 어려웠습니다.
- **구조:** 여러 테스트 노드의 로그를 Filebeat→Logstash→Elasticsearch로 적재하는 Heimdall 파이프라인을 구축하고 Grafana로 시각화했습니다.
- **데이터:** 애플리케이션·테스트 케이스·기기·이벤트 정보를 담은 약 20개의 로그 필드를 정의하고, 솔루션에 부족했던 로깅을 ActionLog.Script로 보완했습니다.
- **자동화:** Jenkins가 신규 앱 빌드를 확인해 다운로드·설치·회귀 테스트 실행을 이어 주고, Grafana 대시보드와 Slack 알림으로 진행 상태를 공유했습니다.
- **결과:** 수동 리포트 메일 작성 부담을 줄이고 테스트 상태를 실시간으로 볼 수 있게 됐습니다. 정량적인 시간 절감 수치는 공개하지 않았습니다.

## 왜 읽을까

테스트 성공률만 보는 대시보드가 아니라 테스트를 '운영 가능한 시스템'으로 만드는 설계 관점을 배울 수 있습니다. 핵심은 ELK 자체보다 공통 이벤트 스키마, 실패 추적, 빌드부터 결과 공유까지 이어지는 실행 흐름입니다.

- [ ] PR 검증 결과를 요약해 실패 원인과 이전 실행 대비 변화를 추적합니다.

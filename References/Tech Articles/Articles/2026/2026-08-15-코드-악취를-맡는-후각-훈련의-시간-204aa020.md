# 코드 악취를 맡는 후각 훈련의 시간

> [!abstract] 한 줄 정리
> 리팩터링은 막연히 코드를 깨끗하게 만드는 작업이 아니라 대상을 정의하고 기존 동작을 테스트로 보호한 뒤 작은 단위로 변경·검증하는 과정입니다.

> helloworld.kurly.com

## 핵심 내용

성능 장애가 아니라 계속 수정하기 힘든 코드를 한 달 동안 세 명이 리팩터링한 기록입니다. 전체를 뜯지 않고 8개 기능 영역으로 나눠 3차에 걸쳐 변경하고 단계마다 QA와 배포를 진행했습니다. 30라인 이상 메서드, 3중 조건문, 5개 이상 파라미터, 모호한 이름 같은 탐색 기준을 먼저 정하고 기존 동작을 보호할 서비스 레벨 테스트를 작성했습니다. 처음에는 공통화한 검수·검품 로직도 조건문이 계속 늘어 이해를 어렵게 하자 다시 분리했습니다.

코드 악취를 없애는 것이 모든 중복 코드를 하나로 합치는 뜻은 아니다. 오히려 공통 로직 안에 계속 조건문이 늘어나면 서로 다른 업무가 하나의 추상화에 억지로 묶였다는 신호일 수 있다. 이번 사례에서는 기능 영역별로 변경 범위를 나누고 서비스 레벨 테스트로 기존 행동을 보호했기 때문에 중간 단계마다 QA와 배포를 할 수 있었다.

| 탐색 기준 | 드러내는 위험 |
| --- | --- |
| 30줄 이상 메서드 | 한 함수의 책임 과다 |
| 3중 조건문 | 분기와 도메인 규칙 혼재 |
| 파라미터 5개 이상 | 객체·책임 경계 불명확 |
| 모호한 이름 | 수정 시 의미 추론 비용 |

숫자 기준은 자동 판정의 절대적인 품질 점수가 아니라 검토 대상을 빠르게 찾기 위한 휴리스틱으로 이해해야 한다.

## 왜 읽을까

리팩터링을 클린 코드 기법이 아니라 범위 선정, 회귀 보호, 작은 변경, QA, 배포의 실제 작업 과정으로 보여줍니다.

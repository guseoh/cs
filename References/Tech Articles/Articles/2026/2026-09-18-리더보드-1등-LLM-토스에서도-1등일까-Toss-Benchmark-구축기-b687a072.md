# 리더보드 1등 LLM, 토스에서도 1등일까? - Toss Benchmark 구축기

> [!abstract] 한 줄 정리
> 범용 벤치마크의 1등 모델이 실제 서비스에서도 최선이라는 보장은 없다. 언어·추론 설정·도메인 정책·실제 업무 데이터를 맞춘 평가 체계가 있어야 모델 선택을 제품 의사결정으로 바꿀 수 있다.

> Toss Tech · 2026-09-16

## 핵심 내용

공개 LLM 리더보드는 주로 영어와 특정 추론 설정으로 모델을 평가하지만 한국어 코드 작성·금융 안내·내부 정책 준수 같은 실제 업무는 다르다. 토스는 '리더보드 1위'라는 외부 평판을 그대로 채택 기준으로 사용하지 않고 도메인 데이터와 작업 조건을 고정한 자체 Benchmark를 만들었다.

코딩 예시에서 Qwen3.5-122B-A10B는 영어 69.40으로 Qwen3.6-27B의 64.93보다 높았지만 한국어에서는 각각 53.73과 55.60으로 순위가 뒤집혔다. Reasoning을 끄면 GLM-5.1은 코딩 점수가 78.7→48.1로 30.6점 하락한 반면 gemma-4-26B-A4B-it는 84.0→78.0으로 6점 하락했다. 점수 비교는 언어·모델 옵션·샘플 구성과 채점기 버전을 함께 통제해야 한다.

| 모델·조건 | 영어 코딩 | 한국어 코딩 | 의미 |
| --- | ---: | ---: | --- |
| Qwen3.5-122B-A10B | 69.40 | 53.73 | 영어에서 우세 |
| Qwen3.6-27B | 64.93 | 55.60 | 한국어에서 역전 |
| GLM-5.1 Reasoning On→Off | 78.7→48.1 | 조건별 비교 | 30.6점 하락 |
| gemma-4-26B-A4B-it On→Off | 84.0→78.0 | 조건별 비교 | 6점 하락 |

*하단 두 행은 언어 비교가 아니라 추론 설정별 결과이므로 같은 열의 절대 우열로 섞지 않는다.*

Toss Benchmark는 실제 운영 태스크, 정책 준수를 보는 Toss IFBench, 커머스·광고·금융·페이의 도메인 지식을 평가하는 Toss Knowledge로 나누었다. 높은 평균 점수보다 업무상 치명적인 오류가 어느 종류에서 발생하는지 확인해야 모델 선택과 비용·지연·안전성의 균형을 정할 수 있다.

## 왜 읽을까

AI 모델 평가도 일반 소프트웨어 테스트와 마찬가지로 '실제 사용 조건을 얼마나 재현했는가'가 핵심이라는 걸 수치로 보여준다. 리더보드 점수를 기술 선택 근거로 그대로 가져오는 위험을 이해하기 좋다.

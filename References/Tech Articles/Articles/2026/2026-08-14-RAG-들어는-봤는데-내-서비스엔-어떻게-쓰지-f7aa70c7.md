# RAG, 들어는 봤는데… 내 서비스엔 어떻게 쓰지?

> [!abstract] 한 줄 정리
> RAG는 유행 때문에 붙이는 기능이 아니라 최신 내부 정보, 도메인 지식, 출처 기반 응답이 정말 필요한지 확인한 뒤 도입해야 합니다.

> techblog.woowahan.com

## 핵심 내용

DB, Google Drive, Calendar에 흩어진 교육 운영 정보를 찾는 문제를 MCP 활용 → MCP 직접 구현 → RAG 서버의 세 단계로 풀어갑니다. MCP 클라이언트 의존성, VPC 접근, Context Window 초과, 페이징 지연을 겪은 뒤 구조를 바꿨고, 프롬프트나 직접 컨텍스트 전달만으로 충분한지 먼저 확인한 후 RAG를 검토하라고 설명합니다. 로딩, 청킹, 임베딩, 저장, 검색, 생성, 평가 파이프라인도 처음부터 완벽하게 만들기보다 작은 흐름을 먼저 완성해 평가하면서 개선합니다.

## 왜 읽을까

RAG가 필요하지 않은 경우까지 구분하고 Spring AI와 LangChain 선택에서도 팀의 기존 스택과 운영 환경을 기준으로 삼는 점이 좋습니다.

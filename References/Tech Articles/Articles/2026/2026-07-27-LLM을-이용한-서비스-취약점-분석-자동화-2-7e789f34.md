# LLM을 이용한 서비스 취약점 분석 자동화 #2

> [!abstract] 한 줄 정리
> AI 보안 분석의 품질은 모델 크기보다 코드 탐색 범위와 증거를 줄여주는 도구, 역할 분리, 재현 가능한 평가셋에 좌우됩니다.

> toss.tech

## 핵심 내용

ctags와 tree-sitter 기반 도구, SAST 결과를 이용해 LLM이 봐야 할 코드 경로를 줄이고 Discovery와 Analysis 역할을 분리합니다. 약 15MB까지 커지던 분석 컨텍스트를 줄이며, 특정 실험에서는 286개 경로를 144개로 좁혀 27개 취약점을 탐지했습니다.

모델도 막연히 최신 모델을 고르지 않고 분석 능력·정밀도·false positive·tool calling을 비교해 선택합니다.

## 왜 읽을까

AI를 보안에 쓸 때도 '잘 찾는 것 같다'가 아니라 통제된 취약점 시나리오와 명시적인 평가 기준이 필요하다는 점이 좋습니다.

**프로젝트에 적용**

**DevPedia·PawCycle 공통** — AI 보안 리뷰를 도입한다면 의도적으로 취약한 테스트 샘플을 두고 탐지율과 오탐을 검증한 뒤, SAST/테스트 결과와 함께 보조 도구로 사용하면 좋습니다.

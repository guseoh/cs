# 프롬프팅에서 워크플로로, AI로 프런트엔드 개발 생산성 끌어올리기

> [!abstract] 한 줄 정리
> 좋은 AI 코딩은 프롬프트 한 번보다 `컨텍스트 → 계획 → 구현 → 검증`을 반복 가능한 워크플로로 만드는 데 가깝습니다.

> LY Corporation Tech Blog · 2026-06-26

## 핵심 내용

- **문제:** Jira·Confluence·Slack·Figma·GitHub 등에 개발 컨텍스트가 흩어져 있어, AI가 코드만 보고는 요구사항과 검증 기준을 충분히 이해하기 어렵습니다.
- **워크플로:** `컨텍스트 수집 → 계획 → 구현 → 검사 → 실패 수정 → 스모크 테스트 → 검증 요약 → PR`로 이어지는 닫힌 루프를 구성합니다.
- **사람의 검토 지점:** 코드 수정 전에 요구사항·관련 파일·테스트 항목·미해결 질문을 먼저 정리하고, 구현 후에는 원래 계획과 실제 결과를 다시 비교합니다.
- **핵심 원칙:** 자동화 범위가 넓은 것보다 **반복 가능하고 검토 가능하며 기존 팀 방식에 맞는 흐름**이 더 중요합니다.

## 왜 읽을까

AI에게 코드를 더 많이 생성시키는 요령보다 **AI가 틀렸을 때 발견하고 수정할 수 있는 개발 프로세스**를 다룹니다. 에이전트에게 구현을 맡길수록 계획과 검증 기준을 어떻게 남길지가 중요해진다는 점이 실무적입니다.

**프로젝트에 적용 — DevPedia·PawCycle**

Codex 작업 흐름을 아래처럼 고정해볼 만합니다.

- 요구사항과 관련 코드 읽기
- 구현 계획 검토
- 구현
- 테스트·빌드
- 실제 실행 검증
- 변경 내용과 남은 위험 보고

구현 자체는 에이전트에 맡기더라도 **설계 판단과 검증 기준은 사람이 유지하는 구조**로 가져가는 것이 핵심입니다.

# 기획서 하나로 결함 등록까지, QA AI Hub를 만들며 배운 것

> [!abstract] 한 줄 정리
> AI 테스트 자동화의 성패는 TC 생성량보다 도메인 정본, 요구사항 추적성, 품질 게이트와 사람의 판정에 달려 있습니다.

> 컬리 기술 블로그 · 박상현 · 2026-11-03

## 핵심 내용

- **문제:** 기존 QA 시간의 절반 이상이 설계·TC 작성에 쓰이고 재활용률은 5% 미만이었습니다.
- **구조:** 기획서·정책·Figma 분석 → 테스트 설계 → 21컬럼 TC 생성 → 실행 → 결함 등록의 다섯 단계를 연결했습니다.
- **접근:** 요구사항과 TC 매트릭스의 100% 연결을 확인하고, 검수된 정답 TC를 Git 정본으로 재사용하며 Python 검사와 hook을 이중 게이트로 적용했습니다.
- **수치:** 137개 과제에서 커머스 준비 기간 3.90→2.55일(-35%), 물류 6.02→5.13일(-15%). AI 실행 10,547건 중 거짓 PASS 67건(0.64%)이었습니다.
- **주의점:** BLOCKED 사례의 71%가 테스트 데이터 문제였고, 물류의 정책 복잡성 때문에 정제 공수가 더 높았습니다.

## 왜 읽을까

테스트를 자동 생성하는 것과 테스트가 실제 요구사항을 검증하는 것은 다릅니다. 정답 TC와 정책 정본을 관리하고, 실패 사례를 재발 방지 규칙으로 바꾸는 실무적인 하네스 설계에 참고할 만합니다.

**프로젝트에 적용 — DevPedia**

- [ ] 모집·지원·승인의 요구사항 ID와 테스트 케이스 ID를 매핑합니다.
- [ ] 상태 전이·권한 매트릭스의 누락을 검사하는 게이트를 추가합니다.
- [ ] AI 생성 테스트에서 거짓 PASS와 테스트 데이터 준비 실패를 구분해 기록합니다.

# 배송최적화 시스템 구축기 Part 01. 올리브영이 멀티 센터 체제로 배송 시간을 14시간 단축한 과정

> [!abstract] 핵심 판단
> 물류 센터를 추가하는 것만으로 출고 병목이 해결되지는 않는다. 실시간 재고·센터 처리 용량·배송 권역을 평가하는 별도 판단 계층과 주문 이관의 정합성 보장이 필요하다.

## 문제와 제약

기존 OMS→TCS→WMS 흐름은 단일 출고 센터를 전제하여 센터를 확장한 뒤에도 주문이 한 곳에 집중됐다. 분산이 자동으로 이뤄지지 않아 운영자가 물량을 수동으로 조정하는 부담이 있었다.

## 접근과 선택 근거

- **아키텍처:** 주문 처리 시스템과 물류 시스템 사이에 배송최적화 판단 계층을 추가한다.
- **정책:** 실시간 재고, 센터 CAPA, 배송 권역으로 출고처를 결정하고 정책을 룰 기반으로 변경한다.
- **실패 처리:** Redis 분산 락과 멱등성을 통해 중복 이관을 방지하고, 외부 API 장애에 서킷 브레이커와 단계별 보상 처리를 적용한다.

### 선택의 세부 근거

기존 OMS→TCS→WMS 흐름의 한계는 센터가 증가해도 실제 출고처를 유연하게 정하는 책임이 분리되지 않았다는 점이다. 개선 구조는 **출고 확정 이전**에 재고, CAPA, 배송 권역을 판단하고, 필터와 점수화 전략을 런타임에 조합하도록 구성했다. 또한 상대적으로 정적인 센터 기준은 Caffeine에, 공유해야 할 실시간 출고량은 Redis에 보관해 데이터의 갱신 특성에 따라 캐시 책임을 나눴다.

## 검증 결과와 한계

- 원문이 비교한 고부하 세일 기간에서 최대 일 출고량 **43.5% 증가**, 수동 개입 **49.2% 감소**, 평균 배송 리드타임 **14시간 단축**을 보고했다.
- 비교 기간의 총 출고량도 달랐으므로 관측 수치를 단일 기술 선택의 순수한 효과로 단정해서는 안 된다.

## 연결할 개념

관련 개념 노트를 직접 학습한 뒤 실제 존재하는 파일에 연결한다. 자동으로 존재하지 않는 Wikilink를 생성하지 않는다.

# 코틀린 함수형 프로그래밍의 길을 찾아서

> [!abstract] 한 줄 정리
> 함수형 프로그래밍을 거창한 추상화로 시작하기보다 불변성, 계산과 외부 의존성의 분리, 반복 패턴의 작은 추출부터 적용하면 변경과 테스트가 쉬워진다.

> 카카오페이 기술 블로그 · 스노우 · 2024-11-21

## 핵심 내용

- **문제:** 결제 요청 객체의 금액을 환율 변환·할인·분할 결제 과정에서 계속 변경하면 이전 단계의 상태가 다음 계산에 영향을 미친다.
- **사례:** 글의 예시에서는 21,000원 결제에 할인을 중복 적용해 MONEY 10,000원과 POINT 9,000원을 결제한다. 원래 의도는 전체 할인 한 번이었다.
- **접근:** 요청 필드를 불변으로 바꾸고 환율은 초기에 한 번 가져온다. 금액별 계산 결과를 KrwPayParams로 분리해 실제 결제 실행과 구분한다.
- **확장:** 예외 처리, 재시도, 배치 같은 반복 패턴은 고차함수로 추출하는 방식을 소개하고 Kotlin Arrow 등의 적용 방향을 검토한다.
- **주의점:** 외부 시스템 의존을 모두 제거할 수는 없으며 재시도는 멱등성과 실패 조건을 고려해 사용해야 한다.

## 왜 읽을까

불변성과 순수 함수가 단순한 코드 취향이 아니라 할인 중복 적용 같은 비즈니스 오류를 예방하고 테스트 범위를 줄이는 설계 수단임을 알 수 있다. Kotlin 예제지만 Java에도 적용할 수 있는 원칙이다.

**프로젝트에 적용 — DevPedia**

- [ ] 모집 지원 상태 변경 과정에서 입력 DTO를 계산용으로 변형하지 않는지 확인한다.
- [ ] 상태 전이 판단 규칙을 외부 조회와 분리해 독립적으로 테스트한다.
- [ ] 재시도 추상화 도입 전 중복 처리와 부작용을 검토한다.

# 끊김 없는 사용 경험을 위하여: 카카오톡 선물함 속 교환권을 배달의민족 주문으로 연결한 여정

> [!abstract] 한 줄 정리
> 라이브러리 실패를 우회하기 전에 실제 입력 변형과 내부 처리 과정을 관찰해야 근본 원인을 찾을 수 있습니다.

> techblog.woowahan.com

## 핵심 내용

카카오톡 교환권 이미지를 배민 앱에 등록하는 바코드 인식 기능에서 일반 캡처는 정상인데 ‘내 앨범에 저장’한 이미지의 노란 테두리 때문에 인식이 실패했습니다. 테두리가 이진화 임곗값에 영향을 줘 바코드 일부가 유실됐고, 단순 이미지 자르기 대신 `zxing.js` 내부 그레이스케일·블록별 이진화 과정을 분석해 원인을 좁혔습니다.

같은 바코드여도 이미지 주변 색상과 테두리가 바뀌면 이진화 알고리즘이 예상과 다른 밝기 분포를 만들 수 있다. 원문은 단순히 바코드 이미지 영역을 잘라내는 우회책보다 `zxing.js`의 그레이스케일과 블록별 이진화가 실제 입력에서 어떤 픽셀을 버리는지 추적했다. 이 과정은 라이브러리를 탓하기보다 **입력 데이터의 특성과 알고리즘의 전제**를 연결한 디버깅이다.

| 재현 입력 | 확인 항목 |
| --- | --- |
| 일반 화면 캡처 | 정상 인식 여부 |
| 카카오톡에서 앨범 저장한 이미지 | 노란색 테두리·밝기 변화 |
| 그레이스케일 변환 | 색상 정보가 밝기 분포로 바뀌는 방식 |
| 블록별 이진화 | 바코드 선이 배경과 합쳐지는지 |

유사한 이미지 처리 장애라면 디코더를 전면 교체하기 전에 실패한 샘플을 회귀 테스트로 저장하고 전처리 단계별 결과를 비교하는 것이 효과적이다.

## 왜 읽을까

라이브러리가 실패했을 때 임시 우회보다 내부 처리 과정을 읽고 가설을 세우는 트러블슈팅 흐름이 구체적입니다. 실제 사용자 입력이 개발 샘플보다 훨씬 다양하다는 것도 잘 드러납니다.

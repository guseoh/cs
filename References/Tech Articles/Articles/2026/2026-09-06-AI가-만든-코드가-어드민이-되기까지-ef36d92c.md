# AI가 만든 코드가 어드민이 되기까지

> [!abstract] 한 줄 정리
> AI가 코드를 생성하는 것만으로는 제품이 되지 않는다. 보안 정책은 서버가 통제하고, AI가 만든 UI 코드는 사용자별로 격리된 실행 환경에서 안전하게 빌드·실행하도록 경계를 설계해야 한다.

> Toss Tech · 2026-09-04

## 핵심 내용

- **문제:** 어드민마다 스캐폴딩·인증·배포·개인정보 마스킹·조회 사유 기록 같은 작업을 반복해야 했고, AI가 만든 React 코드를 즉시 제품에서 보여 줄 안전한 실행 환경도 필요했다.
- **구조:** 개인정보 마스킹·다운로드 암호화·조회 사유 수취 등 필수 정책과 API 호출 기록은 TOI 서버 프록시가 책임지고, 화면 생성은 AI에게 맡겨 정책과 표현 계층을 분리했다.
- **수치:** TOI는 2026년 2월 사내 공개 후 8월까지 6개월 동안 439개 프로젝트와 2,418개 하위 페이지가 만들어졌다.
- **트레이드오프:** Next.js Dev Server는 여러 사용자가 실행 환경을 공유해 한 사용자의 컴파일 오류가 다른 사용자 화면까지 오염시켰고, Sandpack은 사용자 격리는 해결했지만 첫 Preview가 47초 걸리고 private registry 인증·CORS/PNA 문제가 추가됐다.
- **접근:** 최종적으로 브라우저 안에 가상 파일 시스템과 esbuild-wasm 기반 Preview Runtime을 두고, 패키지는 미리 준비해 실행 시 연결하는 방향으로 전환했다.

## 왜 읽을까

AI 기능을 제품에 넣을 때 모델이나 프롬프트보다 더 중요한 것이 실행 경계와 권한이라는 점을 보여준다. PoC에서 잘 동작한 Dev Server와 Sandpack을 실제 다중 사용자·보안·응답시간 조건에 대입해 버린 이유도 구체적이라, 기술 선택을 제품 요구사항으로 검증하는 사고를 배우기 좋다.

**프로젝트에 적용 — DevPedia**

- [ ] AI가 생성하는 영역과 서버가 강제해야 하는 인증·권한·데이터 보호 정책을 명시적으로 분리한다.
- [ ] AI 생성 코드나 플러그인을 실행한다면 사용자/작업 단위 격리와 Secret 비노출을 완료 조건에 넣는다.
- [ ] PoC 도구를 채택하기 전에 첫 실행 지연, 의존성 공급, CORS와 인증 경계를 실제 환경에서 측정한다.

# AI 에이전트를 위한 Playwright E2E 테스트 하네스 구축하기

> [!abstract] 한 줄 정리
> AI가 코드를 많이 만드는 것보다 실패를 실제 사용자 흐름에서 재현하고 스스로 수정할 수 있는 피드백 루프가 더 중요합니다.

> d2.naver.com

## 핵심 내용

AI 에이전트가 기능 코드를 작성하는 데서 끝나지 않고 Playwright 기반 E2E 테스트를 생성·실행해 결과를 검증하도록 만든 워크플로입니다. AI 사용 후 사람이 실패 원인을 계속 찾고 수정해 생산성이 떨어지는 문제를 해결하려고 실제 브라우저 검증 환경을 하네스에 포함했습니다.

Playwright를 에이전트에 연결하면 UI를 구현한 뒤 '컴파일이 성공했다'는 수준에서 벗어나 실제 브라우저 동작을 확인할 수 있다. 하지만 테스트가 자동 생성되었다는 사실만으로 적절한 행동을 검증했다고 보장할 수는 없다. 사용자의 핵심 흐름과 실패 시나리오를 기준으로 **테스트 Oracle(예상 결과)**을 정하고 실행 결과를 AI 수정 루프에 연결하는 것이 중요하다.

| 피드백 단계 | 확인 대상 |
| --- | --- |
| 정적 검사·빌드 | 타입·문법·번들 문제 |
| Playwright E2E | 탐색·입력·화면·네트워크 상호작용 |
| 실패 증거 수집 | 스크린샷·trace·console·요청 결과 |
| AI 수정 제안 | 실패 원인과 변경 범위 |
| 재실행 | 재현된 실패와 기존 회귀 |

시각적으로 그럴듯한 화면보다 테스트하기 쉬운 결정론적 절차를 마련해야 사람의 반복 확인 부담이 줄어든다.

## 왜 읽을까

AI 품질을 프롬프트나 리뷰만으로 보장하지 않고 실제 사용자 흐름을 실행할 수 있는 환경이 필요하다는 관점이 PawCycle의 에이전트 검증과 잘 맞습니다.
